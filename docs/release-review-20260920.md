## 변경 범위

- OX 문항 수 10·15·20개 선택, 단원 전체를 섞은 뒤 세트 분할, 이어 풀기 순서 보존.
- OX 지문·해설 나눔고딕 폰트와 북마크 위치 조정. 폰트 파일과 OFL 라이선스 포함.
- OX 홈의 요약 데이터와 학습에 필요한 지문을 분리해 로딩. 새 읽기 전용 DB 함수 1개 추가.
- OX 기기 인증 서명 쿠키로 반복적인 기기 확인 DB 요청 생략.
- 기존 띄어쓰기 교정 결과·감사 기록과 로컬 검증 스크립트 포함. 이미 반영한 교정을 다시 실행하지 않는다.
- 서버 비용 감사 문서는 기록만 포함하며 서버·과금 설정 변경은 없다.

## 검토 중 보완

설치된 앱의 서비스워커가 이전 파일을 캐시에서 계속 제공할 수 있었다.
캐시를 `outing-auth-app-v443-ox-learning`으로 갱신하고 `app.js` 및 OX JS/CSS에
`20260920-ox-learning` 버전을 적용했다. 모듈 사전 로드·실제 import·스타일·사전 캐시의
주소를 맞추고 회귀 검사에 추가했다. 열린 화면을 강제로 새로고침하는 처리는 추가하지 않았다.
교사 화면의 변경은 공유 `app.js` 파일의 버전 주소뿐이다.

브라우저 QA 스크립트도 새 DB 함수와 폰트를 사용하도록 갱신했다.

## 최종 확인할 인증 동작

기기만 차단한 경우 이미 발급한 OX 쿠키는 최대 12시간 유효하다. 만료 시간은 사용 중 연장되지 않는다.
OX 등록 해제·계정 비활성화·서비스 중지는 매 요청 검사하므로 다음 요청부터 적용된다.
이는 의도된 동작 변경이며, 이번 배포 승인에 포함되어야 한다.

## 승인 후 반영 순서

1. 현재 검토한 파일을 커밋하고 원격 `main`에 새 변경이 없는지 재확인한다.
2. `20260920114238_ox_progressive_loading.sql`만 운영에 적용하고 함수 권한과 요약 응답을 읽기 검증한다.
   이전 OX 생성·등록 마이그레이션 및 띄어쓰기 교정·초기 import를 재실행하지 않는다.
3. `main`에 한 번 푸시해 연결된 Vercel 자동 운영 배포를 진행한다. 별도 CLI 배포는 중복 실행하지 않는다.
4. 배포 커밋·Ready·운영 자산 버전·공개 설정·미인증 API 차단을 확인한다.
   실제 학생의 답안·메모를 검증용으로 생성하지 않는다.

새 함수가 없는 동안 새 API는 기존 전체 bootstrap으로 대체하며, 기존 앱도 계속 지원한다.
앱 문제가 있으면 이전 Vercel 운영 배포로 복구할 수 있다. 새 함수는 추가만 하는 변경이므로
앱 롤백을 위해 삭제하거나 학생 데이터를 되돌릴 필요가 없다.

로컬 저장된 Vercel API 인증으로 조회 시 403 Not authorized가 발생했다. 브라우저에서는
운영 상태와 Git 자동 배포 연결을 확인했으므로 푸시 기반 배포 준비를 막지는 않는다.
CLI/API 직접 배포가 필요해지면 해당 인증을 갱신해야 한다. 로컬 `.vercel` 환경 파일은
배포 URL 검증을 통과하지 못해 사용하지 않았으며, 이를 운영 환경에 올리거나 덮어쓰지 않는다.
이번 로컬 빌드 검증은 공개 운영 설정으로 수행했으며, Vercel의 실제 원격 빌드 성공은 배포 후 확인한다.
