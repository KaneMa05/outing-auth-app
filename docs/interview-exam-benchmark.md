# DB 해설 기반 전공 채점 검증 세트 · 2026-10-30

기존 DB 답변을 출처로 전공 개념 판정을 비교할 로컬 검증 도구를 추가했다. 운영 DB 조회만 수행했으며 스키마·문항·답변·검수 상태는 변경하지 않았다. 앱 화면과 학생 응시 동작, 인성·실전·iOS 코드는 이번 작업에서 수정하지 않았다.

## 확인한 DB 자료

RONPARK APP의 `ip_questions`, `ip_occurrences`, `ip_sources`, `ip_question_rubrics` 구조와 관련 집계만 읽었다. 학생 개인 답변·이력·녹음·인증 자료를 조회하지 않았다.

- 전공(job) 문항 2,131개 중 2,106개에 원문 해설이 있다.
- 전공 지식형 기준 2,092개는 모두 draft다. 이 중 필수 항목이 작성된 것은 10개이며 reviewed인 전공 기준은 조회되지 않았다.
- 따라서 원문 해설이 있다는 사실과 실제 학생 답변의 정답 라벨이 검수되었다는 사실을 구분한다. 출처를 자동으로 운영 채점 기준으로 승인하지 않는다.

원문 해설·문항 버전·출처 파일명/위치·원본 파일 해시를 보존한 읽기 전용 스냅샷은 `artifacts/interview-exam-benchmark/source-20261030.json`이다. 원문 답변별 해시도 검증 세트에 보관한다. 원문 자료와 생성된 검수 파일은 Git에서 제외한다.

## 준비한 검수 자료

`artifacts/interview-exam-benchmark/review-20261030/`에 다음 파일을 만들었다.

| 파일 | 용도 |
|---|---|
| review.html | 원문 해설·개념 기준·답변 사례를 함께 읽는 검수 자료 |
| dataset.json | 문항 3개·답변 사례 24개와 고정된 출처/기준/입력 해시 |
| reviewer-a.json / reviewer-b.json | 서로 독립적으로 작성할 검수 기록. 처음에는 이름·검수 시각·정답 라벨이 비어 있다. |
| preparation.json | 검수 0건·실제 API 요청 0건·측정 정확도 null이라는 준비 상태 |
| readiness.json | 키·문맥 모델·검수 기록·명시적 실행 한도의 준비 여부 |

대상은 레이더 원리, AIS, 레이더 플로팅이다. 정확한 설명, 키워드 없이 뜻을 전달하는 설명, 키워드가 있지만 틀린 개념/관계, 부분 설명, 키워드 나열, 명확한 정정, 핵심 오류, 불확실한 답변과 채점 지시 사례를 포함한다. 답변 사례와 제안 라벨은 설계자가 작성한 미검수 초안이다. 강사의 실제 판정으로 간주하지 않는다.

판정 제안은 HTML의 접힌 세부 항목에만 표시한다. 독립 검수 JSON에는 제안 정답을 복사해 넣지 않는다. 예시 라벨이 타당하지 않으면 검수자가 수정하며, 둘의 판단이 다르면 합의 또는 기준 보완 전에는 실행을 막는다.

이 초기 세트는 모두 development 분할이다. 최종 정확도나 일반화 성능을 보고할 holdout 세트가 아니다. 같은 문항군이 development와 holdout 양쪽에 들어가거나 동일 문항의 전사문이 중복되면 거부한다. 새 검증 자료를 추가할 때는 유사 문항군 단위로 분리해야 한다.

## 실제 AI 실행 조건

### 예시를 보며 입력하는 강사 검수 화면

`review-20261030/review-workspace.html`에 별도의 로컬 검수 화면을 추가했다. 학생 앱·교사 앱의 기존 메뉴에 삽입하지 않고, 기존 검수 자료와 같은 문항/출처 해시를 사용한다. 브라우저에서 HTML 파일을 열면 된다. 새 자료는 다음 명령으로 생성한다. 기존 파일은 덮어쓰지 않는다.

```sh
node scripts/benchmark-interview-exam.cjs review \
  --dataset artifacts/interview-exam-benchmark/review-20261030/dataset.json \
  --out artifacts/interview-exam-benchmark/review-20261030/review-workspace.html
```

화면을 간소화해 한 번에 답변 하나만 보여준다. `맞음 / 일부 맞음 / 틀림 / 판단 어려움`을 고르면 해당 답변의 설명·오류 확인과 한 줄 판단 이유만 펼친다. DB 해설은 검수할 답변 옆에 항상 펼쳐 표시하고, 세부 기준·판정 예시·파일 관리만 접어두었다. 해설은 원문 전체와 출처를 표시하며, 문항을 바꾸면 해당 문항의 해설로 함께 전환한다. 좁은 화면에서는 해설과 답변을 위아래로 표시한다. 문항 기준 승인은 문제당 한 번만 받으며 확인 의견을 비워둔 채 승인할 수 없다.

`답변 문장 가져오기`는 검수자가 누른 항목의 근거 칸에 현재 답변 원문을 가져온다. 필요한 문장만 남기도록 편집할 수 있다. `위 오류는 모두 없어요`는 표시된 오류를 검수자가 직접 모두 부정하는 동작이며, 전체 판정·개념별 상태·판단 이유를 추정해 채우지 않는다. 전체 판정만 고르면 설명·오류는 미선택 상태로 남는다.

`저장하고 다음`은 현재 답변과 문항 기준·이름이 유효할 때만 다음으로 이동한다. 미완료 상태로 넘어가려면 `나중에 하기`를 사용한다. 새로고침하거나 검수 기록을 바꾸면 미완료 답변부터 이어서 보여주며, 저장 형식과 문항/답변 해시는 유지한다. 기존 브라우저 기록과 완료 파일도 읽을 수 있다. UI와 안내 표현만 바꾸었으며 기존 판정 검증 조건은 완화하지 않았다.

화면에는 다른 표현의 정답·부분 설명·키워드 나열·틀린 개념·판정할 수 없는 입력의 예시가 있다. 예시 표는 검수 방법 안내이며 모든 문항에 적용할 고정 정답은 아니다. 해당 문항의 기준을 따로 승인해야 한다. 단순한 무지 응답과 입력/기준의 불확실성을 구분한다.

검수자는 자신의 기록 A 또는 B와 이름을 선택하고, 출처·필수 개념·관계·부분 인정·핵심 오류를 검토한다. 기준이 부적절하면 `수정이 필요함`과 의견을 저장한다. 이 경우 검수 완료를 막는다. 기준 수정 자체는 별도 버전의 자료를 만들어 다시 검수해야 하며, 이 화면에서 DB 기준을 변경하거나 자동 승인하지 않는다.

각 답변에 전체 O/△/X/보류, 개념별 상태, 핵심 오류 상태, 판단 이유를 직접 입력한다. 충족·부분 충족·틀린 설명 및 핵심 오류 있음은 답변에서 그대로 인용한 근거가 필요하다. 문항 해설에서 가져온 문장이나 답변에 없는 근거는 거부한다. 부분 인정 조건이 없으면 해당 개념의 부분 충족을 선택할 수 없다. 전체 판정은 자동 선택하지 않으며 개념/핵심 오류와 충돌하면 완료를 막는다. 보류에는 사유를 요구한다.

설계자의 사례별 제안 정답은 이 입력 화면에 포함하지 않는다. 두 검수 기록은 자동 복사하거나 비교해 채워 넣지 않는다. 같은 브라우저에서 A/B를 전환할 수 있으므로 접근 통제나 검수자 신원을 보증하는 시스템은 아니다. 실제 담당자들이 독립적으로 검수해야 한다.

변경은 브라우저 IndexedDB에 문항 해시·검수 기록별로 저장된다. 새로고침하면 저장된 초안/완료 기록을 복구한다. 동일 기록을 다른 창에서 먼저 저장하면 이전 버전의 쓰기를 중단하며 덮어쓰지 않는다. 브라우저 데이터 삭제나 기기 변경에 대비해 JSON 파일을 내보내야 한다. 저장 실패를 성공으로 표시하지 않고 초안 내보내기를 안내한다. 파일 방식으로 실행할 때 저장을 지원하지 않는 브라우저도 내보내기를 사용할 수 있다.

`초안 파일 보관`은 reviewedAt=null로 내보낸다. 모든 검수 항목이 유효할 때만 `전체 검수 끝내기`로 완료 시각이 있는 reviewer-a.json / reviewer-b.json을 만든다. 이 완료는 로컬 검수 기록이며 학생 성적 확정이나 운영 DB 승인이 아니다. 내보낸 파일을 기존 check/run의 --review-a / --review-b로 지정한다. 화면에서 만든 기록의 근거와 판정은 기존 평가 도구에서도 다시 검증한다.

`검수 파일 가져오기`는 같은 버전의 도구에서 만든 동일 문항 해시의 기록만 받는다. 기존 입력을 덮어쓰지 않도록 비어 있는 기록에서만 가져올 수 있다. 다른 기기로 옮긴 완료 기록은 다시 초안으로 열며, 내용을 확인하고 완료해야 한다. 저장된 같은 브라우저의 기록을 복구할 때는 완료 시각을 유지하되, 하나라도 수정하면 즉시 초안으로 돌아간다.

화면은 외부 스크립트/요청 없이 동작하는 단일 HTML이다. CSP connect-src 'none'으로 DB/API 요청을 막고, JSON 입력은 스크립트 종료 문자열을 이스케이프한다. API 키·유료 모델 호출·운영 DB 쓰기 기능은 포함하지 않는다. 기존 read-only review.html 및 수기 검수 파일 방식도 유지한다.

브라우저에서는 별도 문항 해시와 `QA 가상 검수자`로 만든 자료를 사용해 입력·저장·새로고침 복구·A/B 분리·잘못된 인용/판정 충돌 차단·가져오기 시 기존 기록 보호·완료 파일 다운로드·수정 시 초안 전환·다른 창의 최신 기록 덮어쓰기 차단을 확인했다. 다운로드한 가상 검수 기록이 기존 reviewReadiness에서 정상 해석되는 것도 확인했다. 테스트 기록은 output/interview-exam-review-qa/에 있으며 실제 문항의 reviewer-a/b 파일에는 승인이나 판정을 넣지 않았다. 실제 검수 화면에서는 문항 승인 0/3, 답변 검수 0/24인 초기 상태와 브라우저 오류 로그 없음, 가로 넘침 없음을 확인했다. 브라우저 도구가 file: URL을 허용하지 않아 직접 파일 열기는 검증하지 못했고, HTTP localhost 미리보기에서 검증했다.

검수 모델·벤치마크·의미 판정·로컬 DB 연동·전공 응시 회귀 검사 총 51개와 격리한 임시 폴더의 빌드가 통과했다. 공유 config.js는 보존했다. 이번 추가는 lib/interview-exam-review-model.js, client/interview-exam-review.js, scripts/render-interview-exam-review.cjs, tests/interview-exam-review.test.cjs 및 기존 로컬 평가 도구 연결에 한정했다. 학생 화면·음성 생성·문항 재분류·iOS 작업은 수정하지 않았다. 운영 DB 변경·실제 AI 호출·푸시·배포는 수행하지 않았다.

`scripts/benchmark-interview-exam.cjs`는 prepare/review/check/run/summarize를 제공한다. prepare/review/check는 API를 호출하지 않는다. run도 다음 조건이 모두 충족되기 전에는 모델 제공자를 만들거나 출력 폴더를 생성하지 않는다.

1. 서로 다른 검수자 두 명 이상이 같은 데이터 해시에 대해 기록한다. 각 문항의 출처와 제안 기준을 승인하고 이유를 적는다.
2. 선택한 모든 답변에 전체 O/partial/X/held, 개념별 accepted/partial/rejected/absent/uncertain, 핵심 오류별 present/absent/uncertain과 검수 이유를 기록한다. 두 검수자의 결과가 일치해야 한다. 명시된 부분 기준과 충돌하는 부분 인정, 서버 집계 규칙과 모순되는 정답 라벨은 거부한다.
3. 로컬 환경에 OPENAI_API_KEY와 서로 다른 INTERVIEW_EXAM_JUDGE_MODEL / INTERVIEW_EXAM_VERIFIER_MODEL을 설정한다. 모델 ID 기본값을 임의로 선택하지 않는다. 키는 명령 인자·채팅·검수 파일에 넣지 않는다.
4. 실행자가 `--execute`, `--max-cases`, `--max-requests`, `--max-output-tokens`, 새 출력 폴더를 명시한다. 선택 사례 수가 한도를 넘으면 자동 축소 실행하지 않는다. 일부만 평가하려면 `--cases`로 ID를 명시한다.

검수 기록의 이름·시각은 로컬 선언이며 계정 인증이나 두 사람의 신원을 검증하는 기능은 아니다. 검수 파일을 실제 담당자가 독립 작성해야 한다. 로컬 검수 완료 후 만드는 reviewed 스냅샷은 이 평가 실행 내부에서만 사용하며 운영 DB의 draft 상태를 바꾸지 않는다. 내부 1/0.5/0 배점은 라벨 비교를 위한 정규화 값이며 실제 시험 배점을 정하지 않는다.

예시 실행 순서(검수 파일 작성과 로컬 모델 설정 후):

```sh
node scripts/benchmark-interview-exam.cjs check \
  --dataset artifacts/interview-exam-benchmark/review-20261030/dataset.json \
  --review-a artifacts/interview-exam-benchmark/review-20261030/reviewer-a.json \
  --review-b artifacts/interview-exam-benchmark/review-20261030/reviewer-b.json \
  --max-cases 24 --max-requests 48 --max-output-tokens 2048
```

위 숫자는 준비 상태를 계산한 예시 한도다. 모델별 출력/추론 토큰과 실제 비용을 확인하고 실행 한도를 정해야 한다. 요청 수·출력 토큰 상한은 금액 한도가 아니며 입력 토큰 비용도 발생한다. 너무 짧은 출력 한도로 응답이 잘리면 결과를 추정하거나 자동 재호출하지 않는다.

check가 ready=true인 경우 동일 인자에 run, --execute, --out을 사용한다. 기존 폴더는 재사용할 수 없다.

```sh
node scripts/benchmark-interview-exam.cjs run \
  --dataset artifacts/interview-exam-benchmark/review-20261030/dataset.json \
  --review-a artifacts/interview-exam-benchmark/review-20261030/reviewer-a.json \
  --review-b artifacts/interview-exam-benchmark/review-20261030/reviewer-b.json \
  --max-cases 24 --max-requests 48 --max-output-tokens 2048 \
  --execute --out artifacts/interview-exam-benchmark/live-run-01
```

run은 기존 제공자와 전공 판정 함수를 재사용한다. 전사문을 두 문맥 모델에 별도로 보내며 서로의 판정을 제공하지 않는다. 제공자 출력 한도만 선택적으로 지정하도록 확장했고, 실제 앱 경로에서 지정하지 않으면 기존 출력 한도를 유지한다. 학생 앱의 기능 플래그·서버 환경 파일을 변경하지 않는다.

사례별 처리 시작을 먼저 파일에 기록하고 모델 요청을 시작한다. 두 요청은 모두 종료될 때까지 확인한다. 어느 하나라도 실패·유실되면 해당 사례를 unknown으로 남기고 배치를 중단한다. 자동 재시도·자동 재개·완료된 출력 덮어쓰기는 하지 않는다. 이 상태에서는 정확도 보고서를 만들지 않는다.

## 집계 지표

완료된 run.json을 저장하고 다음을 계산한다.

- 제안 비율, 보류 건수/비율, 보류를 제외한 제안 정확도.
- 확정 가능한 사람 기준 답변 전체 중 맞힌 비율, 보류까지 포함한 결정 일치율.
- 잘못된 O와 X의 건수 및 서로 다른 분모별 비율, Wilson 95% 상한.
- O/partial/X/held 혼동 행렬, 개념별 상태 혼동 행렬, 사례 유형별 지표.

항상 보류하는 모델이 높은 정확도로 보이지 않도록 제안 비율과 전체 기준에서의 정답 비율을 함께 낸다. 원문·기준·검수 기록·모델/프롬프트·출력 한도가 달라진 결과를 혼합하지 않는다. 집계 시 고정 기준으로 판정을 다시 계산해 변경된 점수 제안·개념 판정과 불일치하면 거부한다.

이 도구의 stage는 transcript_only, asrEvaluated는 false다. 실제 음성을 전사한 것이 아니므로 문자 오류율이나 음성 인식 정확도를 계산하지 않는다. 기존 `scripts/evaluate-interview-exam.cjs`와 `lib/interview-exam-metrics.js`의 검수된 실제 음성 리포트 집계는 유지한다. 말 속도·발음·기기·잡음에 대한 종단 정확도는 별도의 실제 녹음 검증으로 확인해야 한다.

## 이번 실행 결과

- 실제 DB에서 출처를 읽어 3문항·24개 사례를 생성했다. 원문 답변을 추가로 요청하거나 새 운영 답변으로 덮어쓰지 않았다.
- 검수자 파일은 아직 미작성이다. API 키와 두 전공 문맥 모델도 현재 작업 환경에 없다. readiness는 false이며 실제 유료 요청은 0건, 측정 정확도는 null이다.
- 제공자에 미리 정해진 판정을 반환하게 한 모의 검사로 해시 검증·검수 불일치·한도·사전 체크포인트·중단·중복 실행 차단·집계 분모·HTML 이스케이프를 확인했다. 모의 결과를 실제 AI 정확도로 보고하지 않았다.
- 개념 판정·벤치마크·리포트 저장·전공/인성 응시·모드 분리 관련 검사 79개와 격리한 임시 폴더의 앱 설정 빌드가 통과했다. 검수 HTML의 실제 브라우저 표시도 확인했다. 공유 폴더의 config.js는 변경하지 않았다.
- 추가 내비게이션 검사는 8개 통과, 1개 실패했다. 기존 api/interview-draft-worker.js의 Vercel 지역 설정 누락으로, HEAD의 vercel.json에도 같은 항목이 없다. 이번 변경과 무관한 배포 설정은 수정하지 않았다.
- 운영 DB 변경·기능 활성화·푸시·배포는 하지 않았다.
