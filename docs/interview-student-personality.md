# 학생 인성 연습모드 연결

2026-10-29 로컬 구현·검증 기록. 운영 DB 적용·유료 API 호출·푸시·배포 없음.

## 학생 흐름

면접반 학생 앱 `모의면접 → 인성 연습모드`에만 연결했다.

1. 본인 직렬에 맞는 공개·검토 완료 인성 경험/의견 문항을 선택한다. 단순 이력 확인(profile)이나 전공 문항은 제외한다.
2. 시작 동작에서 마이크 권한을 받은 뒤 서버에 연습 기록을 생성하고 질문·승인 버전·분석 규칙 버전을 고정한다.
3. 최대 90초 녹음하여 공통 IndexedDB 저장소에 personality 모드로 보존한다. Web Locks로 다른 창의 녹음과 충돌하지 않게 한다.
4. 녹음 종료 후 원음을 재생하고 명시적으로 제출한다. 브라우저에서 16 kHz·모노·16비트 PCM WAV로 변환하고 인성 전용 제출 캐시에 확정한다. 재전송 시 같은 바이트를 사용한다.
5. 서버에서 WAV 실제 형식·기간·용량을 검사하고 답변 해시를 고정한다. 비공개 인성 버킷에 저장한 뒤 전사와 구조 분석을 실행한다.
6. 리포트를 저장하여 학생에게 표시한다. 새로고침 이후에도 본인 음성·리포트를 조회하고 다시 연습할 수 있다. 조회만으로는 AI를 재호출하지 않는다.

초기 제한은 문항별 90초, 시작 후 3분 이내 최초 제출, 하루 3회 시작, 인성 처리 동시 5건이다. 전공 제한과 별도이며 기존 전공 동작은 바꾸지 않았다. 취소한 시작도 일일 횟수에 포함한다.

## 구조 분석

`lib/interview-personality-analysis.cjs`에서 버전 `personality-structure-1`을 관리한다.

| 요소 | 확인 내용 |
|---|---|
| 결론 | 질문에 대한 입장·직접 답 |
| 이유 | 결론의 구체적인 근거 |
| 경험 | 본인의 상황·행동·결과 |
| 마무리 | 배운 점·직무에서 실천할 방향 |

요소별 존재 여부(present/missing/uncertain)와 내용 충실도(clear/partial/insufficient/not_assessable)를 구분하고 실제 답변 인용·보완 의견을 제공한다. ‘결론’, ‘이유’ 같은 이름을 말했는지만으로 충족시키지 않도록 모델에 지시한다.

경험의 상황·본인 행동·결과도 각각 원문 근거로 표시한다. 경험이 충분(clear)하려면 세 근거가 모두 있어야 한다. 결론→이유, 이유→경험, 경험→마무리의 연결도 각각 확인한다. 연결 근거는 양쪽 요소의 인용을 포함해야 한다.

순서는 모델이 주장한 숫자를 쓰지 않고 서버가 정확한 인용의 전사문 위치로 계산한다. 같은 문장이 반복되거나 근거 구간이 겹치면 순서를 확정하지 않는다. 확인된 일부 요소가 권장 순서를 따르는 것과 네 요소가 모두 있는 것은 구분한다.

반복·모순은 두 개의 실제로 존재하는, 겹치지 않는 인용과 보완 의견을 제공한다. 마지막에 요약과 다음 연습 과제를 표시한다. 점수·O/△/X·등수·성격·합격 가능성 평가를 요구하지 않으며 서버 리포트의 grade/score는 항상 null이다.

### 근거 검증과 보류

- 음성은 기존 파일 전사 경로를 재사용하여 두 번 전사한다. 질문·모범답안·이전 전사문은 음성 전사에 보내지 않는다.
- 두 결과가 다르거나 음성이 너무 작음/클리핑/전사 실패이면 구조 분석을 보류한다.
- 분석 응답은 고정 JSON Schema를 사용한다. 모든 요소, 상태값, 글자 수, 연결 쌍, 실제 인용, 중복·겹치는 근거, 임의 점수 필드를 서버에서 다시 검사한다.
- 원문에 없는 문장이나 잘못된 응답은 정상 피드백으로 저장하지 않는다. `review_required`와 보류 사유·원음/전사 기록을 남긴다.
- 정상 피드백은 `practice_feedback`이다. 유효한 구조 응답이어도 의미 판단의 정확도를 보증하는 것은 아니다. 같은 전사 모델의 두 요청도 통계적으로 독립적인 검증은 아니다.

공식 OpenAI documentation의 [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses)를 확인하고 Responses API의 strict JSON Schema를 사용했다. 형식 일치가 사실·분석 정확도를 보장한다고 해석하지 않는다. 실제 사람 음성의 품질·의미 판정 평가는 후속 검증이다.

## 저장·권한·중복 처리

새 `/api/interview-personality`, `ip_personality_attempts`, `ip_personality_service`, 비공개 버킷 `interview-personality`를 추가했다. 전공 테이블·버킷·분석 모델·기능 플래그와 분리했다.

인성 질문은 관리자 분류가 personality_experience/personality_opinion으로 검토 완료되고, 원문과 검토 기준의 본문·분류가 일치하며 공개된 문항만 사용한다. 빈 전공 채점 기준이나 배점을 요구하지 않는다.

기존 웹 세션/기기 인증을 재사용하며 기기 인증에는 기존 previewAllowed 제한을 유지한다. 학생 ID만으로 접근하거나 학생이 분석·전사·점수를 위조해 제출할 수 없다. 본인의 활성 수강·직렬·기간을 검사하고 본인 기록만 조회한다. 공개 응답에는 모델 설정·내부 감사 정보·검토자 메모를 보내지 않는다.

DB는 RLS를 활성화하고 anon/authenticated의 직접 접근을 차단했다. 함수는 SECURITY INVOKER와 빈 search_path를 사용하며 service_role에만 실행을 허용한다. 원음은 DB 바이너리로 저장하지 않고 비공개 Storage의 `{attemptId}/answer.wav`에 보관한다. 같은 이름의 기존 버킷이 공개라면 새 마이그레이션이 거부한다.

`started → uploading → evaluating → completed`로 처리한다.

- 저장 실패(upload_failed)는 같은 기기 WAV로 재시도할 수 있으며 이 단계에서 AI를 호출하지 않는다.
- 동일 제출이 중복·동시 도착하면 DB claim으로 한 요청만 처리한다. 완료된 리포트는 재사용한다. 같은 응시의 다른 음성 바이트는 충돌로 거부한다.
- 분석/결과 저장이 불확실하면 unknown으로 표시한다. 과금될 수 있는 분석은 자동 재실행하지 않는다.
- 빈 녹음·권한 거절·화면 파괴·전송 실패 시 녹음 상태와 마이크를 정리한다. 인성 화면의 중단 복구는 personality 기록만 대상으로 한다.
- 기기 원본과 인성 제출 WAV는 서버 전송 후에도 보존한다. 기기 녹음 삭제는 그 기기의 사본만 제거한다.

서버 음성·리포트는 시작 시 수강 종료일을 기준으로 종료 후 30일째 날까지 보관한다. 만료 즉시 접근을 차단하며, 최대 60초의 재생 링크도 남은 보관 기간보다 길게 발급하지 않는다. `cleanup` POST는 CRON_SECRET Bearer 인증을 요구하고 Storage 실제 삭제 성공 후 DB를 삭제한다. 정리 스케줄은 아직 등록하지 않았으며 운영 활성화 전에 연결해야 한다.

Supabase의 [Storage access control](https://supabase.com/docs/guides/storage/security/access-control)을 확인했다. 로컬 PGlite에서 RLS·권한·함수 설정을 검사했으며 운영 Advisors나 운영 DB를 호출하지 않았다.

## 운영 적용 전 준비

공식 CLI `supabase migration new interview_student_personality`로 생성한 파일:

`supabase/migrations/20261029135643_interview_student_personality.sql`

운영에 적용하지 않았다. 기존 기반 마이그레이션 이후 적용하고, 전용 모델·비공개 저장소·보관 정리·실기기 검증을 확인한 뒤 활성화해야 한다.

```text
INTERVIEW_PERSONALITY_ENABLED=false
INTERVIEW_PERSONALITY_ANALYSIS_MODEL=<구조화 출력을 지원하는 검증할 모델>
OPENAI_API_KEY=<기존 서버 전용 키>
SUPABASE_URL=<기존 프로젝트>
SUPABASE_SERVICE_ROLE_KEY=<서버 전용 키>
CRON_SECRET=<32자 이상 서버 정리 비밀>
```

기능은 기본 비활성이다. 전공/관리자 검증 플래그를 켠다고 인성 연습이 켜지지 않는다. 전용 모델 값의 기본값은 두지 않았다. 유료 API는 실행하지 않았다.

새 Vercel 함수에만 syd1·최대 240초를 추가했다. 기존 전공 함수와 다른 함수 설정은 유지했다. 실제 요금제 실행 시간, 비용·부하, 서비스워커 캐시 갱신은 배포 단계에서 별도로 검토해야 한다.

## 검증 기록

신규 검사 27개:

- 구조 분석 8개: 네 요소의 근거·존재/충실도, 누락·순서·불확실성, 반복/모순 구간, 잘못된 인용·점수 주입 거부, 전사 불일치와 분석 실패 보류, 공급자 요청·거절 처리.
- 학생 API/로컬 DB 10개: 수강·직렬·승인 문항, 질문 고정, 리포트 저장/본인 조회, 중복·동시 제출, 전송 재시도, 저장 실패 후 자동 재분석 방지, 만료·일일 한도·RLS.
- 학생 UI 7개: 늦은 마이크 응답과 화면 파괴, 이동 차단·종료 저장, 제출 실패 보존, 리포트 표시·HTML 이스케이프, 전공 기록 복구/표시 방지.
- Storage 2개: 인성 전용 경로·불변 업로드·재생 시간 제한, 비공개 버킷 생성과 기존 공개 버킷 거부.

실제 내장 브라우저의 학생 앱 경로에서 합성음으로 MediaRecorder 녹음 → 기기 저장 → WAV 변환 → HTTP 제출 → 로컬 서버 음성/DB 저장 → 모의 구조 분석 → 네 요소 리포트 표시를 확인했다. 녹음 중 홈 이동 차단, 새로고침 후 본인 리포트·기록 재조회, 경험 근거와 권장 순서·연결성·다음 연습 표시도 확인했다. 물리 마이크·실제 AI 품질 테스트는 아니다.

기존 학생 전공 검사 19개, 키워드/관리자 리포트 13개, 공통 저장 12개, Live UI 5개, 네이티브 launcher 4개, release-safety 3개와 면접 DB/API 검사도 통과했다. 고유 임시 폴더에서 격리 빌드·변경 파일 구문 검사와 config.js 보존, 기존 함수 설정 보존을 확인했다.

기존 탐색 검사에서는 8개 통과, `interview-draft-worker.js` 지역 설정 누락 1개 실패가 남아 있다. 새 인성/전공 함수의 지역은 등록되어 있으며 범위 밖 설정을 수정하지 않았다.

격리 재현:

```sh
PGLITE_MODULE=/path/to/@electric-sql/pglite node scripts/interview-student-personality-preview.cjs
```

운영 계정·실제 학생 자료·운영 DB·유료 모델을 사용하지 않는다. 마이크 합성 대체는 tests/fixtures 안에만 있다.

## 남은 운영 검증과 작업 분리

실제 한국어 답변으로 요소 누락·빈약한 경험·주장/행동 모순·반복·정정·불분명한 발화·기기 차이를 평가해야 한다. iPhone/Android의 권한·절전·단절·원음 재생, 실제 Supabase 업로드/삭제와 만료 정리도 확인해야 한다. 숫자 점수화·공식 평가·관리자 확정 UI는 추가하지 않았다.

iOS 작업 파일, 무료 AI 테스트 서버, package.json, 전공 화면/서버/저장 모듈은 수정하지 않았다. 공통 녹음·WAV 변환은 기존 코드를 읽어서 재사용했고 인성용 학생 화면·분석·저장·캐시는 새 파일로 분리했다. 운영 DB 적용·푸시·배포 없음.
