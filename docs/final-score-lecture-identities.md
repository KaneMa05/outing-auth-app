# 파이널 성적 인강 아이디 구분

운영 적용 전 검토본. 원본 표의 123행 전체를 읽어 11개 열과 고유 인강 아이디 123개를 검증했다. 원본 성적은 운영 서버에 입력하지 않았다.

## 사용자 동작

- 엑셀에서 `이름 / 인강 아이디 / 직렬 / 법규 / 개론 / 형사 / 영어 / 항해 / 기관 / 형소법(공판) / 오답 수` 순서로 복사한다. 헤더 유무 모두 지원한다.
- 같은 기수의 동일 인강 아이디는 다른 회차 및 재입력에서도 같은 응시자로 처리한다. 대소문자와 앞뒤 공백은 정규화한다.
- 기존 아이디 없는 10열 입력도 유지한다. 이름·직렬이 겹치거나 서로 다른 아이디가 같은 학생에 연결될 경우 먼저 구분 화면을 표시한다. 한 학생에게 두 행을 덮어쓰지 않는다.
- 승인된 인강 가입 정보가 있으면 아이디로 기존 학생을 확인한다. 현재 기수 밖의 응시자는 별도 응시자로 석차에 반영한다. 기존 학생과 연결할 수 없는 경우에도 고유한 내부 응시자 번호를 사용한다.
- 입력 아이디는 관리자 붙여넣기 및 구분 화면에서만 사용한다. 관리자 성적표, 수강생 성적표와 공통 성적 데이터에는 넣지 않는다. 별도 응시자의 내부 번호도 성적표의 번호 칸에 표시하지 않는다.

## 저장 구조 및 범위

- 기존 `students.id` PK와 `final_exam_scores` 테이블 구조는 유지한다.
- `final_score_identities`는 `(cohort, lecture_id_normalized)`를 고유 키로 사용하며 기존 학생 또는 무작위 내부 응시자 번호를 연결한다.
- 새 테이블에 RLS를 적용하고 PUBLIC/anon/authenticated 권한을 제거한다. 서버 service_role에는 조회·추가 권한만 준다. 원문 아이디는 이 테이블에서만 보관하고 학생 브라우저의 상태/캐시에 넣지 않는다.
- 인증된 관리자 성적 권한을 확인하는 `/api/final-score-identities`를 추가한다. 일반 학생·비로그인 요청은 거부한다. 조회 결과와 오류 응답은 no-store다.
- 최초 연결은 점수 저장 전에 저장된다. 점수 저장 실패 시 다음 시도에서 같은 내부 번호를 재사용한다. 회차 삭제 시에도 식별자 연결은 남겨 다음 입력을 구분한다.
- 기존 학생 삭제는 FK의 SET NULL로 계속 가능하며 성적 데이터는 변경하지 않는다.

- 별도 사본 `tmp/final-score-lecture-id-release/candidate`에서 전체 `npm test` 통과.

- UI 로직 검사에서 신규·기존 형식, 동명이인 구분, 재시도, 인강 아이디의 공통 성적 데이터 유입 방지를 검증.
- 제공된 123행의 모든 식별/과목/오답 열을 원본과 비교했다. 테스트에는 가상 이름·아이디만 저장했다.
- 기존 운영 공개 설정으로 로컬 빌드 성공. app.js/student.js/학생 HTML 등 다른 작업은 별도 사본에 포함하지 않았다.
- 운영 기준은 `dpl_G2zKGZVdnQksXL7LG9TU1x64JNYs`. 이번 버전은 아직 운영 DB 적용·푸시·배포하지 않았다.

최종 승인 후 새 테이블 마이그레이션 `20260917025621_final_score_lecture_identities.sql`만 적용하고 접근 권한을 검증한 뒤, 별도 수정본을 배포한다. 다른 미적용 마이그레이션이나 기존 작업 폴더 전체를 일괄 적용하지 않는다. 관리자 화면의 성적 코드와 서비스워커에는 `final-score-lecture-id` 버전이 준비되어 있다. 원본 표는 사용자가 회차를 선택한 후 입력한다.
