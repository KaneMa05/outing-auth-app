면접반 반려 신청을 재신청 없이 승인 — 운영 반영 완료
2026-11-27

사용 방법
- 관리자 → 수강생·이용 관리 → 신청·승인 → 상태 '반려' 검색
- 대상 학생의 '다시 검토·승인'에서 기존 반려 사유를 확인한다.
- 수강 과정, 수강 만료일, 승인 안내를 확인하고 '승인'을 누른다.
- 반려 신청이 승인 완료로 이동하며 기존 반려 이력은 보존된다.

변경 범위
- 반려 → 승인만 추가 허용한다. 승인 완료 신청의 재처리와 반려 → 반려 재처리는 차단한다.
- 기존 승인 트랜잭션을 사용해 과정·만료일·등록 권한·처리 이력을 함께 반영한다.
- 관리자 쓰기 권한, revision 충돌 검사, 실패 시 입력 보존을 유지한다.
- 신규 면접 전용 계정은 일반 수강생 명단에 추가하지 않는다.
- 관리자 진입 스크립트와 모듈 버전을 갱신했다. 다른 수강생 화면의 UI는 변경하지 않는다.

DB 변경
- 20261127044253_interview_rejected_application_approval.sql
- 기존 ip_portal_service의 상태 검사 1곳만 변경한다.
- SECURITY INVOKER, search_path, RLS, service_role 전용 실행 권한을 유지한다.
- 사용자 최종 승인 후 운영 DB에 적용했다. 기존 신청 133건·등록 132명의 전체 데이터 체크섬과 함수 권한이 유지됐다.
- 관리자 화면도 후보 검증 후 운영에 배포했다. 기존 승인 대기 처리는 계속 호환된다.

검증
- 신청 과정·승인 DB/API 13개 통과: 세 과정, 신규·기존 계정, 이력·작성 답변 보존,
  만료일, 권한, 동시 수정·중복 요청, 실패 원자성 검사.
- 데스크톱/모바일 브라우저 통과: 반려 목록 재검토, 승인, 사유 표시, 읽기 전용 권한,
  실패·충돌 입력 보존, 중복 클릭 방지, 기존 반려·학생 재신청 흐름.
- 최신 main 기준 전체 면접 마이그레이션 96개와 시드 5개 검증 통과: RLS·RPC 권한·기존 학생 보존.
- 신청 요약·관리자 홈·이용 종료·인증 회귀 검사, 관리자 진입 버전 검사 통과.
- 격리 빌드·문법 검사 통과. 기존 config.js 보존.

사용자가 별도로 지정한 신청 1건
- 사용자 지시에 따라 기존 운영 승인 함수를 이용해 2026-12-20 만료로 승인했다.
- 대상 신청의 식별 정보·기존 상태·revision을 확인하고 단일 트랜잭션으로 처리했다.
- 기존 반려 이력과 구매 과정을 유지했으며, 승인 후 실제 면접 이용 권한을 다시 조회했다.
- 이 개별 데이터 처리는 기능 배포와 별개이며, 개별 승인 당시 공통 함수·스키마 변경은 없었다.
