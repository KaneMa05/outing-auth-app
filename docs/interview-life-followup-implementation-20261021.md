# 기본 정보 분리·인생그래프 추가 질문 구현

## 적용 범위

면접반의 나의 DB 정리하기에 적용한다. 기본 이력의 학교, 전공·학과, 동아리, 봉사 경험, 인턴 경험, 회사 경력, 담당 직무, 성과·역량을 각각 입력한다. 각 항목의 ‘해당 없음’ 체크는 별도 boolean으로 저장한다. 체크 전에 입력한 문장은 보관하고, 체크하면 AI 입력에서는 해당 없음으로 취급한다.

기존 `background`는 삭제하거나 자동 분해하지 않는다. 학생은 ‘이전에 작성한 소개’에서 확인할 수 있다. 새 `basicInfo`가 저장되면 초안 생성의 기본 정보와 완성 여부는 새 항목을 사용한다. 아직 전환하지 않은 기존 클라이언트는 기존 저장 형식을 사용할 수 있다. 관리자 조회에도 항목별 값을 표시한다.

## 학생 흐름

### 추가 질문 진입 위치 보완 (2026-10-21)

- 각 경험 카드의 ‘내용 수정’ 바로 옆에 추가 질문 버튼을 제공한다. 그래프 점을 눌러 연 상세보기에도 같은 버튼을 제공하며 같은 경험의 문답으로 연결한다.
- 미저장 변경이 있으면 ‘저장 후 추가 질문 시작’, 저장된 경험은 ‘추가 질문으로 자세히 쓰기’, 기존 문답이 있으면 ‘추가 질문 이어쓰기’, 최신 입력으로 만든 미반영 정리가 있으면 ‘정리 내용 확인’을 표시한다.
- ‘정리 내용 확인’은 질문 패널의 정리 결과로 이동한다. 원본·답변이 변경된 정리나 이미 반영한 정리는 이 상태로 표시하지 않는다.
- 모바일의 상세보기 버튼은 공간에 맞춰 줄바꿈한다. 기존 저장·수정 버튼과 관리자 화면 범위는 유지한다.
- `20261021085056_interview_life_followup_entry_state.sql`은 기존 인증·소유권 검사 뒤의 availability 응답에 `summary_ready`만 추가한다. 경험마다 별도 조회 요청을 보내지 않으며 테이블 권한과 기능 활성화 설정을 바꾸지 않는다.
- 로컬 PGlite에서 상태·소유권·반영 검사를 통과했고, 격리 Chrome에서 카드/그래프 진입·저장 후 시작·문답 복원·새로고침 후 정리 상태 복원·모바일 배치를 확인했다. 기존 인생그래프 DB/API·그래프 검사와 설정을 보존하는 격리 빌드도 통과했다.
- 운영 적용 시 이 신규 마이그레이션과 면접반 자산의 캐시 갱신을 함께 반영한다. 기존 추가 질문 기능이 비활성인 환경에서는 버튼이 표시되지 않는다. 이번 작업에서 운영 DB 변경·활성화·푸시·배포는 실행하지 않았다.

1. 경험의 나이·키워드·내용을 작성하고 ‘추가 질문으로 자세히 쓰기’를 누른다. 미저장 경험은 먼저 기존 `life_save`로 저장한다. 전체 이력 완성이나 어필할 점 작성은 시작 조건이 아니다.
2. 별도 패널에서 질문을 시작하고 답변한다. ‘기억나지 않아요’, ‘건너뛰기’도 저장한다.
3. ‘답변 저장’, ‘저장하고 다음 질문’, ‘지금까지 내용 정리’를 사용한다. 다음 질문·정리는 답변 저장 성공 후 실행한다.
4. 저장한 문답은 ‘추가 질문 이어쓰기’로 복원한다. 문답은 경험 원문과 별도로 보관한다.
5. 정리 결과의 근거를 펼쳐 확인하고, 기존 내용과 비교하여 편집한다. 내용과 어필할 점을 각각 선택하고 확인한 후 저장한다.
6. 반영 전 값으로 되돌릴 수 있다. 반영·복구 모두 최신 프로필 revision과 경험 원본 해시가 일치해야 한다.

질문·정리 이용 한도에 도달해도 답변 저장과 직접 정리는 가능하다. ‘다른 경험으로 추가하기’는 기존 입력 화면으로 연결하며 새 경험을 자동 생성하거나 기존 경험을 삭제하지 않는다.

## 생성 경로와 현재 제한

기본 제공 경로는 **검토된 기본 질문 + 원문 발췌 정리**다. AI 결과라고 표시하지 않는다. 질문의 탐색 항목, 답변 상태, 일부 명시적인 표현을 사용해 이미 다룬 항목을 제외한다. 이는 제한된 규칙 기반 분기이며 모든 자연어의 의미 중복을 이해하는 것은 아니다.

전용 생성 처리기를 연결할 수 있는 서버 어댑터와 출력 검증을 구현했다. 실제 유료 처리기를 선정하거나 호출하지 않았다. 연결 전에도 기본 질문, 답변 저장, 직접 비교·반영은 작동한다. 실제 AI의 질문 품질·처리 시간·요금은 별도 검증이 필요하다.

- 서버 활성화: `INTERVIEW_LIFE_FOLLOWUP_ENABLED=true`와 DB의 `ip_life_followup_config.enabled=true`를 모두 설정한다. 기본값은 비활성이다.
- DB의 `student_ids`에 시범 계정 ID를 지정한다. 빈 배열은 활성 면접반 전체이므로 공개 전 확인한다.
- 기본 한도: 학생당 하루 30회, 전체 하루 300회. 설정 값이며 운영 예산을 보장하는 금액 제한은 아니다. 학생당 동시 생성은 1건이다.
- 한 묶음 최대 3개, 최대 5묶음·15문항. 충분히 질문한 경우 추가 질문 없이 정리한다.
- 선택 연결: `INTERVIEW_LIFE_FOLLOWUP_ENGINE=remote`, `INTERVIEW_LIFE_FOLLOWUP_ENGINE_URL`(HTTPS), `INTERVIEW_LIFE_FOLLOWUP_ENGINE_TOKEN`(서버 비밀값).
- 요청: 선택한 경험·관련 문답, 허용 탐색 항목, 정책 버전, 기본 후보만 POST한다. 전체 프로필과 등록번호는 전달하지 않는다.
- 처리기 응답: 질문은 `questions[{topic,kind,text,refs}]`. 정리는 `facts[{text,refs}], appeals[{text,refs}], remaining[], content, appeal`. 현재 정리 검증은 근거 원문을 발췌하고 연결한 글만 허용한다. 자유로운 창작·의역 생성은 허용하지 않는다.
- 20초 내 생성 실패·출력 검증 실패 시 기본 질문/원문 정리로 전환한다. 90초 이상 끝나지 않은 요청은 재조회 때 만료 처리한다. 별도 유료 서비스 설정·호출은 하지 않았다.

## 서버와 저장

`api/interview-life-followup.js`는 포털 또는 기존 기기 인증으로 확인한 학생 ID만 사용한다. 공개 action은 availability/start/get/status/save_answers/generate_questions/summarize/apply/restore다. 내부 claim/finish를 클라이언트가 호출할 수 없다.

신규 마이그레이션: `supabase/migrations/20261021082149_interview_basic_fields_followup.sql`.

- 세션, 질문, 답변, 정리 결과, 생성 요청을 별도 테이블에 저장한다.
- 모든 테이블은 RLS 활성화, PUBLIC/anon/authenticated 권한 차단, service_role 경로만 허용한다. RPC는 security invoker이며 모든 동작에서 학생 소유권·등록 상태·경험 존재를 검사한다.
- 계정 삭제는 owner FK를 통해 문답·결과·요청까지 cascade한다. 경험 삭제 후에는 기존 세션 접근과 결과 반영을 거절한다.
- 경험 원본 해시는 선택 경험의 나이·만족도·키워드·내용·어필할 점으로 만든다. 다른 경험 편집은 이 해시를 바꾸지 않는다.
- 답변 수정은 revision 충돌 검사 후 저장한다. 과거 답변이 바뀌면 후속 질문과 정리에 이전 입력 기준임을 표시한다. 후속 답변은 삭제하지 않는다.
- 늦게 도착한 결과는 원본·답변 버전이 달라지면 stale 처리한다. 반영은 기존 `life_save`를 사용해 검증·프로필 크기·수정 상태 정책을 유지한다.
- 내용 12,000자, 어필할 점 2,000자를 넘으면 저장하지 않는다. 조용히 자르지 않는다.
- 학생이 검토해 반영한 내용만 기존 교사 화면에 표시한다. 교사 문답 열람 UI는 이번 범위에 없다.

위 검증은 모두 통과했다. 전체 브라우저 검사에는 추가 질문뿐 아니라 작성하기 AI 요청·채택·피드백, 관리자 학생 조회, 등록, 기존 일반 수강생 화면도 포함했다. 12개 가상 경험의 질문 규칙과 잘못된 근거 출력의 기본 정리 전환을 확인했다. 실제 AI 모델의 품질·비용·응답 시간 실측을 의미하지 않는다.

최종 로컬 미리보기: `http://127.0.0.1:1281/interview`. 기존 13304 미리보기의 저장된 경험 6개를 내용 변경 없이 복사해 검증했다. 기존 소개 역시 보존했으며, 자동으로 학교·회사 등으로 추측해 나누지는 않았다. 로컬 서버는 메모리 DB이므로 종료하면 초기화된다. 원본 백업은 프로젝트 `.tmp/life-before-followup-13304.json`에 있다.

## 후속 수정: 간결한 입력칸·진단 질문 직접 답변

기본 정보는 PC와 모바일 모두 한 행에 한 항목씩 세로로 배치한다. 학교·전공·동아리·담당 직무는 기본 높이 44px, 나머지는 80px이며 필요한 경우 학생이 세로로 늘릴 수 있다. 입력 한도와 저장된 내용은 유지한다.

2026-10-23: 지원자 기본 정보 상단에 이름(100자 이하), 생년월일(날짜 선택), 성별(남성·여성·응답하지 않음)을 추가했다. `basicInfo.name/birthDate/gender`에 기존 프로필 저장·수정 이력과 함께 저장하며, 교사 기본 정보 조회에서도 표시한다. 신규 세 필드는 선택 입력이고 기존 초안 생성 준비 조건은 유지한다. 계정 이름·등록 직렬·수험번호는 변경하지 않는다. 실제 날짜와 미래 날짜 여부를 검증한다. 운영 적용 전 `20261023052344_interview_applicant_identity.sql` 적용이 필요하다. 로컬 DB·브라우저 저장 검증을 수행했으며 운영 DB에는 적용하지 않았다. 웹 상단의 실전 모의면접 탭은 숨기고 앱의 모의면접 메뉴는 유지했다.

진단하기의 5개 보완 질문 바로 아래에 답변칸과 개별 저장 버튼을 추가했다. ‘답변 모두 저장’도 제공한다. 개별 저장은 해당 질문만 반영하며 다른 칸의 미저장 내용은 유지한다. 저장 실패·버전 충돌에도 입력을 보존하고 재접속하면 본인의 답변을 다시 불러온다.

답변은 `ip_diagnosis_answers`에 질문 원문과 함께 저장한다. 인생그래프를 자동 생성·덮어쓰기하지 않으며 기존 진단표는 인생그래프만으로 계산한다. 학생별 소유권·등록 상태·revision·문항 매칭·2,000자 제한을 서버에서 확인한다. RLS와 service_role 전용 권한 및 계정 삭제 cascade를 적용한다. 마이그레이션은 `20261021084708_interview_diagnosis_answers.sql`이며 운영 DB에는 적용하지 않았다.

변경 파일: `interview-life-ui.js`, `interview-prep.css`, `interview-diagnosis-ui.js`, `interview-workspace.js`, `api/interview-prep.js`, `sw.js`, 신규 마이그레이션 및 관련 테스트.

검증: `node tests/interview-diagnosis-answers.test.cjs`, `node scripts/interview-prep-ui-qa.cjs --diagnosis-only`, 전체 브라우저 QA, 격리 빌드·출시 안전성 검사. 최신 로컬 미리보기는 `http://127.0.0.1:4026/interview`이며 기존 1281 화면의 저장 내용을 백업 후 동일하게 옮겼다.
