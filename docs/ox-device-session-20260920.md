# OX 반복 기기 인증 조회 제거

OX API의 첫 정상 학생 요청에서 기존 `validate_student_device`를 실행하고,
학생 ID와 기기 토큰 해시에 연결된 서명 쿠키를 발급한다. 이후 같은 기기의
유효한 쿠키는 API 서버에서 검증하며 기기 인증 DB 호출을 생략한다.
채점 시 DB 왕복은 기기 확인 + `ox_service`의 2회에서 `ox_service` 1회로 줄어든다.
운영 환경에서의 실제 응답 시간 개선 폭은 배포 후 측정해야 한다.

- 쿠키: `outing_ox_device_session`, HttpOnly, SameSite=Strict,
  Path=/api/criminal-law-ox, HTTPS/Vercel에서 Secure.
- 유효 기간: 발급부터 12시간. 사용 중에도 만료 시각을 연장하지 않는다.
- 서명 키: `OX_SESSION_SECRET`, `TEACHER_SESSION_SECRET`,
  `SUPABASE_SERVICE_ROLE_KEY` 순으로 사용한다. 키가 없거나 쿠키가 없거나
  유효하지 않으면 기존 기기 확인 경로를 사용한다.
- 원본 기기 토큰은 쿠키에 저장하지 않는다. 학생 또는 기기 토큰이 달라지면
  기존 쿠키를 사용할 수 없다. 교사 세션과 서명 용도를 분리한다.
- 계정 비활성화, 학생 유형, OX 이용 등록, 서비스 공개 여부, 문제 버전 및
  중복 제출 검사는 계속 `ox_service`에서 수행한다.
- **기기만 차단한 경우 기존 OX 쿠키는 최대 12시간 유효할 수 있다.**
  즉시 OX 접근을 중단하려면 OX 이용 등록 해제 또는 계정 비활성화를 사용한다.
  이는 매번 기기 조회를 생략하는 데 따른 명시적인 동작 변경이다.

변경 범위는 OX API와 관련 테스트다. 화면, 다른 API의 기기 인증 및 DB
스키마는 변경하지 않는다. 기존 클라이언트도 동일 출처 요청에 쿠키를 자동으로
전송하므로 호환된다. 운영 반영에는 사용자 최종 확인 후 앱 배포가 필요하다.

검증: 첫 요청 후 인증 조회 생략, 서명 위조, 다른 학생/기기,
12시간 만료/갱신, 이용 제한 유지, 교사 세션 분리, 쿠키/키 미지원 시
기존 처리, 실패 응답의 쿠키 미발급을 자동 테스트한다.
