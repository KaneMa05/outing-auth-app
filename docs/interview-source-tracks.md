출처 393건이 질문 373개에 연결된다. 같은 문장이 여러 직렬에 실렸으면 해당 직렬을 모두 유지하므로 고유 질문 수 열의 합계는 373보다 크다. 공채·항해 등 다른 원본에서 공유한 직렬도 보존한다. 원본의 `중특단` 표기는 구조 구간의 소속 표기이며 독립 직렬 제목으로 만들지 않는다.

예를 들어 ‘수상구조법에 의거해서 현장지휘관을 어떻게 선정할거냐?’는 **특공(전술)** 구간에, ‘전복된 어선에 사람이 있는데 어떻게 구조할건지’는 **특임** 구간에 있다. 내용에 ‘구조’가 있어도 구조 직렬로 옮기지 않는다.

## 변경과 보존 범위

- 기존 기타 질문 373개에 원본 구간의 직렬을 연결한다. 이번 운영 스냅샷은 공개 승인 225개·승인 대기 147개·보관 1개다. 각각의 상태를 유지하며 공개 문항은 한 트랜잭션 안에서 다시 승인한다.
- 직무·인성 분류, 질문 ID·원문·출처·해설·음성, 채점 기준·요소 분석과 학생 작성 내용은 바꾸지 않는다. 이전 전공·법령 지식 분류 결과도 유지한다.
- 관리자 질문 편집·필터, 학생 등록·신청, 검토·과제 현황과 네이티브 진입 정보에 같은 19개 선택값을 사용한다. 기존 5개 주요 직렬과 원본 13개 세부 직렬, 호환용 ‘기타’로 구성된다.
- 기존 ‘기타’ 회원 4명의 실제 세부 직렬은 추측해서 변경하지 않는다. 기존에 볼 수 있던 질문과 핵심인성·답변 작성·AI·실전 연습 접근을 유지한다. 세부 직렬 회원은 해당 직렬과 공통 질문을 이용한다.
- 관리자·신청 화면의 진입 파일 및 관련 모듈 버전을 함께 갱신하여 이전 브라우저 캐시를 사용하지 않도록 한다. 일반 수강생 앱의 홈·출석·외출·성적 등은 수정하지 않는다.

## 적용 준비 및 검증

`scripts/prepare-interview-source-tracks.cjs --snapshot <json> --output <json>`은 전체 질문·출처와 기타 원문 출현 393건을 검증하여 계획만 생성한다. 변경 시 revision·원문·기존 직렬·출처 지문이 달라지면 적용을 중단한다.

`scripts/interview-source-tracks.cjs`는 서버 쓰기를 직접 하지 않는 트랜잭션 생성기다. 기존 관리 함수를 사용하고 문항별 이전/이후 상태 및 원본 문단 근거를 감사 이력에 남긴다. 원문·수강생·작성 내용·분석·채점 기준·보관 및 승인 상태의 보존, 나머지 질문 불변, 반복 실행을 검증한다.

스키마 마이그레이션은 허용 직렬과 공통 비교 함수만 확장한다. 공통 비교 함수는 `security invoker`이며 `public`·`anon`·`authenticated` 실행 권한을 주지 않는다. 기존 서비스의 인증·소유자 검사를 유지하고 직렬 비교 부분만 바꾼다. 질문의 직렬 변경은 이 마이그레이션과 별도 데이터 트랜잭션으로 처리한다.

새 로컬 테스트 `node tests/interview-source-tracks.test.cjs`는 원본 393건→373개 연결, 복수 직렬, 등록 신청/회원 허용값, 네이티브 정보, 기존 기타 회원의 조회·상세·핵심인성·답변 작성, 세부 직렬 접근 제한, 충돌 시 전체 롤백, 학생 자료와 검토 상태, 감사 기록 및 반복 적용을 검증한다.

**운영 반영 전 사용자 최종 확인이 필요하다.** 프로젝트 `AGENTS.md`의 ‘푸시와 배포는 비용이 발생하므로 사용자의 최종 확인을 받은 후 진행한다’ 지침에 따른다. 승인 후 최신 스냅샷으로 다시 충돌을 확인하고, 스키마 확장 → 이번 변경만 푸시·배포 → 직렬 데이터 변경 → 운영 검증 순서로 적용한다.
