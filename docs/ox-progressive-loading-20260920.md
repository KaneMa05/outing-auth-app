# OX 첫 화면 단계별 로딩

## 문제와 변경

기존 첫 진입은 모든 공개 문제의 지문과 상황을 다운로드한 뒤 화면을 표시한다.
운영 DB 읽기 전용 확인 결과 공개 문항은 2,543개이며, 문제 객체의 JSON 크기 합은
997,631바이트였다. 신규 초기 응답의 문제 ID·단원·버전 합은 251,641바이트로
약 75% 작다. 이는 압축 전 문제 데이터만 비교한 값이며, 전체 응답이나 실사용
소요 시간의 감소율을 의미하지 않는다. 기존 bootstrap의 운영 DB 실행 시간은
단일 측정에서 134.6ms였다. 네트워크·인증·화면 표시 시간은 포함하지 않는다.

새 클라이언트는 `bootstrap`에 `summaryOnly:true`를 전달한다. OX 홈과 단원 목록은
지문 없이 표시한다. 문제 풀이 시 선택한 묶음의 지문을 요청하며, 긴 모아 풀기는
20문항 단위로 읽는다. 오답노트와 북마크는 표시할 문항만 읽고 한 번 받은 지문은
현재 OX 화면 안에서 재사용한다. 요청 한도는 50문항이며 큰 목록은 순차 요청한다.

## 호환성과 권한

- 신규 `ox_learning_data` 함수만 추가한다. 기존 `ox_service`와 테이블은 변경하지 않는다.
- 함수는 security invoker이며 public/anon/authenticated 실행 권한을 제거하고
  service_role만 허용한다. API에서 확인한 학생 ID만 전달한다.
- 계정 활성화, 학생 계정 유형, OX 활성화 및 이용 등록을 매번 확인한다.
- 지문 조회는 제출 기록을 만들지 않으며 정답·해설·메모는 반환하지 않는다.
  초기 요약에는 기존과 동일하게 현재 버전의 기풀이 문항 정답만 포함한다.
- 문제 버전 변경 및 비공개 전환은 오류로 처리한다. 클라이언트는 묶음을 검증한 뒤
  반영하며 실패 시 재시도할 수 있다. 늦게 끝난 요청은 이동한 화면을 덮어쓰지 않는다.
- 기존 클라이언트의 전체 bootstrap은 유지한다. DB 함수가 아직 없는 경우 신규
  API는 전체 bootstrap으로 돌아가며, 이미 지문이 있으므로 추가 조회하지 않는다.
- 별도 준비한 OX 기기 인증 쿠키 개선과 함께 사용할 수 있다.

## 검증 및 반영

`npm test`, `node tests/criminal-law-ox.test.cjs` 통과. SQL 권한·버전·학생 격리 및
기존 학습 데이터 동등성, 지문 중복 요청 방지, 재시도, 이동 중 응답, 50문항 한도를
검증했다. 실제 브라우저의 격리된 가짜 데이터 화면에서도 홈·단원 진입 0회,
10문항 풀이 시작 1회, 채점 후 다음 문제 추가 0회의 지문 요청을 확인했다.

운영 반영은 사용자 최종 확인 후 신규 마이그레이션 적용, 앱 배포 순서로 진행한다.
배포 후 OX 진입 응답량과 소요 시간을 별도로 확인한다. 운영 DB 쓰기·푸시·배포는
아직 수행하지 않았다. 다른 진행 중인 화면 수정과 배포 범위를 혼동하지 않는다.
