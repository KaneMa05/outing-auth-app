# 면접 초안 PC 처리기 설치·운영

개발 계약은 [개발문서](interview-ai-development.md)를 따른다. 이 문서는 운영을 켜기 위한 절차이며, 실제 운영 활성화가 완료되었다는 뜻이 아니다.

현재 기본 실행 경로는 사용자 허용을 받은 Codex CLI다. [CLI 연결 검증·실행 안내](interview-ai-cli.md)를 함께 따른다.

## 답변 지침을 입력하는 곳

`tools/interview-worker/guidelines/instructions.txt`에 공통 규칙과 self_intro, motivation, public_service, core30별 작성 지침을 작성한다. 프로젝트 대화에만 적어 두면 새 자동 생성 세션에 동일하게 적용된다는 보장이 없으므로, 이 파일을 기준으로 사용한다.

현재 지침에는 학생 본인 DB만 사용, 명령이 들어 있는 학생 입력 무시, 자료 부족 시 보완 요청, 완성된 자기소개 본문에 경험 3개 이상, 외부 자료·예시 답안 사용 금지를 반영했다.

`output.schema.json`은 결과 형식이다. 두 파일을 묶어 해시를 계산하고 서버 설정과 PC가 같은 버전을 쓰는지 확인한다.

```powershell
python tools/interview-worker/worker.py bundle-hash
```

지침 수정 순서: PC 신규 작업 일시중지 → 실행 중이거나 실행 여부가 불명확한 작업 해결 → 파일 수정·검증 → 새 해시로 관리자 설정 → PC 재시작. 진행 작업이 있으면 해시 변경을 거부한다. 구 지침의 대기 작업은 취소 상태가 되므로 사용자가 새 지침으로 명시적으로 다시 요청한다. 완료 결과는 보존한다.

## 로컬 준비

Python 3.11 이상과 ChatGPT 계정으로 로그인한 Codex CLI가 필요하다. PC 창은 Python의 tkinter를 사용한다. 별도 Python 패키지 설치는 필요 없다.

1. `tools/interview-worker/config.example.json`을 같은 폴더의 `config.json`으로 복사한다.
2. `web_origin`에 배포된 웹앱의 HTTPS 원점을 입력한다. 경로·쿼리·아이디·비밀번호를 넣지 않는다.
3. `codex_executable`은 현재 PC의 Codex 실행 파일 또는 PATH의 `codex`다.
4. `engine`은 `cli`, `poll_seconds`는 기본 2초다. `desktop_verified`는 CLI 경로에서 사용하지 않는다.
5. `hours`는 PC 현지 시각의 시작·종료 시간이다. 기본 `[0,24]`이며 PC 시간대는 한국으로 맞춘다.
6. 저장 경로 기본값은 `%LOCALAPPDATA%/InterviewDraftWorker`다. 웹앱 배포 폴더 밖의 사용자 전용 경로를 사용한다.

```powershell
python tools/interview-worker/worker.py --config tools/interview-worker/config.json doctor
python tools/interview-worker/worker.py --config tools/interview-worker/config.json set-token
python tools/interview-worker/worker.py --config tools/interview-worker/config.json ui
```

또는 `Start-Worker.ps1 -Python <python.exe 경로> -Command ui`를 사용한다. set-token은 입력을 화면에 표시하지 않고 Windows 현재 사용자 DPAPI로 저장한다. 토큰을 명령 인자·스크린샷·깃·대화에 붙여 넣지 않는다.

`doctor`는 Codex CLI의 ChatGPT 로그인 상태를 검사하며 AI 생성을 요청하지 않는다. 웹 토큰/서버 연결과 실제 답변 생성은 별도 시험으로 확인한다.

현재 PC에서 독립 `codex exec` 실제 생성과 로컬 웹 저장을 검증했다. 기존 앱의 proxy 소켓 연결은 실패했지만 현재 기본 경로에서 사용하지 않는다. 예약 작업과 앱 창 자동 조작은 필요 없다.

## 관리자 설정 API

기존 관리자 로그인과 interview.write 권한으로 `POST /api/interview-ai`를 호출한다. 브라우저 Origin은 앱 원점이어야 한다. 토큰 발급·설정 기능의 별도 관리자 화면은 기존 관리자 UI 작업에서 아래 API로 연결할 수 있다.

| action | 필수 입력 | 설명 |
|---|---|---|
| admin_configure | 변경할 enabled/bundleHash/dailyCallLimit/coreQuestionIds | 운영 설정 |
| admin_register_worker | label, studentIds[] | 해당 학생만 처리하는 기기 토큰 1회 반환 |
| admin_revoke_worker | workerId | 이후 요청 즉시 차단 |
| admin_overview | 없음 | 상태별 수, 오늘 실행 수, 기기 접속, 확인 필요한 작업 |
| admin_retry_job | jobId | 안전이 확인되는 실패·설정 차단 작업 재대기 |
| admin_resolve_unknown | jobId, executionId, confirmedStopped:true | 실제 앱 실행 종료를 확인한 뒤 불명 작업 종결 |

초기 설정 예시:

```json
{
  "action": "admin_configure",
  "enabled": false,
  "bundleHash": "bundle-hash 명령의 64자리 값",
  "dailyCallLimit": 20,
  "coreQuestionIds": ["실제로 확정한 published 질문 ID 30개"]
}
```

위 coreQuestionIds는 형식 설명이며 유효한 실행 데이터가 아니다. 정확히 30개의 서로 다른 공개 인성 문항 ID가 필요하다. 사용자가 확정한 선정 기준은 **본문 25개 필수 + 부록에서 무작위 5개**다. 선정한 목록을 저장해 재조회·부분 재요청 때 바뀌지 않도록 한다. 학생 직렬에 해당하는 공개 인성 30문항인지 요청 시 다시 확인한다. 로컬 미리보기에만 적용했으며 운영 설정은 최종 확인 전이다.

최신 학생 화면은 이 목록 중 선택한 질문 1개만 생성한다. `generate`의 `questionId`가 필수이며 단일 질문 마이그레이션이 적용돼 있어야 한다. 일괄 생성 시절의 대기 작업이 있는 환경에서는 활성화 전에 해당 작업을 별도 점검한다. 완료 결과를 삭제하거나 대기 작업을 새 요청으로 자동 복제하지 않는다.

기기 등록 응답의 token은 한 번만 반환하고 DB에는 SHA-256 해시만 저장한다. 등록 후 set-token으로 PC에 입력한다. 기본 만료는 30일이며 새 토큰을 등록·입력한 뒤 이전 기기를 폐기한다. 처리 중인 결과의 업로드까지 확인하고 교체해야 한다. 토큰 폐기 후 대기 중인 암호화 자료가 자동으로 다른 기기로 전송되지는 않는다.

초기 서버 설정과 PC 검증을 마친 후에만 enabled=true를 적용한다. 이는 배포·활성화 최종 확인 절차에 포함한다.

## D0: 실제 Codex CLI 연결 인수

실제 CLI와 가상 학생 데이터로 확인하고 CLI 버전·테스트 결과를 기록한다. 이번 검증 범위와 남은 운영 인수는 CLI 문서에 구분되어 있다.

- 저장된 ChatGPT 로그인으로 `codex exec`를 실행하고 별도 API 키를 사용하지 않는다.
- 작업마다 새 세션이 생성되고 이전 학생 문맥이 전달되지 않는다.
- 웹·파일·셸·외부 앱·MCP 도구·개인 메모리/지침이 학생 답변에 다른 사실 자료를 공급하지 않도록 실제 설정과 이벤트를 확인한다. 현재 어댑터의 옵션만으로 차단을 보장한다고 가정하지 않는다.
- 학생 입력에 도구 호출·다른 학생 조회·외부 사실 추가 명령을 넣어도 실행하지 않는다.
- 스키마에 맞는 최종 답변을 회수하고 답변 출처와 경험 수를 검증한다.
- 실행 중 PC 처리기 재시작, 실행 시작 응답 유실, 업로드 응답 유실에서 암호화 영수증을 회수하고 중복 모델 호출을 하지 않는다.
- 계정 제한·로그인 만료·절전·앱 종료 시 작업이 유실되지 않고 학생에게 대기/확인 필요 상태가 표시된다.
- CLI는 ephemeral 세션을 사용한다. PC 로컬 정리와 OpenAI 측 보관 정책은 별개다.

CLI 실제 생성·결과 회수·출처 검증은 통과했다. 운영 활성화 전 최종 브라우저 인수와 제한된 시험 운영을 수행한다.

## 정상 운영과 비용 제한

교사 PC와 처리기가 켜져 있고 CLI 로그인이 유효해야 한다. PC 처리기 창은 신규 작업 일시중지/재개를 지원한다. 일시중지해도 이미 받은 결과의 업로드와 진행 작업의 복구는 수행한다.

- 서버 동시 생성은 1개다. 학생별 최근 배정 시각으로 순환한다.
- 기본 서버 하루 생성 예약 한도 20회, 학생별 하루 요청 한도 40회, 미처리 문항 한도 66개다.
- 핵심 30제 한 묶음을 하루에 완료하려면 하루 생성 예약 한도를 최소 30회 이상으로 조정해야 한다. 여러 학생 수요에 맞춘 한도는 운영 활성화 시 확정한다.
- 하루 기준은 한국 시간이다. 실행 직전 예약하므로 실제 모델 전송 전에 실패한 예약도 보수적으로 집계한다.
- 업로드 재시도와 상태 조회는 새 모델 생성을 하지 않지만 웹·DB 요청은 발생한다.
- 이 구현은 금액 기반 결제 한도나 Codex 구독 사용량 잔여를 자동 조회하지 않는다. 호출 수 제한과 실제 계정 과금·한도는 구분한다.
- 1,650개 대기 등록 검증은 실제 1,650회 생성 실행 또는 동시 50명 처리 시간 보장이 아니다.

## 장애 복구

| 증상 | 자동 동작 | 운영자 조치 |
|---|---|---|
| 웹 연결 끊김 | 암호화 OUTBOX 유지, 같은 결과 업로드 재시도 | 웹 연결 복구 |
| 업로드 성공 후 응답만 유실 | 같은 실행 ID·결과로 재전송 | 생성 재실행 불필요 |
| 처리기 재시작, 암호화 결과 존재 | 기존 결과 영수증을 회수 | 웹 연결 복구 |
| 시작 요청 응답 유실 | 같은 실행 디렉터리 결과 조회, 없으면 UNCERTAIN/BLOCKED | 해당 CLI 실행 종료 여부 확인 |
| 형식·근거 오류 | FAILED, 학생에게 잘못된 결과 미표시 | 해당 문항만 명시적 재요청 |
| 자료 부족 | NEEDS_INPUT, 보완 질문 즉시 표시 | 학생이 DB 자료 보완 후 해당 문항 재요청 |
| 지침 버전 불일치 | claim 거부 | 서버·PC 해시 일치 확인 |
| 기기 토큰 만료·폐기 | 인증 거부, 새 실행 없음 | 권한 확인 후 새 기기 등록 |
| 하루 한도 | 새 생성 대기 | 다음 날짜 또는 승인된 제한 변경 |

실행 불명 상태는 해당 CLI 실행기의 종료 여부와 암호화 결과 영수증을 확인한다. 결과를 회수할 수 있으면 기존 실행을 복구한다. 회수 불가이고 실행 종료를 확인한 경우만 `admin_resolve_unknown`을 호출한다. 이 API가 Codex 실행을 대신 중단하는 것은 아니다. 단순 오류 화면이나 시간 경과를 종료 확인으로 간주하지 않는다.

해결된 작업은 CANCELED로 남고 학생이 선택 재요청할 수 있다. 오래된 처리기가 뒤늦게 돌아와도 과거 executionId의 관리자 종료 기록을 확인하고 다시 실행하지 않는다.

서버의 disabled는 신규 작업 접수를 막는다. 진행 중인 모델 호출을 원격으로 취소하지는 않는다. 장애 시 데이터·테이블을 삭제하여 초기화하지 않는다.

## 보관과 보호

PC 토큰과 SQLite payload는 Windows 현재 사용자 DPAPI 암호화다. 같은 Windows 계정의 프로그램은 복호화 가능하므로 공용 계정으로 운영하지 않는다. 성공 확인 후 로컬 자료 payload를 영수증으로 바꾸며 영수증은 24시간 후 정리한다. 해결되지 않은 OUTBOX/UNCERTAIN은 자동 폐기하지 않아 수동 점검이 필요하다.

서버 요청·답변·근거 사본은 현재 자동 만료 삭제가 없다. 학생 등록 삭제 시 연결 자료는 FK cascade로 삭제되지만, 운영자의 보관 기간 정책·백업·Codex 세션 기록은 별도로 정해야 한다. 무기한 보관이 운영 정책으로 승인되었다는 뜻은 아니다.

배포 제외에 `tools/interview-worker/`를 포함한다. .gitignore만으로 웹 공개 방지를 판단하지 않는다. 특히 outputDirectory가 저장소 루트인 앱에서는 운영 DB 자료·PC 설정·암호화 파일을 정적 파일로 배포하지 않도록 확인한다.

## 출시와 되돌리기

1. 로컬 및 별도 테스트 DB 검증을 완료한다.
2. 최종 앱 버튼 연결과 학생·관리자 UI 인수를 완료한다.
3. D0 CLI 연결·격리 검증과 실제 품질 검증을 완료한다.
4. 사용자 최종 확인 후 마이그레이션·푸시·배포를 진행한다.
5. 등록한 시험 학생에게만 낮은 한도로 활성화한 뒤 확대한다.

중단 시 enabled=false와 PC 신규 작업 일시중지를 적용한다. 기존 일반 입력·저장 API는 계속 사용할 수 있다. 이미 생성된 결과를 보존하고 운영 DB 테이블을 즉시 제거하는 되돌리기는 하지 않는다.
