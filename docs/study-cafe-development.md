# RONPARK STUDYCAFE 개발 규칙

## 이용 대상과 권한

- 등록번호가 `2`로 시작하고 활성 기기토큰 검증을 통과한 온라인 수강생만 이용한다.
- 오프라인 학생에게는 스터디카페 메뉴와 API를 모두 노출하지 않는다.
- 브라우저는 스터디카페 테이블에 직접 쓰지 않는다. 모든 읽기·쓰기는 학생 ID와 기기토큰을 검증하는 `/api/study-cafe`를 통한다.
- 좌석 화면에는 마스킹된 이름, 요약 직렬, 오늘 총 순공시간만 공개한다. 과목은 본인에게만 보인다.

## 상태 흐름

1. `browsing`: 좌석 없이 스터디카페를 둘러보는 상태
2. `seated`: 좌석은 유지하지만 측정 중인 과목은 없는 상태
3. `countdown`: 과목을 선택하고 `3 → 2 → 1`을 진행하는 상태
4. `studying`: 서버 시작 시각을 기준으로 순공시간을 측정하는 상태
5. `paused`: 좌석과 과목은 유지하고 시간 측정만 중지한 상태

허용 전이는 다음과 같다.

- `browsing → countdown`: 빈 좌석과 과목 선택
- `seated → countdown`: 같은 좌석에서 다음 과목 선택
- `countdown → studying`: 3초 완료
- `studying → paused`: 일시정지
- `paused → countdown`: 다시 시작
- `studying|paused → countdown`: 과목 변경
- `studying|paused → seated`: 과목 종료
- `seated → browsing`: 사용자가 `좌석 비우기` 선택

## 시간 계산

- 3초 카운트다운과 일시정지 시간은 순공시간에서 제외한다.
- 서버가 반환한 시각을 기준으로 시작·일시정지·재시작·종료 시간을 계산한다.
- 과목 변경 시 기존 과목 시간을 먼저 확정하고 새 과목은 새 세션으로 기록한다.
- 새로고침하면 서버의 활성 세션과 좌석을 복원한다.
- 한 학생에게 동시에 하나의 활성 세션만 허용한다.

## 좌석과 연결 끊김

- 좌석 선택은 데이터베이스의 고유 제약으로 원자적으로 처리한다.
- 클라이언트는 공부 화면에서 주기적으로 heartbeat를 전송한다.
- 마지막 heartbeat 이후 2분이 지난 좌석은 새 좌석 선택 시 정리할 수 있다.
- 사용자가 과목을 종료해도 좌석은 유지한다.
- 사용자가 `좌석 비우기`를 누르면 활성 과목을 종료한 뒤 좌석을 반납한다.

## 집계와 랭킹

- 일간 기준은 `Asia/Seoul`의 오전 4시부터 다음 날 오전 3시 59분 59초까지다.
- 자정을 넘어 계속 실행 중인 타이머는 끊지 않고 전날 공부시간으로 누적하며, 오전 4시 경계에서 같은 과목의 새 세션으로 자동 이월한다.
- 일간·주간·월간 랭킹은 확정된 세션 시간과 현재 실행 중인 세션 시간을 합산한다.
- 랭킹에는 마스킹된 이름과 총 순공시간만 표시한다.
- 동일 시간은 공동 순위로 처리하고, 내 순위는 항상 별도로 찾을 수 있어야 한다.

## 출시 원칙

- 데이터베이스 마이그레이션 적용 전에는 기존 화면 미리보기 상태로 동작한다.
- 원격 저장 실패가 기존 오프라인 관리반 기능을 막아서는 안 된다.
- 온라인 학생 소수 계정으로 새로고침, 화면 잠금, 중복 기기, 네트워크 끊김을 검증한 후 전체 공개한다.
- 푸시와 배포는 최종 확인 후 진행한다.
