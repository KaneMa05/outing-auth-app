# 모의면접 시험모드와 실전 면접 개발 기획 초안

작성일: 2026년 10월 21일

면접반의 모의면접 탭에 전공 시험, 인성 연습, AI 실전 모의면접을 제공한다. 학생 앱과 관리자 사이트는 같은 응시 영상과 전사문을 조회한다. 전공 시험은 지정된 표현의 실제 발화와 문맥을 근거로 판정하며, 음성 인식 오류를 오답으로 확정하지 않도록 검토 절차를 둔다.

## 확정한 요구사항

- 영상 보관 기간은 해당 면접 수강 종료 후 30일까지다.
- 3 시험모드 아래에 3-1 전공 직무 시험모드와 3-2 인성 연습모드를 둔다.
- 4 실전 모의면접 AI를 별도 이용 방식으로 제공한다.
- 전공 시험은 API를 이용하며 O·△·X로 판정한다.
- 지정 단어와 관리자가 등록한 허용 표현만 인정한다. 지정 표현을 부정하거나 틀린 맥락으로 사용하면 인정하지 않는다.
- 필수 항목 모두 충족은 O, 일부 충족은 △, 미충족 또는 핵심 오류는 X라는 판정 초안을 채택한다. 숫자 배점은 별도 확정한다.
- 인성 연습은 결론 → 이유 → 경험 → 마무리 순서로 답변 구조를 평가한다.

## 학생 화면 구성안

모의면접 탭에서 시험모드와 실전 모의면접을 선택한다. 시험모드는 전공 직무 시험과 인성 연습으로 나눈다. 공통으로 내 기록에서 이전 응시와 공개된 평가를 조회한다. 기존 면접반의 다른 탭과 오프라인·온라인 관리반·인터넷 수강생 및 교사 화면은 변경 범위를 분리한다.

| 모드 | 진행 | 결과 |
|---|---|---|
| 전공 직무 시험 | 승인된 질문 제시 → 제한 시간 내 음성 답변 → 제출 → 전사와 채점 | O·△·X, 충족·누락 항목, 불인정 근거, 영상과 전사문 |
| 인성 연습 | 질문 선택 → 답변 녹화 → 구조 분석 → 재연습 | 결론·이유·경험·마무리의 근거 문장, 순서와 연결성, 보완 의견 |
| 실전 모의면접 AI | 배정 세트 → AI 질문 → 답변 → 허용된 꼬리질문 → 종료 | 전체 기록, 문항별 분석, 담당자 피드백 |

시험 도중 정답 표현과 실시간 채점 힌트는 표시하지 않는 안을 기본으로 한다. 제출 후 전사문을 열람하며, 시험 답변 원문은 학생이 수정하지 못하게 한다. 인식 오류는 해당 구간의 검토 요청으로 접수한다. 실전 모드의 질문 수·시간·구성 비율·꼬리질문 한도는 세트 설정으로 정의한다.

## 전공 직무 시험 채점 설계안

### 질문별 기준 관리

관리자는 질문 본문, 모범답안, 필수 평가 항목, 항목별 지정 단어·허용 표현, 인정 문맥, 불인정 문맥, 핵심 오류 조건을 등록한다. 여러 단어를 모두 말해야 하는 항목과 그중 하나만 말해도 되는 항목을 구분한다. 배점이 확정되면 질문별 배점과 △ 부분점수 규칙을 추가한다.

공백·문장부호·조사 변화에 대한 정규화 범위는 검증된 규칙으로 제한한다. 발음이 비슷하다는 이유만으로 오인식 단어를 정답 단어로 자동 치환하지 않는다. 미등록 동의어나 AI가 유추한 표현에는 점수를 부여하지 않는다.

### 판정 절차

1. 제출한 원음으로 최종 전사문을 생성한다. 실시간 자막이 있는 경우 임시 표시로만 취급한다.
2. 서버의 표현 검사로 지정 단어와 허용 표현이 나타난 구간을 찾는다.
3. 문맥 검사에서 해당 구간의 부정, 조건, 주체, 개념 간 관계, 모순을 확인한다. 단어를 단순 나열한 답변도 정답 문맥 충족 여부를 검사한다.
4. AI 문맥 판정은 전사문에 실제 존재하는 근거 문장을 반환해야 한다. 서버는 인용 구간과 항목 ID를 검증한다. 근거가 없거나 판단이 충돌하면 검토 대기로 보낸다.
5. 유효한 항목 판정을 서버 규칙으로 합산하여 O·△·X를 결정한다. AI가 필수 표현 검사 결과를 우회하여 점수를 부여할 수 없게 한다.

| 결과 | 판정 기준 |
|---|---|
| O | 모든 필수 항목의 표현과 문맥 충족, 핵심 오류 없음 |
| △ | 필수 항목 일부만 충족, 핵심 오류 없음 |
| X | 충족 항목 없음 또는 사전 정의한 핵심 오류 확인 |
| 검토 대기 | 핵심 발화 인식 불확실, 손상·누락된 음성, 문맥 판정 충돌 또는 처리 실패 |

검토 대기는 점수가 아니며 0점으로 합산하지 않는다. 부정 표현이 있다는 이유만으로 무조건 오답으로 처리하지 않고, 질문의 정답 관계와 함께 판정한다. 학생이 답변 중 잘못 말한 뒤 명확히 정정한 경우의 처리 규칙은 예시 답안으로 확정한다.

질문·허용 표현·핵심 오류·배점의 버전을 응시 시작 시 고정한다. 관리자 수정으로 과거 점수가 자동 변경되지 않게 하고, 재채점은 이전 결과와 사유를 보존하는 새 평가 버전으로 남긴다.

## 음성 인식과 텍스트 검증 설계안

학생 마이크 입력과 AI 면접관 음성 출력을 별도 경로로 관리한다. 전공 채점은 학생 답변 구간만 사용하며 질문 음성이 정답 발화로 인정되지 않도록 한다. 스피커 반향, 주변 사람 목소리, 겹쳐 말하기는 실제 기기에서 검증한다. 처리 경로 분리만으로 물리적 반향 제거를 보장하지 않는다.

녹음 전 마이크 크기·클리핑·소음을 점검하고, 제출된 원음과 최초 전사문을 보존한다. 전사 API에는 검증된 공통 전문용어 사전을 제공할 수 있지만 질문의 모범답안을 넣어 전사를 정답 쪽으로 유도하지 않는다. 용어 힌트로 발화하지 않은 단어가 추가되는지도 검증한다.

점수에 영향을 주는 불확실한 구간은 원음으로 제한적으로 재전사하고, 불일치가 해소되지 않으면 담당자가 확인한다. 반복 전사 횟수와 비용 한도를 둔다. 모델이 제공하는 신뢰도 지표가 있더라도 실제 정답 확률로 해석하지 않으며, 높은 신뢰도만으로 핵심 용어가 정확하다고 확정하지 않는다.

학생과 관리자는 전사문에서 근거 구간을 선택해 해당 녹화 구간을 재생할 수 있게 한다. 타임스탬프 또는 음성 정렬 기능의 지원 여부와 정확도는 선택한 API별로 검증한다. 관리자의 전사 정정은 원음 확인, 수정 전후 내용, 수정자, 사유를 기록하고 재채점과 연결한다.

## 인성 연습 평가 설계안

| 요소 | 확인 내용 |
|---|---|
| 결론 | 질문에 대한 입장이나 답을 먼저 제시했는지 |
| 이유 | 결론의 이유가 구체적이고 논리적으로 연결되는지 |
| 경험 | 자신의 상황·행동·결과가 이유를 뒷받침하는지 |
| 마무리 | 배운 점과 직무에서의 실천 방향으로 정리하는지 |

각 요소의 존재 여부와 내용 충실도를 구분한다. 네 요소의 순서, 누락, 반복, 연결성을 실제 답변 문장에 근거해 보여준다. “결론”, “이유”, “경험”이라는 단어 자체를 발화할 필요는 없다. 답변 구성에 대한 피드백이며 개인의 성격이나 합격 가능성을 단정하지 않는다. 숫자 점수화 여부와 세부 가중치는 미정이다.

## 실전 모의면접 AI 설계안

관리자가 승인·배정한 질문 세트를 기본으로 사용한다. AI는 학생 답변을 받아 허용된 범위에서 꼬리질문을 진행하며 제한 시간과 최대 질문 수를 서버에서 통제한다. 면접 중 코칭을 제공하지 않고 종료 후 결과를 제공하는 안을 기본으로 한다.

전공 문항은 동일한 필수 표현 채점 체계를 재사용하고 인성 문항은 답변 구조 평가를 사용한다. 자유 꼬리질문처럼 승인된 정답 기준이 없는 문항은 임의로 전공 O·△·X 총점에 포함하지 않는다. 기존 통합기획안의 담당자 공개 정책을 유지하되, 연습용 자동 피드백과 공식 공개 평가의 범위를 구분하여 확정한다.

## 영상 저장과 보관

영상은 비공개 Storage에 한 번 업로드하고 학생 본인과 권한 있는 관리자가 같은 파일을 조회한다. DB에는 응시·수강 등록·파일 경로·길이·용량·만료일·처리 상태·전사·평가를 저장한다. 영상 파일은 DB 본문에 넣지 않는다.

영상 만료일은 해당 응시가 연결된 면접 수강 종료일로부터 30일 후다. 다른 과정 재등록만으로 과거 과정의 영상 보관 기간이 자동 연장되지 않게 한다. 동일 수강의 기간 변경, 취소, 종료일 미설정에 대한 계산 규칙과 날짜 경계는 운영 설정에서 확정한다.

학생과 관리자에게 삭제 예정일을 표시하고 만료 전 다운로드를 제공한다. 서버가 삭제한 뒤에도 사용자가 내려받은 파일은 사용자 기기에 남는다는 점을 안내한다. 원본·파생 영상·별도 음성·썸네일을 같은 보관 정책으로 관리한다. 만료된 미디어는 저장소 API로 삭제하고 실패 시 재시도한다. DB 경로만 삭제하는 처리는 실제 저장 용량을 줄이지 못한다.

전사문과 평가의 보관 기간은 영상과 별도로 확정한다. 영상 만료 후 결과 화면에는 재생 불가와 사유를 표시한다. 업로드 미완료·중복·고아 파일의 정리 기준도 별도로 둔다.

수강 기간 전체에 영상이 누적되므로 업로드 시점부터 30일 보관하는 계산을 적용하지 않는다. 용량은 학생 수 × 기간 중 응시 수 × 평균 영상 용량으로 산정하고 재생량은 별도로 관리한다. 화질, 비트레이트, 최대 길이, 응시 횟수 한도는 실측과 예산으로 결정한다.

## 정확도 검증과 개발 순서

실제 직무 질문과 동의받은 한국어 음성으로 평가 자료를 구성한다. 전문용어, 숫자·단위, 부정문, 조건문, 자기 정정, 침묵, 소음, 억양, 반향을 포함한다. 전사 개선용 자료와 최종 성능 검증용 자료를 분리하고 담당자 정답 판정과 비교한다.

검증 지표는 전체 전사 오류율뿐 아니라 필수 표현을 놓친 비율, 발화하지 않은 표현을 추가한 비율, O·△·X 혼동, 오답을 O로 인정한 비율, 검토 대기 비율, 응답 시간과 비용을 포함한다. 소수 샘플의 평균 정확도만으로 출시하지 않는다. 허용 오류율과 최소 표본 수는 본 평가 자료를 확보한 뒤 확정하며, 검토 대기를 제외한 정확도와 전체 자동 처리 비율을 함께 보고한다.

1. 관리자 질문별 채점 기준과 예시 답안 등록 규격을 확정한다.
2. 음성 전사 API 후보를 동일한 한국어 검증 자료로 비교한다.
3. 전공 표현 검사·문맥 검사·검토 대기를 구현하고 판정 테스트를 통과시킨다.
4. 인성 답변 구조 분석과 실제 근거 문장 표시를 구현한다.
5. 학생 녹화·업로드·복구와 관리자 재생·정정·재채점을 연결한다.
6. AI 실전 진행과 제한된 꼬리질문을 연결한다.
7. 보관 만료·삭제, 비용 한도, 기존 앱 회귀를 검증하고 최종 확인 후 푸시·배포한다.

`interview-app-ui.js`의 `mock` 경로에 시험모드(전공·인성)와 실전 모의면접(AI)의 진입 버튼 및 모드별 안내 화면을 추가했다. 각 버튼은 `mockMode=job|personality|ai` 경로로 이동하며 새로고침·뒤로가기·목록 복귀를 지원한다. 인성 안내 화면은 결론 → 이유 → 경험 → 마무리의 평가요소를 표시한다. 실제 시험·녹화·채점·AI 면접 실행 기능은 아직 연결하지 않아 각 모드의 시작 버튼은 준비 중으로 비활성화했다. 실제 API 공급자·모델, O·△·X 숫자 배점, 인성 점수화, 결과 공개 시점, 시험 시간과 횟수는 후속 확정 항목이다. 운영 DB 적용·푸시·배포는 하지 않았다.
