# 기존 스터디카페 봇 관리자 기능

## 사용 방법

관리자 → 온라인 스터디카페 → **봇 관리 열기** → 기존 봇의 **상점 · 봇 관리**를 선택한다.

- 상점: 보유 포인트 확인 → 상품의 구매하기 → 가격과 구매 후 잔액 확인 → 구매 또는 구매 후 착용.
- 보관함: 기존 구매 아이템 착용·해제. 머리·의상·머리 장식·의자는 슬롯별 하나, 책상 장식은 최대 4개.
- 운영 설정: 중지·재개, 관리용 이름, 고정/자동 닉네임, 직렬, 과목, 색상, 선호 좌석, 기존 3개 시간대 편집.
- 내역: 최근 포인트 적립·사용과 작업 관리자 조회.

운영 중지는 공부를 종료하고 좌석을 반환한다. 재개·설정 변경은 다음 분 단위 자동 실행에 반영된다. 다른 관리자가 변경한 설정을 오래된 화면에서 덮어쓰지 않도록 버전을 확인한다.

## 기존 데이터와 포인트

봇을 생성하거나 재등록하지 않는다. `private.study_cafe_agents`에 이미 등록된 봇을 조회하며 기존 ID·운영 설정·공부 기록·지갑·구매 아이템을 보존한다. 설치용 `add-study-cafe-agents.sql`을 다시 실행하지 않는다.

사용자 확인에 따라 기존 공부 기록도 소급 정산한다. 기존 상점과 동일하게 한국 시간 04:00부터 시작하는 공부일별 순공시간 30분당 5P이며, 해당 날짜에 이미 지급한 포인트를 제외한 차액을 적립한다. 30분 미만의 나머지는 같은 공부일 안에서 합산한다. 계산은 기존 공부 기록의 `elapsed_seconds`와 진행 중인 활성 구간을 사용하며, 과거 기록 자체를 수정하지 않는다.

기존 봇 자동 실행 함수는 `private.run_study_cafe_agents_core`로 보존한다. 동일한 기존 cron 진입점에 운영 충돌 방지, 고정 닉네임 적용, 포인트 정산을 연결한다. 새로운 cron 작업은 만들지 않는다. 정산 오류는 봇별로 격리하고 이후 실행에서 다시 처리한다. 관리자 목록·상점 조회도 미정산 포인트를 정산한다.

운영 DB 읽기 전용 확인(2026-09-11)에서 기존 봇은 모두 가동 중이며 지갑·구매 아이템은 없었다. 2026-09-07부터 5개 공부일의 조회 시점 예상 정산 포인트는 다음과 같다. 실제 반영 시 공부 기록에 따라 달라진다.

## 권한과 처리 방식

- `/api/study-cafe-admin`의 `bot_*` 요청은 서명된 관리자 세션만 허용한다. 교사에게 스터디카페 쓰기 권한이 있어도 봇 관리는 허용하지 않는다.
- DB에서도 등록된 봇 ID인지 검사한다. 일반 수강생 ID로 바꿔 보낸 구매 요청은 거절한다.
- DB 함수는 `security invoker`, 서비스 역할 전용이다. private 스키마는 브라우저에 공개하지 않는다.
- 구매는 기존 구매·착용 함수를 재사용한다. 구매 후 착용은 하나의 트랜잭션으로 묶으며, 실패하면 구매도 취소한다.
- 요청 UUID와 처리 결과를 저장해 응답 유실 후 재시도 시 같은 결과를 반환한다. 관리자 이름은 요청 본문이 아닌 검증된 세션에서 가져온다.
- 공개 좌석에는 봇의 착용 아이템 ID·슬롯·아이콘만 전달한다. 지갑·보관함·관리자 내역은 학생에게 전달하지 않는다.
- 봇 외 학생의 상점 접근 권한과 자신의 장비 렌더링은 유지한다. 봇 외형 조회가 실패하면 기존 좌석 표시로 계속 동작한다.

## 검증

`npm run test:study-cafe-bots`는 관리자 API·UI 동작 검사와 격리된 인메모리 PostgreSQL 검사를 실행한다.

DB 테스트는 `@electric-sql/pglite@0.3.14`를 사용한다. 기본 경로는 `.tmp/reward-test/node_modules/@electric-sql/pglite`이며 `PGLITE_MODULE`로 별도 설치 경로를 지정할 수 있다. 테스트용 의존성·샘플 데이터는 운영 배포에 포함하지 않는다.

검사 범위:

- 과거 여러 날짜 정산, 기존 적립분 차감, 04:00 경계, 작업 누락 후 정산, 재시도 중복 방지.
- 잔액 부족, 가격 변경, 중복 구매, 구매와 착용의 원자성, 머리 착용·해제.
- 관리자 전용 권한, 일반 학생 ID 거절, 서버 기준 관리자 작업 이력.
- 설정 충돌 감지, 운영 중지 후 자동 재입실 방지, 고정 닉네임 유지, 다른 봇 설정 보존.
- 마이그레이션 재실행 시 기존 데이터 보존.
- 화면의 구매 확인, 잔액 부족 버튼, 요청 중 중복 클릭, 응답 유실 후 같은 요청 재시도, 계정 변경 후 늦은 응답 차단.
- 공개 봇 장비 렌더링과 기존 수강생 본인 장비 렌더링 유지.

실제 브라우저가 연결되지 않아 화면 캡처·화면 크기별 육안 검증은 미완료다. 운영 반영 전 관리자 모달의 데스크톱·모바일 표시를 추가 확인해야 한다.

## 운영 반영 순서

2026-09-11 사용자 승인으로 운영 DB 적용을 완료했다. 적용 마이그레이션 버전은 20260911080239이다. 기존 봇 5개의 설정과 원래 자동 운영 함수 본문, 기존 cron 작업 보존을 확인했다. 과거 포인트 정산, 서비스 역할의 관리자 조회, 일반 학생 ID 거절, 공개 외형 조회를 검증했고 구매·착용·재시도 검사는 트랜잭션 전체를 롤백하여 검증용 구매를 남기지 않았다. 자동 운영 작업은 적용 후 정상 실행됐다. 관리자 화면·API의 푸시·배포는 아직 진행하지 않았다.

1. 현재 작업 트리에 다른 기능의 미반영 변경도 있으므로 함께 배포될 범위를 확인한다.
2. 기존 봇·상점·머리 상점 기능이 설치된 환경에 `supabase/migrations/20260911080239_add_study_cafe_bot_admin.sql`을 적용한다. 동일 내용의 `supabase/add-study-cafe-bot-admin.sql`은 검토·단독 적용용이며 둘을 따로 적용할 필요는 없다.
3. 기존 cron의 다음 실행부터 과거 기록 정산과 자동 적립이 시작된다. 관리자 화면 적용 전에도 정산될 수 있으므로 DB 적용 역시 운영 반영 단계로 취급한다.
4. 관리자 화면·API·공개 좌석 장비 반영 코드와 갱신된 정적 파일 버전을 함께 배포한다.
5. 관리자에서 기존 봇 5개와 잔액을 확인하고, 실제 구매는 의도한 상품·봇을 대상으로 수행한다. 교사·학생 접근 차단과 학생 좌석·타이머도 확인한다.

복구 시 앱을 이전 버전으로 되돌려도 기존 봇·지갑·아이템을 삭제하지 않는다. 관리 기능만 중단하려면 서비스 역할의 `public.study_cafe_bot_admin(text,text,jsonb,text,uuid)` 실행 권한을 회수한다. 자동 정산까지 중단해야 한다면 보존된 `private.run_study_cafe_agents_core` 본문을 기존 cron 진입 함수에 복원한다. 이미 적립·구매된 내역은 유지한다. 원본 봇 설치 SQL 재실행이나 지갑 초기화로 복구하지 않는다.
