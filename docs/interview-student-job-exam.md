# 학생 전공 시험 연결

2026-10-29. 로컬 개발·검증 완료. 운영 DB 적용·유료 API 호출·푸시·배포 없음.

## 제공 흐름

면접반 학생 앱 `모의면접 → 전공(직무) 시험모드`에만 연결했다. 인성·실전 모드의 기존 준비 중 화면, 일반 수강생 화면, 관리자 전공 검증 경로는 유지한다.

1. 본인 직렬의 공개·검토 완료 전공 문항을 조회한다. 정답 표현과 채점 기준은 응시 전에 전송하지 않는다.
2. 학생의 시작 동작에서 마이크 권한을 요청한다. 권한을 확보한 뒤 서버에서 응시를 생성하고 문항·채점 기준을 고정한다.
3. 공통 녹음 모듈로 최대 90초 녹음하고 조각을 IndexedDB에 저장한다. 녹음 중에는 탭 이동을 막고 마이크와 저장 상태를 정리한다.
4. 종료 후 기기 원음을 재생하고 명시적으로 제출한다. 브라우저가 빈 녹음을 반환하면 성공 처리하지 않고 중단으로 기록한다.
5. WebM/MP4를 브라우저에서 디코딩·다운믹스하여 16 kHz 모노 16비트 PCM WAV로 만든다. 제출 WAV를 별도 기기 저장소에 한 번 확정하여 재시도할 때 같은 바이트를 사용한다.
6. 서버가 WAV 실제 형식·1~90초·3 MB 이하를 검사하고 답변 해시를 고정한다. 원음은 비공개 Storage에 한 번 저장하고 키워드·허용 표현·모두/하나 조건과 문맥으로 판정한다.
7. 전사·키워드별 발화/누락·문맥 근거·판정 제안을 저장하고 학생에게 표시한다. 새로고침 후에도 본인 기록과 리포트를 조회한다. 조회에는 AI를 다시 호출하지 않는다.

초기 제한은 문항별 90초, 하루 3회 시작, 제출 기한은 시작 후 3분, 전체 저장/분석 동시 5건이다. 취소한 응시도 일일 시작 횟수에 포함한다. 숫자 판정은 검토용 제안이며 확정 grade/score는 null이다. 실제 자동 확정 성적이나 관리자 검토 UI는 추가하지 않았다.

## 권한과 고정 기준

`/api/interview-job-exam`은 기존 면접 웹 세션을 우선 사용한다. 기존 설치 앱의 기기 인증에서는 기존 previewAllowed 제한을 동일하게 적용한다. 임의 학생 ID, 전사문, 정답, 배점, 판정 입력을 신뢰하지 않는다. 학생이 질문을 선택해도 서버에서 공개 상태·직렬·기준 승인·수강 활성 상태·수강 종료일을 다시 검사한다.

응시 시작 시 서버 DB에 질문과 rubric_detail을 복사한다. 응시 중 관리자가 기준을 변경해도 해당 응시는 시작 당시 기준으로 판정한다. 기존 관리자 음성 검증의 최신 기준 변경 감지 동작은 수정하지 않았다.

새 `ip_job_exam_attempts` 테이블은 RLS를 켜고 anon/authenticated 접근을 차단했다. RPC는 SECURITY INVOKER와 빈 search_path를 사용하며 service_role에만 실행을 허용한다. 내부 처리·저장·삭제 동작은 서버 actor만 허용한다. 학생 조회는 본인 응시만 반환하고 관리자 검토 메모·모델 설정·내부 rubric_detail은 제거한다. 판정 완료 전에는 결과의 키워드/해설을 노출하지 않는다.

## 상태와 실패 복구

`started → uploading → evaluating → completed`

- 음성 저장 실패는 `upload_failed`다. 기기 WAV를 보존하고 같은 바이트로 재제출할 수 있다. 이 단계에서는 AI를 아직 호출하지 않는다.
- 분석·리포트 저장 결과가 불확실하면 `unknown`이다. 이미 과금되었을 수 있으므로 자동 재분석하지 않는다. 학생은 결과 확인으로 저장된 상태를 조회한다.
- 같은 응시·같은 답변의 완료 결과는 재사용한다. 다른 답변 바이트로 바꾸면 충돌로 거부한다. 여러 함수 인스턴스의 중복 제출은 DB claim으로 직렬화한다.
- 중복 업로드로 기존 음성을 덮어쓰지 않는다. 업로드 응답만 유실된 경우 기존 객체를 읽어 해시가 같은지 확인한다.
- 브라우저 새로고침/중단 시 마지막 저장 이후 조각은 빠질 수 있다. 기존 Web Locks를 사용해 다른 탭에서 실제 녹음 중인 기록은 복구가 변경하지 않도록 한다. 전공 화면의 자동 복구는 전공 모드 기기 기록만 대상으로 한다.
- 제출 기한이 지난 녹음은 원본을 보존하지만 새 답변으로 제출할 수 없다. 새 응시에서 다시 녹음해야 한다. 기기 녹음 삭제는 서버 기록을 지우지 않는다.

원음 재생 링크는 최대 60초이며 보관 만료까지 남은 시간보다 길게 발급하지 않는다. 서버 응시·음성·리포트는 해당 응시 시작 시 수강 종료일 기준 종료 후 30일째 날까지 보관하도록 구성했다. 재등록으로 과거 기록 기간을 자동 연장하지 않는다. 기기 원본은 별도 사용자 사본으로 남으며 기기 녹음 삭제로 제거한다.

## 서버 저장과 만료 삭제

비공개 버킷 `interview-job-exam`에 `{attemptId}/answer.wav`로 저장한다. DB에는 파일 경로·해시·응시·리포트를 저장하며 음성 바이너리는 넣지 않는다. 새 마이그레이션은 버킷을 비공개로 생성하고, 같은 이름의 기존 버킷이 공개라면 안전하지 않은 구성으로 거부한다.

`cleanup` POST 동작은 CRON_SECRET Bearer 인증만 허용한다. 만료 조회 → 실제 Storage 객체 삭제 → DB 삭제 순서다. Storage 삭제에 실패하면 해당 DB 기록을 보존해 다음 정리에서 재시도한다. 학생에게는 만료 즉시 조회를 차단한다. 실제 정리 스케줄은 아직 등록하지 않았으며 운영 활성화 전에 연결해야 한다.

### 운영 준비 파일과 설정

새 마이그레이션은 공식 CLI로 생성한 `supabase/migrations/20261029025804_interview_student_job_exam.sql`이다. 앞선 키워드 조건 마이그레이션 다음에 적용한다. 운영 적용은 하지 않았다.

```text
INTERVIEW_JOB_EXAM_ENABLED=false
OPENAI_API_KEY=<기존 서버 전용 키>
INTERVIEW_EXAM_JUDGE_MODEL=<설정한 문맥 모델>
INTERVIEW_EXAM_VERIFIER_MODEL=<서로 다른 검증 모델>
SUPABASE_URL=<기존 프로젝트>
SUPABASE_SERVICE_ROLE_KEY=<서버 전용 키>
CRON_SECRET=<32자 이상 서버 정리 비밀>
```

학생 모드는 별도 INTERVIEW_JOB_EXAM_ENABLED 플래그로만 켠다. 기존 관리자 검증 활성화 플래그만으로 학생 모드가 켜지지 않는다. 공급자 모델·저장 설정·정리 비밀이 없으면 시작을 제공하지 않는다. 비활성 상태에서도 인증된 본인의 기존 응시 기록 조회는 유지한다.

Vercel 설정에는 새 함수의 syd1 지역과 최대 240초만 추가했다. 기존 함수 설정이 그대로인지 비교 검증했다. 실제 요금제 실행 시간 지원과 비용·부하 검증은 운영 활성화 전 확인해야 한다. 기존 서비스워커 캐시 갱신과 실제 정리 스케줄 연결도 배포 단계에서 별도로 필요하다. 현재 배포나 활성화는 하지 않았다.

## 검증

신규 학생 경로 검사 19개 통과:

- 학생 API/로컬 SQL: 승인 문항·직렬·수강 권한, 기준 고정, 제출과 비공개 저장, 소유권, 만료 삭제, 일일 한도, 중복·동시 요청, 저장 실패 재시도, all 조건 누락 거부·허용 표현 인정, 판정 저장 실패 시 자동 재분석 방지.
- 학생 UI 수명: 늦게 도착한 마이크 권한 응답 처리, 녹음 중 이동 차단, 종료·저장·마이크 해제, 전송 실패 시 원본 보존, 화면 파괴 후 늦은 응답 차단.
- WAV/Storage 계약: 서버 검사와 맞는 PCM 인코딩, 스테레오 다운믹스·90초 제한, 불변 업로드와 제한된 재생 링크, 비공개 버킷 생성과 기존 공개 버킷 거부.

공통 녹음의 빈 출력은 성공으로 표시하지 않고 interrupted로 기록하는 검사도 추가해 통과했다. 기존 전공 채점·평가 지표·키워드/리포트 13개·공통 응시/저장 12개·Live UI 5개·native launcher 4개·release-safety 3개 및 면접 DB/API 검사도 통과했다.

실제 내장 브라우저에서 학생 앱 경로를 열고 합성음으로 MediaRecorder 녹음 → IndexedDB 저장 → 재생 → 실제 WAV 변환 → HTTP 제출 → 로컬 DB/임시 서버 음성 저장 → 모의 AI 판정 → 학생 리포트 표시를 확인했다. 새로고침 후 리포트 재조회와 인성/실전 모드의 기존 준비 중 화면 유지도 확인했다. 제출 WAV를 실제 IndexedDB에 저장하고 DB를 재연결해 같은 바이트가 복원되며 다른 계정에서는 조회되지 않는 것도 확인했다.

검증 중 합성 녹음이 빈 파일을 반환한 사례를 발견해 잘못된 성공 안내를 보완했다. 이는 물리 마이크 품질 측정 결과가 아니다. 실제 iPhone/Android 마이크·장시간/절전·권한 거절·네트워크 단절·외부 전사/판정 정확도·Supabase 실제 업로드와 삭제는 추가 검증 대상이다.

고유 임시 폴더에서 격리 빌드와 변경 파일 구문 검사가 통과했고 config.js 원본은 유지했다. 새 함수 외 Vercel 설정은 HEAD와 동일함을 확인했다.

기존 `interview-navigation-loading.test.cjs`는 8개 통과, `interview-draft-worker.js`의 기존 Vercel 지역 설정 누락 검사 1개 실패다. 새 전공 함수 지역은 등록되어 있다. 이번 범위 밖 설정 누락을 함께 고치지 않았다. 앞선 자료 검수 테스트의 corpus 해시 불일치도 이번 학생 경로와 무관하며 관련 원본 자료는 변경하지 않았다.

격리 브라우저 검증 재현:

```sh
PGLITE_MODULE=/path/to/@electric-sql/pglite node scripts/interview-student-job-preview.cjs
```

출력 localhost는 기존 서버와 분리된 포트다. 테스트 HTML에서만 마이크를 합성음으로 대체하며 실제 앱 모듈에는 그런 대체 동작이 없다. 운영 계정·운영 DB·유료 모델은 호출하지 않는다.
