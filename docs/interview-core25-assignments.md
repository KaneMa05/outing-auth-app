# 핵심 25제 작성하기

2026-10-23 확정 구현. 초기 사전과제 설계서의 STEP별 37개 과제와 학습 체크리스트를 대체한다.

## 학생 화면

- 앱은 하단 `작성하기 → 핵심 25제`, PC는 기존 핵심문항 메뉴 위치의 `핵심 25제 작성하기`로 제공한다. 별도 하단 탭과 중복 핵심 30제 메뉴는 제거했다. 이전 사전과제 링크는 통합 화면으로 연결한다.
- 기존 핵심인성 자료의 본문 25문항을 순서대로 표시한다. 질문은 입력하지 않는다.
- 각 문항 상단의 `요약서 보기`로 원본 수정본 PDF의 2쪽을 이미지로 펼쳐 본다. 원본의 표·문단·여백을 그대로 유지하며 이미지를 누르면 새 탭에서 크게 볼 수 있다. 필요한 문항의 이미지만 불러오고, 접어도 작성 중인 답변은 유지한다. 접근성을 위해 텍스트 읽기도 제공한다.
- 각 문항은 `내 답변` 한 칸(최대 4,000자)으로 임시저장·제출한다.
- 학생 작성 대상은 핵심인성 25문항만이다. 기타질문은 학생 목록·작성·제출·진단 대상에서 제외한다. 기존 기타질문 답변과 지침은 삭제하지 않고 관리자에게만 이력으로 보존한다. 전체 제출 완료는 핵심 25문항만으로 계산한다.
- 빈 답변 제출은 차단한다. 출제 의도·주의사항·답변 구성별 입력, STEP 1/2/4 과제, 학습 체크리스트, 파일 대체·일괄 제출은 포함하지 않는다.
- 학생이 `내 답변 진단하기`를 직접 누른다. 입력 중인 답변을 먼저 저장하고, 서버에서 본인 답변과 저장 버전을 검증한다. 임시저장은 제출 원본을 변경하지 않는다.
- 학생이 요청하면 확정 강의 기준으로 각 항목을 충분·보완·미확인으로 진단한다. 원문 근거 인용, 판단 이유, 보완 질문, 답변 구성 순서를 표시한다. 점수·합격 판단·모범 답안은 생성하지 않는다. 진단 버튼은 제출 버튼과 별개다. 실행기 미연결 시 연결 대기로 표시하고 결과를 만들지 않는다.
- 저장 실패 시 입력을 유지한다. 중복 요청은 접수 번호를 재사용하고 다른 화면의 변경은 버전으로 보호한다.

## 교사 화면

`면접반 → 핵심 25제 과제 관리`에서 학생·상태별 조회, 핵심인성 25문항 진도, 기타질문 상태, 제출 답변과 회차 이력을 조회한다. 교사 확인·보완 요청 UI 및 처리 API/RPC는 제거했다. 학생의 미제출 초안은 교사 API에 제공하지 않는다.

제출 운영 설정에서 제출 열기, 최초 마감, 수정 답변 마감, 지각 제출 허용을 설정한다. 기본값은 제출 닫힘이다. 최초·수정 답변 마감은 2026년 11월 9일 23:59까지(한국시간)다. 해당 분 전체를 포함하도록 DB에는 배타적 종료 시각인 11월 10일 00:00 KST를 저장하며 화면과 관리자 입력은 11월 9일 23:59로 표시한다. 마감 후 지각 제출 허용 설정은 그대로 유지한다.

## 질문별 진단 지침

관리자 `면접반 → 핵심 25제 과제 관리 → 질문별 진단 지침`에서 핵심 25문항과 기타질문 각각의 지침을 입력·저장·수정한다. 질문 원문, 지침 작성 여부, 저장 버전·일시·작성자와 수정 이력을 제공한다. 최대 10,000자이며 빈 내용으로 저장하면 현재 지침을 비우고 이전 버전은 이력에 남긴다.

`20261023073656_interview_preassignment_guidance.sql`의 별도 비공개 테이블과 RPC를 사용한다. 관리자 읽기·쓰기 권한을 분리하고 동시 편집은 버전으로 보호한다. 학생 API에는 지침 원문과 수정 이력을 포함하지 않는다. 지침 저장은 학생 답변·제출 이력을 변경하거나 진단을 실행하지 않는다.

## 확정 진단 기준과 실행

`output/pdf/core-personality-25-20261023/진단기준_수정본/핵심인성_25제_진단기준.json`의 `2026-10-23-lecture-only` 버전을 사용한다. 핵심인성 1~7강 외 자료는 사용하지 않는다. 25문항, 각 4개 기준을 새 마이그레이션에 원문대로 저장했으며 소스 SHA256을 주석으로 기록했다. 이미 저장된 관리자 지침은 보존하고 비어 있는 문항만 강의 지침으로 초기화한다.

`ip_pa_rubrics`와 `ip_pa_diagnoses`는 RLS 및 service_role 전용 RPC로 보호한다. 서버만 기준과 답변 스냅샷을 읽으며 학생에게 내부 지침 전체나 다른 학생 기록을 반환하지 않는다. 모델의 충분·보완 판정은 학생 답변의 정확한 원문 인용을 요구한다. 누락·중복 기준이나 답변에 없는 인용은 저장하지 않는다.

답변 내용, 기준·지침 버전, 실행기 버전이 같으면 완료 결과를 재사용한다. 동시 요청은 하나만 실행한다. 실행 중 답변이나 지침이 바뀌면 결과를 보존하면서 이전 내용에 대한 결과로 표시한다. 서버 결과는 다시 열어도 조회할 수 있다. 중단된 실행은 4분 뒤 실패로 전환하며 자동 재실행하지 않는다. 모델 호출은 180초로 제한하고 학생별 동시 1건·하루 40건, 전체 동시 3건·하루 500건을 제한한다.

로컬 실연결은 `node scripts/interview-prep-ui-qa.cjs --serve --core25-diagnosis`를 명시한 경우만 켜진다. 기존 ChatGPT 로그인 기반 CLI를 사용하며 API 키는 전달하지 않는다. 문항 1개의 기준과 학생이 누른 답변만 전송한다. 도구·웹·개인 메모리를 비활성화하고, 도구 이벤트가 나오면 결과를 거부한다. 로컬 미리보기는 서버 종료 시 자료가 초기화된다.

배포 환경은 기본 비활성이다. 별도로 승인한 HTTPS 실행기만 `INTERVIEW_CORE25_DIAGNOSIS_ENABLED=true`, `INTERVIEW_CORE25_DIAGNOSIS_URL`, `INTERVIEW_CORE25_DIAGNOSIS_TOKEN`, `INTERVIEW_CORE25_DIAGNOSIS_ENGINE_VERSION`으로 연결한다. 실행기 계약은 POST `{instructions,schema,snapshot}`에 지정 JSON schema 결과를 반환하는 것이다. 리디렉션·자동 재호출을 허용하지 않는다. 원격 실행기 배포·보관 정책·운영 활성화는 이번 로컬 변경에 포함하지 않는다.

## 저장 및 접근

`20261023064604_interview_preassignments.sql`은 독립된 `ip_pa_*` 테이블 6개와 RPC를 추가한다. 기존 답변·인생그래프·진단·AI 기록을 수정하지 않는다. 문항 원본과 답변은 접수 회차별 스냅샷으로 보존한다.

기존 면접반 로그인과 이용 권한을 검증한다. 교사 읽기·쓰기 권한을 각각 확인한다. 모든 테이블에 RLS를 적용하고 브라우저 역할에는 직접 접근과 RPC 실행을 허용하지 않는다. 개인 답변 API는 `no-store`로 응답한다. 새 Storage 버킷은 없다. AI 호출은 학생의 명시적인 진단 요청과 실행기 설정이 있을 때만 수행한다.

문항은 `lib/preassignment-catalog.cjs`와 SQL 시드에 동기화되어 있다. 원본은 `supabase/seeds/interview-core30.json`의 `main` 25개이며 기존 컬렉션의 공개 상태는 변경하지 않는다.

## 검증

- `npm run test:preassignments`: 로컬 PostgreSQL 기반 저장·접수·이력·동시 수정·기한·권한·기존 데이터 분리와 API 검증.
- `node tests/interview-preassignments-browser.cjs`: 로컬 가상 학생으로 저장 실패 복구, 제출, 학생의 진단 요청·자동 저장·기준별 결과·근거·보완 질문 표시, 교사 확인 제거, 재제출, PC 메뉴 및 모바일 레이아웃 검증. Playwright/Chrome 경로는 실행 환경에 맞게 지정한다.
- `npm run test:interview`, `node tests/release-safety.test.js`: 기존 면접반 기능과 빌드/서비스워커 보호 회귀 확인.
- `node scripts/interview-prep-ui-qa.cjs --serve`: 로그인 포털을 포함한 통합 미리보기에도 과제 API와 로컬 DB를 연결한다.
- `node scripts/preassignment-preview.cjs`: 운영 DB에 연결하지 않는 로컬 미리보기. 재시작하면 가상 데이터가 초기화된다.

- `node tests/interview-preassignment-diagnosis.test.cjs`: 기준·지침 로딩, 결과 저장, 근거 검증, 캐시, 동시 요청, 소유권, 실패 및 제한 검증.
- `node tests/core25-diagnosis-live.cjs`: 가상 답변 1건의 실제 CLI 연결 인수. 외부 전송 승인을 받은 뒤 실행한다. 현재 실제 연결 인수는 미완료이며 로컬 DB·API·브라우저 검증과 구분한다.

## 운영 반영 대기

사용자의 최종 확인 전에는 푸시·배포·원격 DB 마이그레이션을 실행하지 않는다. 현재는 로컬 구현과 검증만 수행했다. 승인 후 기존 미배포 변경을 확인하고, DB 마이그레이션을 먼저 적용한 다음 앱을 배포한다. 기본 제출 닫힘 상태에서 로그인과 기존 기능을 확인하고 교사가 운영 설정을 열도록 한다. 롤백 시 제출 설정을 닫고 기존 앱 버전을 복원하며 새 테이블의 접수 데이터는 삭제하지 않는다.
