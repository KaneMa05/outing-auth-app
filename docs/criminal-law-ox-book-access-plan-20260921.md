# 형사법 OX 교재별 이용 권한 기획안

작성일: 2026-09-21

확정된 요구: 교재는 형법·수사·증거·공판 3권으로 판매하며, 구매한 권에 해당하는 OX만 제공한다. 학원·자체 판매이며 관리자가 구매를 확인한 뒤 개방한다.

이 문서는 기획안이다. 이용 기간, 기존 이용자 전환 정책 등 아래의 제안은 아직 확정된 운영 정책이 아니다. 앱 코드와 운영 데이터는 변경하지 않았다.

## 1. 상품과 이용 범위

| 구매 교재 | 개방 범위 | 미구매 범위 |
| --- | --- | --- |
| 형법 | 형법 총론·각론 OX | 수사·증거, 공판 잠금 |
| 수사·증거 | 수사·증거 OX | 형법, 공판 잠금 |
| 공판 | 공판 OX | 형법, 수사·증거 잠금 |
| 2권 | 구매한 두 영역 | 나머지 한 영역 잠금 |
| 3권 | 세 영역 전체 | 없음 |

- 학생 계정마다 교재별 권한을 독립적으로 관리한다.
- 추가 구매는 기존 권한에 더한다. 다른 교재의 권한이나 이용 기간을 덮어쓰지 않는다.
- 권한은 문제 풀이, 정답·해설, 오답노트, 북마크, 메모, 취약 분석에 일관되게 적용한다.
- 초기 버전은 기존 계정을 대상으로 한다. 교재만 구매한 비수강생도 이용하게 할 경우 별도 가입·로그인·계정 유지 정책을 먼저 정해야 한다. 출석·성적 등에 영향을 주는 수강생 유형을 임의로 부여하지 않는다.

## 2. 관리자 운영 흐름

기존 ‘형사법 OX 관리 → 이용 수강생 관리’를 교재별 관리로 확장한다.

1. 이름 또는 학생 ID로 계정을 검색한다. 동명이인은 학생 ID와 반 정보를 함께 확인한다.
2. 해당 학생의 현재 교재별 권한을 확인한다.
3. ‘교재 구매 등록’을 열어 구매 교재를 선택한다. 여러 권 동시 선택을 지원한다.
4. 구매일, 판매 기록 번호 또는 확인 메모, 이용 기간을 입력한다. 카드·계좌 등 결제정보는 수집하지 않는다.
5. 저장 전에 ‘이번에 형법을 추가합니다. 기존 공판 권한은 유지됩니다’처럼 변경 범위를 표시한다.
6. 저장이 성공하면 해당 영역을 개방하고, 처리자·처리 시각·변경 사유를 기록한다.

관리 목록 예시:

| 학생 | 형법 | 수사·증거 | 공판 | 작업 |
| --- | --- | --- | --- | --- |
| 홍길동 / 학생 ID | 이용 중 | 미등록 | 이용 중 | 구매 등록 · 이용 관리 |

- 상태는 미등록 / 이용 중 / 만료 / 중지로 구분한다.
- 필터는 교재, 이용 상태, 이름·학생 ID를 제공한다.
- 이미 이용 중인 교재의 중복 등록은 자동 연장하지 않고 현재 상태를 안내한다.
- 구매 취소 또는 오등록 수정 시 교재를 지정해 중지하고 사유를 남긴다. 권한 기록 자체는 삭제하지 않는다.
- 여러 관리자가 동시에 처리할 때 중복 권한이나 서로의 변경 덮어쓰기가 발생하지 않도록 한다.
- 1차 버전은 개별 등록과 여러 권 선택까지 제공한다. 구매자 명단 일괄 등록은 운영량에 따라 후속 개발한다.

## 3. 수강생 화면

최소 한 권의 유효한 권한이 있는 학생에게 기존 홈의 ‘형사법 OX’ 진입점을 표시한다. 구매 이력이 전혀 없는 학생의 홈은 현재처럼 유지하는 안을 권장한다.

OX 안에서는 세 영역을 모두 표시하되, 미구매 영역은 잠금 상태로 안내한다.

| 영역 | 형법만 구매한 학생에게 표시할 내용 |
| --- | --- |
| 형법 | 이용 중 · 학습하기 |
| 수사·증거 | 잠금 · 교재 구매 확인 후 이용 가능 |
| 공판 | 잠금 · 교재 구매 확인 후 이용 가능 |

- 잠금 영역을 누르면 ‘수사·증거 교재 구매자에게 제공되는 학습 서비스입니다. 구매하셨다면 학원에 구매 확인을 요청해주세요’라는 안내를 보여준다.
- 현재 판매 방식에 맞춰 안내를 제공하며, 별도 결제·인증코드 절차는 초기 범위에 넣지 않는다.
- 처음 진입할 때 실제로 이용 가능한 영역을 선택한다. 공판만 구매한 학생도 바로 공판으로 진입해야 한다.
- 오늘 학습, 단원 수·문항 수, 진도율, 오답노트, 북마크, 취약 분석은 현재 이용 가능한 영역만 대상으로 한다.
- 전체 권한이 만료되거나 중지된 기존 이용자에게는 이용 종료 안내를 제공한다. 단순 미구매와 구분한다.
- 추가 구매 후 OX 재진입 또는 권한 새로고침으로 개방 상태를 반영한다. 네트워크 오류를 미구매로 표시하지 않는다.
- 공부 중 권한이 중지되면 다음 서버 요청에서 안내 후 해당 영역 학습을 종료한다. 이전에 내려받은 내용을 소급 회수할 수는 없으므로 화면 상태와 메모리 캐시도 갱신한다.

## 4. 운영 정책 제안과 미확정 사항

| 항목 | 제안 |
| --- | --- |
| 구매 확인 | 관리자가 판매 기록을 확인한 뒤 등록 |
| 권한 귀속 | 구매자 본인 계정 1개 |
| 이용 기간 | 등록일부터 365일을 제안하되 판매 안내 전에 확정. 기간 제한 없이 제공하는 방식도 선택 가능 |
| 추가 교재 구매 | 교재별로 별도 개방일·만료일 관리 |
| 중지·만료 | 해당 영역 접근을 중지하고 풀이 기록·메모는 보존 |
| 재개방 | 보존된 기록에서 이어서 학습 |
| 정오표·해설 정정 | 구매한 판본의 수정 사항에 반영 |
| 새 판본 | 기존 구매 권한에 포함할지 별도 구매로 취급할지 출시 전에 결정 |

365일은 확정 조건이 아니다. 기간 제한을 둘 경우 학생 화면에 정확한 만료일을 표시한다. 기록 보존 기간은 기존 서비스 정책과 맞춰 정하며 영구 보존을 약속하지 않는다.

기존 전체 이용 허가자는 구매 교재 정보가 없으므로 구매자로 자동 간주하지 않는다. 권장 전환안은 기존 이용 범위를 ‘기존 이용자 권한’으로 명시해 보존하고, 이후 신규 구매자부터 권별 등록을 적용하는 것이다. 기존 이용자도 구매 내역 기준으로 제한하려면 먼저 명단을 검토하고 사전 안내한 뒤 전환한다. 운영자의 정책 결정 없이 일괄 잠그거나 구매 기록을 만들어서는 안 된다.

## 5. 현재 코드와 구현 방향

로컬 코드에서 확인한 현재 구조:

- `ox_members.allowed`는 학생별 OX 전체 허용 여부를 관리한다.
- 화면의 학습 영역은 이미 세 갈래이며, 형법에는 총론·각론 구분이 있다.
- `ox_service`와 `ox_learning_data` 두 경로에 학습 데이터 제공 기능이 있다. 기존 전체 데이터 응답과 점진 로딩 경로 모두에 권별 검사가 필요하다.
- 홈 진입점과 OX 화면에 상태 캐시가 있어 권한 변경 시 캐시 반영도 필요하다.

권장 데이터 구성:

- 교재: 교재 ID, 이름, 학습 영역, 판본. 표시 순서가 아니라 고정된 ID로 연결한다.
- 학생별 권한: 학생 ID, 교재 ID, 상태, 개방일, 만료일, 구매일, 구매 확인 근거, 등록 출처.
- 변경 이력: 권한 ID, 변경 전후 상태, 처리자, 시각, 사유.
- 기존 전체 이용 제어는 서비스·계정의 중지 기능으로 역할을 명확히 하고, 실제 학습 범위는 교재별 권한으로 판정한다. 구매 등록 시 필요한 이용 허용 처리도 한 번에 수행한다.

실제 학습 허용 조건은 ‘서비스 운영 중 + 유효한 학생 계정 + OX 이용 허용 + 해당 교재의 유효한 권한 + 공개 문항’이다.

화면 잠금과 별도로 서버에서 문제의 소속 단원·영역을 조회해 권한을 확인한다. 학생이 전송한 영역 값은 권한 판정의 근거로 사용하지 않는다. 문제 목록·본문·상세·정답·해설·채점·메모 저장·학습 통계를 모두 동일한 규칙으로 제한한다. 여러 문항을 요청할 때 잠긴 영역이 섞이면 요청을 거부한다.

잠금 화면에는 교재명 등 안내에 필요한 정보만 제공한다. 미구매 문제 내용·정답·해설을 미리 내려주거나 앱의 정적 자료에 포함하지 않는다. 구버전 앱의 응답 경로도 같은 권한 검사를 적용한다.

권한 테이블은 학생의 직접 수정 경로를 차단하고 관리자 작업 권한을 검사한다. Supabase의 접근 제어는 객체 접근 권한과 행 접근 정책을 함께 고려해야 한다. 현재 서버 전용 구조를 유지하면서 서버 내부에서 교재별 권한을 확인하는 설계를 권장한다. 참고: [Supabase API 보안 문서](https://supabase.com/docs/guides/api/securing-your-api).

## 6. 적용 순서와 완료 기준

1. 이용 기간, 기존 이용자 전환, 비수강생 구매자 제공 여부를 확정한다.
2. 기존 학습 영역과 교재를 연결하고 학생별 권한·변경 이력을 추가한다.
3. 관리자 구매 등록·중지·재개방 기능을 구현한다.
4. 모든 서버 학습 경로에 권한 검사를 적용한다.
5. 수강생 잠금 화면, 진입 영역 선택, 권한 변경 반영을 구현한다.
6. 테스트 계정으로 단권 3가지·2권 조합 3가지·3권·미구매의 8가지 조합을 검증한다.
7. 빌드와 기존 기능 확인 후 사용자의 최종 확인을 받아 푸시·배포한다.

완료 기준:

- 형법 구매 시 총론·각론만 이용되고, 수사·증거·공판 내용은 서버에서도 제공되지 않는다.
- 추가 구매가 기존 권한·학습 기록을 변경하지 않는다.
- 한 권 중지가 다른 권에 영향을 주지 않으며 재개방 시 학습 기록이 유지된다.
- URL 직접 진입, 문항 ID 변경, 혼합 문항 요청, 구버전 요청으로 제한을 우회할 수 없다.
- 만료·중지 직후, 앱 재실행, 다른 기기에서도 같은 권한이 적용된다.
- 오프라인·온라인 관리반·인터넷 수강생에서 동일한 교재 권한 규칙이 적용되고, 출석·외출·성적·플래너 등 기존 기능은 유지된다.
- 기존 이용자는 확정된 전환 정책에 따라 이용 범위를 유지한다.

기획 문서 작성 단계이므로 빌드·테스트·운영 DB 변경·푸시·배포는 수행하지 않았다.
