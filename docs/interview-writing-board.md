# 제출물 첨삭 게시판

교사 화면의 **면접반 → 수강생 작성 내용**은 제출물 게시판을 먼저 표시한다. 자기소개·지원동기·공직관의 최신 제출을 한 줄씩 표시하고, 제목·학생 이름·수험번호·학생 ID 검색, 항목·처리 상태 필터, 30건 단위 페이지 이동을 제공한다. 기존 나의 DB와 미제출 답변 조회는 **학생별 전체 기록**에서 유지한다.

## 첨삭과 학생 확인

1. 목록에서 제목 또는 **첨삭**을 누른다.
2. 제출 원문에서 문장을 선택해 **밑줄 / 빨간 취소선 / 괄호**를 누른다. 코멘트는 원문의 원하는 위치를 클릭해 바로 입력한다. 별도 삽입 버튼은 없으며 학생 원문은 보존한다.

글자색은 원문 문장을 선택하거나 원문 안의 코멘트를 누른 뒤 색상 선택기에서 색을 골라 **글자색 적용**을 누른다. 같은 부분에 색을 다시 적용하면 마지막 색을 사용한다. 글자색도 저장·회차 기록·학생 화면에 함께 반영한다.

3. 처리 상태를 정하고 **첨삭 저장 · 학생에게 전달**을 누른다. 별도 표시 목록·메모 입력란·총평 칸은 없다. 원문 안의 교사 코멘트는 그 자리에서 수정하거나 ×로 삭제한다. 선택한 서식은 **선택 표시 지우기**, 직전 변경은 **되돌리기**로 취소한다.
4. 학생은 해당 작성 화면에서 첨삭을 확인한다. 재제출 전후의 원문·첨삭은 회차별 기록에 남는다.

표시와 코멘트는 원문 기준 Unicode 코드 포인트 범위로 저장한다. 코멘트는 글자 사이에도 삽입할 수 있고, 앞에 코멘트를 넣어도 뒤쪽 원문의 위치는 변하지 않는다. 기존 텍스트 피드백은 원문 끝의 코멘트로 표시하며 보존한다. 사용자 HTML을 실행하지 않으며, 교사가 학생 원문을 변경하지 않는다. 재제출 후에도 이전 표시에는 이전 원문을 연결한다. 표시는 최대 100개이며 각 메모는 최대 1,000자다. 미저장 이탈 확인, 저장 실패 시 입력 유지, revision 충돌 처리는 기존 저장 흐름을 따른다.

게시판 API는 기존 교사 세션의 `interview.read`, 첨삭 저장은 `interview.write` 권한을 검사한다. 브라우저 DB 역할에는 새 RPC 실행 권한이 없으며, 서버의 검증된 actor만 기존 service_role 경로로 접근한다. 게시판 목록에는 답변 본문을 포함하지 않는다.

## 로컬 검증

- `npm run test:interview`: 기존 면접 기능 회귀 및 첨삭/게시판 DB·API 테스트.
- `node tests/release-safety.test.js`: 설정 보호, 서비스 워커 자산 및 API 캐시 제외.
- `node scripts/interview-prep-ui-qa.cjs`: 격리된 메모리 Postgres와 실제 로컬 API를 사용하는 교사·학생 브라우저 흐름.
- `node scripts/interview-prep-ui-qa.cjs --writing-board-only`: 첨삭 선택·저장 실패/재시도·재조회·삭제 및 PC/휴대폰 화면 집중 검증.

브라우저 결과는 `.tmp/interview-qa/annotation-*.png`와 `student-annotation-feedback-mobile.png`에 저장한다. 테스트 중 운영 DB나 외부 AI는 호출하지 않는다. 프로덕션 모드 빌드는 `.tmp/writing-board-build`에서 예시 공개 설정으로 확인하여 작업 폴더의 설정을 변경하지 않는다.

## 운영 반영 순서 — 사용자 최종 확인 후

1. `20261024111532_interview_writing_annotations_board.sql` 마이그레이션을 적용한다. 기존 행 삭제 없이 열·함수·인덱스를 추가한다. 이전 클라이언트의 텍스트 피드백도 호환된다.
2. 첨삭 모듈, 게시판, API, 갱신한 CSS·진입 모듈·서비스 워커를 함께 배포한다. 같은 체크아웃에 있는 별도 작업 변경은 이번 변경과 따로 검토한다.
3. 허가된 테스트 계정에서 제출 → 교사 첨삭 → 학생 확인을 점검한다.

프런트엔드를 이전 버전으로 되돌려야 해도 새 DB 열과 기록은 보존한다. 첨삭 JSON을 모르는 이전 화면에서도 텍스트 피드백은 계속 동작한다. 이 작업에서는 푸시·배포·운영 DB 적용을 수행하지 않았다.
