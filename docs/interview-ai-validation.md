# 자동 처리 구현 검증 기록

검증일: 2026-10-20

## 최신: CLI 방식 전환 후 검증

사용자가 CLI를 허용하여 실제 연결을 완료했다. 버튼 연결 모듈 → 로컬 HTTP API → DB 대기열 → `codex exec` → 결과 저장 → 학생 조회가 통과했다. 23.78초, 402자, 경험 3개, 근거 9개, 도구 실행 0개. 별도 CLI 테스트 7개는 시작 응답 유실·재시작·암호화 영수증 회수·예상 밖 도구 차단을 확인한다. [상세 및 실행법](interview-ai-cli.md).

아래는 CLI 전환 이전의 검증 이력이다. 데스크톱 소켓 경로는 여전히 미통과지만 현재 CLI 경로의 출시 조건은 아니다. 운영 반영·브라우저 인수·정확한 30문항 지정·처리량 검증은 남아 있다.

추가 검증: 사용자 허용 후 실제 Codex 앱에 테스트 작업을 생성했다. 32.765초 만에 생성된 504자 자기소개, 근거 9개, 경험 3개를 회수하여 JS/Python 검증과 테스트 DB 저장·학생 조회를 통과했다. 아래 최초 검증표의 “실제 모델 미실행”은 이후 보완되었다. 일반 PC 처리기의 소켓 연결은 여전히 미통과다. [추가 검증 상세](interview-ai-desktop-generation.md).

## 결과

서버 API·DB 대기열·PC 처리기·버튼 연결 모듈을 앱 저장소에 추가했다. 실제 Codex 앱 연결은 미통과이므로 운영 생성은 비활성 상태다. 푸시, 배포, 운영 DB 적용, 실제 학생 자료의 모델 전송은 하지 않았다.

빌드 검증 첫 시도는 복사 폴더에 `interview-preview-config.json` 의존 파일이 없어 실패했다. 해당 기존 의존 파일을 함께 복사한 후 성공했다. 기존 core30 테스트의 ES 모듈 형식 경고는 테스트 실패가 아니며 이를 없애려고 기존 package.json을 바꾸지 않았다.

## 앱에 추가한 범위

- 신규 파일 20개: API 2개, 공통 검증 2개, 연결 모듈 1개, 마이그레이션 1개, 테스트 4개, PC 처리기 관련 7개, 문서 3개.
- 기존 `local-dev-server.js`: 새 API 경로 2개 등록.
- 기존 `.vercelignore`: `tools/interview-worker/` 제외.
- 기존 학생·교사 화면, 저장 API, 인증 코드, 운영 설정을 수정하지 않음.

앱 화면 작업에서 기존 네 버튼을 새 연결 모듈에 연결하는 작업은 아직 인수하지 않았다. 모든 개발·운영 단계가 완료되었다고 판단하지 않는다.

## 출시를 막는 항목

1. Windows Codex 데스크톱의 실제 연결·새 세션·결과 회수 경로를 확보하고 D0를 통과해야 한다.
2. 외부 도구·파일·다른 학생 문맥이 사용되지 않는지 실제 앱에서 확인해야 한다.
3. 핵심 30문항의 정확한 ID 목록을 확정해야 한다. 기존 묶음은 본문 25개와 부록 22개다.
4. 완성된 앱 버튼과 테스트 DB를 연결하여 브라우저→PC→앱→결과 화면을 검증해야 한다.
5. 실제 PostgreSQL 다중 연결 임대 경쟁과 제한된 시험 운영의 품질·처리량을 확인해야 한다.
6. 사용자 최종 확인 후에만 운영 DB 적용·푸시·배포·활성화를 수행한다.

PGlite 단일 프로세스 검증은 실제 서버의 동시 연결 성능이나 경쟁 조건 전체를 보장하지 않는다. 가짜 앱 어댑터 검증은 Codex 데스크톱 사용 가능성을 보장하지 않는다.
