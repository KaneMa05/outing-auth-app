# 면접반 관리자 수강생 작성 내용 조회

면접반 관리 메뉴의 **수강생 작성 내용**에서 학생별로 저장한 자료를 모아 읽는다. 학생 등록·첨삭 화면은 기존대로 유지한다.

- 이름·학생 ID·수험번호 검색, 직렬 및 작성 상태 필터, 최근 변경 순 정렬, 30명 단위 페이지 이동.
- 인생그래프·경험·자격·소속·수상·인성 준비 노트, 자기소개·지원동기·공직관·핵심 30제 답변과 기존 피드백을 조회.
- 임시저장과 보관된 준비 항목·비공개 전환된 질문의 기존 답변도 표시. 서버에 저장하지 않은 편집 중 내용은 조회 대상이 아니다.
- 면접반에 등록된 기존 학생·면접 전용 신규 학생을 모두 포함하며 계정 비활성, 이용 중지, 기간 만료로 기록을 숨기지 않는다.
- 목록은 작성 내용의 개수와 상태만 가져오고 선택한 학생의 본문은 한 번의 별도 요청으로 조회한다. 목록의 최근 변경 시각에는 피드백 변경도 포함된다.
- 학생별 영역 전환과 모두 펼치기·접기를 제공한다. 조회 화면에서는 학생의 원문을 수정하지 않는다.

## 권한과 DB 변경

`admin_review_students`, `admin_review_detail`는 기존 관리자 세션 및 `interview.read` 권한을 검사한다. 학생이 보낸 `actor` 값은 사용하지 않는다.

`20261020074815_interview_student_review.sql`은 `ip_review_service` 읽기 전용 함수를 추가한다. `STABLE SECURITY INVOKER`이며 행 잠금이나 데이터 변경이 없다. `PUBLIC`, `anon`, `authenticated`의 함수 실행 권한을 제거하고 `service_role`에만 허용한다. 기존 테이블·정책·수강생 인증 흐름은 변경하지 않는다.

운영 적용 시 이 마이그레이션과 코드 배포가 함께 필요하다. 이 작업은 로컬 구현·검증 범위이며 운영 DB 적용·푸시·배포는 별도 최종 확인 후 진행한다.

## 로컬 확인

`npm run preview:interview-prep`로 격리된 테스트 서버를 시작한다. 출력된 `/__qa/login`에서 `18120 / demo2026!!`로 로그인해 작성·저장하고, 같은 서버의 `/admin`에서 **수강생 작성 내용** 메뉴를 연다. 이 서버의 데이터는 종료 시 초기화된다.

검증 명령:

```text
npm run test:interview
node scripts/interview-prep-ui-qa.cjs
node scripts/verify-interview-build.cjs
```

DB/API 검증은 조회 권한, 역할별 함수 권한, 학생 분리, 신규·비활성·기간 만료 계정, 임시저장, 필터·검색·페이지 이동과 읽기 전용 동작을 확인한다. 브라우저 검증은 실제 관리자 메뉴, PC·모바일 레이아웃, 본문 이스케이프, 학생 전환, 검색·필터·페이지 이동을 확인한다.
