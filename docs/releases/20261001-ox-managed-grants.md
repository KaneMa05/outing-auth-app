# OX 온라인 관리반 일괄 지급 및 지급 확인 시간초과 수정

상태: 사용자 최종 승인 후 운영 DB 적용 및 검증 완료. 앱 푸시·배포 진행 중.

## 원인과 변경

- 2026-10-01 08:11:37 UTC 운영 Postgres 로그에서 `admin_grant_preview`의 대상 인원 계산 중 `statement timeout` 확인. `ox_grant_targets` → `ox_grant_track_eligible` → `ox_normalize_grant_track`에서 같은 직렬·과목 설정을 반복 계산했다. 확인 시점 지급 건은 0건이었으며 이번 조사로 지급을 실행하지 않았다.
- 일괄 지급 기수 선택에 `온라인 관리반` 추가. API와 DB는 `online_managed` 값을 명시적으로 허용한다. 기존 빈 값과 숫자 기수는 오프라인 대상 의미를 유지한다.
- 관리반에서도 형사법 응시 직렬·활성 학생 조건을 적용한다. 직렬 필터, 개별 선택·조건 전체 선택, 지급 확인, 이력과 회수를 기존 흐름으로 사용한다. 기수 변경 시 선택은 초기화된다.
- 관리반 이용권은 관리반 재원 중에만 유효하며, 기존 오프라인 이용권은 오프라인 재원 조건을 유지한다. 인터넷 수강생, 교사 계정, 비활성 학생은 새 지급 대상에 포함되지 않는다. 실제 교재 구매 권한은 독립적으로 유지한다.
- 대상 조회에서 학생 범위를 먼저 좁히고, 서로 다른 직렬과 과목 설정을 한 번씩 정규화한다. 지급 확인에서는 적격 대상 명단을 한 번 생성하여 선택 검증·인원 계산·지급 명단 저장에 재사용한다. 최종 지급 시 대상 변경·10분 유효시간·중복 요청 검증은 유지한다.
- SQL은 `supabase migration new`로 생성한 `20261001082345_ox_managed_grants_and_fast_preview.sql`. 대상 조회, 지급 확인, 이용권 판정 함수와 배치 기수 제약만 변경하며 이용권을 자동으로 지급하지 않는다.

## 검증

- 전체 `npm test` 및 `npm run test:criminal-law-ox`: LF로 정규화한 `.tmp/managed-grants-validation`에서 통과. 기존 미완료 성적·회독 변경은 검증 배포본에서 제외했다.
- 실제 운영과 같은 168개 과목 설정, 가상 학생 320명 중 55명 지급 확인: 기존 약 19초 → 수정 후 28ms. 대상 ID 명단 동일 확인. 로컬 PGlite 측정값이며 운영 환경의 응답 시간 보장은 아니다.
- 오프라인 기존 지급·구매·만료·회수·학습 기록 회귀 검증 통과. 관리반 지급·미선택 학생 제외·비활성 및 유형 변경·구매 권한 유지·선택 변경·반복 지급의 중복 방지 검증 통과.
- 변경 함수의 SECURITY INVOKER 유지, anon/authenticated 실행 차단 및 service_role 실행 허용 확인.
- `scripts/ox-books-ui-qa.cjs`: 실제 UI/API/SQL과 가상 학생으로 관리반 선택 → 확인 → 지급 → 학습 이용 → 회수 검증. PC 1100px/모바일 390px 가로 넘침 없음. 운영 학생 데이터는 수정하지 않았다.
- 운영 공개 설정을 사용한 격리 빌드와 서비스워커 자산 검사 통과. 로컬 설정 파일은 변경하지 않았다.
