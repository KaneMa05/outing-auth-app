# 경험 질문 생성기 상태 표시

관리자 면접반 홈에서 작업기 연결, 생성 중·대기 건수, 마지막 접속과 최근 완료·실패 시각을 확인한다. 화면이 보일 때 10초마다 조회하고, 다른 화면으로 이동하거나 탭을 숨기면 반복 조회를 멈춘다. 실패한 조회는 기존의 정상 표시를 유지하지 않고 확인 불가로 표시한다.

상태 조회는 관리자 `interview.read` 권한이 필요하다. 서버가 기존 `ip_draft_worker_presence` 및 질문 작업 테이블의 상태·시각만 읽는다. 학생 이름·경험 내용·질문·작업기 인증 토큰은 응답에 포함하지 않으며, 작업을 가져오거나 새로 생성하지 않는다. 새 테이블이나 DB 마이그레이션은 없다.

작업기는 생성 중 15초 간격으로 인증된 생존 신호를 보낸다. 대기 중에는 기존 5초 주기 poll이 접속 시각을 갱신한다. 45초 넘게 신호가 없으면 연결 확인 지연이다. 생성 중 건수는 만료되지 않은 배정 기준으로, 실제 모델 처리 진척률은 아니다. 연결됨은 AI 제공자 인증·잔여 한도·생성 성공까지 보장하지 않는다. 최근 실패는 보존된 마지막 실패이며, 그 뒤 완료가 있으면 복구된 경우일 수 있다. 만료 작업은 기존 poll/status 흐름에서 실패로 정리되므로 만료 직후에는 실패 시각 반영이 늦을 수 있다.

## 적용 순서

1. 사용자 최종 확인 후 API와 관리자 화면을 함께 배포한다. 기존 학생 생성 요청과 DB 권한은 유지한다.
2. 현재 작업 완료를 확인한 뒤 작업기를 새 버전으로 재시작한다. 기존 프로세스는 파일을 갱신해도 이미 읽은 코드를 계속 사용한다. 실행 중 작업기를 강제 종료하지 않는다.
3. 관리자 홈에서 마지막 접속, 생성 중/대기, 최근 완료 시각을 확인한다. 새 작업기 적용 전에는 긴 생성 중 접속 시각 갱신이 지연될 수 있다.

로컬 검증: 상태·권한·생존 신호 및 UI 수명 주기 테스트, 기존 질문 API/큐/관리자 테스트, 격리 빌드. 운영 배포, 운영 DB 변경, 실제 AI 요청, 기존 작업기 재시작은 구현 검증에 필요하지 않다.

## 대시보드 메뉴 이동 오류 수정

생성기 상태 모듈이 관리자 화면의 공통 `canLeave()` 계약을 구현하지 않아 대시보드에서 메뉴를 누르면 `life.canLeave is not a function` 오류가 발생했다. 읽기 전용 상태 모듈에 `canLeave: () => true`를 추가했다. 조회·생성·승인 처리나 DB는 변경하지 않는다.

상태 모듈 단위 테스트와 실제 브라우저 테스트에서 상위 메뉴의 이동 검사, 대시보드에서 직무·인성으로 이동, 다시 홈으로 돌아온 뒤 재이동, 폴링 정리를 검증했다. 기존 대시보드 집계·공개 승인·배포 안전성 검사와 빌드도 통과했다.
