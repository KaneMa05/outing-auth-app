## 로컬 수정

1. 첫 로딩은 기존 병렬 조회를 유지한다. 수강생·교사 화면의 독립적인 조회가 앞선 응답을 기다리지 않고 모두 시작하는 것을 테스트했다. 조회 대상, 결과 순서, 페이지 수, 호환 스키마 처리와 상태 반영은 그대로다. `shared.js`와 관련 자산 URL에는 최종 변경이 없다.
2. OX의 학습·저장·heartbeat·재진입 요청을 화면별로 순서대로 보낸다. 서버에서 같은 학생의 잠금을 기다리며 여러 연결을 차지하는 상황을 줄인다. 성공한 학습 요청도 서버 세션을 연장하므로 다음 heartbeat를 그 시점부터 60초 뒤로 조정한다.
3. OX 화면을 숨기거나 종료했을 때 아직 보내지 않은 요청은 폐기한다. 이미 전송한 요청은 완료 여부가 확인될 때까지 기다리고, 실패한 저장을 자동 재전송하지 않는다. 다른 탭·기기에서 발생한 동시 요청은 기존 DB 잠금과 기기 정책으로 계속 보호된다.
4. 변경된 JS URL과 서비스 워커 캐시 버전을 함께 갱신했다. 수강생 세 유형 및 교사 화면의 UI 구성, 인증, 권한, 학습·성적·보상 규칙은 유지한다.
5. `20261013112204_ox_compact_summary_sort.sql`은 `ox_learning_data`의 문항 목록 정렬만 변경한다. 작은 요약 JSON과 정렬 키를 먼저 추출하는 `MATERIALIZED` CTE로 본문·해설이 정렬 단계에 전달되지 않게 했다. 테이블, 학습 데이터, 권한, 기기 잠금, 타임아웃과 메모리 설정은 변경하지 않는다. 검토한 함수 소스 해시가 다르면 적용을 거부하므로 다른 변경을 덮어쓰지 않는다. [PostgreSQL CTE 설명](https://www.postgresql.org/docs/17/queries-with.html)

클라이언트 요청 직렬화가 서버 트랜잭션의 즉시 취소를 보장하지는 않는다. Supabase 전체 연결·자원 지연과 cron startup timeout을 이 코드만으로 제거한다고 보장할 수 없다.

## 운영 반영과 후속 확인

승인 범위는 위 SQL 마이그레이션 1개와 앱 변경의 푸시·배포이며 증설은 포함하지 않는다. 운영 함수 원본과 ACL은 `.tmp/20261013-db-pressure-function-backup.json`에 보관했다. 적용 후 소스 해시는 `b956f220f24270bffdf102e7ce997adc`로 검증한 결과와 같으며, service_role 전용 실행 권한·security invoker·빈 search_path가 유지됐다. 원본 해시는 `07aa2d5f13ccf6df68a87f9ca3de6900`이다. MCP가 기록한 실제 마이그레이션 버전 `20261013112204`에 로컬 파일명을 맞췄다.

20:22 적용 직후 학생·출석·공지 API는 모두 200(267/190/159ms)을 반환했다. 이 값은 각 ID 1건의 조회이며 전체 앱 로딩 시간으로 해석하지 않는다. 이후 초기 조회, OX, 기기 정책, 스터디카페, 서비스 워커 자산을 확인한다. 기능 회귀 시 보관한 기존 함수 정의로 복구하고 앱은 이전 배포(`dpl_5oe8rBqapWCMFfG9gAVrJWoCdXLL`, 커밋 `a18a722`)로 되돌린다. 기존 작업 파일 `docs/releases/20261012-supabase-503-incident.md`와 별도 장애 복구 기록 `docs/releases/20261013-evening-db-recovery.md`는 이번 커밋에 포함하지 않는다.

같은 종류의 DB timeout, cron 시작 실패, swap 페이지 교체, API 지연과 임시 블록 증가량을 반영 전후로 비교해야 한다. 첫 화면과 OX 진입·저장 지연도 함께 측정하고, 최초 방문과 캐시가 있는 재방문을 구분한다. 첫 로딩을 늦추는 일괄 동시 실행 제한은 사용하지 않는다. 운영 반영 후 관측과 실제 사용량이 많은 시간대 검증이 남아 있으므로 전체 장애가 완전히 해결됐다고 선언하지 않는다. 재발하면 당시 실행 중인 SQL/세션·호스트 지표를 대조해 다음 병목을 확인한다.
