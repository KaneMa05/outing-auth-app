# OX 오답노트 과목·단원 필터, 정렬과 저장 오류 복구

상태: 2026-09-28 사용자 푸시·배포 최종 승인. 로컬 검증을 마친 변경을 main에 푸시하고 연결된 Vercel 운영 배포로 반영한다.

## 재현한 문제

답안이 서버에 저장된 뒤 클라이언트가 오류 응답을 받으면, 사용자는 풀이 화면을 나가 오답노트로 이동할 수 있다. 기존 화면은 서버 기록을 다시 읽지 않아 누적 오답 횟수와 최신 정오답을 이전 값으로 표시했다. 가상 기록으로 `누적 3회 → 서버 4회 저장 → 응답 오류 → 오답노트 3회 표시`를 재현했다.

운영 계정의 기록과 bootstrap 조회에서는 누적 기록이 일치했다. 사용자에게 발생한 현상의 원인이 위 오류 경로와 동일한지는 확정되지 않았다. 정상 응답 경로의 횟수 갱신도 별도로 검증했다.

## 수정

- 답안 제출 응답 오류가 발생한 경우, 다음 화면 행동 전에 기존 bootstrap 읽기 API로 학습 기록을 다시 동기화한다. 실패하면 화면 이동을 중단하고 다시 시도할 수 있게 한다.
- 정상 제출과 일반 화면 이동에는 추가 요청이 없다. 새 API나 DB 변경은 없다.
- 이미 동기화한 답안을 동일 제출 ID로 다시 시도해도 클라이언트의 풀이 횟수를 중복 가산하지 않는다.
- 생성 스크립트와 학습 모듈을 함께 수정하고 변경된 JS의 캐시 버전을 갱신했다. 기존 화면 디자인은 변경하지 않았다.

## 검증

- 신규 회귀 테스트 8건: 취약단원 직접 재풀이, 이력 목록 재풀이, 저장 지연, 응답 누락, 저장 전 실패, 재조회 실패, 복구 후 동일 제출 재시도.
- `npm.cmd run test:criminal-law-ox`: 전체 통과. DB 테스트는 로컬 PGlite에서 실행하며 매 제출 응답의 누적 횟수도 확인했다.
- `node tests/criminal-law-ox-loading.test.cjs`: 24건 통과.
- `node tests/release-safety.test.js`: 2건 통과.
- JS 구문 검사, 생성 스크립트 실행, diff 공백 검사, 격리 폴더에서 테스트 설정으로 `npm.cmd run build` 통과.

운영 학습 기록은 변경하지 않았다. 기존 사용자 변경 파일 `final-scope-data.js`는 이 수정에 포함하지 않는다.

## 오답노트 필터와 정렬

- ‘형법 전체 · 수사·증거 전체 · 공판 전체’와 개별 단원을 선택할 수 있다. 최신순/누적 오답 횟수순 정렬을 추가했으며, 최신순은 마지막 풀이 시각 내림차순이다.
- 복습 목록과 전체 이력 모두 단원·정렬을 적용하며, 모아 풀기도 표시된 목록 순서를 따른다. 이력 상태 필터와 재풀이 후 복귀에서도 선택을 유지한다.
- 추가된 정렬·필터 회귀 테스트와 기존 저장 복구/지연 로딩/릴리스 검증이 통과했다.
- `node scripts/ox-review-preview.cjs`로 `http://127.0.0.1:4318`에서 예시 기록을 사용하는 로컬 화면을 제공한다. 운영 API는 호출하지 않는다.

배포 전 전체 OX 테스트, 지연 로딩 24건, 릴리스 검증 2건을 다시 통과했다. 로컬 화면에서 과목 선택과 정렬 동작을 확인했다. DB 마이그레이션은 없으며 main 푸시로 연결된 운영 배포 한 번만 진행한다.
