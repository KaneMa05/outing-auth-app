# 인생그래프·경험 DB 서식 입력

2026-10-20 · 로컬 구현 · 운영 DB 적용·푸시·배포 전

## 원본과 범위

사용자 제공 `[론박스터디] 인생그래프 DB 만들기 서식.hwp`를 읽어 5개 입력 영역과 30개 역량의 51개 액션 질문을 반영했다. 원본 예시의 자격증·복무·수상·경험은 학생 답변으로 가져오지 않는다.

학생 경로: **면접 준비 → 인성 → 인생그래프·경험 DB**

관리자 경로: **기존 관리자 페이지 → 면접반 → 학생 등록·첨삭 → 학생의 인생그래프**

현재 학생 화면의 나의 DB 메뉴는 **기본 이력**(소개·자격/어학·소속·수상/성과)과 **인생그래프**(핵심 경험·경험 흐름·역량별 경험 찾기)를 구분한다. PC 좌측 메뉴와 모바일 선택 메뉴에 모두 제공한다. 저장 API와 학생 소유 자료는 공유하므로 한 화면을 저장해도 다른 화면의 기록은 보존한다.

| 영역 | 입력 내용 |
|---|---|
| 기본 정보 | 등록 직렬·수험번호 조회, 주요 이력·전공 입력 |
| 자격·어학 | 구분, 취득·예정 시기, 자격명, 발급기관, 취득 노력 |
| 소속 이력 | 소속 구분, 소속명, 기간, 직책·역할, 담당 업무·활동 |
| 수상·성과 | 시기, 대회·프로젝트명, 기관, 등급, 기여도, 본인이 한 일 |
| 핵심 경험 | 시기, 관련 소속, 경험 제목, 상황, 본인의 행동, 결과, 배운 점, 관련 역량 |

종이 서식의 ‘3줄 요약’을 상황·행동·결과의 세 입력칸으로 나눴다. 경험 입력 목록은 ‘위로’ 버튼으로 순서를 조정한다. 그래프는 입력 목록과 별개로 나이 순서로 표시한다.

2026-10-21 인생그래프: 기본서의 경험 기록 구조를 바탕으로 가로축은 나이, 세로축은 학생이 직접 입력한 만족도로 표시한다. 사용자가 확정한 점수 범위는 **−25~+25점(정수)**이다. 세로축 눈금은 5점 간격이며 입력은 1점 단위다. 점수를 입력·수정하면 그래프가 즉시 갱신된다. 가로축은 표시 가능한 경험의 최소~최대 나이에 맞추며, 나이가 하나뿐이면 중앙에 표시한다. 각 점에는 점수와 경험 제목 앞 두 단어(최대 12자)의 키워드를 함께 표시한다. 점이나 경험 카드를 누르면 전체 내용이 모달로 열리고, ‘내용 수정’으로 기존 입력칸으로 이동한다. 닫기와 Escape를 지원한다. 같은 나이의 경험도 각각 유지하며, 나이 또는 점수가 비어 있으면 해당 점은 표시하지 않는다. 빈 점수를 0으로 바꾸거나 AI로 추정하지 않는다. 실제 0점은 정상 표시한다.

만족도는 선택 입력으로 기존 초안 생성 조건을 바꾸지 않는다. 저장·재접속 및 관리자 조회에 함께 반영하지만 면접 평가 점수나 AI 근거 점수로 사용하지 않는다. 신규 `20261021065038_interview_life_satisfaction.sql`은 기존 저장 RPC에 선택 점수 검증만 추가한다. 운영 DB에는 아직 적용하지 않았다.

2026-10-21 변경: 기본 정보의 ‘간단히 소개’에는 학교, 전공(학과), 동아리, 봉사·인턴 경험, 회사 경력과 직무, 성과(역량)를 구체적으로 작성하도록 안내한다. 핵심 경험은 `year`(연도), `age`(당시 나이), `period`(세부 시기·기간, 선택)로 분리했다. 연도는 1900~현재 연도의 네 자리 숫자, 나이는 0~120세의 정수로 검증한다. 날짜·나이의 사실 여부를 자동 확인하는 기능은 아니며 학생이 정확한 값을 입력해야 한다.

새 필드는 임시저장 시 비워둘 수 있으나 작성 완료 저장과 AI 초안 생성에는 모두 필요하다. 기존 `period`와 본문은 보존하고 연도·나이는 추정하지 않는다. 관리자 조회와 경험 흐름에도 분리된 정보를 표시하며 AI 근거 자료에 두 필드를 포함한다. 마이그레이션 `20261021063447_interview_experience_year_age.sql`은 저장 RPC와 AI 준비 상태·자료 추출을 갱신한다. 이전 양식의 자료도 조회·임시저장할 수 있지만 작성 완료 또는 초안 생성 전에는 새 필드를 보완해야 한다. 운영 DB 적용·푸시·배포는 별도 최종 확인 후 진행한다.

## 현재 인생그래프 입력 구성 (2026-10-21 최종 변경)

- 그래프 정보: 당시 나이(필수), 만족도(−25~+25), 키워드.
- 본문 입력은 **내용 / 면접관에게 어필할 점** 두 칸으로 정리한다. 연도, 별도 시기·소속, 상황·행동·결과·배운 점, 역량 체크 입력은 화면에서 제거한다.
- 기존 자료는 시기·소속·상황·행동·결과를 ‘내용’에 이어서 표시하고 배운 점을 ‘면접관에게 어필할 점’에 표시한다. 기존 원본과 피드백·수정 이력은 지우지 않는다. 새 내용을 명시적으로 입력하면 해당 값이 우선한다.
- 작성 완료와 초안 생성은 나이·키워드·내용·어필할 점을 확인하며 연도를 요구하지 않는다. 자기소개는 서로 다른 내용의 경험 3개 이상 조건을 유지한다. 키워드·나이·어필 문구만 바꾼 복제 내용은 다른 경험으로 세지 않는다.
- 관리자 조회와 경험 상세 모달도 같은 두 본문 항목을 표시한다. 내용은 기존 글을 합칠 수 있도록 최대 12,000자, 어필할 점은 2,000자다. 일반 인성 준비 노트의 질문 구조는 바꾸지 않는다.
- 저장된 경험은 읽기 상태로 보이고 각 경험의 ‘수정’을 눌러 편집한다. 새 경험은 바로 편집할 수 있다. 각 경험의 ‘저장’은 해당 경험만 저장하며 다른 경험·기본 이력의 미저장 변경은 포함하지 않는다. 저장 전·저장 중·저장됨·실패 상태를 표시하고, 실패하면 입력과 편집 상태를 유지한다. 기존 하단 전체 저장 및 첨삭 제출 흐름도 유지한다.
- `20261021071011_interview_experience_age_only.sql`을 마지막에 적용한다. 기존 연도 필수 조건에 대한 위 설명보다 이 최종 구성이 우선한다. 운영 DB 적용은 별도 확인 전까지 진행하지 않는다.

## 입력과 첨삭 흐름

1. 각 영역에 필요한 만큼 항목을 추가한다. 자격·소속·수상 이력이 없으면 ‘해당 없음’을 선택한다.
2. ‘임시저장’으로 서버에 저장한다. 이 화면은 수동 저장 방식이며 미저장 상태를 표시하고 이동·종료 시 확인한다.
3. 기본 이력을 적고 각 영역을 작성하거나 해당 없음을 표시한다. 핵심 경험은 최소 1개에 시기·제목·상황·행동·결과·배운 점을 적어 첨삭을 요청한다.
4. 관리자는 영역별 내용을 확인하고 보완 요청 또는 강사 확인 완료로 피드백을 공개한다.
5. 학생은 피드백을 확인해 수정하고 다시 첨삭 요청한다. 승인 후 수정하면 작성 중 또는 첨삭 대기로 돌아간다.

각 영역 최대 40개, 전체 최대 80개 항목, 각 칸 최대 2,000자를 허용한다. 전체 내용의 DB 저장 한도는 JSON 텍스트 기준 160,000바이트다. 제출 조건은 기본적인 형식 확인이며 경험의 질을 자동 평가하지 않는다.

## 30개 역량과 기존 인성 요소 연결

원본의 30개 역량을 그대로 별도 목록으로 보존한다. 기존 31개 인성 요소와는 준비에 참고할 수 있는 관계를 연결했으며, 두 분류가 완전히 같다는 의미가 아니다. 계획력·수리감각·분석력 등의 원래 이름도 합쳐서 없애지 않는다.

학생은 51개 질문을 읽고 ‘이 역량의 경험 추가’로 소재를 작성하거나, 기존 경험에 여러 역량을 선택할 수 있다. ‘소재 연결 N/30’은 본인이 연결한 역량의 수다. 공식 평가 점수, 강사 검토 결과 또는 기존 13개 준비 항목 작성률로 취급하지 않는다. 직무 기출에는 개인 경험 DB를 만들지 않는다.

## 저장과 접근 제어

- `ip_life_competencies`: 30개 역량, 질문, 기존 요소 연결, 원본 파일명·SHA-256·문단 위치.
- `ip_life_profiles`: 학생별 5개 영역의 구조화 내용, 상태, 피드백, 수정 버전.
- `ip_history`: 저장·피드백 변경 시 스냅샷. 기존 학생 삭제 연쇄 정리를 적용한다.
- `ip_life_service`: 서버 전용 RPC. 기존 학생 기기 인증, 테스트 허용 범위, 면접반 등록·이용 기간 검사를 적용한다.
- 학생은 본인 자료만 읽고 쓴다. 관리자는 기존 `interview.read` 또는 `interview.write` 권한으로 조회·피드백을 수행한다.
- 두 테이블에 RLS를 적용하고 브라우저 역할의 직접 접근을 차단한다. 기존 인증 구조를 유지하며 클라이언트가 보낸 사용자 역할·소유자 값은 신뢰하지 않는다.
- 모든 저장은 버전을 비교한다. 다른 기기나 관리자가 먼저 수정하면 기존 입력을 덮어쓰지 않고 충돌을 알린다. 실패한 입력은 화면에 남기며 개인 내용을 localStorage·서비스 워커에 저장하지 않는다.
