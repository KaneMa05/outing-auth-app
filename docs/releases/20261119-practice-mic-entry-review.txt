모의면접 마이크 권한 및 목록 진입 화면 검토 — 2026-11-19

검토 범위
- 운영 직무·인성 연습모드의 준비 → 면접 시작 권한 검사.
- 모의면접 목록 → 연습모드 진입 시 상단 잘림/임시 화면 노출.
- 앞서 준비한 무음 입력 자동 완료 방지 수정(4fe51eb)에 추가한 로컬 수정이며 아직 푸시·배포하지 않음.

확인 결과
- 기존 코드도 getUserMedia 권한 거절 시 면접 진행 화면으로 넘어가지 않았다.
- 마이크 권한을 허용했지만 소리가 들어오지 않는 경우의 4초 자동 완료 문제와 구분한다.
- 이전 두 회차의 무음 원인이 권한 거절이었다고 확정할 증거는 없다. 기존 녹음·전사·회차는 변경하지 않음.
- 목록에서 진입하면 이전 스크롤 위치를 유지한 채 기존 목록, 준비 중 임시 화면, 스타일 미적용 준비 화면이 순차적으로 노출됐다. 모든 초기 로딩 뒤에만 맨 위로 이동했다.
- 4fe51eb 기준 느린 권한 조회/문항 로딩/CSS 및 scrollY=80 조건으로 재현했다. 프레임 증빙에 목록 → 준비 중 → home 화면과 제목 위치 변동이 남아 있다.

수정
- 준비 화면에서 마이크 권한이 필수임을 연습 시작 버튼 위에 안내.
- 권한 거절/차단 시 준비 화면 유지. 권한 대기 중에도 카운트다운·면접 화면·연습 회차를 생성하지 않음.
- 권한 요청이 성공해도 사용 가능한 live/enabled 오디오 트랙이 없으면 시작 차단.
- 권한 거절과 마이크 연결/사용 불가에 다른 안내를 표시하고 설정 변경 후 재시도 가능.
- 입력 감지 시 disabled 트랙도 사용할 수 없는 입력으로 처리.
- 운영 연습 화면 진입 즉시 이전 내용을 안정된 로딩 화면으로 교체하고 스크롤을 먼저 초기화.
- 화면 틀 스타일을 초기 app CSS로 옮기고, 연습 CSS 완료 및 문항 로딩 후 완성된 준비 화면을 표시.
- 목록/준비 중 임시 페이지와 미완성 준비 폼을 중간에 표시하지 않음. 로딩 제목과 완료 제목 위치 동일.
- 다른 탭의 기존 로딩 후 스크롤 동작과 테스트 앱의 기존 네이티브 흐름 유지.
- JS/CSS 진입 캐시 키를 20261119-mic-entry로 갱신.

검증
- Chrome의 실제 microphone 권한 denied 상태로 직무·인성 시작 모두 차단, home 유지, sync 회차 생성 없음.
- microphone granted로 변경 후 새로고침 없이 같은 버튼으로 재시도, 카운트다운 및 녹음 정상 진입.
- getUserMedia가 빈 MediaStream을 반환해도 시작 차단.
- 권한 응답 대기 중 준비 화면 유지, 뒤로 취소 뒤 늦은 응답의 트랙 종료 회귀.
- 느린 CSS/권한 조회/문항 로딩 프레임에서 scrollY=0, 목록/준비 중 화면 노출 없음, 제목 위치 일정 확인.
- 입력 감지/화면 이동/권한 라우팅/배포 안전성 46개 검사 통과.
- 실제 앱 UI 브라우저 회귀(녹음, 다시 듣기, 답변 돌아보기, 결과, 기록, 업로드, 계정 분리, 무음 입력) 통과.
- 기존 모드 메뉴/테스트 네이티브 브라우저 회귀 및 320/390/844px 레이아웃 통과.
- 격리 빌드·구문 검사 통과. 운영 설정 원본 유지. 실제 모바일 기기에서의 확인은 아직 수행하지 않음.
