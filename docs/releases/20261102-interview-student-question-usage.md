# 생성 질문에 대한 학생 저장 답변 조회

기존 AI 생성 기록은 생성 시점의 경험 사본과 질문만 보여줘 이후 학생이 저장한 답변을 확인할 수 없었다. 생성 기록의 누락된 학생 활용 내용을 보완한다.

학생은 인생그래프에서 **내용 수정 → 꼬리질문 2개 받기 → 답변하기**를 누른다. 질문이 같은 경험의 내용 끝에 `질문: ...` 형식으로 추가되며, 그 아래에 직접 답변한 뒤 저장한다. 별도 문답 패널의 답변은 전용 답변 테이블에 저장된다.

## 관리자 변경

- 생성 기록 목록에 현재 저장된 질문별 답변 수를 표시한다.
- **질문·답변 보기**에서 질문별 학생 답변과 어느 경험에 저장했는지 표시한다.
- 질문만 저장한 경우와 같은 질문을 현재 저장 내용에서 찾지 못한 경우를 구분한다.
- 현재 저장 인생그래프 전체를 펼쳐볼 수 있어, 학생이 질문 문구를 바꾸거나 다른 방식으로 경험을 보완한 경우에도 직접 확인할 수 있다.
- 생성 당시 경험 사본과 생성 질문은 기존 기록으로 유지한다.
- 별도 심화 질문 패널의 저장 답변·기억나지 않음·건너뜀 상태도 연결한다.

현재 저장 내용의 같은 질문 아래에 있는 글을 읽는 방식이다. 과거 기록에 경험 ID나 클릭 이력이 없으므로, 질문 문구가 같은 여러 경험이 있으면 모두 표시하며 특정 생성 요청을 사용했다거나 열람했다는 증거로 단정하지 않는다. 마지막 저장 시각은 학생 자료 전체의 저장 시각이다. 미저장 내용은 조회하지 않는다.

## 범위와 검증

- 학생 입력·저장 경로를 변경하거나 새 답변을 작성하지 않는다. 관리자 `interview.read` 권한으로 기존 저장 자료만 조회한다.
- 프로필은 요청 기록의 학생 ID로 한정한다. 목록에서는 최대 25명분을 한 번에 읽고 답변 본문은 반환하지 않는다. 상세를 열었을 때 답변과 경험을 표시한다.
- 조회 실패를 미작성으로 표시하지 않는다. HTML·스크립트 문자열은 이스케이프한다.
- 로컬 검증: 여러 줄 답변, CRLF, 질문 구분, 질문만 저장, 같은 질문의 여러 경험, 오래된 경험 형식, 학생 범위, 본문 노출 범위, 오류 처리, PC·모바일 화면.
- 학생의 기존 답변 추가·저장·재접속 브라우저 검사와 관리자 메뉴·과제·탐색·격리 빌드 검사.
- 운영 읽기 전용 확인: 질문 생성 기록 70건 중 34건에서 현재 저장된 동일 질문을 찾았으며 33건에서 답변 내용도 확인했다. 답변이 확인된 학생은 10명이다. 같은 질문이 여러 생성 기록과 연결될 수 있으므로 이 수치를 고유 답변 수로 해석하지 않는다. 운영 학생 자료 쓰기는 0건이다.
- 기존 포털 자산 버전이 바뀐 뒤 남아 있던 릴리스 검사 예상값을 갱신해, 공개 전 캐시보다 최신 버전을 사용한다는 원래 검증 목적을 유지한다.

구현과 검증은 완료했다. DB 구조 변경이나 생성 한도 변경은 없다. 사용자가 학생 답변 조회 보완의 푸시·배포를 최종 승인하여 운영에 반영한다.
