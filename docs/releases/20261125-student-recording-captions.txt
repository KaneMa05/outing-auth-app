수강생 모의면접 결과 · 녹음 자막 (운영 반영 전)

요청 범위
- 직무·인성 연습 결과와 내 면접 기록에서 본인의 녹음 자막을 읽고 잘못 인식된 부분을 직접 수정할 수 있다.
- 수강생 화면 명칭은 '녹음 자막'으로 통일한다.
- 점검 항목, 평가, 점수를 추가하지 않는다. 수정 화면에서는 중복된 기존 자막·수정 시각·입력창 제목과 안내 문구를 빼고 입력창 및 저장·취소 버튼을 표시한다.
- 기존 iPhone 베타 답변 돌아보기의 점검 항목도 베타 화면에서는 숨긴다.

예상 소요 시간
- 고정 문구 대신 녹음 길이, 최근 100개 유효 완료 작업의 변환 속도, 본인 작업 앞의 대기 작업과 진행 중인 작업의 남은 예상 분량을 사용한다.
- 속도 표본은 decoded_seconds>=10, processing_seconds>0으로 제한해 짧은 무음 결과가 전체 속도를 과장하지 않게 한다.
- 중앙값과 90백분위 속도를 사용하며 파일당 기본 처리 여유와 재시도 대기를 포함해 분 단위 범위를 안내한다.
- 현재 PC 워커가 idle일 때의 최대 5분 확인 주기를 상한에 포함한다. 완료 시각을 보장하는 카운트다운은 제공하지 않는다.
- 워커 신호가 90초 이상 없거나 중지·오류 상태이면 확정적인 숫자 대신 작업 재개 대기 안내를 표시한다.
- 녹음 전송이 끝나기 전에는 전송 후 산정 안내를 표시한다. 완료 후에는 상단 안내 상자와 문구를 숨긴다.
- 수강생 결과 화면의 자막 새로고침 버튼과 자동 변환 설명 상자를 제거했다. 준비 중인 경우에만 예상 시간을 간단한 글로 표시한다.

조회 흐름
- 결과 진입 시 현재 상태 조회. 화면을 보고 있는 동안 30초 간격으로 최대 약 10분간 갱신한다.
- 완료/최종 실패 상태나 화면 이탈·백그라운드 전환 시 불필요한 반복 조회를 멈춘다. 자동 재시도가 남은 실패 작업은 계속 확인한다.
- 자동 갱신과 내 면접 기록 재진입으로 다시 확인할 수 있다.
- 웹과 Android의 자막 갱신은 녹음 플레이어를 교체하지 않는다.
- iPhone 자막 조회 상태는 로컬 답변/업로드 지문과 분리한다. 자막 조회로 녹음을 재전송하지 않는다.

수강생 수정과 관리자 확인
- 자동 생성 원문, 수강생 수정본, 기존 관리자 검수본은 각각 분리한다.
- 수강생은 본인의 완료된 자막에만 수정 저장할 수 있다. 일부 또는 전체 내용을 비운 수정본도 자동 원문으로 되돌아가지 않는다.
- 수강생 수정 시각·작성자·별도 수정 버전을 보관한다. 관리자 상세 화면에 수강생 수정본과 수정 시각을 표시한다.
- 수정본 저장은 원본 녹음, 자동 자막, 관리자 검수 내용이나 관리자 검수 버전을 덮어쓰지 않는다.
- 다른 창에서 먼저 수정한 경우 409 충돌을 반환하고 입력한 초안은 유지한다. 오래된 조회 응답도 더 최신 수정본을 덮어쓰지 않는다.
- 웹 화면 이탈 시 미저장 수정 확인, iPhone 편집 화면 닫기 시 미저장 수정 확인을 제공한다.

서버·DB
- 기존 녹음 업로드·전사 작업 큐·워커·관리자 검수 방식은 유지한다.
- POST /api/interview-practice-records action=captions는 로그인한 본인의 회차만 조회한다.
- 새 RPC ip_practice_student_captions는 SECURITY INVOKER 및 service_role 전용 실행 권한을 사용한다.
- 기존 archive get의 활성 수강 권한과 소유권 검사를 재사용한다. 최신 이용 종료 상태는 두 새 RPC에서도 확인하며, 수정 저장 시 회원 공유 잠금으로 종료 처리와 직렬화한다.
- 답변 번호·상태·자동 자막·본인 수정본·수정 버전/시각과 집계 예상 시간만 반환한다. 관리자 메모·검수 수정본·임대 정보·다른 수강생의 개별 정보는 반환하지 않는다.
- caption_update와 새 RPC ip_practice_update_student_caption은 수강 권한, 소유권, 연습 모드를 확인한 뒤 별도 학생 수정 버전을 비교해 저장한다.
- 필요한 migration 순서:
  1. 20261125060053_interview_practice_student_captions.sql
  2. 20261125060103_interview_practice_caption_edits_eta.sql
- 추가 schema 작업은 lock_timeout 1초, statement_timeout 15초와 트랜잭션을 사용한다.
- 운영 DB에 두 마이그레이션을 적용했다. 적용 직전/직후 회원 126명과 녹음 자막 109건의 기존 데이터 체크섬이 동일했고 학생 수정 쓰기는 0건이었다. 공개/학생 RPC 권한과 보안 WARN/ERROR도 0건으로 확인했다.

검증
- API/게이트웨이: 본인 인증, 다른 모드 차단, 조회 전용 허용 필드와 응답 필드 제한 통과.
- 로컬 PostgreSQL: 본인/다른 학생/권한 만료/익명 차단, 전송 대기·자막 대기·완료 상태 및 검수 정보 제외 통과.
- 기존 녹음 보관·전사 큐 SQL 회귀 검사 통과.
- 브라우저: 자막 준비/완료/빈 자막/연결 실패, HTML 문자 처리, 재생 노드 유지, 이전 회차 응답 무시, 조회 종료 통과.
- 수정/예상 시간 SQL: 앞선 작업량 증가, 뒤쪽 작업 제외, idle 확인 지연, 워커 응답 없음, 학생 소유권/모드/수강 권한, 수정 버전 충돌, 원문/검수본 보존, 관리자 조회 통과.
- 수정 브라우저: 새로고침과 충돌 시 초안 유지, 수정 저장, 오래된 조회의 역전 방지, HTML 문자 처리, 기존 관리자 화면의 원문/학생 수정본 표시 통과.
- 기존 실제 마이크 녹음·재생·이력·계정 분리·즐겨찾기·문항 진행 브라우저 검사 통과.
- 최신 main 기준 전체 npm test(pretest/test/posttest), 95개 마이그레이션+5개 시드 및 수강 종료 계정의 자막 조회/수정 차단 검사를 통과했다.
- 웹 로컬 build 및 release-safety 검사 통과. 운영 환경 변수 없는 로컬 build는 비어 있는 로컬 config.js만 생성한다.
- Android 모듈의 Release/Debug Java 컴파일 및 기존 단위 검사 45개 통과. 변경한 Java 원본과 빌드 입력 파일의 SHA256 일치를 확인했다.
- Android 검증은 별도 임시 프로젝트와 새 Gradle 캐시를 사용하고, 모듈만 포함해 스토어 서명 키 없이 실행했다. 기존 공용 캐시는 삭제하지 않았다.
- 기존 관리자 UI 전용 브라우저 검사는 Mac의 Chrome/afconvert 경로가 필요하여 Windows에서 실행하지 못했다.
- iPhone Swift/Xcode 빌드는 Mac 환경에서 추가 확인해야 한다.
