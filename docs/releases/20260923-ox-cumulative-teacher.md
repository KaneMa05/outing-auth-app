# OX 누적 정답률과 교사 학습 접근

상태: 2026-09-23 사용자 푸시·배포 최종 승인. 운영 DB 마이그레이션 2건 반영 및 검증 완료. 이번 커밋의 main 푸시에 연결된 Vercel 운영 배포로 화면을 반영한다.

## 확정한 동작

- 사용자가 선택한 누적 정답률을 사용한다. 정답 횟수 / 모든 풀이 횟수 × 100이며 재풀이도 포함한다. 20회 중 8회 오답 후 8회 정답이면 20/28 = 71.4%다.
- 취약 이력/현재 상태 전환을 없애고 하나의 취약단원 목록에서 누적 정답률 낮은 순으로 정렬한다. 이전 오답 문항과 남은 오답, 다시 맞힘 상태를 함께 표시한다.
- 오답 이력이 있는 단원은 모두 다시 맞히거나 복습 완료해도 목록에 남는다. 같은 문항을 여러 번 틀려도 이전 오답 문항 수는 한 번만 센다.
- 소수 첫째 자리까지 반올림한다. 오답이 있으면 반올림 상한을 99.9%로 두어 100%로 잘못 표시하지 않는다. 정렬은 원래 수치로 한다.
- 기존 ox_attempts를 집계하므로 새로 시작하지 않는다. 현재 접근 가능한 공개 문항의 현재 버전을 대상으로 하며, 타 계정의 기록은 포함하지 않는다. 재시도된 동일 submissionId는 중복 집계하지 않는다.
- 활성 teacher 계정은 별도 OX 회원/교재 구매 등록 없이 공개 교재를 학습할 수 있다. 계정 유형과 구매 이력은 변경하지 않는다. 기존 앱 기기 인증, OX 세션, 서비스 중지, 비활성 계정 차단을 유지한다.
- 교사 학습 기록은 본인에게만 저장하며 전체 수강생 오답률에서는 제외한다. 교사의 학습 진입은 관리자 권한을 부여하지 않는다. 수강생 구매·일괄 지급·관리 명단은 유지한다.

## 변경 및 적용 순서

1. `20260923022213_ox_teacher_learning_access.sql`: 검토한 운영 함수의 해시를 확인하고 교사 학습 권한과 수강생 통계 필터만 수정한다.
2. `20260923022226_ox_cumulative_learning_accuracy.sql`: 본인 시도 집계 함수를 추가하고 bootstrap/submit 응답에 attemptCounts를 추가한다. 기존 응답 필드를 유지해 구버전 클라이언트도 계속 동작한다.
3. DB 검증 후 해당 변경만 main에 푸시한다. 연결된 Vercel 운영 배포를 사용하며 중복 수동 배포하지 않는다. 새 클라이언트는 DB 집계 필드가 필요하므로 DB를 먼저 반영한다.
4. 운영에서 4번 활성 교사 계정의 status와 읽기 전용 bootstrap, 함수 ACL, 보안 advisor를 확인한다. 교사 계정으로 테스트 답안을 저장하지 않는다.

DB 마이그레이션은 데이터 삭제·재작성 없이 함수만 추가/변경한다. 새 함수는 SECURITY INVOKER, 빈 search_path이며 service_role만 실행 가능하다. 기존 앱 공통 UI는 자산 버전만 변경한다. 별도 작업 중인 final-scope-data.js는 이번 릴리스에서 제외한다.

## 검증

- `npm.cmd run test:criminal-law-ox`: 이력/누적률 8건과 기존 SQL·교재·코호트·기기·일괄 지급 테스트, 신규 교사/누적 집계 DB 시나리오 통과.
- 신규 DB 시나리오: 교사 2계정 격리, 공개 교재 접근, 정답/메모 저장, 수강생 제한, 기기/세션/비활성 차단, 관리자 권한 차단, 역할 회수, 기존 기록 유지, 20/28 계산, 중복 제출, anon/authenticated 접근 차단.
- `node tests/criminal-law-ox-loading.test.cjs`: 24건, 누적 필드 보존 포함.
- `node tests/release-safety.test.js`: 2건, 자산 버전/캐시 및 설정 보존.
- `node docs/criminal-law-ox-proposal/chapter-flow.test.cjs`: 단원 완주·재풀이·기록 보존.
- `node scripts/ox-history-ui-qa.cjs`: 세 수강생 테마 × 320/390/768px. 통합 화면, 누적률 변화, 이력 유지, 필터, 지연 로딩/재시도, 완료 토글, 재마운트 검증. 가상 데이터만 사용.
- Python 생성 스크립트, JavaScript 구문, 격리 폴더 내 빌드, diff 공백 검사.

운영 DB 검증: 4번 계정은 teacher 유형을 유지하며 status.enabled=true, 공개 교재 3개·문항 2,543개 조회, attemptCounts 응답 필드를 확인했다. 테스트 답안이나 학습 세션을 생성하지 않았다. 변경 함수 6개 모두 SECURITY INVOKER, anon/authenticated 실행 불가, service_role 실행 가능이다. 보안 advisor는 RLS 정책 없음 INFO 56건만 반환했으며 변경 함수 관련 경고는 없었다. 해당 OX 테이블은 service_role 전용 접근 구조를 유지한다.

CLI로 생성했던 파일명은 MCP 운영 반영 후 실제 migration version(20260923022213, 20260923022226)에 맞춰 정렬했다. 기존 20260923-ox-weakness-history 문서는 이전 배포 기록이며, 취약단원 수치와 화면 구성은 이 문서로 변경한다.
