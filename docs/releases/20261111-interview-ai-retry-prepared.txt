면접 초안 재요청 반복 오류 수정 — 운영 반영 준비
2026-11-11 한국시간

상태
로컬 구현·검증 완료. 운영 DB 변경, 처리기 재시작, 푸시·배포는 아직 하지 않았다.
최종 확인 후 운영에 적용한다.

변경
- DB에서 재요청 가능 여부와 사유를 계산해 화면에 제공한다.
  같은 자료로 두 번 시도한 실패 작업과 자료 보완 전 NEEDS_INPUT은 선택할 수 없다.
  실제 입력 자료가 바뀌면 기존 규칙대로 재요청을 허용하고 시도 횟수를 초기화한다.
- 오래 열린 화면의 재요청도 최신 상태로 재검사한다.
  서버의 정상적인 재요청 거절은 구조화된 결과로 반환하고 웹 API는 HTTP 409로 응답한다.
  해당 거절 때문에 Supabase에 P0001/unsafe_retry가 반복 기록되지 않게 한다.
- 선택 문항을 모두 잠금·검사한 다음 접수와 변경을 진행한다.
  여러 문항 중 하나라도 불가하면 앞 문항의 상태·입력·시도 횟수를 바꾸지 않는다.
- 생성 실패, 결과 형식 오류, 근거 불일치, 자기소개 경험 반영 부족을 구분한다.
  실패 사유는 DB 작업/이벤트와 암호화된 로컬 완료 기록에 보존한다.
  정상 완료와 실패 처리 후에는 기존처럼 학생 원문을 로컬 완료 기록에 남기지 않는다.
- 면접 화면의 버전 URL을 갱신한다. 일반 수강생·교사 기능의 코드는 바꾸지 않는다.

한계
이미 정리된 과거 실패 결과에서 세부 원인을 복구할 수는 없다.
이번 수정은 반복되는 재요청 거절을 해결하고 이후 실패 원인을 구분한다.
모든 AI 생성이 항상 성공한다고 보장하는 변경은 아니다.
PostgREST의 Warp server 로그는 별도 호스팅 문제이며 이번 앱 수정에 포함하지 않는다.

검증
- npm.cmd run test:interview-ai-retry 통과:
  실제 로컬 PostgreSQL 엔진에서 상태별 허용/거절, 자료 변경 후 재시도,
  혼합 문항의 원자성, 거절 시 무변경, 다른 학생 접근 차단, 권한, 실패 사유 검증.
  API의 409 응답, 사전 상태 재검사, 상태 경쟁 후 재조회 검증.
  Chrome 390px 화면의 제한 안내, 버튼 차단, 보완 후 재활성화와 대기 전환 검증.
- 기존 AI DB/준비 조건/입력 보완/이력/폴링 검사 7개 파일 통과.
- 기존 관리자 진입과 캐시·배포 안전성 검사 통과.
- Python 처리기 검사 13개와 기존 CLI 복구 검사 8개 통과.
  Windows DPAPI 검사는 샌드박스 밖에서 검증했다.
- 운영 함수 정의를 복사한 로컬 DB에도 새 migration을 적용해 같은 검사를 통과했다.
- 기존 공개 설정을 사용한 격리 production-mode build와 변경 JS 구문 검사 통과.
- origin/main 10b5f2f6 위에 이번 수정만 적용한 별도 검증본에서도 관련 검사를 통과했다.
  interview-app-ui.js의 다른 미커밋 수정과 음성·Android·모델 설정 작업은 제외했다.
- 전체 migration 초기화 검사는 기존 테스트 데이터 누락으로 실패한다.
  Windows CRLF를 정규화한 격리 복사본에서도
  20261111021951_interview_mock_test_question_scope.sql의 기존 문항 FK 오류가 재현된다.
  이번 migration을 제외한 기준 소스에서도 동일 실패를 확인했다.
  이 검사의 전체 통과를 주장하지 않으며 기존 migration/실학생 데이터를 수정하지 않았다.
- 추가 AI 생성 또는 유료 음성/API 호출은 수행하지 않았다.
