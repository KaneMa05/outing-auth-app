- 기존 직무 중 원문 해설이 없는 문항: 25개.
- 관리자 검토 완료 및 자동 채점 사용 가능 문항: 현재 0개.
- 인접 문항은 같은 자료·연도·지역 등의 순서상 이웃으로 제공하며, 실제 부모 질문으로 확정하지 않는다.

## 저장과 검토 규칙

각 필수 항목 안에서는 지정 단어·허용 표현 중 하나 이상을 인정하고, 전체 항목의 충족 여부와 문맥으로 판정하도록 기준을 관리한다. 합의된 판정은 모두 충족 O, 일부 충족 △, 미충족 또는 핵심 오류 X다. 실제 답변의 표현 검출·문맥 판정 실행기는 이번 범위에 포함하지 않았다.

배점은 미정이므로 기본값을 넣지 않았다. 입력 시 `O > △ > X ≥ 0`을 검증한다. 전공 지식형을 검토 완료로 저장하려면 필수 항목, 핵심 오류, 배점, 검증 근거가 모두 있어야 한다. 문맥 확인 보류 문항은 검토 완료로 저장할 수 없다.

질문이 수정되면 기존 검토 완료 상태를 해제한다. 질문 및 기준의 버전을 함께 검사하여 동시 수정 덮어쓰기를 막고, 수정 이력을 저장한다. 학생 계정의 접근은 차단하며 관리자 읽기·쓰기 권한을 각각 검사한다. 저장은 원문 질문의 분류나 학생 공개 상태를 변경하지 않는다.

## 변경 파일과 운영 적용 자료

- 관리자 UI: `interview-rubric-ui.js`, `interview-prep-ui.js`, `interview-prep.js`, `teacher.html`
- API: `api/interview-prep.js`의 기준 목록·상세·저장 액션
- DB: `supabase/migrations/20261021052648_interview_question_rubrics.sql`
- 초안 생성: `scripts/prepare-interview-rubrics.cjs`, `scripts/data/interview-rubric-examples.json`
- 생성 자료: `supabase/seeds/interview-rubric-drafts.json`, `interview-rubric-drafts.sql`, `interview-rubric-report.json`
- 검증: `tests/interview-rubrics.test.cjs`, 로컬 미리보기와 격리 빌드 스크립트

초기 자료는 기존 질문·출처와 인성 분석 자료에 의존한다. 기존 면접 스키마와 질문 자료, 이번 마이그레이션이 준비된 후 기준 SQL을 적용하는 순서다. 초기 자료 재실행은 이미 작성된 기준을 덮어쓰지 않으며, 원문 질문·분류가 달라진 항목을 그대로 주입하지 않는다. 운영 적용 전 현재 DB의 마이그레이션 상태와 기존 자료를 확인해야 한다. 저장소에는 다른 미완료 작업도 있으므로 전체 변경을 일괄 배포하지 않는다.
