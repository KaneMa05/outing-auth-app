녹음 두 회차 무음 조사 및 자동 진행 수정 검토
2026-11-19 / Asia/Seoul

대상 및 확인 결과
- 사용자 화면의 11:23 인성/11:24 직무·관제 두 회차, 각 3답변을 대상으로 조사했다.
- 6개 모두 업로드 및 전사 완료. 저장소 파일 크기/SHA256이 DB 기록과 일치한다.
- 관리자 재생과 같은 서명 링크로 6개 모두 HTTP 206 Range 재생 정상, 반환 바이트 일치.
- 원본 Opus/MP4를 PyAV와 Chrome Web Audio로 각각 디코딩했고 Chrome 재생 시간 진행/오류 없음 확인.
- 3개는 전체 PCM이 무음. 나머지 3개는 평균 약 -76/-81/-93 dBFS로, 정상적인 답변을 듣기 어려운 아주 작은 신호 수준이다.
- 각 답변의 기록 시간이 약 4.002~4.005초, 실제 디코딩 길이는 약 3.88~3.94초다.
- 문제는 저장 파일에 유효한 음성이 거의 없는 것이다. 당시 수강생이 발화했는지, 기기/권한/입력 경로 중 무엇 때문에 목소리가 들어오지 않았는지는 서버 기록만으로 확정하지 않는다.
- 원래 전사기는 vad_filter=False로 처리하며, 무음 파일에도 짧은 문장이 생성됐다. 해당 전사문을 실제 발화의 증거로 취급하지 않는다.
- 기존 녹음·전사·검수·회차 데이터는 수정하거나 삭제하지 않았다.

확인된 앱 문제
- 기존 웹 녹음 코드는 recorder 시작 시 lastSpeech를 현재 시간으로 설정했다.
- 실제 입력을 한 번도 확인하지 않아도 4초가 지나면 answer()를 실행해 다음 질문으로 이동했다.
- 따라서 무음 3답변도 회차 완료 3/3으로 저장될 수 있었다.
- 0 레벨의 합성 입력으로 같은 자동 진행 경로를 재현했다.

준비한 수정
- 별도 입력 활동 타이머: 연속적인 마이크 신호를 먼저 확인한 뒤에만 4초 무음 자동 진행.
- 짧은 클릭/일시적 신호나 지연된 타이머 틱은 입력 확인으로 인정하지 않음.
- 입력 없음이 지속되면 권한/연결 확인 안내. 계속 무음일 때 질문 1에서 자동 완료하지 않음.
- 입력을 확인하지 못한 채 120초 제한에 도달하면 완료 대신 중단 처리.
- 다시 듣기 중의 시간은 무음 자동 진행 타이머에서 제외. 기존 녹음·재생·전송·계정 저장 구조 유지.
- 입력 레벨 검사이며 음성 인식/답변 품질 판정은 아니다. 기기에서 실제 목소리가 수집되지 않는 근본 원인을 자동 복구한다고 주장하지 않는다.
- 운영 로더 캐시 키를 갱신해 승인 후 배포 시 수정 코드를 새로 불러오도록 준비.
