# 면접반 AI 초안 화면 연결

2026-10-20. 로컬 구현·검증 범위다. 운영 DB 적용, 푸시, 배포, 운영 기능 활성화는 하지 않았다.

## 학생 동작과 버튼 활성화

기본 이력과 인성 경험·가치관을 한 DB 화면에 모으고, 자기소개·지원동기·공직관·핵심 30제 작성 탭을 둔다. 각 탭은 해당 초안 버튼과 결과를 **나의 답변 편집기보다 먼저** 표시한다. DB 탭의 공통 생성 영역과 요청한 두 설명 문단은 제거했다. 네 초안 버튼은 모든 원자료 항목을 입력·저장했을 때 활성화한다.

- 기본 이력: 주요 이력·전공, 자격·어학, 소속 이력, 수상·성과, 경험·인생그래프. 자격·소속·수상 이력이 없으면 명시적인 ‘해당 없음’을 인정한다.
- 입력한 행은 선택 항목인 기여도, 경험의 관련 소속, 역량 태그를 제외한 칸을 모두 채운다. 경험은 최소 1개이며, 자기소개는 상황·행동·결과가 있는 서로 다른 경험 3개를 추가로 요구한다.
- 인성 항목: 해당 학생에게 적용되는 활성 항목 전체. `required` 표시와 관계없이 모두 확인하고, 각 양식의 입력칸은 기존 작성 완료 기준인 10자 이상이며 최신 양식이어야 한다.
- 임시저장 내용도 완성돼 있으면 인정한다. 교사 승인은 조건이 아니다. 빈 영역·행 번호·입력칸을 보완 목록으로 표시한다.
- DB 수정 중에는 버튼을 잠그고 저장 성공 후 다시 확인한다. 새 완성도 마이그레이션이 없어 `dbReady`가 응답에 없으면 버튼을 활성화하지 않는다.

생성은 기존 저장 → prepare → generate → status 순서다. 현재 답변 편집기의 미저장 내용을 먼저 저장하며 실패·충돌 시 생성을 요청하지 않는다. 요청 중에는 중복 클릭과 편집 화면 전환을 막는다.

핵심 30제는 설정된 30문항 중 **선택한 질문 하나만** 생성한다. 질문 선택 → ‘이 질문 초안 만들기’ → 해당 초안 → 나의 답변 순서다. 질문을 바꾸면 저장된 답변과 생성 이력도 해당 질문으로 바뀐다. 편집 중인 답변은 기존 저장 기능으로 저장한 뒤 질문을 전환한다. 설정 누락·비공개·직렬 불일치 때 임의 선정하지 않고 관리자 설정 안내를 표시한다.

`generate(kind=core30)`는 `questionId`가 필수이며 서버가 설정 목록·인성 분류·공개·직렬 범위를 검증한다. 누락·위조된 질문은 거부하고 단일 작업만 등록한다. 핵심 질문의 재요청도 한 문항씩만 허용한다. 30개 일괄 생성은 최신 화면에서 제공하지 않는다.

결과는 기존 작성 내용과 강사 피드백에서 분리한다. 완료된 자기소개·지원동기·공직관·공개 핵심 질문은 학생이 **답변에 채택**한 경우에만 편집창으로 이동하고, **저장**을 눌러야 기존 답변이 바뀐다. 기존 답변이 있으면 교체 확인을 받는다. 공직관 본문도 별도 작성 답변으로 저장하며 교사가 같은 피드백 흐름을 사용할 수 있다.

학생 안내는 대기 중 “순서대로 초안을 준비하고 있습니다. 완료되면 이 화면에 표시됩니다.”, 생성 중 “초안을 만들고 있습니다. 완료되면 이 화면에 표시됩니다.”로 표시한다. 처리기 연결 같은 내부 구현 용어를 노출하지 않는다.

실패·보완 필요·관리자가 종료 확인한 취소 문항만 선택 재요청할 수 있다. 완료 결과는 유지한다. 자료 보완 여부·원자료 전체 완성도·재시도 한도를 서버가 다시 검사한다.

재접속 시 로그인한 본인의 최근 요청을 조회한다. 로그아웃·화면 해제 시 결과, 요청 키, 조회 타이머를 폐기하고 늦은 응답을 무시한다. 웹 fetch는 취소한다. 처리기가 없으면 대기 상태이며 완료 결과를 만들어 표시하지 않는다.

## 검증 명령과 범위

```powershell
npm.cmd run test:interview
npm.cmd run test:interview-ai
node scripts/interview-prep-ui-qa.cjs
node scripts/verify-interview-build.cjs
npm.cmd test
```

DB·API 검사는 학생 격리, 원자료·교사 피드백 분리, 완성 본문의 경험 3개 연결, 정확한 30문항, 부분 재요청, 실행 미확정 중복 방지, RLS/권한을 포함한다. 완성도 검사는 다른 학생 자료로 조건을 만족할 수 없고 어떤 인성 항목이든 미입력 시 generate/retry가 차단되는지 확인한다.

자동 브라우저 검사는 실제 로컬 API와 테스트 DB를 사용한다. 카카오 인증 응답과 AI 처리 결과는 **테스트 전용 고정 데이터**다. 이 검사를 실제 모델 실행이나 운영 처리기 연결 성공으로 해석하면 안 된다. 일반 미리보기는 서버 AI 활성화를 끈 상태로 시작한다.

별도 명령 `npm.cmd run preview:interview-ai`는 사용자가 요청한 실제 생성 검증용이다. 기본 이력 5개 영역, 자격·어학, 서로 다른 경험 6개, 인성 13개 항목을 가상 자료로 입력하고 실제 CLI를 연결한다. 학생 번호 `18120`, 테스트 비밀번호 `demo2026!!`이며 출력된 `/__qa/login` 주소로 들어간다. 메모리 DB이므로 서버 종료 시 입력·생성 이력은 초기화된다. 실행별 토큰은 학생 18120에만 적용하며 stdin으로 전달하고 DPAPI로 보관한다.

사용자가 지정한 **본문 25개 필수 + 부록에서 무작위 5개** 기준으로 한 번 선정한 30문항 목록을 로컬 설정에 저장한다. 조회·부분 재요청 시 다시 추첨하지 않는다. 로컬 자료의 기존 공통 기출 분류가 남아 있던 2문항도 인성으로 정리하여 정확히 30개를 공개한다.

실제 Chrome에서 발견한 타이머 `Illegal invocation` 오류를 수정했다. 기본 타이머는 브라우저 전역 객체를 통해 호출하며, 동일 조건의 회귀 검사를 추가했다. 실제 자기소개·지원동기·공직관의 완료와 원문 편집기 미변경을 확인했다.

최종 단일 질문 검증: 실제 브라우저 클릭으로 요청 1개·작업 1개만 등록되어 `COMPLETED`, 342자 초안이 표시됐다. 질문 2로 이동하면 이전 초안이 섞이지 않고 질문 1로 돌아오면 기존 결과가 복원됐다. 검증 기록은 `.tmp/interview-qa/local-actual-single-question.json`이다. 이전 로컬 일괄 생성은 신규 배정을 끈 뒤 환경을 종료했으며 새 환경에는 일괄 대기 작업이 없다.

생성 횟수에 대해서는 최초 1회 + 다시 만들기 2회의 총 3회를 제안했다. 횟수 제한과 남은 횟수 표시는 아직 구현하지 않았다. 완료된 초안 아래에 학생용 ‘다시 만들기’ 버튼을 추가했다. 이 버튼은 기존 저장 → prepare → generate(`regenerate: true`) → 상태 자동 조회 흐름으로 새 요청을 만들며, 핵심 30제는 현재 선택한 질문 한 개만 다시 생성한다. 일반 ‘초안 만들기’ 재클릭은 기존 완료 요청을 재사용하고, 자료 보완·오류 재요청은 기존 안전 조건을 따른다.

‘다시 만들기’는 자료 미완성·기능 비활성·요청 진행 중에는 사용할 수 없다. 이전 초안 요청은 DB에 남기며 새 결과가 기존 답변·교사 피드백을 덮어쓰지 않는다. 기존 요청 선택창을 제거한 상태이므로 과거 초안을 선택하는 UI는 제공하지 않는다. 브라우저 회귀 검사에 새 요청 생성, 중복 클릭 방지, 이전 초안 및 채택한 답변·교사 피드백 보존 검증을 추가했다.

### 초안 작성 안내 간소화

학생 화면의 ‘내 생성 요청’ 선택창과 ‘상태 새로 확인’ 버튼을 제거했다. 탭·질문별 최근 요청 복원과 진행 상태 자동 조회는 유지한다. `interview-ai-ui.js`, `interview-portal.css`, 기존 브라우저 검사 선택자를 수정하고 정적 파일 버전을 갱신했다.

`tools/interview-worker/guidelines/instructions.txt`에서 실제 경험을 업무와 연결하는 문장까지 학생이 사전에 작성해야 한다는 조건을 수정했다. 경험의 행동·결과에서 확인되는 강점을 정리하고, 해양경찰 업무에 활용하는 미래 실천 문장은 AI가 작성한다. 없는 경력·성과·전문 능력·지원 계기는 만들지 않으며, 실제 경험이나 필수 사실 자체가 없는 경우에만 보완을 요청한다. 자기소개 본문에 서로 다른 실제 경험 3개를 포함하는 검증은 유지한다.

기존 로컬 계정의 입력 자료와 요청 이력을 유지하고 지침 묶음 및 로컬 처리기만 교체했다. 동일 자료로 실제 생성한 결과는 `COMPLETED`, 본문 582자, 본문과 연결된 서로 다른 경험 3개, 보완 질문 0개다. 브라우저에서 자동 완료 표시와 ‘나의 답변’ 입력란 미변경을 확인했다. 기록은 `.tmp/interview-qa/local-actual-self-intro-revised.json`이다.

이 변경 후 학생·교사·관리자 범위를 포함한 기존 브라우저 검사, AI 클라이언트 검사, 격리 빌드·문법 검사, 배포 안전성 검사를 통과했다. 운영 환경에는 적용하지 않았다. 운영에서 새 작성 지침을 사용하려면 최종 승인 후 지침 해시를 맞추고 처리기를 갱신해야 한다.

최근 화면 정리: 학생 작업 공간의 기본 정보·자격/어학·소속 이력·수상/성과·경험/인생그래프 메뉴를 ‘기본 이력’ 한 개로 합쳤다. `mountLife`의 학생용 통합 표시 옵션으로 다섯 영역을 한 화면에 표시하고 기존 `life_save`로 함께 저장한다. 교사·관리자의 기존 영역별 화면은 유지한다. 데스크톱/모바일 단일 메뉴, 여러 영역의 동일 필드명 구분, 추가·순서 변경·삭제, 해당 없음, 저장 및 재접속을 로컬 API 브라우저 검사로 검증한다.

화면 디자인은 남색·청록 계열의 상단 배너, 브랜드 마크, 선택 메뉴 강조, 영역별 카드로 정리했다. 기본 이력의 짧은 필드는 PC에서 두 열, 모바일에서 한 열로 배치한다. 장식은 CSS로 구현하고 학생 면접 작업 공간에만 스타일을 적용했다. 390px·1200px 레이아웃 및 기존 입력·저장·초안·교사/관리자 브라우저 검사를 통과했다.

- `interview-portal.js`: 설치 앱/Android 앱 진입 또는 명시적 `?app=1`에서 앱 화면을 사용한다. 카카오 등 웹 인증으로 등록한 면접반 전용 학생은 기존 반 전환을 표시하지 않는다. 앱 시작 주소 `/index.html`에서는 이전 웹 앱 진입 표시가 있을 때 서버 세션을 확인한 뒤 면접반으로 복귀한다. 이 표시는 인증 권한이 아니다. 로그아웃하면 세션·화면·조회와 진입 표시를 정리한다.
- 입력 중 이동 확인, 브라우저 뒤로가기, 입력 포커스 시 하단 메뉴 숨김, 화면 하단 안전 여백을 반영했다. 홈에 표시하는 피드백 수는 미확인 건수가 아닌 등록된 피드백 총수다.

검증: `npm run test:interview`, AI 클라이언트 검사, 배포 안전성 검사, 격리 빌드, 로컬 API·PGlite·Chrome 브라우저 검사를 통과했다. 브라우저 검사는 신규 면접반 계정의 일반 메뉴 차단, 웹 세션을 통한 앱 재진입·로그아웃, 기존 계정의 모드 전환·실제 페이지 재실행 복원·뒤로가기, 세 가지 일반 학생 화면 및 교사·관리자 화면, 390px/1200px 레이아웃을 포함한다. 브라우저 검사에서 사용하는 카카오 인증·AI 완료 데이터는 명시적 테스트 데이터다.

운영 DB 변경이나 신규 마이그레이션 없이 기존 API를 사용했다. 기존 앱의 기기 인증 면접반 진입은 현재 미리보기 허용 계정 범위를 유지한다. 운영 공개 전에는 대상 계정 범위와 웹 인증 설정을 최종 확인해야 한다. 이번 작업은 현재 저장소의 앱 화면 연결이며 APK/AAB 생성·스토어 배포 또는 실제 Android/iOS 기기 검증을 수행한 것은 아니다. 실기기의 재실행·OAuth 복귀·키보드·시스템 뒤로가기 최종 확인이 남아 있다.

## 남은 운영 연결 작업

### 교사에게 제출 · 2026-10-21

학생 작성하기의 자기소개·지원동기·공직관·핵심 30제 각 답변에 **임시저장 / 저장 / 교사에게 제출**을 제공한다. 핵심 30제는 선택한 문항만 제출한다. 제출은 현재 편집 내용을 저장하면서 제출 당시 본문·일시·리비전을 같은 트랜잭션으로 기록한다. 일반 저장과 AI 생성 전 자동 저장은 제출하지 않는다.

관리자 **면접반 → 수강생 작성 내용 → 학생 내용 보기 → 답변 → 피드백 작성**에서 제출본을 보고 보완 필요·확인 완료로 피드백한다. 기존 학생 등록·첨삭의 작성 답변 화면도 같은 제출본을 사용한다. `interview.write` 권한을 가진 관리자 계정만 피드백할 수 있으며 조회 권한만 있으면 버튼을 표시하지 않는다. 기존 일반 교사 역할의 권한을 확대하지 않았다.

학생은 교사 확인 대기·보완 필요·확인 완료 상태와 제출본을 확인할 수 있다. 제출 후 수정해 저장해도 제출본과 피드백은 유지된다. 다시 제출하면 최신 제출본을 갱신하고 이전 피드백은 이전 제출에 대한 피드백으로 구분한다. 이전 제출·피드백의 전체 스냅샷은 기존 `ip_history`에 남는다. 빈 답변 제출, 타인 자료 접근, 오래된 리비전의 저장·피드백을 서버에서 거절한다. 같은 대기 답변의 중복 제출은 새 리비전을 만들지 않는다.

추가 로컬 마이그레이션: `supabase/migrations/20261021051139_interview_writing_submission.sql`. 기존에 검토 완료·보완 필요였던 답변은 제출본으로 보존하며, 일반 저장만 한 답변은 자동 제출하지 않는다. 운영 적용은 아직 하지 않았다. 앱 전용 화면 연결 자체에는 마이그레이션이 필요 없었으나 이 제출 기능에는 새 마이그레이션이 필요하다.

수정 범위: `interview-writing-ui.js`, `interview-review-ui.js`, `interview-prep-ui.js`, `interview-prep.css`, 관련 모듈 버전 및 앱 캐시. 검증은 기존 작성·리뷰 DB/API 테스트와 브라우저 검사에 제출 실패 시 입력 보존, 제출본과 수정본 분리, 관리자 화면 피드백 저장, 기존 피드백 보존을 추가했다.

### 제출·피드백 회차 기록 · 2026-10-21

자기소개·지원동기·공직관·핵심 30제의 각 답변에서 제출을 1차·2차·N차로 구분한다. 학생이 다시 제출할 때만 회차가 증가한다. 임시저장·저장·AI 초안 편집과 교사의 피드백 수정은 회차를 늘리지 않는다. 같은 확인 대기 답변을 반복 제출하면 기존 제출을 유지한다.

학생 작성 화면과 관리자 수강생 작성 내용/피드백 편집 화면에서 최신 제출 회차, 상태, 피드백 회차·일시를 표시한다. ‘회차별 제출·피드백 기록’을 펼치면 최신순으로 각 회차의 제출본·제출일·피드백·피드백 수정일·상태를 읽는다. 10회차씩 조회하며 이전 기록에도 페이지로 접근할 수 있다. 새 제출의 교사 피드백 입력란은 비워서 이전 회차 내용을 잘못 재등록하지 않도록 했다. 이전 피드백은 해당 회차 이름으로 별도 표시한다.

추가 파일 `supabase/migrations/20261021053835_interview_writing_rounds.sql`은 `ip_writing_rounds`와 최신 회차/피드백 날짜를 추가한다. 기존 저장 RPC의 같은 트랜잭션에서 트리거로 제출본과 피드백을 보관하며 리비전 충돌·중복 제출 처리를 유지한다. `ip_history`에서 확인 가능한 제출 리비전을 순서대로 복원한다. 감사 기록이 없는 기존 제출본은 남아 있는 자료로 보존하며, 알 수 없는 과거 피드백 날짜를 임의로 만들지 않는다. 과거 교사 수정 감사 스냅샷은 `ip_history`에 유지하고 회차 화면에서는 해당 회차의 최종 피드백을 보여준다.

`api/interview-prep.js`에 학생 본인 전용 `writing_history`와 관리자 읽기 권한용 `admin_writing_history`를 추가했다. 요청은 `kind`, `itemId`, 선택적 `page`; 관리자는 `targetStudentId`도 전달한다. 응답은 `rounds`, `total`, `page`, `pageSize`. 학생 요청의 대상 ID는 무시하고 인증된 계정만 사용한다. 학생 만료·등록 중지, 직접 테이블/RPC 접근 차단, 계정 삭제 시 연쇄 삭제를 유지한다. 화면 전환·로그아웃 후 늦은 조회 응답은 폐기한다.

검증 완료: `npm.cmd run test:interview`, `node scripts/interview-prep-ui-qa.cjs`, 격리 빌드와 배포 안전 검사. 회차 복원, 다른 회차로 피드백 오귀속 방지, 14회차 페이지 조회, 동시 제출 충돌, 학생 격리, 관리자 읽기/쓰기 권한, 교사 수정 시 동일 회차 유지, 학생 재로그인·재제출 후 이전 기록 조회를 검사했다. 390px/1200px 브라우저 검사를 통과했고 `.tmp/interview-qa/student-submission-resubmitted.png`에 회차 화면을 기록했다. 운영 DB 적용·푸시·배포는 수행하지 않았다.

### 운영 적용 절차

제출 기능 최종 검증: `npm.cmd run test:interview`, `node scripts/interview-prep-ui-qa.cjs`, `node scripts/verify-interview-build.cjs`, `node tests/release-safety.test.js` 통과. 학생 재로그인 → 교사 피드백 확인 → 수정 → 다시 제출까지 확인했다. 검사 중 브라우저 탐색 순간의 실행 컨텍스트 소멸은 기다림에서만 재시도하도록 테스트를 보완했다. 새 미리보기는 별도 메모리 DB에서 실행하며 이전 미리보기 서버의 데이터를 삭제하지 않았다.

1. 기존 면접·인증·작성 답변·AI 대기열 마이그레이션과 완성도·부하 보호·공직관·단일 질문 마이그레이션을 순서대로 검토한 뒤, 사용자 최종 확인 후 운영에 적용한다.
2. 본문 25개와 부록 무작위 5개 기준으로 운영 문항 목록을 확정·저장한다. 기존 질문의 분류·공개·직렬 범위도 확인한다. 로컬 가상 자료를 운영 DB로 복사하지 않는다.
3. 현재 저장소의 [CLI 구현·검증 문서](../interview-ai-cli.md)를 기준으로 운영 주소, 기기 토큰·학생 범위, 지침 해시, 하루 생성 한도를 설정한다. 이번 실제 실행은 로컬 가상 학생에만 연결했다.
4. 최종 확인 후 푸시·배포하고 실제 학생 계정 두 개로 전체 입력 조건, 로그인·본인 자료 격리, 원문 보존, 생성·조회·재요청·로그아웃을 점검한다.

세부 API 계약은 [AI 개발문서](../interview-ai-development.md), 운영 절차는 [운영 문서](../interview-ai-operations.md)를 참조한다.
