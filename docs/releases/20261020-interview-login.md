# 면접반 웹 로그인·신청·승인

2026-10-20 · 로컬 구현 및 검증 · 운영 DB 적용·푸시·배포 전

## 접속과 이용 흐름

사용자가 선택한 접속 주소는 **기존 앱 도메인의 `/interview`**다. 새 도메인은 필요하지 않다. PC와 모바일 브라우저에서 동일하게 이용하며, 일반 수강생 앱 화면을 먼저 열지 않는다.

1. 신규 학생은 첫 화면의 ‘회원가입’을 펼쳐 ‘카카오로 회원가입’을 누른 뒤, 인증 후 ‘신규 면접반 학생입니다’를 선택한다.
2. 이름·직렬·수험번호를 입력하고 면접반 수강을 신청한다.
3. 기존 관리자 페이지의 **면접반 → 수강신청·승인**에서 신청을 조회하고 승인 또는 반려한다. 승인 시 이용 기간을 지정할 수 있고, 반려 시 사유를 반드시 입력한다.
4. 승인되고 면접반 기능이 활성화되어 있으면 본인의 인성 준비 노트·인생그래프·경험 DB에 접근한다. 승인 대기나 반려 상태에서는 작성 자료에 접근할 수 없다.
5. 학생이 수정 후 다시 신청하거나, 자료를 작성·제출하고 관리자 피드백을 확인·재제출한다. 기존 자료 작성과 첨삭 기능을 그대로 연결했다.

기존 학생은 카카오 로그인 후 ‘기존 수강생입니다’를 선택하고 기존 학생 번호·비밀번호로 계정을 연결한다. 연결 후에는 카카오 로그인으로 바로 이용한다. 기존 학생 ID를 유지하므로 작성한 준비 노트와 인생그래프가 이어진다. 이름이나 수험번호가 같다는 이유만으로 계정을 자동 연결하지 않는다.

카카오 계정이 이미 신규 면접 계정에 연결된 경우 다른 기존 학생 계정과 자동 병합하지 않는다. 기존 학생은 첫 진입에서 기존 수강생 경로를 선택해야 한다.

면접반 전용 신규 계정은 일반 수강생 명단에 추가하지 않는다. `/interview` 재접속 시 유효한 세션과 승인 상태를 확인하여 면접 화면으로 돌아온다.

최종 학생 웹 UI는 로그인 카드에 론박스터디를 표시하고 카카오 로그인·회원가입 버튼 두 개를 먼저 표시한다. 회원가입을 누르면 가입 안내와 ‘카카오로 회원가입’ 버튼을 펼친다. 별도 아이디·비밀번호 가입은 제공하지 않는다. 로그인 후 상단에는 로그아웃만 남기고 로고·학생명·계정 연결·기존 앱 이동 영역을 제거했다. 등록 상태 확인은 신청 대기 화면 안에 배치한다. 메인 제목과 첫 메뉴는 **나의 DB 정리하기**이며, 인생그래프·경험 DB와 핵심인성 30제를 함께 제공한다. 직무 메뉴는 현 단계의 웹 포털에서 제외했다. 공유 학생 모듈의 기본값과 기존 관리자·앱 화면은 유지한다.

## 구현과 데이터 소유권

- `interview.html`, `interview-portal.js`, `interview-portal.css`: 독립된 면접반 웹 입구, 로그인·계정 연결·신청 상태 화면.
- `api/interview-auth.js`, `lib/interview-web-auth.js`: 카카오 코드 교환, 기존 계정 인증, 세션·신청 API.
- `api/interview-prep.js`: 웹 세션으로 확인한 학생만 기존 면접 자료 API에 연결. 관리자 신청 조회·심사 추가.
- `interview-prep-ui.js`, `interview-prep.js`, `teacher.html`: 기존 관리자 면접반 메뉴에 신청 심사 화면 추가.
- `supabase/migrations/20261020062512_interview_portal_auth.sql`: 면접 자료 소유자·카카오 연결·웹 세션·신청 테이블과 서버 전용 함수.

`ip_owners`에 기존 학생과 신규 면접 전용 계정을 구분하여 저장한다. 기존 자료의 학생 ID는 변경하지 않고, 면접 회원과 이력의 외래 키를 이 소유자 테이블에 연결한다. 신규 계정 ID는 `iw_`로 시작한다. 면접 전용 조회 뷰 `ip_student_directory`를 통해 기존 관리자 기능에서 두 종류의 학생을 함께 관리한다.

기존 학생의 삭제 시 자료 정리 동작을 유지한다. 일반 학생 명단·출결·외출·성적·스터디카페·기존 학생 로그인 함수는 면접 신규 가입 과정에서 변경하지 않는다.

기존 네이티브 앱의 기기 인증과 18120번 면접 시험 노출 제한은 유지한다. 신규 웹 경로는 웹 세션과 면접 등록·이용 기간을 검사하므로, 관리자가 승인한 신규 학생도 이용할 수 있다. 이 구현은 웹 로그인이며 네이티브 카카오 SDK 로그인은 포함하지 않는다.

## 인증과 접근 제한

- 웹 세션은 7일 만료다. 원본 토큰은 HttpOnly·SameSite=Lax 쿠키에, 해시는 DB에 저장한다. HTTPS에서는 Secure를 적용한다.
- 로그아웃 시 서버 세션을 삭제한다. 매 요청에서 세션 만료·계정 활성·면접 이용 자격을 검사한다.
- 로그인과 계정 연결은 세션을 교체한다. 비밀번호로 다시 로그인해도 기존 카카오 연결 정보는 유지한다.
- 카카오 `state`는 10분 만료이며 브라우저 쿠키에 결합해 한 번만 소비한다. 연결 시작 시점의 로그인 세션도 확인한다.
- 쓰기 요청은 설정된 동일 출처에서만 허용한다. 클라이언트가 전송한 학생 ID·역할로 데이터 소유권을 결정하지 않는다.
- 카카오 액세스·리프레시 토큰은 저장하지 않는다. 카카오 앱과 사용자 고유 ID의 조합으로 연결한다.
- 비밀번호 시도 제한은 계정당 15분에 10회, 네트워크당 300회다. 비밀번호가 없는 기존 학생 계정을 새 비밀번호 입력만으로 점유할 수 없다.
- 테이블은 RLS를 사용하고 브라우저 DB 역할의 직접 접근을 금지한다. 서비스 역할 서버만 검증된 요청을 처리한다.
- 관리자 조회는 기존 `interview.read`, 심사·변경은 `interview.write` 권한을 사용한다. 신청 수정 버전을 비교해 동시 승인·덮어쓰기를 차단한다.

## 운영 설정

2026-10-20 카카오 개발자 콘솔 및 Vercel Production 환경 변수 설정을 완료했다. 새 코드와 DB 마이그레이션은 아직 운영에 반영하지 않았으므로 실제 로그인 완료까지의 운영 검증은 배포 후 진행해야 한다. 비밀 값은 프런트엔드 코드·문서·저장소에 기록하지 않는다.

| 설정 | 저장한 값 또는 상태 |
|---|---|
| 카카오 앱 | 론박스터디 · ID `1615325` |
| 회사명·카테고리 | 유한회사 론박 · 교육 |
| 카카오 로그인 | ON |
| OpenID Connect | OFF (현재 구현은 사용자 정보 조회 API 사용) |
| REST API 키 | Vercel Production의 `KAKAO_REST_API_KEY`, Secret 유형 |
| 카카오 로그인 Client Secret | 기본 ON 유지, Vercel Production의 `KAKAO_CLIENT_SECRET`, Secret 유형 |
| `INTERVIEW_ORIGIN` | `https://outing-auth-app.vercel.app` |
| `INTERVIEW_PORTAL_ENABLED` | `true` |
| 카카오 로그인 Redirect URI | `https://outing-auth-app.vercel.app/api/interview-auth?action=callback` |
| Vercel 프로젝트 | RONPARK 팀의 `outing-auth-app` |

[카카오 로그인 설정](https://developers.kakao.com/console/app/1615325/product/login)과 [Vercel 환경 변수](https://vercel.com/ronpark/outing-auth-app/settings/environment-variables)에서 저장 상태를 확인했다. REST 키 상세 화면을 다시 열어 Redirect URI가 유지되는 것도 확인했다. 환경 변수는 다음 배포부터 적용되며 이번 작업에서 Redeploy 버튼은 누르지 않았다.

운영 프로젝트에는 `app.ronparkpass.com`도 연결되어 있으나, 이번 면접반 로그인 기준 주소는 위 Vercel 도메인 하나다. 안내 링크는 `https://outing-auth-app.vercel.app/interview`를 사용한다. 별칭 도메인까지 면접 로그인을 제공하려면 인증 원본 주소와 세션·리다이렉트 정책을 별도로 맞춰야 한다.

연결 해제 웹훅은 아직 구현·등록되지 않았다. 카카오 콘솔의 안내대로 서비스 외부 연결 해제와 개인정보 처리 연동은 일반 공개 전에 별도 점검한다. 이번 설정에서 이메일·전화번호 등 추가 개인정보 동의항목이나 비즈니스 인증 권한은 신청하지 않았다.

```dotenv
INTERVIEW_PORTAL_ENABLED=true
INTERVIEW_ORIGIN=https://<현재 앱 도메인>
KAKAO_REST_API_KEY=<카카오 REST API 키>
KAKAO_CLIENT_SECRET=<카카오에서 Client Secret을 사용하는 경우 해당 값>
```

`INTERVIEW_ORIGIN`에는 `/interview` 등의 경로를 붙이지 않는다. 실제 학생이 접속할 HTTPS 원본 도메인과 정확히 일치해야 한다. 기존 Supabase 서버 환경 변수도 필요하다. 포털 활성화 값이나 유효한 원본 주소가 없으면 신규 포털 인증 기능은 닫힌 상태다. 카카오 키가 없으면 카카오 로그인·회원가입 버튼은 비활성화된다.

카카오 개발자 콘솔에서 카카오 로그인을 활성화하고 사용할 웹 도메인을 설정한다. Redirect URI는 다음 문자열과 정확하게 일치하도록 등록한다.

```text
https://<현재 앱 도메인>/api/interview-auth?action=callback
```

로그인 성공 후 이동 주소는 `/interview`로 고정되어 있다. 이메일·전화번호·프로필은 계정 연결에 필요하지 않다. 설정은 [카카오 로그인 사전 설정](https://developers.kakao.com/docs/ko/kakaologin/prerequisite) 및 [REST API 문서](https://developers.kakao.com/docs/ko/kakaologin/rest-api)를 참고한다.

사용자 최종 확인 후 운영에 적용할 순서:

1. 기존 면접 마이그레이션 네 개를 시간 순서대로 적용하고 관련 기출·분석·핵심인성·인생그래프 시드를 준비한다. 이미 적용한 버전은 반복 실행하지 않는다.
2. `20261020062512_interview_portal_auth.sql`을 적용한다. 기존 함수 정의가 예상 구조와 다르면 마이그레이션이 중단되도록 했으므로, 불일치를 확인하고 수정한 후 진행한다.
3. 위에 저장한 서버 환경 변수와 카카오 Redirect URI를 확인하고 앱/API를 배포한다. 현재 코드를 푸시·배포하려면 사용자의 최종 확인이 필요하다.
4. 실제 카카오 계정으로 신규 가입→신청→관리자 승인→본인 자료 저장→로그아웃·재로그인을 확인한다. 기존 학생의 카카오 연결 후 기존 자료 유지도 확인한다.
5. 관리자 면접반 기능 활성화 상태와 회원 이용 기간을 점검한다. 일반 수강생 화면에 신규 면접 계정이 섞이지 않는지 확인한다.

운영 중 웹 입구를 닫으려면 `INTERVIEW_PORTAL_ENABLED`를 끄고 환경 변수 변경을 반영한다. 관리자 면접 기능 중지는 기존 방식으로도 가능하다. 어느 경우에도 자료를 삭제할 필요는 없다.

## 로컬 검증과 미리보기

```powershell
npm.cmd run test:interview
node scripts/interview-prep-ui-qa.cjs
node scripts/verify-interview-build.cjs
npm.cmd test
npm.cmd run preview:interview-prep
```

미리보기 실행 시 출력되는 주소의 `/interview`에서 학생 번호 **18120**, 비밀번호 **demo2026!!**로 로그인한다. 이 자격 증명은 로컬 메모리 DB 전용이며 운영 계정 설정이 아니다. 출력되는 관리자 주소에서 신청과 자료를 검토할 수 있다. 서버를 종료하면 미리보기 데이터가 사라진다.

자동 브라우저 검사에서는 카카오 응답만 모의 처리하며, 실제 로컬 API와 SQL을 연결해 신규 신청·관리자 승인·기존 계정 연결·자료 저장을 검사한다. 대화형 미리보기에서는 모의 카카오 로그인 경로를 제공하지 않고 카카오 버튼을 비활성화한다.

인증 테스트는 세션 만료·재사용·로그아웃, CSRF, OAuth state 재사용, 다른 학생 ID 위조, 권한 없는 관리자 심사, 잘못된 비밀번호 시도 제한, 승인·반려·재신청 충돌, 기존 자료 이관·삭제 정리를 검사한다. 브라우저 검사는 PC·모바일 화면과 일반 학생의 기존 진입 경로도 확인한다. 격리된 빌드 디렉터리에서 빌드하여 실제 `config.js`를 보존한다.

파일 업로드, AI 초안 생성, 네이티브 모의면접 전체 기능을 새로 추가한 변경은 아니다. 해당 기능은 별도 기획·구현 범위이며, 이번 변경은 기존 인성 자료 작성·첨삭 기능에 로그인·소유권·신청·승인을 연결한다.

기존 구현 상세: [면접 준비 DB와 화면](20261020-interview-preparation.md), [인생그래프·경험 DB](20261020-interview-life-database.md).
