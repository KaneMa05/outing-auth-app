# 앱·OX 기기 통합 및 구매 확인 정책

상태: 2026-09-22 사용자 배포 승인. 운영 DB 적용 완료, 앱 배포 진행.

## 최종 동작

- `student_devices`를 유일한 기기 등록 저장소로 사용. 기존 등록 ID와 로그인 기기를 그대로 인정하며 OX 추가 등록 없음.
- 모든 학생의 마이에 동일한 기기 등록·관리 항목 하나를 표시. 구매 여부와 관계없이 기기 관리 가능.
- OX는 관리자가 구매 확인한 교재 또는 별도로 지급한 유효 이용권 영역만 개방. 등록 기기, 학생 등록, OX 전체 이용 재개만으로 교재 권한을 얻을 수 없음. 이용권은 `20260922-ox-bulk-grants.md` 참고.
- 교재 3종을 합쳐 OX 동시 학습은 계정당 1대. 등록된 2대 간 학습 전환은 제한 없이 가능하며 명시적 전환 시 기존 세션 차단.
- 등록 기기는 계정당 최대 2대. 새 기기의 로그인에서 기존 비밀번호를 확인하고 교체할 기기를 선택. 직접 교체는 최근 30일간 1회, 추가 교체는 관리자 승인.
- 마이에서 다른 기기를 해제해 새 기기의 자리를 비울 수도 있으며 직접 교체 1회에 포함. 기존 학생 전체 초기화 경로는 교체 절차로 대체하여 제한 우회 차단.
- 관리자의 기존 기기 해제·비밀번호 초기화 기능 유지. 해당 동작은 OX 세션도 종료하고 교체 이력은 지우지 않음.
- 승인 대기 기기 토큰은 브라우저에 보존하여 새로고침 후에도 같은 기기로 신청 상태 확인 가능. 비밀번호 변경 후에는 기존 인증으로 제출한 신청 승인 불가.
- 문제 화면에는 기기 메뉴나 이름·학생 번호를 표시하지 않음. 답안·메모 기록 유지.

## 구매 확인 강화

- 운영 DB 읽기 점검에서 구매 확인 없이 승계된 `source=legacy`, `active=true` 교재 권한 9건 확인(2026-09-22). 인원수가 아니라 교재 권한 수. 승인 후 9건 잠금 및 변경 이력 기록 완료.
- `20260922044806_ox_verified_purchase_required.sql`은 미확인 활성 권한을 잠그고 변경 이력을 남김. 구매 확인된 기존 권한과 학습 기록은 유지.
- 활성 권한은 `source=purchase` 및 구매일이 있어야 한다는 DB 제약 추가. `ox_has_book`도 동일 조건 확인.
- 잠긴 기존 이용자는 관리자 교재 구매 등록에서 실제 구매 교재와 구매일을 확인하면 해당 범위만 다시 이용. 기존 등록 여부로 3권 전체를 자동 개방하지 않음.

## 구현·권한

- 새 테이블: `ox_device_sessions`, `student_device_changes`, `student_device_requests`. 모두 RLS 및 public/anon/authenticated 접근 차단.
- 새 함수는 security invoker, 빈 search_path, service_role만 실행. 기존 등록·해제·초기화 함수를 활용하여 기존 로그인 및 실시간 해제 알림 유지.
- 등록·해제·교체·승인·학습 요청은 기존 앱과 동일한 학생별 트랜잭션 잠금을 사용. 교체 후 이전 기기는 캐시 인증 쿠키가 남아 있어도 OX 서버 요청 차단.
- 공통 관리 API는 기기 토큰 해시와 인증한 학생 ID를 서버에서 구성. 새 기기 관리에는 기존 비밀번호 확인 필수. 교재 권한 변경 입력은 받지 않음.
- OX 모든 문제 조회·해설·답안·메모 요청에서 현재 기기·현재 학습 세션·구매 범위를 재확인. 누락된 게이트웨이를 이전 경로로 우회하지 않음.
- 교체 신청 조회는 students.read, 승인은 students.reset. 기존 학생 관리의 등록 기기 관리와 OX 관리 화면에서 공통 신청 목록 열기 가능.
- 학습 세션 3분 만료, 화면 표시 중 60초 간격 확인. 백그라운드 복귀 시 최신 기록 로드. 이미 표시된 화면은 다음 요청/상태 확인까지 남을 수 있음.

## 검증

- 실제 기본 기기 SQL을 로드한 가상 DB에서 기존 기기 승계, 신규 로그인 등록, 구매 전후 관리, 중복·초과 등록, 교체·승인·취소·초기화 및 저장 기록 보존 검증.
- 미구매자 학습 요청 차단, 구매하지 않은 교재의 문제·해설·답안·메모 접근 차단, 구매 취소 차단, 승계 권한 잠금 및 구매 확인 후 기존 기록 복원 검증.
- API에서 위조한 관리자/학생 식별자 무시, 기기 관리로 구매 권한 부여 불가, 관리자 권한 분리 검증.
- 실제 화면/API/SQL 브라우저 검증: 세 학생 유형, 교재 등록·중지, 기수·인강 검색, 기기 전환·교체·승인, 390/1100px 표시.
- 전체 npm test는 CRLF 영향을 제외한 LF 격리 사본에서 검증. 관련 없는 final-scope-data.js는 검증 사본에서 HEAD로 대체하며 작업 원본은 보존.
- 운영 모드 빌드도 격리 디렉터리에서 진행하며 실제 config.js는 변경하지 않음.

## 최종 확인 후 배포 순서

1. 관련 없는 final-scope-data.js 변경을 제외하고 이번 변경만 준비.
2. 승계 권한 9건은 구매 재확인 전까지 잠긴다는 동작을 최종 확인. 구매 여부를 임의로 추정하여 활성화하지 않음.
3. 기수/인강 `20260922044735`, 통합 기기 `20260922044751`, 구매 확인 `20260922044806`, 별도 이용권 `20260922044821` 마이그레이션을 순서대로 적용. 운영 적용 완료.
4. 마이그레이션 이력 확인 후 푸시하고 Vercel 자동 배포 확인. 중복 배포하지 않음. 신규 API는 준비된 DB 함수를 요구하므로 DB부터 적용.
5. 서비스 워커 v449-ox-device-policy와 새 자산 로드 확인. 기존 앱 기기 재등록을 요구하지 않으며 구버전 OX 화면은 새로고침 후 이용.

두 사람이 처음 등록한 두 기기에서 시간을 나누는 행위까지 판별할 수는 없음. 이번 정책은 동시 학습과 반복적인 기기 교체를 제한함.
