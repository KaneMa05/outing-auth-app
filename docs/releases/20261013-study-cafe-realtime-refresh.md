# 스터디카페 실시간 재조회 중복 감소

상태: 로컬 구현·검증 완료. 2026-10-13 사용자가 커밋·푸시·운영 배포를 승인하여 진행한다. 운영 DB 변경 없음. 실제 배포 완료 여부는 해당 커밋의 Vercel 배포 상태와 서비스 응답으로 확인한다.

## 변경과 사용자 영향

다른 이용자의 변경 알림이 들어올 때마다 전체 카페 조회가 반복되고, 사설 방은 요청 중 발생한 알림을 놓칠 수 있었다. 공개 카페와 사설 방에 각각 재조회 대기열을 두어 연속 알림을 합쳤다.

- 단발 알림은 기존 대기 시간(공개 350ms, 사설 방 250ms)을 유지한다.
- 연속 알림으로 시작하는 조회는 종류별로 최소 1초 간격을 둔다. 이는 요청 시작 간격이며 네트워크 응답 완료까지 1초를 보장하는 의미가 아니다.
- 이미 예약된 시각을 뒤로 밀지 않아 연속 알림 중에도 화면을 갱신한다.
- 조회 중 추가된 알림은 하나의 후속 예약으로 합친다. 조회가 시작되기 전 알림만 처리 완료로 기록하여 마지막 변경을 놓치지 않는다.
- 본인 조작이나 정기 조회가 알림 이후 시작해 성공했다면, 그 결과로 충족된 중복 예약은 생략한다.
- 본인 조작·화면 복귀 경로에 1초 제한을 적용하지 않는다. 30초 heartbeat, 2분 안전 조회, 포인트·장비 조회, 학습 기록·자동 일시정지·퇴실 규칙을 보존한다.
- 숨김 화면, 다른 학생/방으로 전환된 예약, 타이머 복구 중인 예약은 실행하지 않는다. 실패 자체만으로 추가 요청을 예약하지 않는다.
- 오프라인 수강생과 교사/관리자는 새 대기열 대상이 아니다. 공통 app.js URL과 서비스 워커 캐시 버전을 함께 갱신했고 열린 화면을 강제로 새로고침하지 않는다.

## 검증

- 신규 동작 테스트 17개 통과: 단발/연속 알림, 느린 요청 중 후속 변경, 본인 조작 우선 처리, 실패 후 복구, 학생·방 전환, 퇴실 화면 갱신, 실제 로더의 이벤트 처리 시점.
- 400ms마다 25개 알림이 발생하는 모의 테스트에서 종류별 조회 11회 이하이며 마지막 알림까지 반영한다. 이 수치는 전체 운영 API 절감률이 아니다.
- 기존 타이머·복귀·자동 일시정지·좌석 해제 테스트 및 UI 검증 통과.
- 전체 npm test 통과: 기존 Windows CRLF 소스 추출 테스트 실패를 피하기 위해 기존 `.tmp/normalize-test-newlines.cjs`를 NODE_OPTIONS로 로드했다. 일반 실행은 기존 `grade-ranking-groups.test.js` 줄바꿈 문제로 중단된다. 제품 소스 줄바꿈이나 해당 테스트 단언을 변경하지 않았다.
- production 모드 build-config 검증 통과. 로컬 환경변수를 사용했고 검증 후 config.js를 원래 바이트로 복구했다.
- app.js 구문 검사와 git diff --check 통과.

## 반영 후 확인

동일한 활성 학습 시간 대비 snapshot 호출 수, 좌석·타이머 변경 반영, 오류율을 비교한다. 이번 변경은 클라이언트 중복 재조회 감소이며 전체 조회 1회당 기본 8개의 Supabase 호출을 통합하는 변경은 아니다. 실제 절감량은 알림 발생 간격과 동시 이용 패턴에 따라 달라진다.

기존에 수정되어 있던 `20261012-supabase-503-incident.md`는 이번 작업에서 변경하지 않았다.
