하프 1회 이전 기수 성적 통합 준비 (2026-11-16)

상태: 사용자 최종 승인 후 운영 DB 반영 및 운영 데이터 검증 완료 (2026-11-16).
사용자 지정: 이전 기수를 현재 기수와 합쳐 전체 등수에 포함한다.

원본 대조
- 사용자 제공 론박스터디_적성_모의고사_하프1회_통합성적표.xlsx를 읽기 전용으로 분석했다.
- 25년 하반기 28명, 26년 상반기 31명으로 총 59명이다. 두 기수 모두 현재 운영 기수의 이전 성적으로 취급한다.
- 채점상세 59명 × 75개 답안을 원본_25하/원본_26상 시트와 전부 대조했다.
- 정답표 75개가 운영 하프 1회 정답과 일치한다. 5영역 정답 수 및 총점이 전부 일치한다.
- 통합 성적표의 점수 분포도 채점상세와 일치한다. 최고 62개, 최저 24개 정답이다.
- 채점상세 통합등수 열 59개에는 #NAME? 캐시 오류가 있다. 해당 값은 가져오지 않고 정답 수로 등수를 계산한다.
- 엑셀 원본은 변경하지 않았다.

변경 내용
- ip_aptitude_historical_attempts에 기수, 원본 ID, 이름, 응답 시각, 실제 75개 답안, 원본 정답 수, 현재 채점 결과, 파일 해시 및 원본 행을 보관한다.
- 학생 로그인 계정이나 면접반 등록 계정을 새로 만들지 않는다. 기존 ip_aptitude_attempts는 그대로 보존한다.
- ip_aptitude_rankings는 같은 회차의 현재 최종 제출자와 이전 기수 기록을 합쳐 공동등수 1,1,3 방식으로 계산한다.
- 학생에게는 본인 점수, 합산 등수/인원만 제공한다. 다른 사람의 이름/답안/기수별 명단은 전달하지 않는다.
- 관리자 응시·성적 현황에는 이전 기수의 원래 기수명을 표시한다.
- 정답 정정 시 양쪽 응시 기록을 같은 트랜잭션에서 재채점한다. 원본 성적은 source_correct_count에 보존한다.
- 서버 전용 접근 구조를 유지한다. 신규 테이블은 RLS를 활성화하고 anon/authenticated/PUBLIC 권한을 회수한다. 신규 함수는 security invoker 및 고정 search_path를 사용한다.
- 새 고유키 (round_id, cohort, source_id)는 조회용 round_id 인덱스도 제공한다. 같은 파일 재실행은 중복 생성하지 않고, 기존 값이 다르면 트랜잭션 전체를 중단한다.
- 정답표가 준비 시점과 달라져도 import를 중단한다. 회차 잠금 및 3초 lock_timeout으로 기존 응시 처리와 충돌할 때 오래 대기하지 않는다.
- 웹 UI/API 형식과 호환되므로 웹 빌드 배포 없이 DB 변경만으로 기존 앱에서 합산 등수를 조회할 수 있다.
