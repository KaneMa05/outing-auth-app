안드로이드 베타 면접 구현 — 테스트 시작 전

범위
- Debug 전용 InterviewPracticeActivity에 직무·인성 연습을 구현.
- 기존 일반앱 InterviewActivity의 실시간 모의면접과 기존 iOS 구현은 유지.
- 기존 기기 데모 진입 Activity는 새 로그인 진입 화면으로 연결. 개발용 기존 데모는 legacyDemo=true로 열 수 있도록 보존.
- Debug Manifest의 기존 localhost 전용 네트워크 설정과 기존 진입 Activity 등록을 보존.

구현 내용
- 빠른 연습: 조건에 맞는 최대 3문항을 무작위 선택.
- 질문 골라 연습: 서버 승인 문항만 표시, 분야별 목록과 즐겨찾기 필터, 질문 1개 선택 연습.
- 연습 설정: 분야/지역 및 3·5·10·15·20문항 설정. 해당 조건의 실제 문항 수까지만 사용.
- 즐겨찾기와 문항 수는 인증 계정별로 기기 저장.
- 질문 음성 재생 → 답변 녹음 → 수동 완료 또는 무음 4초 자동 진행. 질문 재생 중에는 답변 완료를 비활성화.
- 결과: 질문별 원본 WAV 듣기·일시정지·이어 듣기·재생 위치 조절. 같은 질문 재연습, 연습 홈 이동.
- 상단 닫기와 뒤로 동작 분리. 기록에서 연 결과는 기록 목록으로, 새 결과는 연습 홈으로 돌아감.
- 관리자 수동 재전송 버튼과 하단 전송 안내 문구 없음. 직무·인성 AI 피드백 및 자동 분석 호출 없음.
- 시작 요청 중 뒤로 나가거나 백그라운드로 이동하면 늦은 응답/권한 콜백이 녹음을 시작하지 않게 취소 처리.
- 종료 확인 중에는 무음 자동 진행을 보류하고, 백그라운드 이동 시 현재 답변을 저장한 뒤 종료.

인증·서버 연결
- 기존 일회용 네이티브 진입 코드를 교환해 계정에 묶인 연습 전용 토큰을 메모리에서만 사용.
- 연습 토큰은 별도 aud/HMAC 용도 및 2시간 만료를 사용하며 기존 실시간 면접 토큰과 혼용하지 않음.
- 서버에서 수강/테스트 권한과 공개 문항 범위를 확인. 사용자 입력 계정 ID나 임의의 질문 목록을 신뢰하지 않음.
- 시작 직전에 서버 목록을 다시 확인해 공개 종료된 문항의 녹음을 시작하지 않음.
- Android + nativePractice=1 진입에서만 새 Debug 패키지(com.ronpark.study.nativepreview)를 여는 링크 제공.
- 일반 웹/iOS의 기존 네이티브 호출 경로는 유지. 실전 AI 모드는 기존 실시간 면접 Activity로 연결.

저장·관리자 아카이브
- 인증 계정 해시별 no-backup 폴더, AtomicFile로 메타데이터 기록.
- WAV 원본은 기기에 보관하고 별도 작업 스레드에서 16kHz mono / AAC-LC 목표 32kbps M4A로 압축.
- 소스 WAV 해시별 압축 파일을 캐시하고, 완료된 M4A만 전송. 단일 압축 파일 상한 16MiB.
- 관리자 아카이브의 iOS와 같은 sync/uploaded 프로토콜과 비공개 Storage를 사용.
- 업로드 주소는 HTTPS Supabase의 해당 녹음 경로만 허용하고, 브라우저 쿠키/사용자 토큰을 Storage 업로드에 전달하지 않음.
- 업로드와 완료 확인이 끝나야 동기화 완료로 표시. 전송 중 추가된 답변을 덮어쓰지 않음.
- 미전송 기록은 기기에 남겨 연습 진입/복귀 시 자동 재시도. 전송 완료 전의 기기 기록 삭제는 보류.
- 과거 무계정 로컬 데모 녹음을 특정 학생 계정으로 임의 귀속하지 않음.

빌드 준비
- scripts/play-store/prepare-android-beta.cjs: 독립 Debug 호스트 프로젝트만 생성. 테스트·설치·배포 실행 없음.
- Android SDK 36, AGP 8.11.1, Gradle 8.13, JDK 17 기반. 생성 프로젝트는 .tmp/android-beta.
- Release variant는 비활성화하며 Play 업로드·릴리스 서명을 하지 않음.
- 기존 TWA 생성/릴리스 프로젝트를 변경하지 않고 새 테스트 APK를 별도로 만들 수 있음.

현재 상태
- 대기 요청 이전의 첫 Android APK 빌드는 성공한 이력이 있음.
- 이후 접근성·기존 Manifest 보존·뒤로 이동/백그라운드 취소·플레이어 준비 상태 처리를 추가 보완.
- 사용자 요청에 따라 재개 후 테스트, 재빌드, 기기 설치, 서버 DB 적용, 푸시 및 배포를 실행하지 않음.
- 기존 빌드 APK는 최신 보완분 이전 산출물이므로 최종 검증 APK로 취급하지 않음.
- 서버 API/DB/웹 변경을 반영해야 실제 로그인·승인 문항·관리자 아카이브 연결이 작동함. 현재 운영 반영은 보류.
- 로컬 fixture는 별도 가상 계정으로 분리되며 운영 서버로 업로드하지 않음.
