# 인성 준비 노트와 직무 기출 관리 구현

후속 변경: [관리자 면접반 모드·학생 질문 개선·핵심인성 교재 반영](20261020-interview-mode-core30.md). 아래 초기 가져오기 수량과 구현 범위에 대한 추가 변경을 정리했다.

서식 추가: [인생그래프·경험 DB 입력 및 첨삭](20261020-interview-life-database.md).

## 구현 범위

상위 카테고리는 **인성 / 직무**로 분리한다. 학생의 개인 데이터베이스, 작성률, 첨삭 및 수정 이력은 **인성 전용**이다. 직무에는 기출 조회만 제공하며 개인 작성 양식이나 필수 작성률을 만들지 않는다.

학생 앱의 마이 화면에서 **테스트 허용 대상 18120번 중 면접반 이용 등록이 확인된 학생**에게만 준비 노트 진입 버튼을 표시한다. PC는 `/interview.html`, 관리자는 기존 `teacher.html#interview-prep-admin`에서 이용한다. PC도 기존 등록번호·비밀번호·기기 인증을 사용하며, 서버가 매 요청마다 테스트 허용 대상 및 유효한 면접 이용 등록을 확인한다. PC 브라우저도 기존 등록 기기 한도를 적용한다.

테스트 허용 목록은 `interview-preview-config.json`의 `studentIdHashes`이며 `SHA-256("interview-preview-v1:" + 학생고유번호)` 값을 저장한다. 빌드는 같은 목록을 `config.js`의 표시 힌트로 전달한다. 빈 목록이나 잘못된 목록이면 모든 학생을 차단한다. 브라우저의 힌트를 변조해도 서버에서 독립적으로 검사하므로 접근 권한이 생기지 않는다. 해시는 비밀번호나 인증 수단이 아니다.

일반 학생은 마이 화면에서 면접반 API를 호출하지 않는다. 전용 UI·CSS·HTML은 서비스 워커 사전 캐시 대상에서 제외하며, 학생 UI·CSS는 서버 이용 권한 확인 후 로드한다. 면접반 진입 스크립트가 누락되어도 기존 앱 경로 렌더링은 유지한다. 학생의 URL 직접 접근이나 API 직접 요청도 자료를 반환하지 않는다. 교사·관리자 권한 체계는 유지한다.

이번 구현은 기출 가져오기, 인성 자료 수집, 관리자 질문 CRUD, 이용 등록, 첨삭에 해당한다. AI 초안 생성, 파일 제출, 네이티브 모의면접 녹화, 신규 면접반 수강 신청 및 면접 전용 앱 모드 전체는 이 변경에서 구현하지 않았다. 기존 학생을 등록한 뒤 관리자가 면접 이용 등록을 부여한다.

## 원본과 분류

입력은 사용자가 제공한 직렬별 HWPX 6개 파일이다. 원본 파일은 수정하지 않았다.

| 구분 | 출제 기록 | 카테고리 내 같은 문구 통합 후 |
|---|---:|---:|
| 인성 및 사전질문지 | 3,239 | 2,952 |
| 직무 | 2,195 | 2,131 |
| 합계 | 5,434 | 5,083 |

인성·직무는 원본 소제목을 기준으로 구분한다. 두 카테고리에 같은 문구가 있어도 별도 질문으로 보존한다. 출처 파일명, SHA256, 직렬, 연도, 지역, 원문 질문 번호, HWPX 문단 위치, 원문 질문과 해설을 출제 기록마다 저장한다. PDF 페이지 번호를 추정하지 않는다.

인성의 세부 항목 연결은 재현 가능한 키워드 규칙의 **제안**이다. 1,577개는 분류 검토 대상으로 남겼다. 원문에서 인성으로 분류된 직무성 질문도 관리자가 상위 카테고리를 수정할 수 있다. 가져온 모든 질문은 검토 대기 상태이며, 자동으로 공개하거나 학습 완료로 처리하지 않는다. 분류 검토 대상은 활성 인성 항목을 지정해야 공개할 수 있다.

인성 필수 항목은 자기이해, 지원동기, 협동심, 소통·갈등, 리더십, 도전·성취, 실패·성장, 책임감, 봉사·배려, 정직·청렴, 공직관, 스트레스 관리, 인성 상황 판단의 13개다. 관리자가 순서·필수 여부·직렬·안내·사용 여부를 조정할 수 있다.

## 화면과 저장

- 학생: 자동 저장, 항목별 작성 현황, 같은 양식의 소재 가져오기, 관련 공개 기출, 출처 조회, 제출, 강사 피드백, 재작성, 최근 수정 이력.
- 입력 양식: 경험형, 가치관형, 인성 상황형. 임시저장은 빈칸을 허용하며 제출에는 각 주요 항목 10자 이상을 요구한다. 이 조건은 형식 검증이고 내용 충실도 판정은 강사가 수행한다.
- 소재가 없는 학생은 도움 요청 상태로 저장한다. 작성 완료나 강사 확인으로 계산하지 않는다.
- 관리자: 인성·직무별 질문 검색/직렬/상태 필터, 원문 해설, 질문 생성·수정·삭제/보관, 최대 30개 선택 공개, 인성 항목 관리, 학생 이용 등록, 학생별 상태표, 미작성·보완·소재 찾기 필터, 피드백 공개.
- 승인된 인성 답변을 수정하면 다시 작성 중 또는 제출 상태가 된다. 질문·항목·학생 답변은 버전으로 동시 수정 충돌을 막는다.
- 출처나 공개 이력이 있는 질문은 삭제 대신 보관한다. 미사용 수동 초안만 삭제한다. 항목은 비활성화로 보관한다.
- 실패한 저장은 입력을 유지한다. 성공 응답 유실 후 충돌 시 기존 입력을 복사해 보관하고 최신 서버 자료를 확인하도록 안내한다.

## DB와 접근 권한

마이그레이션: `supabase/migrations/20261020050641_interview_preparation.sql`

테이블은 `ip_settings`, `ip_topics`, `ip_sources`, `ip_questions`, `ip_occurrences`, `ip_members`, `ip_notes`, `ip_history`다. 기존 학생 유형과 기존 테이블 구조는 변경하지 않는다.

모든 신규 테이블에 RLS를 적용하고 `anon`, `authenticated`, `PUBLIC`의 직접 권한을 회수한다. `service_role`만 서버 전용 RPC `ip_service`를 호출한다. RPC는 `SECURITY INVOKER`이며 클라이언트가 전달한 actor를 신뢰하지 않는다.

API `/api/interview-prep`는 기존 학생 기기 검증 또는 서명된 관리자 세션을 확인한다. 학생은 자기 자료만 접근한다. 관리자 기능은 현재 관리자 역할과 `interview.read`/`interview.write` 권한을 요구하며 기존 관리자 `*` 권한을 사용한다. 일반 학생 관리자는 이 기능을 부여받지 않는다.

직무 질문에 인성 항목을 연결하는 저장을 거절한다. 학생 노트에는 승인된 활성 인성 항목만 사용할 수 있다. 학생에게 기출 원본 해설은 전달하지 않는다. 관리자 출처 상세에서만 원문 해설을 제공한다.

학생 삭제 시 노트·면접 이용 등록·해당 학생의 개인 변경 이력도 제거한다. 질문·항목 변경 이력은 유지한다. 개인 자료를 localStorage나 서비스 워커에 저장하지 않는다. 기존 앱의 인증 저장 방식은 그대로 사용한다.

## 로컬 확인

기존 테스트 도구와 동일하게 임베디드 PostgreSQL인 PGlite를 사용한다. 이 PC에는 기존 도구 경로가 준비되어 있다. 다른 환경에서는 `PGLITE_MODULE`에 설치된 `@electric-sql/pglite` 모듈 경로를 지정한다.

```powershell
npm.cmd run test:interview-prep
npm.cmd run test:interview
node scripts/interview-prep-ui-qa.cjs
node scripts/verify-interview-build.cjs
npm.cmd test
```

브라우저 검증은 로컬의 실제 API와 SQL을 연결해 생성·공개·자동 저장·재접속·전송 실패·제출·피드백·이력을 확인하고 390px/1200px 화면을 캡처한다. 실제 앱 셸에서도 PC 면접 경로와 기존 앱 설치 안내, 관리자 메뉴를 확인한다. 운영 DB나 유료 AI를 호출하지 않는다.

```powershell
npm.cmd run preview:interview-prep
```

출력된 로컬 학생/관리자 주소에서 샘플 계정으로 검토할 수 있다. 미리보기 자료는 메모리에만 저장하며 종료하면 초기화된다.

## 운영 반영 순서

후속 [면접반 웹 로그인·신청·승인](20261020-interview-login.md) 구현으로 `/interview`는 전용 로그인 입구가 되었다. 아래 18120번 시험 허용 범위는 기존 앱의 기기 인증 경로에 해당한다. 신규 웹 경로는 웹 세션과 관리자 승인·이용 기간으로 접근을 판단한다. 운영 설정과 후속 마이그레이션은 해당 문서를 함께 확인한다.

현재 운영 DB 적용·푸시·배포는 하지 않았다. 사용자 최종 확인 후 진행한다.

1. 검토한 마이그레이션을 적용한다. 기본 기능 상태는 중지다.
2. `supabase/seeds/interview-corpus.sql`을 실행한다. 재실행해도 기존 질문이나 관리자 수정본을 덮어쓰지 않는다.
3. 앱/API를 배포하고 관리자에서 인성 세부 분류·질문·준비 항목을 검토한다.
4. 테스트 계정 **18120번**의 면접반 이용 등록에 직렬·수험번호·이용 기간을 지정한다. 테스트 허용 목록만으로 이용 등록을 대신하지 않는다.
5. 검토된 질문을 공개하고 기능 이용을 활성화한다. 18120번의 저장·권한과 일반 학생의 비노출을 확인한다. 다른 학생은 면접반에 등록되어 있어도 테스트 허용 목록 밖이면 계속 차단된다. 일반 공개는 별도 변경과 사용자 확인이 필요하다.

운영 중 중지하려면 관리자에서 이용 중지를 선택한다. 자료를 삭제하거나 기존 수강생 화면을 전환하지 않는다. 마이그레이션/원문 JSON/출처 해설은 `.vercelignore`의 `supabase/` 제외 규칙에 따라 정적 웹 파일로 배포하지 않는다.

AI 초안 생성 연결 시에는 인성 노트의 학생별 원문과 버전을 입력 근거로 사용하고, 모델 생성본을 학생 원문과 별도로 저장하는 후속 구현이 필요하다.

## 인성 질문 요소 분석 추가

기존 13개 준비 항목 아래에 31개 평가 요소를 정의하고 인성 질문 2,952개에 분석 초안을 연결했다. 관리자 인성 메뉴의 ‘질문 요소 분석’에서 평가 요소, 학생 소재 질문, 판단 근거, 수집 구분을 검토·수정한다. 질문 공개와 학생 작성률에는 자동 반영하지 않는다.

상세 결과와 한계는 [인성 질문 요소 분석](20261020-personality-element-analysis.md)을 참고한다. 기존 기출 입력 후 `20261020053550_interview_personality_elements.sql` 마이그레이션과 `supabase/seeds/interview-personality-analysis.sql`을 적용한다. 검증은 `npm.cmd run test:interview`에 포함되어 있다.
