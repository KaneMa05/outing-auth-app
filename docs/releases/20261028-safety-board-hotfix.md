# 신고·차단 오류 및 홈 자유 게시판 지연 수정

## 확인한 문제와 변경

- 신고·차단 저장 요청이 성공한 뒤 본문 없는 HTTP 201 응답을 JSON으로 읽으면서 오류가 발생했다.
  그 결과 기록은 저장돼도 API는 503을 반환하고 화면의 성공 안내·차단 후 갱신이 실행되지 않았다.
  빈 성공 응답은 null로 처리하고 JSON 응답과 실제 저장 실패 처리는 유지한다.
- 홈 미리보기에서 글을 열면 상세 조회 완료 후 불필요한 목록 조회가 시작되며 다시 로딩 화면이 표시됐다.
  목록 모드에서만 초기 목록을 요청하도록 제한했다.
- 게시판 서버의 기본 지역은 미국 iad1, DB는 시드니다. 게시판 및 신고·차단 API에만 syd1을 지정한다.
- 접근 가능한 글의 첨부 이미지 URL 서명을 댓글·작성자 조회와 동시에 시작한다.
- 학생/교사 진입 페이지와 서비스 워커의 게시판 자산 버전을 갱신한다. 열린 화면을 강제로 전환하지 않는다.

## 검증

- 기존 배포 소스로 빈 HTTP 201 응답을 재현하면 두 회귀 검사가 실패한다. 수정 후 두 검사 모두 통과한다.
- 인증·작성자 조회부터 실제 Response 객체를 통한 신고·차단·목록·차단 해제 응답 처리를 검증한다.
  운영 계정으로 직접 수행한 실기기 검사는 아니다.
- 홈에서 상세 진입 시 목록 중복 조회가 없고 상세 화면이 유지되는지 검증한다.
- 이미지/댓글 동시 조회, 차단 작성자 필터 유지, 숨김 글 이미지 서명 거부를 검증한다.
- 격리된 배포 소스에서 전체 기본 회귀 검사와 추가 검사, 격리 빌드·문법 검사를 수행한다.
  결과는 로컬 artifacts/app-review-20261028/hotfix-qa.json에 보관한다.

## 운영 반영

- DB 구조 변경이나 데이터 정리는 필요하지 않다. 이미 저장된 신고·차단 기록은 유지한다.
- 워크스페이스의 별도 네이티브/면접 변경을 제외한 허용 목록만 격리 커밋으로 준비한다.
- 최종 확인 후 GitHub 푸시 및 연결된 Vercel 운영 배포 1회를 진행한다.
- 반영 후 앱을 다시 실행하고 다른 테스트 글에서 신고 성공 안내, 차단 후 내용 숨김, 마이의 차단 해제를 확인한다.
  기존 신고 글에서 '이미 신고' 안내가 나오면 중복 접수 방지 동작이다.
- 홈 자유 게시판 목록 및 상세 열기를 휴대폰에서 확인한다. 실제 운영 로딩 시간 개선 수치는 아직 측정하지 않았다.
- Apple 심사 답변 전송·재제출 및 유료 네이티브 빌드는 이 수정에 포함하지 않는다.
