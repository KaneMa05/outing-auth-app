# 인성 기출의 평가 요소와 학생 데이터 수집 설계

2026-10-20 · 사용자 제공 직렬별 HWPX 6개 파일을 가져온 기출 DB 기준

## 결론

인성 질문은 주제 이름만 붙여서는 학생에게 무엇을 작성시킬지 결정하기 어렵다. **질문 → 평가 요소 → 필요한 개인 소재 → 답변에서 확인할 근거**로 연결해야 한다.

기존 13개 인성 준비 항목 아래에 **31개 세부 평가 요소**를 정의했다. 이 요소들은 원문 질문을 바탕으로 작성한 준비·첨삭용 해석이다. 채용기관이 발표한 공식 평가표나 검증된 예측 점수가 아니다.

한 경험은 여러 요소에 연결할 수 있다. 예를 들어 팀 과제에서 의견 충돌을 해결한 경험은 공동 목표, 경청, 갈등 조정, 책임감의 근거가 될 수 있다. 학생에게 요소마다 별도의 경험을 만들도록 요구하지 않는다. AI가 향후 초안을 만들 때도 실제로 입력한 근거가 없는 요소를 충족했다고 서술해서는 안 된다.

## 분석 범위와 상태

분석 대상은 원본에서 인성·사전질문지로 분류된 **중복 통합 질문 2,952개**, 출제 기록 **3,239건**이다. 질문별 분석은 모두 관리자 검토 대기 상태로 저장한다.

| 질문별 수집·검토 구분 | 질문 수 | 처리 |
|---|---:|---|
| 학생 인성 소재 연결 후보 | 2,377 | 평가 요소와 경험·가치관 소재 연결 |
| 앞선 문맥 확인 | 320 | 앞 질문·답변과 지원자 사례 확인 후 판단 |
| 직무·시사 지식 재분류 검토 | 68 | 인성 원본 분류를 보존하고 별도 검토 |
| 안부·면접 진행 질문 | 105 | 학생 필수 데이터로 만들지 않음 |
| 개인정보 수집 범위 검토 | 82 | 수집 필요성·선택 응답·대체 사례 검토 |
| 합계 | 2,952 | 중복 없는 주된 처리 구분 |

분석 방식은 두 가지다. 2,090개는 질문 표현에 따른 재현 가능한 규칙 제안이다. 기존 규칙으로 연결되지 않았던 862개는 문구를 읽고 개별 문맥을 해석해 분류했다. 두 방식 모두 원문의 실제 평가 의도를 확정하지 않으며, 특히 규칙 제안은 표현이 비슷해도 의도가 다른 경우를 관리자가 검토해야 한다.

‘앞선 문맥 확인’에는 “이유는요?” 같은 꼬리질문뿐 아니라, 경력·군 복무·취미 등을 확인하지만 무엇을 평가하려는지 문구만으로는 정하기 어려운 질문도 포함한다. 원본 해설은 관리자가 참고할 수 있지만 학생의 실제 경험으로 복사하지 않는다.

원문, 출처 문단 위치, 기존 질문 공개 상태, 학생 작성 내용은 변경하지 않았다. 질문별 요소 수는 복수 연결이므로 요소별 빈도의 합은 질문 수와 다르며, 빈도를 점수나 필수 작성 개수로 사용하지 않는다.

## 질문을 요소로 분석하는 예

### 갈등을 해결하여 성과를 낸 경험을 구체적으로 말해보세요.

갈등 해결뿐 아니라 공동 결과에 어떻게 기여했는지 함께 묻는다. ‘소통을 잘한다’는 성향 표현만으로는 부족하다.

- 필요한 소재: 공동 목표, 서로 다른 입장, 본인의 역할, 확인 질문, 조정 행동, 결과.
- 확인할 근거: 갈등 전후에 무엇이 달라졌는지, 팀 성과 중 본인의 기여가 무엇인지.
- 후속 질문: 상대가 동의하지 않았다면 어떻게 했는가, 같은 상황이 반복되면 무엇을 바꾸겠는가.

### 본인이 평가하는 모습과 타인이 평가하는 모습이 달랐던 경험을 작성하세요.

자기이해와 평가 수용을 연결한다. 타인의 평가를 무조건 인정하는지를 묻는 것으로 단정하지 않는다.

- 필요한 소재: 본인의 생각, 타인의 구체적인 평가, 차이를 확인한 행동, 이후 변화.
- 확인할 근거: 자기평가의 이유와 행동 사례가 일치하는지, 외부 평가를 확인한 과정이 있는지.

### 상사가 부당한 지시를 할 때 어떻게 할 것인가

부당한 요구 대응, 판단 기준, 건설적 의사소통을 함께 검토한다.

- 필요한 소재: 무엇을 확인해야 부당함을 판단할 수 있는지, 설명·협의·보고 순서, 본인의 역할 범위.
- 확인할 근거: 불편한 지시와 부당한 지시를 구분하는지, 무조건 복종 또는 즉시 대립으로 답을 단순화하지 않는지.
- 학생에게 실제 유사 경험이 없으면 가치관·가정 상황으로 작성한다. 경험을 꾸며내도록 요구하지 않는다.

### 탕비실 물품을 가져가려는 직원과 다른 직원이 다투는 상황

원문 질문은 직원의 경제적 어려움과 물품 사용 문제가 함께 제시된다. 공정성만으로 분류하면 배려와 갈등 조정이 누락될 수 있다.

- 필요한 소재: 물품의 소유·사용 기준, 당사자의 사정, 갈등 당사자 의견, 가능한 대안.
- 확인할 근거: 사실과 권한을 확인하는지, 어려운 사정에 대한 지원과 기준 적용을 함께 설명하는지.

### 개인정보 보호법을 설명해보세요.

원본의 인성 항목에 포함되어 있어도 문구상으로는 지식 확인 질문이다. 학생의 개인 경험·가치관 입력 항목을 생성하지 않고 직무·지식 재분류 검토 대상으로 둔다. 이 분석에서 법률 해설을 새로 작성하거나 최신성을 검증하지 않았다.

### 이유는요? / 식사여부

첫 질문은 앞선 답변이 필요하고, 두 번째는 면접 진행 질문으로 해석했다. 각각 별도의 필수 개인 데이터 항목을 만들지 않는다.

## 학생 데이터 수집에 적용할 방식

학생에게 요구할 단위는 ‘질문별 완성 답안 2,952개’가 아니라 재사용할 수 있는 **경험·가치관 소재**다.

1. **경험**: 상황·목표 → 본인 역할 → 행동·선택 이유 → 실제 결과 → 배운 점·이후 변화.
2. **가치관·동기**: 본인의 입장 → 형성 계기 → 경험·근거 → 실천 방법과 한계.
3. **가정 상황**: 확인할 사실 → 관련자·충돌 가치 → 판단 기준 → 행동 순서 → 주의점·후속 점검.

관리자는 검토한 질문의 평가 요소를 기준으로 학생 자료에 어떤 근거가 부족한지 판단한다. ‘협동 경험은 있으나 본인 역할이 없음’, ‘청렴의 중요성은 설명했으나 이해충돌 상황의 판단 기준이 없음’처럼 구체적으로 피드백한다.

경험의 크기나 수상 여부를 기준으로 작성 완료를 판단하지 않는다. 작은 학교·아르바이트·군 복무 사례도 행동과 이유가 분명하면 소재가 될 수 있다. 실제 경험이 없으면 소재 찾기 도움 요청을 이용한다. 건강·가족·성적 경험 등 사적인 내용의 고백을 필수 조건으로 삼지 않는다.

현재 구현한 작성률은 기존 **13개 인성 준비 항목의 제출 상태**다. 31개 요소별 근거 충족 여부를 자동 판정하거나 AI 점수로 표시하지 않는다. 요소 분석 저장은 학생 입력 양식·작성 상태를 자동 변경하지 않는다. 요소별 충족 표시를 도입하려면 학생 원문의 어느 문장이 근거인지 확인하는 별도 검토 기능이 필요하다.

## 구현과 검토 절차

- 관리자 인성 메뉴에 **질문 요소 분석**을 추가했다.
- 31개 요소의 정의·학생 소재 질문·확인 기준을 볼 수 있다.
- 질문·평가 요소·수집 구분·검토 상태로 검색할 수 있다.
- 질문별 요소, 답변 형태, 판단 근거를 수정하고 검토 완료로 저장할 수 있다.
- 요소 분석을 검토 완료해도 질문이 학생에게 자동 공개되지 않는다.
- 질문 문구나 상위 카테고리가 바뀌면 기존 검토 완료를 해제한다. 변경된 질문에 저장할 때 이전 문구의 근거를 제거한다.
- 질문 버전과 분석 버전을 함께 검사해 동시 수정 내용을 덮어쓰지 않는다.
- 분석 DB와 RPC는 관리자 전용이다. 기존 학생 데이터 API에는 요소 분석을 추가 노출하지 않는다.

파일:

- 정의·분석 생성: `scripts/analyze-interview-personality.py`
- 개별 문맥 해석 862건: `scripts/data/interview-personality-overrides.json`
- 전체 분석: `supabase/seeds/interview-personality-analysis.json`
- DB 입력: `supabase/seeds/interview-personality-analysis.sql`
- 집계: `supabase/seeds/interview-personality-analysis-report.json`
- 추가 마이그레이션: `supabase/migrations/20261020053550_interview_personality_elements.sql`

운영 반영 시 기존 면접반 마이그레이션과 기출 seed 후 추가 마이그레이션·분석 seed를 적용한다. 분석 seed는 재실행해도 관리자 수정본을 덮어쓰지 않는다. 원문을 변경한 뒤 분석을 새로 생성할 때는 개별 해석의 질문 문구가 일치하는지 검사한다.

운영 DB 적용·푸시·배포는 하지 않았다. AI 초안 생성과 모델 학습도 이 작업에서 실행하지 않았다.
