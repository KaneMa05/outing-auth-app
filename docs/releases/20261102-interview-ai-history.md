# 면접반 AI 초안 활성화 준비 및 전체 생성 기록

2026-11-02. 사용자 요청: AI 초안 활성화, 모든 생성 기록 조회.

## 변경 내용

- 관리자에 **AI 생성 기록** 메뉴 추가. 전체 수강생의 초안, 인생그래프 후속 질문, 핵심 25제 진단, 경험 심화 질문·요약, AI 모의면접, 직무·인성 답변 분석, 관리자 채점 검증 기록을 조회한다.
- 학생별 작성 내용과 첨삭 화면에서도 해당 학생의 모든 생성 종류를 조회한다. 기본이력·인생그래프에서도 조회할 수 있다.
- 최근 1건 제한을 제거하고 25건씩 커서로 탐색한다. 요청 시각의 마이크로초와 같은 시각의 요청 순서를 보존한다. 결과는 선택했을 때만 읽는다. 실패를 기록 없음으로 처리하지 않는다.
- 아직 배포되지 않은 선택 기능의 기록 저장소는 준비 전으로 표시한다. 서버 오류나 권한 오류는 조회 실패로 표시한다.
- 면접반 전용 계정도 처리하도록 PC 처리기의 조회 대상을 `ip_student_directory`로 수정한다. 기존 범위 제한 토큰의 권한은 유지한다. 전체 등록 학생 처리기로 명시적으로 설정한 기기만 이후 신규 등록자도 처리한다.
- `ip_ai_job_history`에 완료·보완·실패·중단 결과와 당시 자료를 보존한다. 재요청으로 현재 결과가 바뀌어도 기존 결과는 남는다. 서버 역할만 조회·추가할 수 있다.
- 관리자 화면의 버전만 갱신한다. 일반 수강생 기능·성적과 공용 서비스워커는 변경하지 않는다.

## 검증

- API 관리자 권한, 학생 범위, 전체 종류 조회, 커서, 결과 조회, 미배포 저장소, 연결 실패, 늦게 도착한 응답 검증 통과.
- 로컬 PostgreSQL에서 면접반 전용 계정의 실제 작업 배정·실행 시작·결과 업로드 통과. 기존 제한 기기의 범위가 확대되지 않음 확인.
- 재요청 후 이전 보완 결과와 원문이 유지되고 새 결과·자료가 별도로 보존됨 확인. 브라우저 역할 접근 금지와 서버 역할 읽기 권한 검증.
- PC·모바일 브라우저에서 관리자 메뉴, 읽기 권한 계정, 종류 필터, 페이지 이동, 결과 확인, HTML 이스케이프와 실패 복구 검증 통과.
- 실제 CLI + 가상 학생 + 로컬 DB 생성 시험 통과: 24.3초, 577자, 서로 다른 경험 3개, 도구 실행 0건. 운영 학생 자료는 사용하지 않았다.
- 운영 DB 읽기 전용 검증: 후속 질문 70건과 진단 1건, 총 71건이 페이지를 거쳐 빠짐·중복 없이 조회됨. 완료된 후속 질문 69건과 진단 1건의 생성 결과를 모두 개별 조회하여 본문까지 확인했다. 나머지 1건은 실패 기록이다. 학생 범위 확인, 운영 쓰기 0건.
- 기존 회귀 검사 두 곳의 오래된 예상값은 원본 코드에서도 실패함을 확인하고, 현재 동작에 맞게 수정했다. 과제 현황의 조회 열을 포함한 데이터 셀 수는 7개이며 학생 홈은 모의면접 권한 확인 후 독립 조회를 시작한다.
- 격리 빌드·릴리스 안전 검사 및 면접 인증·작성·제출·첨삭 회귀 검증 통과.

## 운영 반영 순서 — 최종 확인 후

1. `20261102053618_interview_ai_history_and_owners.sql`을 적용한다. 이 마이그레이션 자체는 기능을 켜지 않는다.
2. 관리자 화면/API 변경을 푸시·배포한다.
3. 로그인한 Windows 사용자로 준비 상태를 확인하고 활성화한다.

```powershell
node --env-file=.env.local scripts/configure-interview-drafts.cjs --check
node --env-file=.env.local scripts/configure-interview-drafts.cjs --activate
```

활성화 스크립트는 등록 학생 수 × 학생별 하루 요청 한도에 25% 여유를 더하고 1,000회 단위로 올림하여 전체 하루 한도를 설정한다. 87명 × 40회 = 3,480회에 여유를 더한 현재 계획은 5,000회다. 이미 더 높게 설정한 한도를 낮추지는 않는다. 지원 상한 10,000회를 넘는 규모는 임의로 잘라 적용하지 않고 별도 조정을 요구한다. `--set-capacity` 옵션은 생성 기능을 켜지 않고 한도만 조정한다.

초안은 자기소개·지원동기·공직관을 대상으로 한다. 현재 학생 화면의 핵심 25제 작성 방식은 그대로 유지한다. 토큰은 Windows 현재 사용자 DPAPI로 저장하고 기기 연결을 인증한 뒤, 처리기를 숨김 실행하고 접수를 활성화한다. 학생의 생성 요청을 임의로 만들지는 않는다. 실패하면 접수를 다시 끄고 기기를 폐기한다. 접수 중지 여부를 확인할 수 없는 통신 장애에서는 복구를 위해 처리기와 암호화 상태를 보존한다.

## 현재 상태와 보관 범위

DB 구조 변경을 운영에 적용했다(원격 버전 20261102053618). 기존 71건 유지, 이력 테이블 RLS와 서버 역할 접근, 면접 전용 계정 처리 대상을 확인했다. 코드 28cc8bc를 GitHub main에 푸시했으며 초안 생성도 활성화했다. 전체 등록 학생을 처리하는 PC 처리기 1대가 정상 대기 중이고 전체 하루 한도는 5,000회다. 관리자 기록 화면 운영 배포는 공식 Vercel CLI 로그인 인증을 기다리고 있다. 저장된 Vercel 인증 파일 직접 읽기는 자동 승인 검토가 거부했으므로 공식 로그인 흐름을 사용한다.

기존에 저장되지 않았거나 이미 덮어쓴 결과를 복구할 수는 없다. 기존 심화 질문·요약 결과는 정확한 요청 ID 대신 자료·답변 버전에 연결되어 있어 화면에 그 범위를 명시한다. 이번 보존 변경은 남아 있는 초안 결과를 이관하고 이후 결과를 보존한다. 기존 모의면접 자료의 보관 기간과 계정 삭제 정책은 유지한다.

초안 PC 처리기는 PC와 네트워크가 켜져 있어야 한다. 현재 실행을 유지하는 방식이며 재부팅 후에는 다시 실행해야 한다. 기기 토큰 기본 유효기간은 30일이다. 사용자의 승인 없이 자동 시작 작업이나 새 유료 서비스를 등록하지 않는다.
