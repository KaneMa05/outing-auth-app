학생 제출 안내 · 피드백 후 재제출 제한
로컬 구현/검증 완료, 운영 DB 적용·푸시·배포는 최종 확인 대기

요청과 적용 범위
- 기존 운영 화면은 제출 버튼에 '11/23 00시부터'만 표시했다. 학생 작성 화면에 '교사 제출은 11월 23일 00시(한국 시간)부터 가능합니다' 안내를 추가했다.
- 개시 전에도 임시저장·저장이 가능하다고 함께 안내한다. 개시 시각이 되면 입력 내용을 유지하고 날짜 제한 안내를 해제한다.
- 같은 항목의 현재 제출이 교사 확인 대기 중이면 새 회차 제출을 막는다. 핵심인성은 질문별로 적용하며 다른 항목의 첫 제출은 허용한다.
- 대기 중에도 임시저장·저장은 허용하며 기존 제출 원문과 회차 기록은 보존한다.
- 보완요청/첨삭완료 피드백을 받은 뒤 작성 화면을 다시 열면 재제출할 수 있다. 새 회차는 다시 그 회차의 피드백을 기다린다.
- 사용자가 선택한 '관리자 삭제 시 재제출 허용'을 유지한다. 이 예외는 삭제된 제출 revision에만 적용된다.
- 학생 화면의 회차별 제출·피드백 기록은 답변/제출 안내와 AI 초안 다음인 페이지 맨 아래에 배치한다. PC/모바일 위치와 기록 펼치기를 확인했다.

서버와 DB
- 추가 마이그레이션: 20261120062003_interview_writing_feedback_before_resubmission.sql. Supabase CLI migration new로 생성했다.
- 기존 작성 RPC의 소유자/등록/수정 충돌/행 잠금/동일 요청 재시도 검사를 보존한다.
- 행 잠금 안에서 새 제출 회차를 검사하고 대기 중 변경 제출은 feedback_pending/HTTP 409로 거부한다.
- awaiting_feedback은 서버가 계산하며 현재 제출 상태와 관리자 삭제 이력의 정확한 revision을 기준으로 한다. 작업본 상태와 과거 회차의 피드백으로 해제하지 않는다.
- 응답 JSON에 계산 결과만 추가한다. 기존 학생 자료·회차·피드백을 갱신하는 데이터 마이그레이션은 없다.
- 새 보조 함수는 SECURITY INVOKER와 빈 search_path를 사용하고 service_role만 실행할 수 있다.
- 운영 읽기 전용 사전 확인: 원래 작성 함수는 invoker, anon/authenticated 실행 권한 없음, service_role 실행 권한 있음. 새 보조 함수는 아직 운영에 없다.
- 운영 함수의 패치 대상 1/2/1개와 로컬 마이그레이션 사전 조건이 일치함을 확인했다. 조건이 다르면 원자적으로 실패한다.
- 운영 보안 advisor 사전 조회에서 WARN/ERROR는 없었다. 이는 새 함수 적용 전 기준선이며 운영 적용 뒤 다시 확인한다.

검증
- npm run test:interview 전체 통과. 새 피드백 제한 테스트도 기본 회귀 명령에 추가했다.
- 날짜 경계·기존 앱 로딩·배포 안전성 테스트 통과.
- 실제 Chrome/격리 Postgres에서 시작 안내 표시, 정각 해제와 입력 보존, 제출 직후 잠금, 대기 중 작업본 저장, 피드백 뒤 재제출, 관리자 삭제 뒤 동일 답변 재제출과 PC/모바일 배치 통과.
- DB에서 과거 피드백/삭제 이력의 예외 범위, 중복/동시 요청, 원문·회차 보존, 직접 API 409, 함수 실행 권한 통과.
- 이전에 완료한 첨삭 창 문구 정리, 일반 글 코멘트, 성공 후 닫기 버튼 흐름도 집중 브라우저 검사에서 통과했다.
- 운영 학생 답변으로 쓰기 시험하지 않았다. 기존 로컬 미리보기는 종료하지 않고 새 메모리 DB 미리보기를 실행했다.

운영 반영 계획
- 사용자 최종 확인 후 새 후보 빌드를 검증한다.
- API의 새 오류 코드 매핑을 포함한 앱을 먼저 전환하고 같은 반영 작업에서 새 DB 규칙을 적용한다. 새 UI는 이전 응답도 호환한다.
- 함수 정의/권한, 양쪽 운영 도메인의 자산/접근 제어와 실제 배포 자산의 격리 브라우저 시나리오를 검증한다.
- 운영 반영 결과는 승인 후 별도 배포 기록에 남긴다.
