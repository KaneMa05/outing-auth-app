승인과 범위
사용자는 '직무모드 판정과 종합피드백을 우선적으로' 요청했고, 종합 피드백은 '실전 모의면접의 종합 피드백'으로 명시했다.
새 운영 DB 변경은 자동 승인 검토에서 최초 거절됐다. 이후 사용자의 '두 수정 모두 적용 승인' 최종 승인을 받은 뒤 적용했다.
일반앱의 기존 접근 정책·모델·추론·음성은 변경하지 않았다. 직무 UI와 개발자 결과 열람은 iOS DEBUG에만 포함된다.

확인한 문제와 수정
1. 종합 피드백 생성의 기존 수강 검사
실제 테스트 계정은 enabled=true, mock_test_enabled=true, expires_on=null이다.
Live 기록 조회는 가능했지만 종합 피드백 claim 함수만 expires_on>=한국 날짜를 요구해 생성 요청이 HTTP 403으로 차단됐다.
생성 전 거절됐으므로 첫 재현에서는 모델 호출과 과금이 없었고 report 행도 없었다.
승인 후 테스트앱 actor.testApp=true이고 승인된 mock 계정일 때만 종료일 없는 수강을 허용했다.
기존 일반앱 접근, 만료·비활성·미승인 계정 제한, 소유권·보관 기한·출처 검사·한 번만 실행하는 claim 구조를 유지한다.

함수 security invoker, 빈 search_path, anon 실행 불가·service_role 실행 가능 상태를 유지했다.

2. 직무 안내 문구
두 전사의 판정이 모든 항목에서 일치해도 '보류된 항목을 확인해 주세요' 문장이 남던 문제를 고쳤다.
새 결과는 실제 보류 유무에 맞는 요약을 저장한다. 기존 저장 결과는 재분석 없이 화면에서 올바른 문구를 보여준다.
일반 서술 피드백을 임의로 바꾸거나 uncertain을 충족/미충족으로 변경하지 않는다.
직무 3개 실제 저장 답변에서 판정·인용 근거·예시답변·피드백을 다시 열어 확인했다.
- 깨진 유리창: uncertain / partial / X. 실제 보류는 남김.
- 선위통보제도: partial / uncertain / uncertain. 실제 보류는 남김.
- V-PASS: partial / X / partial. 보류 없이 부분 충족 표시, 잘못된 보류 안내 제거 확인.
