# OX 첫 진입과 통계 조회 개선

## 최종 변경

- 일반 진입 후 브라우저 요청을 3회에서 1회로, API→DB 게이트웨이 왕복을 3회에서 1회로 줄였다. 홈의 이용 가능 여부 확인과 필요한 최초 기기 인증은 별도이며 유지한다.
- `device_start(includeBootstrap:true,homeOnly:true)`가 기존 기기·이용권·세션 검증과 첫 화면 요약 조회를 한 DB 트랜잭션에서 처리한다. 요약 실패 시 세션 시작·기기 전환도 롤백된다.
- 첫 화면에는 오늘 풀이 수와 복습할 오답 수만 조회한다. 문제 목록·답안·메모·통계는 받지 않는다. 단원·오답노트·북마크에 처음 들어갈 때 요약 문제 목록과 개인 기록을 조회한다. 문제 지문은 기존 묶음 로딩을 유지한다.
- 누적 정답률은 취약 탭에서 처음 조회한다. 전체 수강생 오답률은 해설을 펼칠 때 해당 문항만 조회하며, 채점 응답은 기존처럼 통계를 포함한다. 교사 풀이를 수강생 오답률에서 제외하는 규칙을 유지한다.
- 교재 이용권 확인을 문제·풀이마다 반복하지 않고 교재 목록 단위로 계산한다. 기존 인덱스를 유지하며 인덱스나 테이블을 추가하지 않는다.
- 진행 중인 조회를 공유하되 홈 요약·상세 목록·통계 포함 응답을 구분한다. 탭 이동·화면 이탈·계정/세션 변경 후 늦은 응답은 화면을 바꾸지 않으며, 늦은 통계 응답이 이후 저장된 답안의 통계를 덮어쓰지 않는다.
- 홈에서 이용 가능 확인 후 OX 진입 모듈도 미리 내려받는다. 기기 세션이나 학습 기록은 사전 조회하거나 로컬 저장하지 않는다.
- 이전 DB가 묶음 조회 옵션을 무시하면 API는 기존 게이트웨이로 학습 기록을 조회한다. 이전 API가 추가 옵션을 무시해도 클라이언트는 기존 bootstrap을 읽는다. 기존 클라이언트의 기본 응답과 학습 기록은 보존한다.
- 생성 원본·운영 JS·공용 진입 파일과 서비스 워커 버전 `v458-ox-entry-summary`를 함께 갱신했다. 학습 화면 디자인 변경은 없다.

## 검증과 측정

- OX 기능 테스트 41건, 로딩 테스트 32건, 릴리스 안전성 2건 통과.
- 실제 PGlite SQL로 이전/이후 bootstrap 데이터 동등성, 구매 범위, 공개·현재 버전, 복습 완료, 교사 통계 제외, 세션 전환·롤백, 권한 해제, 익명·인증 역할의 함수 직접 호출 차단, security invoker와 고정 search_path를 검증했다.
- 전체 pretest/test/posttest 73개 파일 통과. 기존 Windows CRLF에 민감한 테스트를 위해 임시 로더가 JS 텍스트 읽기의 줄바꿈만 LF로 보정했으며 원본 테스트·관련 없는 파일은 수정하지 않았다.
- 숨김 Chrome에서 오프라인·온라인 관리반·인터넷 테마 × 320px·390px 검증. 첫 화면→단원→오답노트→해설 통계→취약 통계→첫 화면 이동과 단계별 요청 횟수, 가로 넘침 없음 확인. 스크린샷은 `.tmp/ox-entry-qa`에 저장했다.
- 가상 데이터 2,504문항 비교: 기존 요약 bootstrap JSON 125,253바이트, 첫 화면 요약 176바이트(압축 전 bootstrap 객체만 비교). 같은 로컬 DB의 단일 EXPLAIN ANALYZE 측정은 전체 약 25ms, 첫 화면 약 1.7ms였다. 운영 응답 시간이나 네트워크 성능을 뜻하지 않는다. 측정 원본은 `.tmp/ox-entry-performance/measurements.json`에 저장했다.
- 격리 폴더 `.tmp/ox-entry-summary-build`에서 로컬 빌드 통과. 로컬 공개 설정이 비어 있어 개발용 빈 설정 생성 경로로 검증했고 배포 설정 검증은 릴리스 안전성 테스트로 확인했다. JS 구문 검사와 diff 공백 검사 통과.
- CLI `db advisors --local`과 `migration list --local`은 로컬 Supabase 서비스(127.0.0.1:54322)가 실행 중이지 않아 연결하지 못했다. 대신 PGlite에서 마이그레이션 실행과 SQL 권한·함수 속성을 검사했다. 운영 반영 전 대상 DB advisor 점검이 필요하다.

## 반영 순서

1. 사용자 최종 확인 후 `20260928071629_ox_entry_summary_and_deferred_statistics.sql`을 운영 DB에 적용한다. 기존 함수를 제한적으로 수정하며 테이블·기존 기록을 변경하지 않는다.
2. 대상 DB advisor 확인 후 앱을 배포한다. 먼저 DB를 적용해도 기존 클라이언트의 기본 요청은 그대로 동작한다.
3. 실제 첫 진입 시간과 단원·오답노트·기기 전환을 확인한다. 문제가 생기면 앱을 이전 배포로 되돌릴 수 있으며, DB의 추가 옵션은 기존 클라이언트에 영향을 주지 않는다.

## 운영 반영 승인 및 DB 확인

2026-09-28 사용자가 운영 반영을 최종 승인했다. 운영 DB 마이그레이션 적용 완료.

- 적용 전·후 함수 3개의 본문 해시가 각각 로컬 검증본과 일치한다. 함수 실행 권한과 security invoker 속성을 유지했다.
- 운영 데이터 1건을 식별자 노출 없이 비교했다. 2,543문항의 기존 bootstrap JSON 텍스트는 466,353바이트, 첫 화면 요약은 198바이트였다. 전송 압축·API 포장·네트워크 시간을 포함한 수치는 아니다.
- 첫 화면 복습 수 26문항은 기존 기록 계산과 일치했다. 오늘 풀이 수, 단원/문제 목록, 답안, 메모도 일치하며 지연 조회에서는 통계 집계가 제외됨을 확인했다.
- 적용 전·후 보안 advisor는 동일한 INFO 56건이고 WARN/ERROR는 없었다. 서버 전용 테이블의 기존 [RLS 정책 없음 안내](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy)이며, 이번 변경으로 공개 권한을 추가하지 않았다.
- main 푸시에 연결된 기존 Vercel 운영 배포 경로를 사용한다. 배포 및 공개 자산 검증 결과는 `.tmp/ox-entry-release`에 기록한다.

별도 작업인 final-scope-data.js와 Vercel 관측 비용 문서는 이 변경에 포함하지 않는다.
