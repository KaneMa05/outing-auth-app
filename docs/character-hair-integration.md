# 상점 머리 스타일

마이 > 캐릭터의 무료 머리 선택 메뉴를 제거하고 기존 인터넷 수강생 상점에 `머리 스타일` 카테고리를 추가했습니다. 캐릭터 색상은 무료 변경을 유지합니다. 기존 수강생의 기본 머리는 `default`이며, 상점의 기본 머리 카드로 언제든 무료 복귀할 수 있습니다.

| 머리 | 가격 | 상품 ID |
| --- | ---: | --- |
| 기본 머리 | 무료 | DB 상품 없음 |
| 스포츠 컷 | 50P | `hair_sport` |
| 삐죽 숏컷 | 80P | `hair_spiky` |
| 버섯 머리 | 100P | `hair_mushroom` |
| 내추럴 웨이브 | 150P | `hair_wave` |
| 하이 포니테일 | 200P | `hair_ponytail` |

가격은 2026-09-11 사용자가 확인했습니다. 구매 후 추가 비용 없이 다시 착용할 수 있습니다.

- `study-character.js`: 브라우저와 API에서 공유하는 허용 목록 및 검토 시안의 SVG 도형.
- `save_profile.hairStyle` 요청은 `hair_style_shop_only`로 거절합니다. 머리를 생략한 색상·닉네임·상태메시지 수정은 기존 머리를 유지합니다.
- `study-shop.js`: 상품 미리보기, 가격, 구매·보유·착용·기본 머리 복귀를 제공합니다. `hair` 슬롯은 `head` 모자 슬롯과 별개입니다.
- 기존 구매 RPC의 지갑 잠금·보유 중복 제약·포인트 내역을 재사용합니다. 장착/해제 RPC에서 장비와 프로필의 머리를 한 트랜잭션으로 갱신합니다. 머리 슬롯은 수강생당 하나만 허용합니다. 프로필 트리거로 구버전 클라이언트의 미구매 머리 무료 변경을 차단합니다.
- 공용 좌석, 스터디룸 좌석 및 캐릭터 상세에서 본인과 다른 수강생의 저장된 머리가 표시됩니다. 모자는 기존 착용 기능을 유지합니다.
- 로컬 미리보기는 브라우저 저장소를 사용합니다. 운영 모드는 서버의 프로필을 사용합니다. 저장 실패 시 기존 선택을 유지합니다.

## 검증

`npm test`에 `tests/study-character-hair.test.js`가 포함됩니다. API 무료 변경 차단, 기존 프로필 호환, 미인증·오프라인 접근 거부, 가격, 중복 구매 방지, 포인트 부족, 미보유 착용 차단, 재접속·재착용, 모자 유지, 실패 시 상태 유지를 확인합니다.

`tests/study-character-hair-shop.sql`은 테스트 계정만 만드는 SQL 계약 검증입니다. 로컬 PGlite 0.5.8에서 기존 스키마·상점·머리 컬럼 마이그레이션을 구성한 뒤 새 마이그레이션과 계약 검증을 실제 실행했습니다. 5종 구매·차감, 중복 구매 거절, 미보유 착용 거절, 프로필 우회 차단, 기본 복귀·재착용, 모자 병행, 기존 프로필 값 유지, RPC 반환과 역할 권한을 검증했습니다. 테스트 데이터는 롤백했습니다. PGlite는 단일 연결이므로 동시 트랜잭션 부하 검증은 포함하지 않습니다.

로컬 Chrome에서 320/360/390/430/600/768/1280px의 6종 미리보기 경계를 확인하고, 구매 버튼·50P 차감·착용·캐릭터 화면·기본 복귀 흐름을 검증했습니다.

로컬 화면: `http://localhost:3000/?studentMode=online#study-shop` → 머리 스타일

## 운영 반영 순서

푸시·배포는 AGENTS.md에 따라 사용자의 최종 확인 후 진행합니다. DB 변경은 사용자의 별도 요청으로 2026-09-11 먼저 적용했습니다. 앱/API 배포는 아직 진행하지 않았습니다.

1. 적용 완료: `supabase/migrations/20260911052853_add_study_character_hair.sql`. 운영 대상은 RONPARK APP (`ehzrwkvuarertwvwoyus`), 원격 이력은 `20260911052853 / add_study_character_hair`입니다. 로컬 파일명도 원격 버전에 맞췄습니다. 기본값이 있는 컬럼과 허용 값 제약을 추가하고 공용 스냅샷 RPC에 머리 스타일을 포함했습니다. 잠금 대기는 5초로 제한했습니다.
2. DB 검증 완료: `hair_style`은 NOT NULL, 기본값 `default`, 허용 값 6개입니다. 기존 프로필 54개 모두 기본 머리를 유지하며 잘못된 값은 0개입니다. 서비스 역할로 RPC를 실행해 기존 응답 키 9개와 모든 프로필의 `hair_style` 반환을 확인했습니다. RLS 활성화 및 RPC의 서비스 역할 전용 실행 권한, SECURITY INVOKER를 유지했습니다. 운영 테이블의 제약을 복제한 임시 테이블에서 6개 값 저장과 잘못된 값·NULL 차단을 검증한 뒤 롤백했습니다. 실제 사용자 프로필을 테스트용으로 수정하지 않았습니다. 보안 검사에는 서비스 역할 전용 테이블의 RLS 정책 없음 안내(INFO)만 있었습니다.
3. **추가 상점 DB 적용 완료**: 사용자의 "DB 반영만" 승인으로 2026-09-11 RONPARK APP에 `20260911072426 / sell_character_hairstyles`를 적용했습니다. 로컬 파일 `supabase/migrations/20260911072426_sell_character_hairstyles.sql`도 원격 이력에 맞췄습니다(동일 내용: `supabase/add-study-cafe-hair-shop.sql`). 상품 5종의 50/80/100/150/200P 가격, 머리 슬롯 제약·고유 인덱스, 보유 검사 트리거, 착용·해제 RPC와 권한을 확인했습니다. 새 상품은 모두 `is_active=false`로 등록했습니다. 기존 활성 상품 14종과 기본 머리 프로필 54개를 유지했으며 서비스 역할의 카탈로그·좌석 RPC 조회도 정상입니다. 보안 검사에는 RLS 정책 없음 INFO 안내만 있습니다. 앞선 운영 롤백 테스트는 자동 승인 검토에서 거절되어 실행되지 않았고, 구매·착용 계약은 로컬 PostgreSQL에서 검증했습니다. 이번 운영 검증은 실제 사용자 데이터를 수정하지 않는 조회로 수행했습니다.
4. **앱/API 미배포, 판매 활성화 대기**: 사용자의 최종 승인 후 `study-shop.js`, `app.js`, `styles.css`, `sw.js` 버전을 함께 배포하고 `hair_sport`, `hair_spiky`, `hair_mushroom`, `hair_wave`, `hair_ponytail` 5개 상품만 `is_active=true`로 활성화합니다. 현재는 구버전 상점에 새 상품이 노출되지 않습니다. 이미 적용한 마이그레이션을 재실행하지 않습니다.
5. 구매 후 재접속, 다른 수강생의 공용/개인 스터디룸 좌석, 모자와 병행 착용을 확인합니다.

머리 컬럼은 유지해도 이전 앱에서 무시됩니다. 상점 변경 배포 후 구버전으로 돌아갈 때는 새 머리 상품 판매를 비활성화하고, 구매 이력·보유 아이템·프로필 데이터는 보존합니다.
