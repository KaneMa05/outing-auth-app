면접반 수강생·이용 관리 — 이용 종료/복구 (2026-11-25)

위치와 화면
- 기존 '수강 신청·승인'을 '수강생·이용 관리'로 변경한다. 주소의 applications 키는 유지한다.
- 같은 화면에서 '신청·승인'과 '등록 수강생·이용 종료'를 구분한다.
- 기존 학생 등록·첨삭 화면은 유지하고, 종료 작업은 새 관리 위치에서 수행한다.
- 수강 만료일과 실제 종료 처리일을 구분한다.

관리자 기능
- 개별/일괄 종료: 이름·직렬·수험번호·수강 과정을 확인하고 사유와 종료 범위를 선택한다.
- 여러 페이지의 학생을 최대 100명까지 선택한다. 선택 수에 다른 페이지 포함 여부를 표시한다.
- 종료 확정 전 대상을 다시 보여주며, 처리 결과는 성공과 제외/실패로 구분한다.
- 종료 사유 기본값: 체력 탈락, 서류 탈락, 본인 요청, 환불, 수강 종료, 기타.
- 사유는 직접 선택한다. 기타는 기본적으로 비고 필수이다.
- 사유 추가/이름 변경/사용 중지/비고 필수 여부 설정을 제공한다.
- 과거 종료 이력의 사유명은 사유 설정 변경 후에도 당시 이름을 유지한다.
- 이용 상태·사유·범위·이름/수험번호 필터, 종료 명단 엑셀, 처리 이력을 제공한다.
- 종료 내역과 관리자 비고는 관리자 전용이다. 환불 금액 정산은 별도 업무이다.

권한과 복구
- 구매 과정과 별개인 ip_member_access에 종료 상태를 보관한다.
- 면접 기능 종료: DB/인생그래프/작성/AI/모의면접/면접 기록 접근을 차단한다.
  패키지의 인적성 이용 권한과 성적은 기존 등록 및 이용 기간에 따라 유지한다.
- 면접 앱 전체 종료: 적성 모의고사 및 성적 접근도 차단한다.
- 인적성 단과 학생은 '면접 기능 종료' 대상에서 제외한다.
- 학생 계정 활성 상태, 오프라인/온라인 관리반/인터넷 수강생 화면 권한은 변경하지 않는다.
- 종료/복구는 기록을 삭제하지 않으며 기존 보관 정책을 따른다.
- 되돌리기는 이번 종료 제한만 해제한다. 현재 수강 과정·만료일·이용 중지·모의면접 설정을 그대로 따른다.
- 동시 처리 및 오래된 화면은 접근 상태 revision과 회원 updated_at을 함께 확인한다.
- 종료 후 일반 등록 수정이나 재신청으로 종료 상태를 해제할 수 없다.
- 기존 로그인 세션은 종료 안내·로그아웃·다른 수강생 화면 이동을 위해 유지한다.
- 기존/네이티브 클라이언트도 DB 서비스 단계에서 제한한다.
- 대기 중 AI 작업은 종료 학생에게 새로 배정되지 않는다. 이미 저장된 기록은 보존한다.
  진행 중 작업은 각 서비스의 권한/완료 기준을 따르며 자동 재실행을 추가하지 않는다.
- 열린 학생 화면은 화면 복귀/포커스 및 표시 중 15초 주기로 상태를 확인한다.
  서버의 새 요청 차단은 종료 트랜잭션 반영 직후 적용된다. 숨긴 탭은 주기 요청을 보내지 않는다.
- 진행 중 Live 모의면접은 권한 거절 시 종료하며 추가 유료 꼬리 질문 요청을 차단한다.

DB 변경
- supabase/migrations/20261125054036_interview_member_termination.sql
- 선행 수강 상품 변경을 포함한 기존 마이그레이션 이후 순서대로 적용한다.
- 새 테이블 3개는 RLS 활성화, 공개/학생 역할 접근 차단, service_role 전용이다.
- 새 함수는 SECURITY INVOKER 및 고정 search_path를 사용한다.
- 기존 학생/수강 기록을 초기화하지 않는다. 최초 상태는 정상이다.
- 운영 DB 반영은 배포 절차에 포함하며 사용자 최종 확인 후 진행한다.
