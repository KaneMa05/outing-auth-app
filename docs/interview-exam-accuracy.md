# 모의면접 음성 채점 검증

2026-10-21 기준 로컬 구현 문서. **실제 학생 음성의 채점 정확도는 아직 측정하지 않았다.** 현재 구현은 관리자 검증용이며 학생 성적을 자동 확정하지 않는다.

## 구현한 처리 흐름

1. 관리자 쓰기 권한을 확인하고, 서버 DB에서 검토 완료된 전공 지식형 기준을 읽는다. 클라이언트가 보낸 정답·배점·전사문·판정은 받지 않는다.
2. 음성 파일의 실제 WAV 헤더·길이·표본 형식을 검사한다. 현재 검증 화면은 16 kHz, 모노, 16비트 PCM WAV, 1~90초, 최대 3 MB를 지원한다. 지나치게 작은 음성과 클리핑은 판정 제안을 보류한다.
3. 같은 음성을 두 번 전사한다. 한 번은 언어 힌트만, 한 번은 발화의 부정·숫자·단위·정정을 그대로 보존하라는 일반 지침만 사용한다. 질문·모범답안·필수 단어는 전사 API에 전달하지 않는다.
4. 두 전사문은 NFC·대소문자·연속 공백만 정규화해 비교한다. 숫자·단위·부정 표현·문장부호·단어가 달라지면 보류한다. 원문 전사문은 그대로 남긴다.
5. 별도로 설정한 두 문맥 판정 모델이 전체 답변과 검토 완료 기준을 읽는다. 서로의 판정은 보여주지 않는다. 각 항목과 핵심 오류에 대해 상태·원문 인용·판정 이유를 요청한다.
6. 서버가 결과 구조, 항목 누락·중복, 전사문에 실제로 존재하는 인용, 지정 단어·허용 표현의 포함 여부를 검사한다. 모델이 임의로 점수나 필드를 추가하면 인정하지 않는다.
7. 전사나 문맥 판정의 불일치·불확실성·실패는 X가 아니라 검토 필요다. 두 판정이 일치한 경우에만 서버 규칙으로 검토용 O·△·X와 배점을 계산한다. 핵심 오류는 X, 모두 충족은 O, 일부 충족은 △, 미충족은 X다.
8. API 처리 후 질문과 기준을 다시 읽는다. 수정되었으면 판정 제안을 취소한다. 버전·모델·프롬프트·음성·기준 해시를 결과에 포함한다.

모든 결과의 확정 `grade`와 `score`는 `null`, 상태는 `review_required`다. `suggestion`만 관리자에게 미확정 제안으로 표시한다. 현재 코드에는 환경 변수만 바꿔 학생 점수 확정을 켜는 기능이 없다.

## 표현과 문맥

- 허용 표현은 관리자가 등록한 것만 인정한다. 유사도, 임의 동의어, 자동 약어 확장, 띄어쓰기 삭제, 숫자·단위 환산을 사용하지 않는다.
- 문자 경계와 정해진 조사·서술격 형태만 허용한다. `VHF를`은 `VHF` 후보지만 `XVHF`, `VHF2`는 아니다. `2`를 `2.5`, `-2`, `2%`의 일부로 인정하지 않는다.
- 부정어가 있다는 이유만으로 오답 처리하지 않는다. “UHF가 아니라 VHF”처럼 부정 대상이 무엇인지 문맥 판정이 확인한다.
- 단어 나열, 타인의 주장을 인용한 경우, 잘못된 관계, 가정, 자기 정정, 상충되는 주장을 전체 답변에서 판단하도록 요청한다. 불명확한 정정과 상충되는 주장은 검토한다.
- 필수 표현이 없는 항목을 모델이 충족으로 반환하면 서버에서 거부한다. 원문에 없는 인용도 거부한다.

이 규칙과 프롬프트는 모델의 의미 판단 오류를 완전히 제거하지 않는다. 실제 녹음과 사람의 판정을 비교하는 검증이 필요하다.

## 현재 한계와 모델 선정

두 전사는 현재 같은 `gpt-transcribe` 모델에 대한 별도 요청이다. 서로 독립적인 인식기의 검증이 아니며, 같은 오류가 반복될 수 있다. 다른 문맥 모델 ID 두 개를 사용해도 통계적 독립성을 보장하지 않는다. 일치율을 정답률로 표시하지 않는다.

파형의 크기·클리핑 검사는 잡음, 발화 여부, 여러 사람의 발화, 본인 여부, 실제 명료도를 판별하는 검사가 아니다. 현재 문턱값은 검증 전 초기값이며 신뢰도나 정확도 점수로 사용하지 않는다. 현재 모델 문서에서 확인되지 않은 토큰 신뢰도 필드를 가정해 호출하지 않았다.

전사 모델은 현재 공식 파일 전사 가이드의 권장 경로를 연동했다. 이것이 한국어 해양경찰 면접에서 가장 정확하다는 검증은 아니다. 문맥 모델 두 개는 실제 평가 자료를 비교한 뒤 설정하도록 기본값을 두지 않았다. 후보·모델 버전·프롬프트·판정 규칙이 달라지면 같은 미사용 검증 자료로 다시 측정해야 한다.

## 관리자 사용과 설정

경로: **면접반 관리 → 분류·채점 기준 → 문항 검토 → 음성 채점 검증**.

검토 완료한 전공 지식형 문항에서 WAV 파일을 선택하고 실행한다. 원음을 브라우저에서 재생하면서 전사문 두 개와 문맥 판정 근거를 확인하고 JSON 결과를 내려받을 수 있다. 수정 중인 기준은 저장 전 실행할 수 없다. 검증 중 기준 저장과 화면 이동도 막는다.

서버 환경 변수:

```text
INTERVIEW_EXAM_VALIDATION_ENABLED=true
OPENAI_API_KEY=<서버 전용 키>
INTERVIEW_EXAM_JUDGE_MODEL=<검증할 문맥 모델 ID>
INTERVIEW_EXAM_VERIFIER_MODEL=<다른 검증 모델 ID>
```

두 문맥 모델은 Responses API의 엄격한 JSON Schema 출력을 지원해야 한다. 로컬 환경에서 현재 활성화 및 공급자 설정이 완료되지 않은 것을 확인했다. 실제 유료 API 호출은 수행하지 않았다. API 키를 브라우저나 문서에 넣지 않는다.

새 엔드포인트 `api/interview-exam.js`는 관리자 `interview.write` 권한과 동일 출처 요청을 검사한다. 전사는 최대 두 번, 문맥 판정은 최대 두 번 호출하며 요청 실패를 자동 재시도하지 않는다. 단일 실행 인스턴스에서 동시 한 건·시작 간격 30초 제한을 둔다. 이것은 분산 비용 한도가 아니므로 학생용으로 개방하기 전 영속 작업 큐·멱등성·계정별 한도·전역 예산 제한이 필요하다. 호스팅 실행 시간 한도도 실제 모델 지연에 맞춰 별도 확인해야 한다.

음성과 결과는 이 관리자 검증 API에서 DB나 Storage에 저장하지 않는다. 실제 실행 시 음성·질문·채점 기준·전사문이 외부 API로 전달되며, Responses 요청은 `store:false`를 사용한다. 이는 공급자의 모든 로그·보관 정책이 없다는 뜻이 아니다. 검증용으로 사용 가능한 자료만 사용한다.

학생 녹화·업로드, 관리자와 학생의 보관 영상 재생, 수강 종료 후 30일 삭제는 아직 별도 구현 대상이다. 현재 원음 재생은 관리자가 선택한 로컬 파일이다.

## 실제 정확도 측정

최소한 아래 경우를 포함한 실제 한국어 녹음을 수집한다. 모델을 조정할 자료와 마지막 성능 판정 자료는 분리하고, 같은 사람·문항의 유사 녹음이 양쪽에 섞이지 않도록 관리한다.

- 전공용어·영문 약어·허용된 한글 발음
- 숫자·소수·부호·거리·속력·단위
- 부정문·이중 부정·잘못된 원인과 결과
- 키워드만 나열·질문 반복·모범답안 인용
- 명확한 자기 정정·불명확한 정정·상충되는 답변
- 무응답·작은 음성·클리핑·배경 소음·동시 발화
- 억양·말 속도·마이크·브라우저·기기 차이
- 평가자에게 점수 변경을 지시하는 발화

사람 두 명 이상이 원음을 듣고 전사문과 O·△·X 정답을 검토한다. 판정이 다르면 기준 자체를 조정하거나 별도 합의한 후 정답 자료에 포함한다. 최소 표본 수와 허용 오류율은 실제 검증 자료를 확보한 후 정해야 하며 임의의 “99% 정확도”를 표시하지 않는다.

`scripts/evaluate-interview-exam.cjs`는 외부 API 호출 없이 검토한 결과를 집계한다. 입력은 다음 형태의 배열이다. 값은 실제 검증 자료로 채운다.

```json
[
  {
    "id": "녹음별 고유 ID",
    "source": "human_recording",
    "reviewers": ["검토자 1", "검토자 2"],
    "gold": "O",
    "referenceTranscript": "사람이 확인한 전사문",
    "tags": ["약어", "부정문"],
    "report": "이 자리에는 내려받은 검증 결과 JSON 객체를 넣습니다"
  }
]
```

```powershell
node scripts/evaluate-interview-exam.cjs .tmp/reviewed-samples.json
```

도구는 판정 제안 비율·보류 건수·제안 정확도·전체 중 맞힌 비율·잘못된 O와 X의 비율·문자 오류율·유형별 혼동 행렬·오류율의 Wilson 95% 상한을 출력한다. 보류를 제외한 정확도만 보고하지 않는다. 자료가 없을 때는 정확도를 100%로 만들지 않으며, 다른 처리 파이프라인의 결과·중복 음성·검토자가 부족한 자료는 거부한다. 보고서가 자동 운영 승인으로 연결되지는 않는다.

## 검증 내역

- `npm run test:interview-exam`: 표현 경계, 숫자 부분 일치 방지, 근거 검사, O·△·X 규칙, 불일치·불확실성·실패 보류, WAV 구조, 기준 변경, API 계약, 실제 관리자 쿠키 권한, 통계 분모·보류·혼합 자료 거부 통과.
- `npm run test:interview`: 기존 면접반 회귀 검사 통과.
- `node scripts/verify-interview-build.cjs`: 기존 설정을 보존한 격리 빌드와 구문 검사 통과.
- `node scripts/interview-prep-ui-qa.cjs --serve --exam-fixture`: 메모리 DB와 모의 공급자를 사용해 브라우저 파일 선택·재생 컨트롤·검토용 결과·근거 표시 확인. 합성 테스트 신호를 사용했으며 실제 음성 인식 정확도 검사가 아니다.
- 이번 변경은 운영 DB 적용, 학생 점수 기록, 유료 API 실행, 푸시, 배포를 수행하지 않았다.
