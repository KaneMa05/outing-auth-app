# 면접 초안 생성 지침

2026-11-04 수정안. 사용자가 확인한 기준과 기존 생성 지침을 정리했다. 강의안 원문은 아직 전달되지 않았으며, 원문 확인 후 강의의 구성·용어·예시에 맞춰 추가 검토한다.

## 공통 원칙

- 로그인한 학생이 저장한 기본 이력·인생그래프·인성 노트·진단 답변만 사실 근거로 사용한다.
- 확인되는 자료는 먼저 활용한다. 경험·성과·수치·지원 이유·신념을 만들어내지 않는다.
- 완성 답변을 학생에게 대신 써 달라고 요구하지 않는다. 문장 구성과 근거 있는 강점·미래 활용 방향의 연결은 생성기가 맡는다.
- 사실이 부족할 때만 필요한 내용을 최대 3개의 구체적인 질문으로 요청한다. 인성 13개 항목 전체 작성이나 진단표 4/4는 요구하지 않는다.

## 자기소개

목적은 실제 경험을 통해 본인이 어떤 사람이며 어떤 강점을 갖추었는지 소개하는 것이다.

1. 준비 자료: 기본 이력과 내용·어필할 점이 저장된 서로 다른 경험 최소 3개.
2. 본문: 강점 도입 → 서로 다른 실제 경험 최소 3개의 맥락·본인 행동·결과 → 확인되는 강점을 해양경찰 업무에서 활용할 방향.
3. 경험 도입: 면접관이 처음 듣는다는 전제로 어떤 활동이나 상황인지 먼저 밝힌다. 경험 제목·역량 이름만 나열하지 않는다.
4. 경험 수: 같은 사건의 배경·행동·결과를 나누어 3개로 세지 않는다. 분량을 줄이려고 경험을 1~2개로 축소하지 않는다.
5. 근거: 본문에 포함한 각 경험을 원본 경험 ID·서로 다른 본문 구절·DB 근거와 연결한다. 본문에 없는 경험의 ID만 추가하지 않는다.
6. 부족 처리: 자료가 충분하면 초안을 고쳐 3개를 반영한다. 실제 경험이나 행동·결과가 부족할 때만 추가 사실을 묻는다.

## 지원동기

본인이 저장한 지원 계기·선택 이유 → 강점을 보여주는 실제 행동·결과 → 해양경찰 업무와의 연관성 → 실제 준비와 기여 방향으로 구성한다. 관련 경험은 최소 1개를 확인하며, 본인의 지원 이유가 없으면 추측하지 않고 묻는다.

## 공직관

본인이 중요하게 여기는 가치 → 그 이유 → 관련 경험과 실천 근거를 연결한다. 관련 경험은 최소 1개를 확인하며, 일반적인 공직 가치를 학생의 신념으로 대신 정하지 않는다.

## 생성 후 확인

- 자기소개는 서로 다른 경험 최소 3개가 실제 본문에 있으며, 각 경험에 근거가 있는지 확인한다.
- 생성기·서버 JavaScript·DB 검증에서 1~2개 경험, 같은 경험의 중복, 같은 본문 구절의 중복, 근거가 없는 경험, 본문에서 빠진 경험을 거부한다.
- 기존 학생 답변과 이전 초안은 보존한다. 운영 반영 후에는 학생이 ‘다시 만들기’를 눌러 새 지침으로 생성한다.

수정안은 별도 작업 폴더에서 검증한다. 운영 적용에는 DB 검증·생성기 지침 묶음·생성기 프로세스·웹 안내를 함께 갱신해야 한다.

검증: JS·DB·Python의 경험 수·중복·본문 누락·근거 검사를 통과했다. 가상 학생 자료를 실제 CLI로 1회 생성하여 631자 본문에 조별 과제·안내 봉사·학습 모임의 서로 다른 경험 3개가 포함되고 학생 조회까지 이어짐을 확인했다. 운영 학생 자료를 사용하거나 운영 학생 대신 생성하지 않았다.
