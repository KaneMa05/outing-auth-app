# 취약단원 · 과거 오답 이력 개선 기획

작성일: 2026-09-23. 검토용 기획이며 앱 구현·운영 데이터 변경·푸시·배포는 포함하지 않는다.

> 최신 방향: 사용자 의도를 재확인한 [취약 이력 유지 기획](ox-weakness-history-direction-20260923.md)을 따른다. 아래 내용은 초기안이며, HTML 시안은 최신 방향으로 수정했다.

## 1. 목표와 현재 문제

오답을 다시 맞혀 현재 정답률이 100%가 되어도, 어느 단원에서 어떤 문항을 틀렸는지 확인하고 다시 풀 수 있게 한다. 학습 성취와 과거 오답을 함께 보여준다.

로컬 코드 확인 결과:

- `criminal-law-ox.js`의 `chapterStat`은 문항별 마지막 답변으로 정답률을 계산한다. 모두 다시 맞히면 100%·양호가 되는 것은 현재 산식에 따른 동작이다.
- 같은 파일의 `stats`는 개인별 누적 오답 횟수인 `wrong_count`를 읽는다. 최신 답변이 정답이어도 과거 오답 여부를 식별할 수 있다.
- 오답노트는 복습 완료로 표시한 문항을 제외한다. 화면의 ‘오답 삭제’는 실제 풀이 삭제가 아니라 `mastered` 변경이다. 따라서 완료한 오답을 다시 찾는 경로가 필요하다.
- 로컬 마이그레이션에는 개별 풀이를 저장하는 `ox_attempts`와 최초 풀이 표시가 있다. 운영 기록의 완전성은 아직 확인하지 않았으므로 최초 정답률·전체 풀이 이력의 복원 가능성을 확정하지 않는다.

## 2. 적용 범위

형사법 OX의 취약단원과 연결된 오답노트를 대상으로 한다. 현재 OX 이용 권한이 있는 수강생에게 동일한 규칙을 적용하는 안이다. 오프라인·온라인 관리반·인터넷 수강생의 기존 홈과 하단 탭, 교사·관리자 화면은 변경 범위에 포함하지 않는다.

## 3. 핵심 설계

### 현재 상태와 이력을 함께 표시

기존 ‘정답률’의 이름을 **현재 정답률**로 명확히 한다. 설명은 ‘풀어본 문항의 마지막 답변 기준’으로 한다. 정답률과 기존 취약도 기준은 유지하고, 단원마다 아래 이력을 추가한다.

| 표시 항목 | 정의 | 복습 후 변화 |
| --- | --- | --- |
| 현재 정답률 | 최신 정답 문항 수 / 풀어본 서로 다른 문항 수 | 다시 맞히면 상승 |
| 틀린 적 있는 문항 | 누적 오답 횟수가 1회 이상인 서로 다른 문항 수 | 다시 맞혀도 유지 |
| 아직 틀린 문항 | 마지막 답변이 오답인 문항 수 | 다시 맞히면 감소 |
| 다시 맞힌 문항 | 틀린 적 있고 마지막 답변은 정답인 문항 수 | 다시 틀리면 감소 |
| 반복 오답 문항 | 누적 오답이 3회 이상인 문항 수 | 현재 정답이어도 이력 유지 |

‘틀린 적 있는 문항 = 아직 틀린 문항 + 다시 맞힌 문항’이 성립한다. 반복 오답은 이 중 일부로 별도 합산하지 않는다. 같은 문제를 4번 틀리면 ‘1문항 · 누적 오답 4회’로 구분한다.

단원 등급이 실제로 취약했던 기록을 검증하기 전에는 ‘과거 취약단원’이라고 단정하지 않고 **오답 이력 있는 단원**이라고 표현한다.

### 취약단원 화면

상단에 `현재 상태` / `오답 이력` 보기를 제공한다. 기본은 현재 상태이며, 오답 이력 보기에는 현재 100%인 단원도 포함한다.

- 현재 상태: 기존 취약도 정렬을 유지하고 각 행에 과거 오답 문항 수를 보조 표시한다.
- 오답 이력: 틀린 적 있는 문항이 1개 이상인 모든 단원을 표시한다. 기본 정렬은 반복 오답 문항 수 → 틀린 적 있는 문항 수 내림차순 → 기존 목차 순서다. 이를 별도의 실력 점수로 표현하지 않는다.
- 상단 요약: `오답 이력 N단원 · 틀린 적 있는 M문항 · 아직 틀린 K문항`.
- 최소 풀이 수에 못 미쳐 취약도가 미측정이어도 오답 이력은 보여준다. 미측정 단원의 등급·현재 정답률 표시는 기존 정책을 유지한다.
- 현재 정답률 옆에는 `20 / 50문항 학습`처럼 학습 범위를 함께 표시한다. 100%를 단원 전체 학습 완료로 오해하지 않게 한다.

표시 예시 — 실제 사용자 기록이 아닌 설명용 수치:

```text
형법의 적용범위                       현재 정답률 100% · 양호
20 / 50문항 학습
틀린 적 있는 8문항 · 다시 맞힘 8문항 · 아직 틀림 0문항
반복 오답 2문항
[이전 오답 8문항 보기]                 [이전 오답 다시 풀기]
```

모두 맞힌 경우: ‘현재 남은 오답은 없어요. 이전에 틀렸던 8문항은 다시 확인할 수 있어요.’

### 단원에서 문항까지 이어지는 동선

`취약단원 → 오답 이력 → 단원 선택 → 해당 단원의 과거 오답 목록 → 다시 풀기`.

- 단원에서 진입하면 해당 단원 필터가 적용되고 선택한 단원명이 보인다.
- 목록 필터: `전체 이력 / 아직 틀림 / 다시 맞힘`. `반복 오답만`을 추가 조건으로 제공한다.
- 카드 표시: 단원·문항 번호·지문·누적 오답 횟수·현재 상태·복습 완료 여부.
- 다시 풀기에서는 기존과 같이 정답·해설을 숨기고 제출 뒤 공개한다.
- 모아 풀기는 화면에 적용된 단원·상태·반복 오답 조건과 정확히 같은 대상을 사용한다. 대상이 없으면 실행하지 않는다.
- 목록으로 돌아오면 단원과 필터를 유지한다.

### 오답노트의 완료와 이력 분리

- ‘오답 삭제’를 **복습 완료**로 변경한다. 안내: ‘복습 목록에서 정리하며, 오답 이력은 남아요.’
- 기본 복습 목록은 기존처럼 완료하지 않은 문항을 보여준다.
- `전체 이력 보기`에서 복습 완료 문항까지 조회하고 완료 표시를 취소할 수 있게 한다.
- 정오답 상태와 복습 완료 여부는 독립적으로 표시한다. 완료했어도 마지막 답이 오답이면 ‘아직 틀림’ 집계에 포함한다.
- 한 번 맞혔다고 자동으로 복습 완료나 완전 숙달로 판정하지 않는다.
- 복습 완료 이후 다시 틀리면 완료를 해제하고 복습 목록에 다시 표시한다. 누적 횟수·메모·북마크는 유지한다.
- ‘복습할 오답’과 ‘틀린 적 있는 문항’은 서로 다른 집계임을 명칭으로 구분한다. 과거 이력 때문에 홈의 복습 알림 수를 늘리지 않는다.

## 4. 단계별 개발안

### 1차 — 기존 기록으로 핵심 문제 해결

현재 제공되는 문항별 최신 정오답·누적 오답 횟수·완료 여부를 활용한다.

1. 취약단원에 현재 정답률과 과거 오답 문항 수를 함께 표시한다.
2. 오답 이력 보기를 추가하고 단원별 문항 목록·재풀이로 연결한다.
3. 복습 완료 문항의 이력 조회와 완료 취소를 제공한다.
4. ‘오답 삭제’ 문구를 ‘복습 완료’로 정리한다.

과거 이력 전체를 최초 화면에서 내려받지 않는다. 기존 요약을 활용하고 문항 상세는 현행 지연 로딩 방식에 맞춰 조회한다. 새 데이터 필드 필요 여부는 구현 시 실제 응답 구조로 최종 확인한다.

### 2차 — 최초 실력과 변화 과정 확인

운영 풀이 기록을 검증한 뒤 별도 적용한다.

- `첫 풀이 정답률 60% → 현재 정답률 100%` 표시. 같은 문항 집합·같은 문항 버전 기준으로 비교한다.
- 최초 정답률은 각 문항 최초 제출 1건으로 계산한다. 새 문항을 처음 풀면 집합이 늘어나므로 단원 수치가 달라질 수 있다.
- 문항별 날짜·제출 답·정오답 이력과 마지막 오답일을 제공한다. 최초 상세 열기 시 조회하며 많은 기록은 나누어 불러온다.
- 기록이 불완전하면 ‘첫 풀이 기록 부족’으로 표시한다. 현재 답변으로 과거 값을 추정하지 않는다.
- 모든 재풀이를 섞은 누적 정답률은 대표 지표로 쓰지 않는다. 특정 문제의 반복 횟수가 전체 수치를 과도하게 좌우하기 때문이다.

## 5. 데이터와 예외 처리

- 1차 집계 범위는 현재 이용 가능한 공개 문항의 현재 버전이다. UI 측정 기준에도 이를 명시한다.
- 문항의 정답·내용 버전이 바뀌면 이전 버전 오답을 새 버전 통계와 합치지 않는다. 이전 버전 기록 열람은 2차 이후 별도 범위로 검토한다.
- 비공개·이용 권한 종료 문항은 기존 접근 제어를 그대로 적용한다. 과거 기록을 이유로 정답·해설 접근을 열지 않는다.
- 기록이 없으면 ‘아직 오답 이력이 없어요’로 표시하고 단원 학습으로 연결한다. 조회 실패를 이력 0건으로 표현하지 않는다.
- 재풀이 성공 응답 후 최신 상태와 누적 횟수를 함께 반영한다. 제출 중복·재시도로 횟수가 늘어나지 않는 기존 처리를 보존한다.
- 개인 이력 조회는 본인 기록만 반환한다. 전체 수강생 오답률과 개인 누적 오답은 서로 다른 지표로 유지한다.

## 6. 완료 기준과 적용 순서

핵심 검증 시나리오:

1. 20문항 중 8문항을 틀린 뒤 모두 맞히면 현재 100%, 틀린 적 있는 8, 다시 맞힘 8, 아직 틀림 0으로 보인다.
2. 그 8문항을 모두 복습 완료해도 오답 이력에서 조회·재풀이가 가능하다.
3. 같은 문항을 3번 틀리면 이력 1문항·누적 3회이며, 다시 맞혀도 반복 오답 이력은 유지된다.
4. 완료 문항을 다시 틀리면 아직 틀림으로 이동하고 복습 목록에 복귀한다.
5. 2문항만 푼 단원도 오답 이력을 확인할 수 있으며 취약도는 기존 기준에 따라 미측정이다.
6. 새로고침·재로그인 후에도 이력과 완료 상태가 유지된다.
7. 필터의 문항 수와 모아 풀기 대상이 일치하고, 권한 없는 문항이 포함되지 않는다.
8. 세 수강생 유형에서 OX 진입·풀이·돌아가기가 정상이며 기존 홈·다른 탭·교사·관리자 화면에 영향이 없다.

구현은 승인된 원본 템플릿과 `scripts/build-ox-learning.py` 생성 경로를 따라 진행한다. 생성물인 `criminal-law-ox.js`만 단독 수정하지 않는다. 로컬 화면 검토와 관련 검증·빌드를 완료한 후 변경 내용을 제시하며, 푸시·배포는 사용자의 최종 확인 뒤 진행한다.

권장 착수 범위는 1차 전체다. 별도 점수체계나 자동 복습 일정 없이도 ‘100%가 되면 과거 오답을 찾을 수 없는 문제’를 해결할 수 있다.
