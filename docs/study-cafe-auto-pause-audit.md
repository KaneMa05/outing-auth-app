# 스터디카페 자동 일시정지 모달 점검

점검일: 2026-09-08

범위: 로컬 `app.js`, `styles.css`, `api/study-cafe.js` 및 관련 테스트. 운영 서버 로그와 실제 모바일 기기에서는 재현하지 않았다. 이번 작업은 점검과 수정 설계이며 앱 동작 코드는 변경하지 않았다.

## 결론

모달 누락으로 이어질 수 있는 자동 정지 처리 결함을 모의 실행으로 확인했다. 전체화면 전용 결함은 아직 확인하지 못했으며, 일반 화면과 전체화면이 같은 취약한 생명주기 로직을 사용한다.

현재 기준은 `STUDY_CAFE_AUTO_PAUSE_DELAY_MS = 30 * 1000`이고 최초 이용 안내도 30초다(`app.js:409`). 사용자가 기억하는 15초와 다르므로 운영 배포본과 요구 기준을 확인해야 한다. 이번 점검에서 시간을 변경하지 않았다.

## 확인한 문제

### 1. 자동 정지 실패 후 복구 조건 소실 — 우선 수정

- `scheduleStudyCafeAutoPause`는 요청 결과를 받기 전에 `studyCafeAutoPauseDeadline`을 0으로 만든다(`app.js:9556`).
- `pauseStudyCafeTimer`는 서버 요청 실패 시 실행 상태로 복구하고 자동 정지 실패 알림을 생략한다(`app.js:9638`).
- 복귀 처리에서는 deadline이 남아 있어야 `reconcileStudyCafeAfterBackgroundAutoPause`를 실행한다(`app.js:2641`).
- 결과: 네트워크 실패 후 복귀해도 일반 조회만 예약하고, 자동 정지 재시도와 모달 표시를 놓칠 수 있다.
- 다른 타이머 요청이 진행 중이라 정지를 건너뛰거나, `pagehide` 즉시 정지 요청이 실패한 경우에도 같은 문제가 재현된다.

### 2. 지연된 타이머와 복귀 이벤트 순서에 따라 정지 누락 — 우선 수정

- 백그라운드에서 지연된 콜백이 앱 복귀 후 실행되면 먼저 deadline을 지운다.
- 이어서 화면이 보이고 포커스가 있다는 이유로 정지를 건너뛴다.
- 이후 `focus`/`visibilitychange` 처리도 deadline이 없어 초과 이탈을 인식하지 못한다.
- 같은 10분 이탈에서도 복귀 이벤트가 먼저 실행되면 재확인을 요청하고, 타이머 콜백이 먼저 실행되면 정지가 누락되는 차이를 모의 실행으로 확인했다. 실제 기기에서 이 순서가 발생하는 빈도는 미확인이다.

백그라운드 페이지가 동결되면 타이머와 fetch 콜백이 실행되지 않을 수 있다. 따라서 백그라운드 타이머가 정해진 초에 실행된다는 전제로 설계하면 안 된다. 근거: [Chrome Page Lifecycle API](https://developer.chrome.com/docs/web-platform/page-lifecycle-api).

### 3. 중복 이탈 이벤트가 기준 시각을 뒤로 미룸

`blur`와 `visibilitychange(hidden)`가 모두 새 deadline을 설정한다. 첫 이탈 후 10초 뒤 두 번째 이벤트가 발생하는 조건에서는 정지 기준도 10초 뒤로 밀리는 것을 확인했다. 최초 이탈 시각을 유지해야 한다.

### 4. 장시간 이탈 시 좌석 종료와 안내가 어긋날 수 있음

- 서버는 실행 상태의 마지막 heartbeat가 2분 넘게 오래되면 다음 API 요청의 정리 과정에서 세션을 종료하고 공용 좌석을 비운다(`api/study-cafe.js:29`, `:73`, `:975`). 정확히 2분에 실행되는 예약 작업은 아니다.
- 정지/착석 상태에는 별도로 약 15분 유예가 적용된다. 실행 중 세션의 비정상 종료 시간은 마지막 heartbeat + 최대 30초로 제한하는 보정이 이미 있다.
- 복귀 재확인 경로는 이전 좌석이 사라지면 좌석 종료 모달을 띄우지만, 안내 문구는 항상 “타이머가 15분 동안 정지”로 고정돼 있다(`app.js:2672`, `:9929`). 연결 끊김으로 종료된 경우 실제 원인과 다르다.
- deadline이 소실되어 일반 조회 경로로 들어가면, 이전 로컬 상태가 실행 중인 경우 기존 idle 판정이 실패해 좌석 종료 안내도 빠질 수 있다(`app.js:2455`, `:9921`). 이 항목은 코드 경로 분석 결과다.

### 5. 모달 표시가 서버 응답에 종속됨

정지 요청 성공 후에만 모달이 표시된다. fetch에 애플리케이션 수준의 제한 시간이 없어서 연결이 오래 지연되면 화면은 정지로 바뀌어도 모달과 조작 가능 상태가 늦게 돌아올 수 있다(`app.js:2018`, `:9638`). 응답을 못 받았다는 사실만으로 서버 저장도 실패했다고 단정할 수는 없다.

## 전체화면 점검

- 앱의 전체화면은 CSS 고정 화면이며 해당 함수에서 브라우저 Fullscreen API를 호출하지 않는다(`app.js:7755`).
- 전체화면은 z-index 80, 자동 정지 모달은 body 아래에 추가되는 z-index 210이다(`styles.css:4565`, `:14397`). 단순 z-index 역전은 발견하지 못했다.
- 모의 실행에서 정지 요청 성공 시 일반 화면과 전체화면 모두 모달 표시 함수가 한 번 호출된다. 실제 화면의 렌더링·터치·포커스까지 검증한 결과는 아니다.
- 화면만 강제로 닫거나 z-index만 올리는 수정으로는 위 누락 원인을 해결하지 못한다.

## 권장 수정 설계

1. 최초 이탈 시각, deadline, 대상 학생/세션, 정지 확인 대기를 별도 상태로 관리한다. 중복 이벤트로 deadline을 연장하지 않는다. 실제 세션 식별자를 클라이언트에 유지하도록 한다.
2. 타이머 콜백과 복귀 이벤트를 하나의 처리 함수로 합친다. 현재 포커스보다 실제 이탈 시간 초과 여부를 먼저 판단한다. 정지 확인 또는 해당 세션 종료 확인 전까지 복구 정보를 지우지 않는다.
3. 다른 타이머 작업 진행 중이면 정지 확인을 대기시켰다가 작업 종료 후 수행한다. 복귀 조회·heartbeat·정지 요청의 경합을 막고 같은 복구 작업은 하나만 실행한다. 오래된 요청이 새 과목/세션에 적용되지 않도록 검사한다.
4. 실패 시 자동 정지 의도를 유지하고, 복귀·온라인 연결 회복 시 서버를 다시 확인한다. 재시도는 제한된 간격으로 수행하고 요청 ID/세션 ID 기반 중복 처리를 지원한다.
5. 모달을 “정지 확인 중 / 정지 완료 / 저장 확인 필요 / 좌석 종료” 상태로 표시한다. 서버 확인 전에 저장 성공을 단정하지 않으며, 확인 중에는 재개와 종료가 중복 실행되지 않게 한다. 전체화면에서도 같은 상태를 표시한다.
6. 장시간 이탈 후 서버가 세션을 종료했다면 재개 버튼을 표시하지 않고 종료 사유에 맞는 안내를 제공한다. 모달 표시 대기와 종료 결과는 서버 최신 상태와 함께 조정한다.
7. 페이지 폐기·재실행 대응을 위해 최소 복구 정보를 세션 저장소에 보존하되 서버 상태를 최종 기준으로 삼는다. 로그아웃·학생 변경·세션 종료 시 정리하며, 저장소가 없어도 서버 조회로 복구한다.
8. 공부 시간 보정은 서버에서 별도로 검증한다. 현재 정상 pause API는 요청을 처리한 서버 시각으로 시간을 계산하므로 지연 요청은 이탈 시간을 더 포함할 수 있다(`api/study-cafe.js:420`). 서버가 검증하는 이탈 기준 시각이나 만료 시각을 설계하고, 클라이언트 시각을 무조건 신뢰하지 않는다. 기존 heartbeat 종료 보정은 보존한다.

우선 1~6과 회귀 테스트로 모달 누락을 막고, 7~8로 재실행과 시간 기록까지 보강하는 순서가 적절하다. 시간 기준을 15초로 변경할지는 오류 수정과 별도로 결정한다. 범위는 스터디카페 이용 화면이며 오프라인 수강생·교사·관리자 화면은 변경 대상에 포함하지 않는다.

수정 후에는 위 실패 시나리오가 모두 복구되는지 검증하고, iPhone Safari/설치 앱 및 Android Chrome/설치 앱에서 일반·전체화면, 기준 직전/직후 복귀, 2분/15분/1시간 이탈, 화면 잠금, 통신 차단·회복, 앱 폐기 후 재실행, 공용/사용자 스터디방을 확인한다. 모달 중복, 재개·종료 중복, 공부 시간 과다 집계, 만료 좌석 재개가 없어야 한다.

앱 소스·운영 데이터 변경, 푸시, 배포는 수행하지 않았다. 빌드는 설정 파일 생성 작업이므로 점검만 수행한 이번 작업에서는 실행하지 않았다.

## 2026-09-09 추가 점검: 외부 앱에서 복귀 시 오류 안내

사용자가 보고한 오류의 정확한 문구·기기·진입 방식은 아직 확인되지 않았다. 아래는 다른 앱에서 기존 화면으로 복귀하는 흐름에 대한 추가 검증이며, 사용자가 본 오류와 동일하다고 확정한 결과는 아니다.

### 새로 재현한 문제

`reconcileStudyCafeAfterBackgroundAutoPause`와 `pauseStudyCafeTimer`의 실제 코드를 Node VM에서 실행하고 서버 조회와 이벤트 조건을 모의 구성했다.

| 조건 | 현재 결과 | 문제 |
| --- | --- | --- |
| 서버 조회 성공, 다른 타이머 요청 진행 중, 실행 상태 유지 | 조회 2회, 정지 요청 0회, “타이머 상태를 확인하지 못했습니다. 인터넷 연결을 확인한 뒤 다시 시도해주세요.” 표시 | 요청 진행 중을 연결 문제처럼 안내함 |
| 서버 조회 실패, 로컬 상태는 이전의 paused | 자동 일시정지 모달 표시 | 최신 상태 확인 실패를 무시하고 오래된 상태로 정지 완료를 안내함 |
| 서버 조회와 정지 요청 모두 실패 | 같은 인터넷 연결 확인 안내 표시 | 실제 연결 실패와 작업 경합을 같은 문구로 처리함 |

첫 번째 조건은 아직 진행 중인 타이머 작업이 로컬 상태를 바꾸기 전 등의 상황을 가정한다. 모든 타이머 작업에서 항상 발생하는 것은 아니다. 서버 조회 응답 자체가 아니라 모의 조회 성공을 사용했으므로 운영 발생 빈도는 확인하지 않았다.

복귀 함수는 `ensureStudyCafeRemoteLoaded()`의 반환값을 확인하지 않는다(`app.js:2676`, `:2694`). 조회 성공 여부, 작업 진행 여부, 서버에서 확정한 상태를 구분하도록 수정해야 한다. 진행 중인 작업을 기다린 뒤 다시 확인하고, 재확인 실패 시에는 “연결 확인 중/상태 확인 필요”로 표시하며 재개를 허용하지 않는 편이 적절하다.

### 인증 및 공통 새로고침 점검

- 공통 복귀 새로고침과 스터디카페 복구가 별도 이벤트 처리로 실행된다(`shared.js:850`, `:1317`, `app.js:2641`). 공통 새로고침에는 지연 호출 병합이 있지만, 스터디카페 복구와 공유하는 완료 대기 처리는 없다.
- 공통 자동 복귀는 `forceDeviceValidation: true`를 사용하며 일반 수동 새로고침의 `force: true`는 사용하지 않는다. 따라서 일반적인 자동 복귀 조회 실패만으로 “새로고침 중 오류가 발생했습니다”를 표시하는 흐름은 아니다(`shared.js:1241`).
- 기기 검증은 네트워크 실패나 일반 서버 오류로 로컬 인증을 지우지 않는다. HTTP 403과 `device_not_active`가 함께 반환될 때 등록을 해제한다(`shared.js:1630`). 장시간 외부 앱을 썼다는 이유만으로 인증 만료라고 단정할 근거는 발견하지 못했다.
- 스터디카페 조회의 “현재 기기 인증이 만료되었습니다. 다시 등록해주세요.”는 `device_not_active` 응답 분기에서 표시된다(`app.js:2388`). 실제 오류가 이 문구라면 타이머 수정과 별개로 해당 인증 응답 원인을 확인해야 한다.

추가 실행한 기존 테스트 `refresh-safety`, `student-device-client`, `study-cafe-ui`, `student-wake-lock`은 모두 통과했다. 이번 추가 점검에서도 앱 코드는 수정하지 않았다.

## 2026-09-09 로컬 수정: 모달 누락·타이머 조작 불가·좌석 소실 안내

앞의 절들은 수정 전 점검 기록이다. 사용자가 좌석을 점유한 상태에서 시작·정지가 모두 동작하지 않고 좌석이 갑자기 비워진다고 구체화한 뒤 아래 수정을 적용했다.

### 적용 내용

- 스터디카페와 스터디방 요청에 12초 대기 제한을 적용했다. 응답 본문 읽기도 제한에 포함하며, 복귀 시 실제 경과 시각으로 만료 요청을 정리한다. 오래된 요청이 조작 잠금을 계속 유지하거나 늦은 응답이 로컬 타이머 상태를 다시 덮어쓰는 것을 방지한다.
- 최초 이탈 시각을 유지하고, 복귀·지연 타이머·온라인 연결 회복을 하나의 복구 흐름으로 처리한다. 자동 정지 실패 시에도 복구 의도를 유지한다.
- 복귀 즉시 전체화면 위에 상태 확인 모달을 표시한다. 기존 요청이 끝난 뒤 새 서버 조회로 정지 여부를 확인하고, 확인된 경우에만 재개·종료 선택지를 표시한다. 이미 종료된 과목은 전체화면을 닫고 과목 선택을 안내한다.
- 확인 실패 시 재시도와 ‘나중에 확인하기’를 제공한다. 자동 재확인은 한 번의 복귀에서 최대 3회로 제한하고, 안내를 닫으면 자동 재시도를 멈춘다. 타이머를 다시 조작하거나 앱에 복귀하면 재확인을 수행한다.
- 진행 중인 타이머 작업 또는 미확인 복구 상태에서는 로컬 15분 자동 반납과 주기적인 heartbeat가 복구 흐름과 경합하지 않도록 했다.
- 공용 좌석과 사용자 스터디방 좌석이 서버에서 종료된 경우 안내를 표시한다. ‘15분 정지’ 안내와 서버에서 확인한 좌석 종료 안내를 구분한다. 오래된 스터디방 조회 응답은 진행 중이거나 이후에 수행한 타이머 작업을 덮어쓰지 않는다.
- 학생 앱의 스크립트 URL과 서비스 워커 캐시 버전을 갱신했다. 이 변경의 설치 앱 반영은 실제 배포 이후에 이루어진다.

### 검증

- `tests/study-cafe-lifecycle.test.js`: 25개 실행 테스트 통과. 일반·전체화면, 이벤트 순서 역전, 통신 실패, 응답 본문 지연, 늦은 응답, 잠금 해제, 공용·사용자방 만료, 실제 조회 함수와 snapshot 반영, 중복 모달, 재개, 재시도 제한 등을 검증했다. 서버 응답·시계·DOM은 모의 구성했다.
- `npm test`: 전체 통과. 새 생명주기 테스트를 기본 테스트 명령에 포함했다.
- 프로젝트 `build-config.js`를 별도 임시 디렉터리에서 테스트용 설정으로 실행해 통과했다. 작업 폴더의 기존 `config.js`는 보존했다.
- `app.js`, `sw.js` 구문 검사 통과.
- 브라우저 연결 도구에 사용 가능한 브라우저가 없어 실제 렌더링·모바일 전환 동작은 검증하지 못했다. 배포 전 실기기 확인이 필요하다.

### 범위와 남은 제한

서버 코드·DB·운영 데이터·기존 만료 정책은 변경하지 않았다. 서버 heartbeat가 오래 끊기면 기존 정책에 따라 좌석이 종료될 수 있으며, 이번 수정은 그 경우를 조용히 누락하지 않고 안내한다. 세션 저장소를 통한 앱 프로세스 폐기 후 복구와 서버 측 지연 요청의 원자성·시간 보정은 이번 수정에 포함하지 않았다.

동시에 추가된 과목 설정 관련 변경은 보존했다. 이번 작업에서 푸시·배포는 수행하지 않았다.
