iPhone 테스트앱과 Windows CLI 음성 분석 연결

변경 범위
일반 웹·정식 iOS 앱의 세 모드는 계속 ‘준비 중’이다.
Debug iPhone 테스트앱의 승인된 계정만 전공/인성/AI 연습을 연다.
준비된 질문 음성파일을 재생하고, 답변 WAV를 비공개 저장소에 올린다.
Windows CPU에서 faster-whisper small 한국어 전사 후 기존 ChatGPT CLI로 학습 피드백을 만든다.
실시간 자막·대화형 꼬리질문은 이 녹음 후 분석 경로에서 제공하지 않는다.
공식 성적/OX 판정은 만들지 않으며 기존 검토 기준을 사용하는 전공 시험 경로는 변경하지 않는다.
답변 전송 동의를 받으며 전사문이 CLI로 전송된다는 사실을 알린다.

운영 반영 순서 (푸시·배포는 AGENTS.md에 따른 최종 승인 후)
1. 20261104053835_iphone_practice_cli.sql 적용. 기존 CLI 큐·운영 상태 마이그레이션 이후 적용한다.
   이어서 20261104060123_iphone_practice_unlimited_retention.sql을 적용한다.
2. 서버 INTERVIEW_PRACTICE_CLI_ENABLED=true만 추가한다.
   기존 전용 worker token, ChatGPT 로그인, job/personality ENABLED·AUDIO_READY는 바꾸지 않는다.
3. 검증한 서버 코드를 배포하고 일반 앱 세 모드의 준비 중 상태를 다시 확인한다.
4. Windows의 기존 작업기 저장소에서 아래 명령을 실행한다. 임시 설정 폴더를 지우지 않는다.
5. Debug iPhone 앱 빌드·설치 후 실제 답변의 전사·결과 수신을 확인한다.

Windows PowerShell (기존 프로젝트 폴더에서 실행)
git pull --ff-only
if ($LASTEXITCODE -ne 0) { throw '코드 업데이트 실패: 기존 변경을 보존하고 확인이 필요합니다.' }
node scripts/interview-windows-stt-setup.cjs
if ($LASTEXITCODE -ne 0) { throw '음성 인식 설치 실패: 기존 작업기는 보존됩니다.' }
node scripts/interview-mock-worker-control.cjs restart
if ($LASTEXITCODE -ne 0) { throw '재시작 보류: 표시된 사유를 확인해주세요.' }
node scripts/interview-mock-worker-control.cjs connect
node scripts/interview-mock-worker-control.cjs status

설치는 Python 가상환경과 약 500MB의 공개 모델을 한 번 내려받는다.
faster-whisper 1.2.1, Systran/faster-whisper-small 고정 커밋을 사용한다.
공개 한국어 질문 파일로 실제 전사를 통과해야 설정을 저장한다. 이후 음성 인식은 오프라인이다.
두 전사 패스는 같은 인식기의 설정을 달리한 결과이며 서로 다른 엔진의 독립 검증을 뜻하지 않는다.
원하는 Python/CLI 경로는 기존 config.json을 유지한다. .tmp/interview-mock-control/token.dpapi는 현재 Windows 사용자 전용이다.
토큰·API 키·DB 키를 채팅에 붙여 넣을 필요가 없다.

재시작 보호
서버 대기열을 최대 5분만 잠시 정지하고, 진행 중 작업이 있으면 종료하지 않는다.
worker_busy_retry_after_completion이면 기존 분석 완료 후 restart 명령만 다시 실행한다.
미확인 started/result 영수증이 있으면 보존하고 점검을 요구한다.
PID와 실제 프로세스 명령줄이 기존 작업기인지 확인한 뒤, 유휴 작업기만 종료한다.
그 프로세스에 속한 잠금만 해제하고 새 작업기를 시작한다. 기존 토큰을 갱신하지 않는다.
CLI 로그인과 음성 모델 실제 로딩 검사가 통과해야 음성 처리 준비 상태를 보고한다.

보관과 재조회
기기에는 요청 UUID·원본 질문·녹음이 저장된다. 전송 응답이 끊겨도 같은 UUID로 복구한다.
접수 확인 후에는 결과만 조회하며, 실행 상태가 unknown/failed이면 AI를 자동 재실행하지 않는다.
앱 재실행 후 내 면접 기록 → 분석 결과 확인으로 조회를 재개한다.
학생 접근은 기존 모의면접 승인·계정/소유자 검사·이용 기간 검사를 모두 통과해야 한다.
로그인이 바뀌면 이전 계정의 녹음을 새 계정으로 업로드하지 못한다.
개인당 동시 대기·진행 작업 6개, 하루 9개 제한을 공유한다. 질문별 최대 녹음 85초다.
서버 녹음은 수강 만료일+31일 이후 조회를 차단한다. 종료일 없는 계정은 접수일+31일로 제한한다.
작업기 시작/유휴 루프에서 1시간 간격으로 만료 파일을 삭제한다. PC가 꺼져 있으면 다음 시작 때 정리한다.
Storage 삭제 실패 항목은 별도 GC 표에 남아 재시도하며, 삭제 확인 뒤에만 GC 기록을 지운다.
기기의 기록 삭제는 서버 저장 기간을 단축하지 않는다. 영상은 기기에만 남는다.

검증 범위
로컬 PostgreSQL(PGlite)에서 실제 마이그레이션·권한·접수·임대·전사 결과 저장·재조회·GC를 검증한다.
Windows 설치기 명령 구성과 실패 시 기존 암호화 토큰/설정 보존을 자동 검증한다.
실제 Windows 설치·한국어 인식 품질·iPhone 왕복 연결은 Windows 명령 실행 후 별도로 확인한다.

전공 연습 내용 분야·기출 지역 연결 보완
내용 분야 ID·명칭은 승인된 lib/interview-taxonomy.json을 사용한다.
분야 목록에는 등록 직렬의 공개 승인된 전체 기출문항에 실제 연결된 내용 분야만 표시한다.
공개 전·다른 직렬·분류 검토 대기·원문 변경 문항에만 있는 분야는 표시하지 않는다.
현재 원문·상위 분류와 일치하는 검토 완료 taxonomy의 주분야와 연관 분야를 선택 대상으로 연결한다.
지역은 수강생 직렬에 해당하는 원본 출처의 기출 지역을 사용한다(본청 포함).
공개 승인 및 등록 직렬 범위 안의 전체 문항을 500개씩 조회해 첫 30문항 한정 문제를 해소한다.
내용 분야와 기출 지역은 동시에 적용하며 결과가 0개이면 다른 문항으로 자동 대체하지 않는다.
연습 시작 전 권한·문항 재조회 시에도 선택 조건을 유지한다. 기존 음성파일과 분석 요청 방식은 유지한다.
일반 앱 준비 중 표시와 인성/AI 화면의 선택 UI는 변경하지 않는다.
