# 형사법 OX 운영 연결

2026-09-17: 기존 교사·관리자 화면과 수강생 앱에 저장 구조 및 관리자 등록 수강생 전용 접근을 배포했다. 운영 초기 상태는 학습 중지·등록 수강생 0명이다. [배포 및 검증 기록](../releases/20260917-study-share-ox-members.md).

## 이용 수강생 등록과 공개

- 공부 인증과 OX를 함께 배포하되 OX는 준비 중 상태로 유지한다. 공부 인증에는 OX 등록 조건을 적용하지 않는다.
- 관리자 사이트 → **형사법 OX 관리 → 이용 수강생 관리**에서 표시 대상을 **전체 수강생 · 등록하기**로 바꾸고 이름 또는 학생 ID로 검색한다. 해당 수강생의 **OX 등록**을 누른다. 기존 수강생 계정에 OX 권한만 부여하며 계정을 새로 생성하지 않는다.
- 준비가 끝나면 **등록 수강생 학습 시작**을 누른다. 학습 사용 중이면서 이용 등록된 활성 수강생에게만 홈 버튼이 표시되고 학습 API를 사용할 수 있다. 오프라인·온라인 관리반·인터넷 수강생에 동일하게 적용한다. 전체 공개 모드는 없다.
- **등록된 수강생** 필터로 이용자를 확인하고 **등록 해제**로 이용을 중지한다. 해제 후 시작되는 조회·답안 제출·메모 및 북마크 저장 요청은 서버에서 차단한다. 이미 받아둔 화면을 원격으로 지우지는 않으며, 풀이 기록·메모·북마크는 보존한다. 재등록하면 기존 기록으로 이어서 학습한다.
- **학습 사용 중지**는 등록 여부와 관계없이 모두 차단한다. 등록 목록은 유지된다. 비활성 계정이나 교사 계정은 이용할 수 없다.
- 수강생은 새로고침하거나 다른 탭에서 홈으로 돌아오면 변경된 버튼 표시를 확인할 수 있다. 홈의 반복 렌더링에는 최대 30초 상태 캐시를 사용하지만 실제 학습 요청은 매번 DB에서 등록 여부를 검사한다.
- 등록과 해제, 학습 시작과 중지는 `criminal_ox.write` 권한이 필요하다. `criminal_ox.read`만 있는 관리자는 목록을 조회할 수 있다.

## 로컬 확인

- 서버: PowerShell에서 `$env:PORT='3001'` 후 `node local-dev-server.js`
- 관리자: `http://localhost:3001/_local/admin-preview` → 형사법 OX 관리
- 수강생: `http://localhost:3001/#criminal-law-ox`
- 오늘 학습은 ‘단원 선택하고 시작’으로 단원 목록을 연다. 선택한 단원의 미풀이 문항을 순서대로 최대 10개씩 풀며, 남은 문항이 10개 미만이면 남은 수만 출제한다. 진행 중인 세트는 이어하기를 제공하며 단원 목록을 여는 것만으로 세트를 지우지 않는다. 오답 복습은 별도 바로가기로 연다.
- 오프라인 밝은 테마 시안: `http://localhost:3001/docs/criminal-law-ox-proposal/offline-theme-preview.html` (예시 기록만 사용). 실제 앱은 기존 수강생 유형의 테마를 자동으로 따른다. 밝은 테마의 OX 스타일은 `body:not(.student-online-mode) #criminal-ox-preview` 안에서만 적용한다.
- 로컬 저장: `.tmp/ox-learning-db` (PGlite). 운영 Supabase와 분리되며 브라우저 새로고침·서버 재시작 후 유지된다.
- 개발용 PGlite 0.5.8은 `C:/Users/Public/Documents/ESTsoft/CreatorTemp/ox-db-tools/node_modules/@electric-sql/pglite`에 설치했다. 다른 PC에서는 해당 패키지를 별도 설치하고 `OX_PGLITE_MODULE`에 경로를 지정한다.
- 원본 경로 변경 시 `OX_SOURCE_FILE`을 지정한다. 최초 초기화 시에만 가져오며 기존 관리자가 수정한 내용을 덮어쓰지 않는다.

## 문항 정책

- 2,960문항 전체를 관리자에게 제공한다. 원문 OX 2,533개와 기존 시안에서 문장 정리를 마친 파생 10개는 공개, 나머지 파생 417개는 검토 대기다. 이는 법률 전문가의 최신 법령·판례 검수 완료를 뜻하지 않는다.
- 관리자는 단원·지문·조건·정답·해설·공개 상태를 수정할 수 있다. 공개에는 검토 완료 표시가 필요하다. 삭제 대신 보관으로 전환하며 풀이 이력은 유지한다.
- 원본 문항 ID 및 원문은 보존한다. 문장·조건·정답·단원이 바뀌면 새 버전으로 학습한다. 해설만 고치면 기존 학습 진행을 유지한다.
- 단원 수는 현재 공개 문항만 센다. 검토 대기와 보관 문항은 수강생에게 노출하지 않는다.
- 단원 학습·단원 오답 재풀이·전체 재풀이는 한 번에 최대 10문항씩 진행한다. 중간 결과에서 다음 최대 10문항으로 이어지며 단원 진도는 누적한다. 남은 문항이 10개 미만이면 남은 만큼만 출제한다. 모든 공개 문항을 한 번씩 풀어야 1회독 완료다.
- 오답률은 해당 버전의 학생별 첫 답안으로 계산한다. 10명 미만은 집계 중으로 표시한다. 재풀이로 전체 오답률이 왜곡되지 않는다.
- 학생별 풀이, 최근 정답 여부, 누적 오답, 메모, 북마크, 복습 완료를 DB에 저장한다. 새로고침 후 단원은 미학습 문항부터 이어진다. 진행 중 10문항 세트 자체는 새로고침 시 재구성된다.
- 오답노트는 탭 구분 없이 다시 맞힌 문제까지 한 목록에 표시한다. ‘오답 삭제’는 기존 버전별 복습 완료 필드를 사용해 목록에서 제외하며 풀이 이력·메모·북마크를 보존한다. 다시 틀리면 자동으로 목록에 돌아온다.
- 최초 진입에는 공개 지문과 본인 진행 요약을 불러오고, 해설·메모 본문은 답안 제출 또는 오답 상세를 펼칠 때 해당 문항만 불러온다. 풀지 않은 문항의 해설 조회는 서버에서 차단한다.

## 운영 적용 순서 (최종 승인 후)

1. 운영 백업과 현재 마이그레이션 상태를 확인한다. 기존 DB의 `students.id`는 text, `is_active`는 boolean을 전제로 한다.
2. `supabase/migrations/20260917124608_criminal_law_ox.sql` 다음에 `supabase/migrations/20260917124623_criminal_law_ox_members.sql`을 적용한다. 두 번째 마이그레이션은 등록 목록을 생성하고 학습 스위치를 꺼짐으로 설정한다. 자동 등록은 하지 않는다. 기존 학생·성적 테이블 변경은 없다. 두 마이그레이션 모두 적용한 뒤 앱을 배포한다.
3. `node scripts/import-ox.cjs --source="원본 questions.json 절대경로"`로 가져오기 수량을 먼저 확인한다.
4. 승인된 서버 환경의 `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`로 같은 명령에 `--apply`를 추가한다. 100개씩 재실행 가능한 초기 가져오기이며 기존 ID는 덮어쓰지 않는다. 키를 브라우저나 소스에 넣지 않는다.
5. 앱 변경 배포 후 관리자에서 지문·정답·해설을 최종 검토한다. 이용할 수강생을 등록하고 ‘등록 수강생 학습 시작’을 누르면 등록된 수강생의 홈에만 진입 버튼이 나타난다. 검토 중에는 준비 중 상태를 유지한다.
6. 등록 계정과 미등록 계정으로 버튼 노출·직접 주소 접근을 각각 확인한다. 등록 계정의 답안, 재접속, 북마크, 메모, 교차 기기 기록과 등록 해제 후 차단을 점검한다. 이상 시 학습 사용 중지로 신규 접근·제출을 막을 수 있다.

서버는 기존 관리자 서명 세션 및 수강생 기기 인증을 사용한다. 문항/학습 테이블은 RLS와 명시적 권한으로 브라우저 직접 접근을 차단한다. API를 통해서만 공개 문항과 본인 기록을 제공하며 서버에서 채점한다. 별도 권한을 사용하는 계정은 `criminal_ox.read`, `criminal_ox.write`가 필요하고 관리자 `*` 권한은 그대로 동작한다.

학습 화면은 승인된 기존 시안 템플릿을 재사용한다. `scripts/build-ox-learning.py`는 실제 학습 번들에서 예시 문항·가짜 통계·시드 기록을 제거하고 서버 저장 처리로 교체한다. 생성 파일에는 전체 정답 데이터가 포함되지 않는다.

2026-09-17 등록 기능 검증: PGlite에서 운영 SQL과 API 권한 검사, 등록 전 차단·등록 후 허용·해제 후 차단·기록 보존, 목록 검색과 페이지 나누기, 브라우저 역할의 직접 접근 차단을 확인했다. 로컬 Chrome에서 실제 관리자 렌더러/API/SQL과 예시 수강생을 사용해 등록·해제 및 세 유형의 접근을 검증했다. 390px·1100px 화면을 확인했다. 운영 데이터는 사용하거나 변경하지 않았다.

전체 `npm test`는 Windows CRLF를 LF로 정규화한 별도 배포 브랜치에서 통과했다. 작업 폴더의 기존 `grade-ranking-groups.test.js`는 LF에만 맞춘 소스 추출 정규식 때문에 CRLF 파일에서 실패하므로 복사본에서 줄바꿈을 정규화해 검증했다. 운영 Supabase Advisor는 정보 수준의 RLS 정책 없음 안내만 반환했으며, OX 테이블 9개의 직접 접근 차단과 세 수강생 유형의 비공개 상태를 확인했다. 실제 수강생 등록과 공개는 관리자 운영 단계에서 진행한다.
