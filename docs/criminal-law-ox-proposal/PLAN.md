# 형사법 OX 서비스 기획안

작성일: 2026-09-16 · 상태: 검토용 기획 및 인터랙티브 시안

## 1. 제품의 방향

**“오늘 풀고, 틀린 지문을 다시 맞히고, 취약단원을 줄이는 형사법 OX.”**

형사법 수험생이 짧은 시간에도 학습을 이어갈 수 있는 모바일 중심 서비스다. 핵심 경험은 `단원 선택 → O/X 판단 → 원문 해설 확인 → 오답 재학습 → 취약도 개선`이다. 문제 수, 연속 출석, 랭킹보다 실제로 학습한 문항과 아직 해결하지 못한 오답을 앞에 둔다.

사용자가 확정한 출시 형태는 **기존 수강생 앱에 추가**다. 대상 앱은 `C:\Users\W11\Desktop\Coding\Codex_Project\outing-auth-app`이며, 데이터 프로젝트에는 별도 UI가 없다. 이번 산출물은 기존 앱에 추가할 화면의 기획·시안이고, 실제 앱 코드는 수정하지 않는다.

### 기존 앱에 들어가는 위치

수강생 홈의 학습 영역에 **형사법 OX** 카드를 추가한다. 진입 후에는 `오늘 학습 · 단원 · 오답 · 취약`을 OX 내부 상단 메뉴로 제공한다. 앱의 기존 하단 메뉴는 그대로 두며 새 전역 탭을 만들지 않는다. 문제 풀이 중에는 집중 화면으로 전환하고, 나가기 때 OX 화면으로 돌아온다. 상단 ‘수강생 홈’으로 기존 홈에 복귀할 수 있다.

화면 유형을 따로 지정하지 않은 현재 요청은 수강생 앱 전체에 제공하는 안으로 정리한다. 세 유형의 진입 위치를 구분하되 OX 본문은 공통으로 사용한다. 직렬별 이용 제한이 필요하다면 공개 대상 정책으로 별도 확정한다.

| 수강생 유형 | 제안 진입 위치 | 기존 하단 메뉴 |
|---|---|---|
| 오프라인 | 출석·외출 등 필수 행동 카드 다음, 학습 카드 영역 | 홈 · 출석 · 외출 · 성적 · 마이 |
| 온라인 관리반 | 스터디카페·기존 학습 안내 다음 | 홈 · 스터디카페 · 성적 · 마이 |
| 인터넷 수강생 (`lecture`) | 바로가기 영역 앞 학습 카드, 또는 바로가기 내 형사법 OX | 홈 · 플래너 · 스터디카페 · 마이 |

현재 `renderStudentHome()`과 `renderLectureStudentHome()`이 나뉘어 있어 공통 OX 진입 카드를 각 홈에 넣는 구조가 적합하다. 기존 형사법 커리큘럼에 ‘기출 분석 및 OX 학습’이라는 안내가 있으므로 보조 진입점을 둘 수 있지만, 커리큘럼 회차와 65개 단원의 대응표는 아직 없다. 문항을 풀었다는 이유만으로 기존 과제 완료·성적·보상·순공 시간을 자동 변경하지 않는다.

기존 로그인과 학생 ID를 재사용하고 OX 전용 가입을 요구하지 않는다. 교사·관리자 화면은 이번 사용자 경험 범위에 포함하지 않는다.

- 이번 검토는 데이터 구조와 화면 기획이다. 법령·판례의 최신성 검수 결과를 의미하지 않는다. 상용 공개 전 콘텐츠 기준일과 제공 범위를 확정하는 편집 검수 단계가 필요하다.

## 3. 사용자와 사용 장면

주 사용자는 형법·형사소송법을 학습하는 수험생으로 가정한다. 특정 시험 전용이라고 단정하지 않으며, 시험별 필터는 검증된 분류 데이터가 생긴 뒤 도입한다.

1. 첫 이용: 과목 선택 후 첫 단원에서 10문항 학습을 시작한다. 처음부터 취약하다고 표시하지 않는다.
2. 이동·쉬는 시간: 이전에 중단한 세트를 이어 풀거나 오늘의 10문항을 푼다.
3. 복습 시간: 반복해서 틀린 지문을 먼저 풀고 원문 해설과 메모를 확인한다.
4. 시험 전 정리: 취약단원의 최신 정답률과 학습률을 함께 보고 다음 공부할 단원을 정한다.

## 4. 화면 구성

OX 내부 상단 메뉴는 **오늘 · 단원 · 오답 · 취약**의 네 개다. 앱의 하단 메뉴와 역할을 분리한다. 프로필·계정 관리는 기존 마이 화면을 사용하고, 지문 크기는 OX 읽기 설정으로 둔다. 문제를 푸는 중에는 학습 화면에 집중하고, 나가기 후 돌아오면 같은 세트를 이어간다.

| 화면 | 가장 먼저 보여줄 내용 | 핵심 행동 |
|---|---|---|
| 오늘 | 이어풀기 또는 오늘의 10문항, 미완료 오답 수 | 오늘 학습 시작 |
| 단원 | 세 영역과 목차, 단원별 문항 수·학습률 | 단원 선택 후 풀기 |
| 문제 풀이 | 단원·출처, 맥락, 판단할 지문, O/X | 답 선택 |
| 채점·해설 | 내 답/정답, 원문 밑줄 해설, 북마크·메모 | 해설 확인 후 다음 |
| 세트 결과 | 이번 정답 수, 미응답, 새 오답, 다시 맞힌 오답 | 오답 다시 풀기 |
| 오답 | 반복 오답부터, 상태 필터, 정답·해설·메모 | 다시 풀기/복습 완료 |
| 취약 | 근거가 있는 취약단원부터, 정답률과 학습률 | 해당 단원 학습 |

### 오늘 학습의 선택 규칙 — 신규 제안

기본 세트는 10문항으로 시작하고 5·10·20문항을 설정할 수 있도록 한다. 시간은 사람마다 다르므로 검증 없이 “5분 완성”처럼 보장하지 않는다.

1. 진행 중인 세트가 있으면 이어풀기를 우선한다.
2. 없으면 미완료 오답을 최대 5문항 포함한다. 반복 오답 → 복습 필요 → 다시 맞힘 순서로 채운다.
3. 남은 문항은 선택한 과목의 취약단원 미학습 문제에서 가져오고, 부족하면 목차 순 미학습 문제로 채운다.
4. 그래도 부족하면 선택한 과목의 기학습 문제를 원문 순서로 채운다. 한 세트 안에 같은 문항을 중복 넣지 않는다.
5. 복습 완료 문항은 일반 재학습에는 포함할 수 있지만, “미완료 오답” 수나 우선 복습 대상에는 포함하지 않는다.
6. 대상 문항이 10개 미만이면 실제 개수로 시작하고, 0개이면 다른 단원 선택을 안내한다.

이 규칙은 기존 DB 기능이 아니라 앱에서 추가할 추천 정책이다. 시험 출제 확률이나 합격 가능성 예측으로 표현하지 않는다.

### 단원 학습

- 형법을 선택하면 `형법 총론 / 형법 각론` 범위 선택을 추가로 표시한다. `part_title`의 원문 목차 구분으로 필터링하며, 총론은 14단원·797문항, 각론은 28단원·889문항이다. 기존 형법 collection ID와 단원·문항 ID 및 원문 정렬은 유지한다. 수사·증거와 공판에는 이 범위 선택을 표시하지 않는다.
- 과목 아래 `part_title → chapter_title → section_title` 목차 계층을 활용한다.
- 기본은 원문 순서, 추가 선택은 미학습만·오답만·북마크만이다.
- 번호는 숫자로 정렬하고, 같은 번호는 원문 선택지 순서로 정렬한다. ID와 표시용 원문 번호는 그대로 유지한다.
- 문항 수가 많은 단원은 여러 세트로 나누고 이어풀기 위치를 저장한다.

### 풀이와 해설

- 한 화면에 판단할 지문 하나. 기본 본문 18px, 충분한 행간, 큰 O/X 터치 영역을 사용한다.
- 파생 문항의 `context`는 사례 조건을 포함할 수 있으므로 기본적으로 펼쳐 보여준다. 원문 질문과 O/X 지시를 시각적으로 구분한다.
- O/X를 누르면 저장 중 중복 입력을 막는다. 저장 성공 후 정오답과 해설을 보여준다. 실패하면 재시도하며 다음으로 넘어가지 않는다.
- 해설은 `explanation_html`을 사용하고 `u`만 허용한다. 원문 밑줄을 실제 밑줄로 표시한다. 검색·스크린리더에는 일반 `explanation`을 사용한다.
- 자동으로 다음 문항으로 넘기지 않는다. 명시적인 ‘다음 문제’로 읽는 시간을 보장한다.
- 같은 화면에서 답을 바꾸는 행위와 다시 풀기를 구분한다. 제출 후 답을 수정하지 않고, 재풀이는 새 풀이 기록을 추가한다.
- 북마크와 메모는 정답 여부와 독립적이다. 정답 문항도 따로 저장할 수 있다.
- 출처는 `원문 OX / 객관식 파생`, 문항 번호, 선택지, 파일명, 원본 PDF 페이지로 표시한다. PDF 페이지와 인쇄 쪽수를 혼동하지 않는다.

### 오답노트의 상태

화면 상단 필터는 **복습 필요 / 다시 맞힘** 두 개만 제공한다. 반복 오답은 복습 필요에 포함하되 문항의 배지와 누적 오답 횟수로 구분한다. 복습 완료 문항은 아래의 접힌 ‘복습 완료한 문항’ 영역에서 확인하고 완료를 취소할 수 있다. 모아 풀기도 화면에 표시된 대상과 동일한 규칙을 사용한다. 아래 네 가지 데이터 상태와 정렬 우선순위는 유지한다.

| 상태 | 조건 | 기본 순서 |
|---|---|---:|
| 반복 오답 | 최신 오답이고 누적 오답 3회 이상 | 1 |
| 복습 필요 | 최신 오답 | 2 |
| 다시 맞힘 | 과거 오답이 있으나 최신 정답 | 3 |
| 복습 완료 | 사용자가 완료 표시 | 4 |

완료 표시는 다른 상태보다 우선한다. 한 번 맞혔다고 자동 완료하지 않는다. ‘다시 맞힘’과 ‘복습 완료’를 구분한다. 완료 뒤 새로운 오답이 발생하면 완료를 해제하되 메모와 북마크는 유지한다. 과거 풀이가 늦게 동기화된 경우 시각을 비교해 잘못 해제하지 않는다.

오답 카드 요약에는 단원·지문·틀린 횟수·상태를, 펼친 상세에는 최근 답·정답·해설·메모·북마크를 표시한다. ‘다시 풀기’ 진입 시에는 정답과 해설을 감춘다. 완료 항목은 삭제하지 않고 별도 필터에서 볼 수 있다.

### 취약단원

- 정답률 = 풀이한 서로 다른 문항 중 **문항별 최신 답이 정답인 문항**의 비율.
- 학습률 = 한 번 이상 푼 서로 다른 활성 문항 / 해당 단원 활성 문항.
- 같은 문제 10회 풀이를 10문항 진도로 계산하지 않는다.
- 최소 서로 다른 5문항을 풀어야 등급을 판정한다. 5문항 미만인 단원은 전 문항 풀이 후 판정한다.
- 신규 사용자는 학습률 0%, 정답률 ‘미측정’, 등급 ‘데이터 부족’. 일부만 푼 경우 관측 정답률을 표시해도 등급은 표본 충족 전까지 데이터 부족으로 둔다.
- 50% 미만 매우 취약 / 50% 이상 70% 미만 취약 / 70% 이상 85% 미만 주의 / 85% 이상 양호.
- 등급 우선순위 → 취약점수 내림차순 → 과목·단원 순서로 정렬한다. 취약점수는 오답률 70% + 미학습률 30%이며, 새로운 능력 점수처럼 노출하지 않는다.
- 정답률·학습률 두 막대와 텍스트 등급을 함께 사용한다. 색상만으로 의미를 전달하지 않는다.
- 완료 버튼으로 정답률이 오르지 않는다. 새 정답 풀이가 있어야 실제 지표가 바뀐다.

## 6. 디자인 제안

사용자가 확정한 디자인 원칙은 **기존 앱의 디자인을 해치지 않는 것**이다. 기존 앱의 실제 화면별 스타일을 우선하며 새 브랜드나 테마를 만들지 않는다. 인터넷 수강생의 네이비 배경·민트 강조색과 밝은 톤의 학습 카드를 따르고, 오프라인은 해당 화면의 기존 공통 스타일을 따른다.

- 기존 `Gong Gothic Light` 본문과 온라인 화면의 `Hakgyoansim Poster B` 제목 글꼴을 직접 상속한다.
- 기존 공통 버튼과 바로가기 컴포넌트를 재사용한다. 기존 헤더·하단 메뉴·다른 화면의 CSS는 변경하지 않는다.
- 별도 iframe 화면 대신 기존 앱 DOM 안에 OX 내용을 렌더링한다. 스타일은 OX 루트 아래로만 제한한다.
- 홈 진입점은 큰 홍보 카드 대신 기존 바로가기 형식을 사용한다. 학습 화면의 큰 홍보 문구와 별도 영문 표제는 제거한다.

- 홈: 짧은 한 줄 안내와 하나의 주 행동, 필요한 진도만 표시.
- 풀이: 종이 문제집처럼 읽기 편한 넓은 지문 영역, O/X는 동일한 크기.
- 해설: 정답 영역 아래 원문 밑줄, 북마크와 메모는 보조 행동.
- 취약: 빨강·주황·노랑·초록의 등급을 텍스트와 함께 사용, 학습률은 중립색으로 구분.
- 좁은 화면부터 설계하며 본문 확대, 긴 지문, 긴 해설에서도 버튼과 출처가 가려지지 않게 한다.
- 실제 앱 내 시안에는 별도의 색상 테마 선택을 제공하지 않는다. 앞서 만든 독립 시안은 동작 구조 참고용이며, 로컬 앱에 적용한 스타일이 최신 디자인 기준이다.

## 8. 데이터 연결 원칙

- SQLite 앱이면 기존 뷰·트리거를 재사용한다. 웹 JSON 방식이면 사용자 저장소에서 동등한 채점·복습 상태·취약도 규칙을 구현한다.
- 사용자 인증 정보와 문항 콘텐츠는 분리한다. 첫 대시보드 조회 전에 사용자 프로필을 등록한다.
- 새 풀이 기록은 추가만 하고 과거 기록을 덮어쓰지 않는다. UTC 시각을 저장하고 화면에서 현지 시각으로 표시한다.
- 중복 요청에 대비한 제출 식별자, 진행 중 세트, 콘텐츠 버전은 새로 설계해야 하는 앱 데이터다. 현재 스키마에 이미 존재한다고 가정하지 않는다.
- 현재 앱은 별도 프레임워크가 없는 JavaScript 화면 렌더링 구조다. OX 기능을 모듈로 분리해 기존 렌더링·라우팅 방식에 연결한다. 구체적인 API와 저장소 마이그레이션은 구현 단계에 확정한다.
- 약 5.45MB인 전체 `questions.json`을 앱 시작 때 일괄 로드하지 않는다. 홈에는 요약만, OX 진입 후에는 과목·단원 및 해당 세트 데이터만 지연 조회한다. 정적 콘텐츠 캐시와 개인 풀이 캐시를 구분하고 로그아웃 시 학생 기록을 안전하게 정리한다.
- OX 전용 CSS 범위를 사용하고 기존 전역 스타일을 덮어쓰지 않는다. 서비스워커 변경은 기존 사용자 업데이트·콘텐츠 버전 호환을 확인한 뒤 적용한다.
- 문항 개정·정답 변경은 버전 정책과 기록 보존 정책을 정한 뒤 적용한다. 새 DB 번들로 사용자 DB를 덮어쓰지 않는다.
- 오프라인 지원·계정 간 병합·기기 간 동기화는 출시 형태에 맞춰 별도 확정한다. 네트워크 단절 때 안전하게 기록을 보존하는 방식부터 검증한다.

## 10. 이번 시안의 범위

시안은 수강생 홈 진입 카드·OX 오늘·단원·풀이/해설·결과·오답·취약 화면을 오갈 수 있는 검토용 모형이다. 기존 홈 영역은 진입 위치를 검토하기 위한 축약 표현이며 기존 화면의 전체 복제는 아니다. 65개 실제 단원과 단원별 대표 문항, 첫 단원의 추가 문항을 사용한다. 정답·해설은 제공된 JSON에서 가져온다. 예시 풀이 기록은 시안 안에서만 생성하며 실제 사용자 통계가 아니다.

문항 제출, 오답 재풀이, 복습 완료, 북마크·메모는 시안을 열어둔 동안만 반영된다. 영구 저장, 사용자 인증, 전체 2,960문항 학습, 서버 동기화는 구현하지 않았다. 시안에서 보이는 학습 집계와 상태 전환은 화면 동작을 검토하기 위한 것이다.

초기 산출물은 이 기획 문서와 `criminal-law-ox-preview.html`이다. 원본 PDF·원본 DB·JSON은 변경하지 않았다. 푸시·배포는 별도 최종 확인이 필요하다.

### 후속 반영: 기존 앱 안의 로컬 미리보기

사용자의 요청에 따라 기존 앱 `app.js`에 로컬 전용 홈 진입 카드와 `#criminal-law-ox` 화면을 연결했다. 세 수강생 홈에서 접근하며, 기존 인증과 헤더·하단 메뉴를 사용한다. 운영 호스트와 교사 화면에는 진입점이 노출되지 않는다.

- 실행: 프로젝트 루트에서 `node local-dev-server.js`.
- 주소: `http://localhost:3000/#criminal-law-ox` (기존 로컬 학생 로그인 필요).
- 홈의 ‘형사법 OX 시작하기’에서도 같은 화면으로 이동한다.
- `local-app-preview.js`와 `local-app-preview.css`가 실제 앱 안의 시안 콘텐츠·스타일이다. 별도 시안의 가상 헤더·홈·하단 메뉴는 표시하지 않는다. 이전 `local-app-frame.html`은 더 이상 앱에서 사용하지 않는다.
- `python build-local-preview.py`로 동작 모듈을 다시 생성한다. 앱용 CSS는 기존 디자인 기준에 맞게 별도 유지하며 전역 스타일을 수정하지 않는다.
- 브라우저에서 홈 진입 → 문제 풀이 → 채점·해설 표시를 확인했다. 기존 학생 유형·커리큘럼 UI·스터디카페 UI·배포 안전성 검사가 통과했다. 기존 설정 파일을 보존한 별도 작업 폴더에서 빌드 스크립트도 통과했다.
- 사용자별 영구 저장과 전체 문제 연동은 여전히 후속 구현 범위다. 예시 기록은 새로고침하면 초기화된다. 푸시·배포는 수행하지 않았다.

### 후속 기획: 문제별 전체 수강생 오답률

- 해설에 `전체 수강생 오답률 62%`와 `200명 첫 풀이 기준 · 124명 오답`을 표시한다. 풀이 중에는 숨기고, 답을 제출한 뒤와 오답 복습의 펼친 해설에서 확인한다. 기존 앱의 글꼴·색상 안에서 작은 정보 행으로 제공한다.
- 집계 대상은 이 앱의 오프라인·온라인 관리반·인터넷 수강생 중 해당 문제에 답을 제출한 사람이다. 전체 등록 인원을 분모로 삼지 않는다.
- 권장 산식: 해당 문항을 처음 풀 때 틀린 고유 수강생 수 / 해당 문항을 처음 푼 고유 수강생 수 × 100. 소수점은 반올림한다. 반복 풀이, 제출 재시도, 중복 클릭으로 분모·분자가 늘어나지 않는다. 개인 취약단원의 최신 답변 기준과 구분한다.
- 초기 표시 기준은 고유 수강생 10명 이상으로 제안한다. 미만이면 `집계 중`으로 표시하며 0%로 오인시키지 않는다. 문항의 의미·정답이 바뀌면 새 내용 버전으로 따로 집계한다.
- 실제 구현에는 인증된 서버의 풀이 저장과 문항별 집계 API가 필요하다. 수강생 식별자는 서버에서 확인하고 정오도 서버에서 판정한다. 문항 ID·내용 버전·수강생 ID별 첫 유효 제출 한 건만 집계하며 테스트·시안 기록을 제외한다. 화면에는 익명 집계만 전달한다. 집계 실패는 0% 또는 집계 중으로 위장하지 않고 재조회 안내로 구분한다.
- 현재 로컬 화면은 `question-stats-view.js`의 고정 예시만 사용한다. 수치마다 `예시 통계`를 명시한다. 로컬 정답 제출은 이 통계를 바꾸지 않으며 실제 수강생 데이터 수집이나 서버 집계는 구현하지 않았다.

### 후속 디자인: 문제 풀이 화면 정리

- 제목 아래 `미리보기 · 대표 문항 76개 · 예시 학습 기록` 문구를 삭제했다.
- 나가기·진행 문항 수·북마크를 배경 없는 한 줄로 정리하고 진행 막대를 얇게 표시한다.
- 단원명·문제 출처 번호·원문 맥락·지문·O/X 선택을 하나의 카드에 배치한다. 채점 후 해설도 같은 카드 안에서 이어진다.
- 풀이 중에는 하단의 긴 시안 안내를 숨긴다. 통계의 `예시 통계` 표시는 유지한다.
- `quiz-view.js`에서 풀이 화면을 관리하며 기존 채점·메모·북마크·이어서 풀기 이벤트를 그대로 사용한다. 기존 앱의 전역 스타일·헤더·하단 메뉴는 변경하지 않는다.

### 후속 정리: 해설의 보조 정보 축소

- 사용자 표시 영역에 맞춰 예시 배지·집계 인원·하단 PDF 출처·메모 입력 안내 문장을 화면에서 제거했다. 문항 데이터와 출처 원본은 보존한다.
- 오답률은 이름과 수치만 한 줄로 표시한다. 로컬 수치는 여전히 예시이며 툴팁과 접근성 이름에 이를 남긴다. 위의 예시 배지·참여 인원 표시 기획은 이 변경으로 대체한다.
- 메모 입력창은 별도 안내 문장 대신 접근성 이름을 제공하며 저장 기능은 유지한다.

### 후속 연결: 북마크 목록

- 단원 탭의 제목 옆 `☆ 북마크 N`에서 과목에 관계없이 저장한 문제를 모아 본다. 상단 네 탭은 유지한다.
- 목록에서 개별 풀기·모아 풀기·북마크 해제를 제공한다. 문제 화면에서 나가면 북마크 목록으로 돌아온다. 저장하지 않은 경우 빈 목록 안내를 표시한다.
- 기존 메모·오답 기록과 독립적으로 북마크만 해제한다. 현재 저장 범위는 시안을 열어둔 동안이며 새로고침 시 초기화된다. 사용자별 영구 저장은 서버 연동 단계에서 구현한다.

### 후속 정리: 오늘 학습의 오답 바로가기

- 오늘 화면에서 전체 학습 수치를 제거한다. 단원별 학습 진도는 단원 탭에서 확인한다.
- `복습할 오답 N문항` 전체 행을 누르면 오답 탭의 `복습 필요` 필터로 이동한다. 이전에 선택한 필터와 관계없이 같은 기준의 문제를 보여준다.
- 표시 수와 오늘 학습에 포함할 오답은 반복 오답·복습 필요 상태를 기준으로 계산한다. 다시 맞힘·복습 완료는 제외한다. 0문항이면 바로가기 버튼을 비활성화한다.

### 후속 위치 변경: 상단 북마크 버튼

- 단원 제목 옆의 북마크 버튼을 제거하고 형사법 OX 제목 행의 홈 버튼 왼쪽에 작은 별 버튼을 배치한다. 홈 버튼과 같은 28px 크기로 제공한다.
- 제목 행에서 모든 OX 화면의 북마크 목록에 접근한다. 시안을 다시 마운트하지 않고 내부 화면만 전환하므로 풀이·메모·북마크 상태를 보존한다.

### 후속 정리: 취약단원 한눈에 보기

- 큰 단원 카드와 반복되는 두 개의 그래프를 제거하고 단원명·최신 정답률·취약 상태를 짧은 행으로 나열한다. 위에는 취약(매우 취약 포함)·주의·양호 단원 수를 요약한다.
- 측정된 단원은 기존 취약도 순서대로 모두 보여준다. 단원 행을 펼치면 과목·학습 문항 수·최근 오답 수와 학습 버튼을 확인한다.
- 진단에 필요한 풀이 수가 부족한 단원은 `미측정 N단원 보기`에 접어둔다. 미학습을 0% 또는 취약으로 오인하지 않도록 미측정 행의 정답률은 대시로 표시한다. 기존 최소 5문항(5문항 미만 단원은 전체) 기준은 유지한다.

### 후속 수정: 객관식 파생 문항의 OX 표시

- 객관식의 `가장 옳지 않은 것은?`과 `다음 선택지의 내용은 옳다.`가 함께 노출돼 판단 기준이 혼동되는 문제를 수정했다.
- 로컬 시안의 파생 10문항을 문항별로 검토했다. 완결된 선택지 6개는 안내 접두어만 제거하고, 단어·연결형 선택지 4개는 원 질문의 판단 조건을 포함한 독립 명제로 표시한다. 판례 기준 조건도 유지한다.
- 표시 가공은 `question-display.js`에서 담당하며 풀이·오답·북마크가 같은 문장을 사용한다. 원본 ID·맥락·정답·해설·밑줄과 데이터 수량은 변경하지 않는다. 검토되지 않은 문항의 맥락은 자동 삭제하지 않는다.
- 전체 427개 파생 문항을 실제 서비스에 연동할 때는 나머지 문항의 사례·질문 조건을 개별 확인해야 한다. 이번 검토 범위는 로컬 시안의 10문항이다.

### 후속 배치: 해설 우선

- 채점 후 정오답 결과 → 해설 본문 → 전체 수강생 오답률 → 메모 순서로 표시한다. 오답 복습의 펼친 해설에서도 통계는 해설 아래에 놓는다.
- 오답률의 큰 강조 숫자와 강조색을 없애고 작은 보조 정보로 표시한다.

### 후속 구현: 단원 1회독 완료와 복습

- 실제로 단원의 서로 다른 모든 문항을 풀었을 때 `1회독 완료`를 표시한다. 정답 여부와 무관하게 풀이 완료이며, 최신 답변으로 단원 전체 정답률과 남은 오답을 계산한다.
- 오답이 있으면 `오답만 다시 풀기`가 주 버튼이며, 없으면 `다음 단원 학습하기`가 주 버튼이다. `전체 다시 풀기`는 기존 기록을 초기화하지 않는다. 다음 단원은 같은 과목의 목차 순서이며 마지막 단원은 단원 선택으로 연결한다.
- 완료한 단원은 목록에 `1회독 완료 · 정답률 N%`로 표시하고 누르면 완료/복습 화면이 열린다. 미완료 단원은 미풀이 문항부터 이어간다.
- 샘플만 풀고 단원 완료가 되는 것을 막기 위해 문항 수와 고유 풀이 수를 모두 검사한다. 최초 단원 `형법의 기본개념`은 원본 JSON의 55문항을 전부 포함했다. 다른 64단원은 기존 대표 문항을 유지하므로 로컬 번들은 총 119문항(파생 10, 원문 OX 109)이다. 원본 DB/JSON은 변경하지 않았다.
- 완료 화면 검토 주소: `http://localhost:3000/?ox-preview=chapter-complete#criminal-law-ox`. 로컬 URL에서만 55문항을 푼 예시 기록(정답 52, 오답 3)을 생성한다. 일반 주소에는 기존 초기 예시 기록을 유지한다. 서버/영구 기록을 생성하지 않는다.
- `chapter-flow.test.cjs`는 완주 기준·중복 풀이·오답 복습 후 정답률·전체 재풀이의 기록 보존·다음 단원·대표 문항의 미완료 처리를 검증한다.
