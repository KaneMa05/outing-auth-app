# OX 홈 카드·진입 로딩 개선 — 2026-09-17

기준 운영 커밋: `2464fa0`. 로컬 검증 완료 후 사용자가 푸시·배포를 승인했다.
이번 릴리스를 main에 푸시하고 연결된 Vercel 자동 배포로 운영에 반영한다.

## 확인한 원인

- Vercel 프로젝트의 함수 기본 지역은 `iad1`(미국), 운영 Supabase는
  `ap-southeast-2`(시드니)다. OX 요청마다 기기 검증 → 학생 활성 조회 →
  OX RPC의 세 번의 순차 DB 요청이 발생했다.
- 기기 검증이 이미 활성 수강생을 확인하며, OX RPC도 활성 상태·계정 유형과
  등록·공개 조건을 검사하므로 별도의 학생 활성 조회는 중복이었다.
- 운영 공개 문항 2,543개의 bootstrap JSON 크기는 PostgreSQL JSON 직렬화
  기준 1,311,695바이트였다. 읽기 전용 실행 계획에서 RPC 자체는 약 285ms였다.
  이는 네트워크·서버 시작·브라우저 렌더링 시간을 포함하지 않는다.
- 홈으로 돌아올 때 상태 캐시를 버려 카드가 다시 숨겨졌다. OX 화면은 앱
  전체가 다시 렌더링될 때마다 새 DOM과 bootstrap 요청을 만들었다.

## 수정

- `vercel.json`에서 `api/criminal-law-ox.js`만 `syd1`로 지정한다.
  다른 함수의 지역과 데이터베이스는 변경하지 않는다.
  [Vercel 함수별 지역 설정](https://vercel.com/docs/functions/configuring-functions/region#per-function-configuration).
- 중복 학생 조회를 제거해 순차 DB 요청을 3회에서 2회로 줄인다. 기기 검증과
  OX RPC의 현재 권한 검사는 매 요청 유지하며 서버 응답은 계속 `no-store`다.
- bootstrap에서 학습 화면에 쓰지 않는 출처 메타데이터를 제외한다.
  비교한 동일 응답은 1,027,217바이트로 약 21.7% 감소했다. 이는 압축 전
  데이터 크기 비교이며 실제 로딩 시간이 같은 비율로 감소한다는 뜻은 아니다.
- 홈은 같은 학생·기기에서 30초 이내 확인한 상태를 즉시 표시한다. 홈 복귀 시
  서버에 재확인하고 등록 해제·학습 중지가 확인되면 숨긴다. 오류는 캐시에서
  제거해 바로 재시도할 수 있다. 다른 계정·기기 또는 만료된 상태는 표시하지 않는다.
- OX 모듈은 이용 가능 상태를 확인한 뒤 미리 준비한다. 문항 데이터는 홈에서
  미리 조회하지 않는다. 동시에 진행 중인 bootstrap만 공유하며 완료 응답은
  요청 캐시에 보관하지 않는다.
- 같은 OX 방문 중에는 DOM과 학습 상태를 재사용한다. 다른 화면으로 이동하거나
  로그아웃하면 해제하고, 계정·기기가 바뀌면 다시 조회한다. 오류 화면의 재시도는
  새 화면과 새 요청을 만든다.

## 검증

- 전체 `npm test`, 기존 OX SQL/API 테스트 통과.
- 새 테스트: DB 요청 수, 응답 필드·답안 노출, 상태 만료·기기 변경,
  재확인 후 카드 숨김, 오류 재시도, bootstrap 중복 제거, 늦은 타 계정 응답 차단.
- 실제 API·SQL·화면을 사용하는 로컬 Chrome 검증: 재렌더링 중 bootstrap 1회,
  문제 풀이 상태 유지, 채점·해설, 관리자 등록·해제, 세 수강생 유형 접근 제한 통과.
- Vercel 공식 JSON 스키마의 함수별 `regions` 지원을 확인했다.
- 운영 DB에서는 읽기 전용 조회만 수행했다. 수강생·기기·등록 목록·학습 기록·공개
  설정을 수정하지 않았다. 스키마 변경이나 마이그레이션은 없다.

배포 후에는 OX 함수의 실제 실행 지역과 실기기 홈·진입 응답 시간을 확인한다.
