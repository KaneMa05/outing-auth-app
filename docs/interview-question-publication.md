# 면접 질문 공개 승인

## 인성 준비 항목 선택 연결

인성 기출의 준비 항목 연결은 선택 사항이다. 연결 없이 저장한 질문도 개별·일괄 공개 승인할 수 있다. 기존 `unclassified` 연결 질문도 재분류 없이 승인할 수 있으며, 해당 비활성 준비 항목이나 학생 노트 입력을 활성화하지 않는다. 마이그레이션에서 기존 질문·분류 연결·학생 노트를 변경하거나 자동 공개하지 않는다.

명시적으로 연결하는 항목은 기존처럼 유효한 활성 항목인지 검사한다. 알 수 없는 항목이나 다른 비활성 항목은 연결할 수 없고, 직무 질문에는 인성 준비 항목을 연결할 수 없다. 권한, 수정 충돌, 승인 취소와 내용 변경 시 재승인 규칙은 유지한다.

운영 반영 파일은 `20261031054439_interview_optional_personality_topics.sql`이다. 기존 `ip_service`의 연결 검증만 교체하므로 개별·일괄 승인과 질문 저장에 동일하게 적용된다. 관리자 화면에는 선택 연결 안내 및 미연결 표시를 추가했다.

검증: `tests/interview-optional-personality-topics.test.cjs`에서 미연결·기존 미분류·혼합 일괄 승인, 기존 노트와 연결 보존, 권한·충돌·직무 검증 및 마이그레이션 보존을 검사한다. `tests/interview-optional-personality-topics-browser.cjs`에서 체크박스 전체 해제 후 저장, 개별 승인·취소와 일괄 승인, 수강생 조회 및 모바일 안내를 검증한다.

관리자의 인성 기출·직무 기출 목록과 질문 검토 상세, 핵심인성 문항, 분류·채점 기준 검토 상세에 `공개 승인` / `승인 취소` 버튼을 추가했다. 상태는 `승인 대기`·`공개 승인 완료`·`보관`으로 표시한다. 선택한 대기 문항을 일괄 승인하는 기능도 유지한다.

기존 `ip_questions.status`를 사용한다. `draft`는 미승인, `published`는 공개 승인, `archived`는 보관이다. 기존에 공개된 문항은 이전 공개 승인을 유지하므로 마이그레이션 자체로 이용 중인 질문을 숨기지 않는다. 새 질문의 기본 상태는 승인 대기다.

## 관리자 동작

1. 질문·분류·직렬과 원문 해설을 확인한다.
2. `공개 승인`을 누르고 확인하면 학생의 새 조회·출제에 제공된다.
3. `승인 취소`를 누르면 승인 대기로 돌아가며 학생의 새 조회·출제에서 제외된다.
4. 질문·분류·인성 연결 항목·직렬이 바뀌면 서버에서 자동으로 승인 대기로 되돌린다. 수정한 상태로 `published`를 보내도 승인이 유지되지 않는다. 단순 상태 변경과 내용이 같은 재저장은 별개다.
5. 수정 중인 입력은 먼저 저장해야 승인 버튼을 사용할 수 있다. 보관한 질문은 승인 대기로 복원·저장한 뒤 승인한다.

질문 저장 화면에서는 새롭게 `공개`를 선택하여 저장하는 경로를 제거했다. 기존의 관리자 일괄 공개 API는 명시적 공개 승인으로 계속 동작한다. 분석 검토 완료나 채점 기준 검토 완료가 질문의 공개 승인을 대신하지 않는다.

## 서버 제한

`admin_question_publication` API는 서명된 관리자 세션과 `interview.write` 권한을 요구한다. `{id, revision, approved}`를 전송하며 브라우저가 보낸 역할·사용자 정보는 신뢰하지 않는다. 읽기 전용 관리자와 수강생은 승인할 수 없다.

새 `ip_question_publication_service`는 기존 편집기의 advisory lock → row lock 순서를 따르고 버전을 확인한다. 관리자가 확인한 뒤 다른 곳에서 수정된 질문은 `revision_conflict`로 거부한다. 승인은 기존 공개 처리의 연결 항목·직렬 검증을 재사용하고, 취소는 연결 항목이 비활성화된 경우에도 가능하다. 승인·취소 이력은 기존 `ip_history`에 남긴다. 함수는 SECURITY INVOKER이며 public·anon·authenticated의 실행 권한을 제거하고 service_role만 허용한다.

재승인 트리거는 `ip_questions` 테이블에 적용하므로 재분류 SQL 등으로 공개 문항의 내용·분류를 변경해도 동일하게 승인 대기로 돌아간다. 이전 재분류안의 ‘공개 상태 보존’은 이 마이그레이션 적용 후 수정된 공개 문항에는 적용되지 않는다.

학생의 일반 질문 조회·상세, 핵심인성, 직무·인성 모의면접은 기존 서버의 `status='published'` 제한을 그대로 사용한다. 기존 학생 작성 내용과 시작된 응시의 저장된 스냅샷·이력은 지우지 않는다. 이미 화면에 내려받은 자료는 새 조회 시 상태가 반영된다. 다른 수강생 유형과 일반 교사·관리자 기능에는 변경이 없다.

## 적용 순서

운영 반영은 AGENTS.md에 따라 사용자 최종 확인 후 진행한다.

1. `supabase/migrations/20261030071418_interview_question_publication_approval.sql` 적용.
2. API와 관리자 UI 배포. 관리자 모듈·스타일 URL 버전도 갱신했다.
3. 관리자 화면에서 문항 승인 → 수강생 조회, 취소 → 수강생 미노출, 수정 → 재승인 대기를 확인한다.

코드 작성과 검증 과정에서는 운영 DB를 변경하거나 푸시·배포하지 않았다.

## 검증

`npm run test:interview-publication`은 로컬 PGlite로 승인·취소·버전 충돌, 학생 목록·상세·핵심인성·모의면접의 상태 제한, 직접 SQL 수정에 대한 승인 무효화, 기존 승인·학생 답안 보존, 감사 이력과 HTTP/DB 권한을 검증한다. UI 테스트는 실제 DB와 연결한 관리자 컨트롤러에서 취소된 확인창, 성공·실패 상태, 미저장 입력 보호, 인성·직무·핵심인성 버튼과 읽기 전용 모드를 확인한다.

`scripts/interview-question-publication-preview.cjs`는 127.0.0.1에만 바인딩되는 가상 자료 검증 화면이다. 운영 계정·데이터와 연결되지 않으며 테스트 확인창만 자동 승인한다. 실행 시 기존 `tests/helpers/interview-db.cjs`와 동일하게 `PGLITE_MODULE`로 로컬 의존성 경로를 지정할 수 있다.
