1. 사용자 승인과 현재 범위

사용자는 여성 최초 샘플과 남성 3차 샘플을 청취하고 앱 반영을 승인했다.
이후 맥북 테스트 인계 문서 작성, 커밋·푸시·서버 배포까지 명시적으로 승인했다.
아이폰 실기기 테스트는 맥북에서 이어간다. Windows에서 완료했다고 안내하지 않는다.

변경 범위는 테스트앱의 실전 모의면접(Live) 면접관 음성이다.
직무·인성 연습의 기존 질문 녹음, 일반 배포 앱, App Store/TestFlight 버전은 유지한다.
새 목소리를 다시 생성하거나 기존 샘플에 피치·속도 변조를 하지 않는다.
립싱크, 질문 풀, 다른 연습모드 개편으로 작업을 확대하지 않는다.

목소리는 새 세션 시작 시 정한다. 진행 중인 세션은 종료 후 새로 시작해야 한다.

4. iPhone Debug 빌드와 실행

기존 Xcode·서명 팀·테스트 기기 설정을 유지한다. 새 클라우드 빌드나 스토어
제출은 필요하지 않다. 연결된 실제 iPhone을 대상으로 Debug 앱을 실행한다.
프로젝트를 재생성해야 할 때는 iOS 작업 폴더의 native/ios/App에서:
  xcodegen generate
  open RonparkStudy.xcodeproj

Scheme: RonparkStudy / Configuration: Debug / Bundle ID: com.ronpark.study.
Debug 앱 표시 이름은 '론박스터디 앱'이다. 기존 설치와 저장 데이터를 보존하며 갱신한다.
Release/App Store/TestFlight 업로드는 이번 요청에 포함되지 않는다.
Debug 기본 진입 주소는 https://outing-auth-app.vercel.app/interview?app=1 이다.
기존에 허용된 테스트 계정으로 로그인한다. 새 가짜 수강생 계정을 만들지 않는다.

실제 테스트앱 경로의 조건
- Debug 실행 인수 --ordinary-app-verification이 없어야 한다.
- Debug 웹뷰는 __ronparkMockTestApp과 X-Interview-Test-App: 1을 설정한다.
- InterviewAPI.swift의 네이티브 요청도 같은 표식을 보낸다.
- InterviewModel.swift가 배정된 아바타 파일명(interviewer-woman/man-1/man-2)을
  InterviewCall.interviewer로 전달한다. 서버 서명 actor에도 신원이 보존된다.
- API 키를 앱, Xcode 환경변수, URL, 대화나 Git에 복사하지 않는다.
  iPhone에는 기존 포털에서 발급한 단기 일회용 연결 코드/토큰만 사용한다.

기본 배정은 무작위다. 자동화용 고정 아바타는 원격 iOS 구현에서
INTERVIEW_VERIFICATION_AVATAR로 지원하지만, 유효한 단기
INTERVIEW_LIVE_VERIFICATION_CODE가 있는 검증 경로에서만 적용된다.
없는 코드를 임의 생성하거나 코드/학생 토큰을 문서·로그에 남기지 않는다.
무료 화면 데모나 기존 기기 내 연습 화면을 실제 Live 음성 검증으로 간주하지 않는다.

5. 실제 기기 확인 순서

가. 준비 화면에서 카메라·마이크를 확인하고 실전 모의면접을 시작한다.
나. 여성 아바타는 채택한 여성 음성, 두 남성 아바타는 채택한 남성 3차 음성을
    사용하는지 실제로 듣는다. 연령감과 음색은 청취로 판단한다.
다. 메인 2개 × (메인 답변 1 + 순차 꼬리질문 2) = 총 6문답을 확인한다.
    첫 꼬리질문 답변을 실제로 한 뒤 둘째 꼬리질문이 새로 만들어져야 한다.
라. 메인 질문과 꼬리질문의 면접관 목소리가 같은지 확인한다.
마. 면접관 실시간 발화 자막은 제외되고 질문 문구·응답자 자막은 유지되는지 확인한다.
바. 종료 후 음성이 멈추고 카메라·마이크가 해제되며 기록과 재생이 정상인지 확인한다.
사. 수강생 화면/학생용 API에 사용량·비용이 노출되지 않는지 확인한다.
아. 관리자 면접 기록에서 최종 사용량·비용·미확정 항목을 확인한다.
자. 기존 직무·인성 연습의 질문 녹음과 일반 앱 동작이 그대로인지 확인한다.

확인 결과에는 iOS 소스 SHA, 앱 빌드 정보, 아바타, 성공/실패, 문제 재현 순서를 남긴다.
실제 종료와 최종 사용량 수신이 확인되지 않은 세션을 완료·0원으로 기록하지 않는다.
유료 요청 결과가 불명확하면 자동 재시도하지 않고 먼저 해당 세션 종료 상태를 확인한다.

6. 비용과 권한

채택 전 Windows 샘플 작업은 최종 사용량 총 62초, API 계산액 $0.05166667이었다.
이 금액은 최초 남성/여성과 남성 2·3차의 네 세션을 포함한다. 음성 생성은 $0이었다.
기기에서 진행하는 Live 테스트 비용은 별도로 실제 사용량을 기록한다.
2026-11-11 확인 단가: GPT-Live 분당 $0.05, 초 단위. 별도 모델·도구 호출 비용은 별도.
session.usage.updated는 누적 값이므로 합산하지 않는다.
session.closed.usage.seconds 최종 값을 한 번 사용하고 WebRTC 초기화 15초를 다시 더하지 않는다.
실제 청구서·세금·환율·서버·저장 비용을 API 계산액과 구분한다.

선택한 voice ID는 Windows에서 생성한 OpenAI 프로젝트에 속한다.
운영 키가 같은 프로젝트에서 해당 음성을 쓸 권한이 있어야 한다.
운영 Secret을 추출하거나 보호를 우회하지 않는다. 권한 변경 직후에는 인증
캐시 전파가 대부분 15분 이내지만 더 걸릴 수 있다. 같은 오류를 연속 재요청하지 않는다.

7. 문제가 있을 때

- 음색이 기존 noeul/meridian이면 Debug 표식·아바타 신원과 서버 배포 SHA부터 확인한다.
- 음성 401/404는 서버 키의 프로젝트/권한/삭제 여부를 확인한다. iPhone에 키를 넣지 않는다.
- 첫 질문부터 소리가 없으면 기기 음량·오디오 출력 경로와 실제 session.started 여부를 구분한다.
- 무료 데모 성공, 로컬 빌드 성공, 준비 화면 성공만으로 실제 음성·꼬리질문 검증을 완료 처리하지 않는다.
- 립싱크는 보류 상태다. 기존 고정 질문 영상과 Live 음성 교체를 혼동하지 않는다.

9. MacBook 버튼 문구 후속 수정

최신 main 186ef59를 fast-forward로 가져오고 이 인계문서를 확인했다.
서버 테스트앱 버튼은 이미 '면접 준비하기'로 반영되어 있으나, 사용자 기기에서는
이전 '앱에서 모의면접 열기'가 계속 보인다는 보고가 있었다.
iOS 전용 브랜치 48af957에서 Debug 테스트앱 웹뷰의 기존 웹 캐시와
서비스 워커 캐시를 이 수정 버전에 한해 한 번 갱신하도록 했다.
쿠키·로컬 스토리지·학생 녹음은 삭제하지 않는다. 일반 앱 검증 인수에서는 실행하지
않으며 Release에는 캐시 갱신 코드가 포함되지 않는다.
