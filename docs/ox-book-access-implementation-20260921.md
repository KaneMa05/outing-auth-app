# 형사법 OX 교재별 이용 권한 구현

상태: 사용자 최종 승인 후 2026-09-21 운영 DB 적용 완료. 앱 배포는 연결된 main 푸시로 진행한다.

## 동작

- 관리자 ‘교재 구매 · 이용 수강생 관리’에서 학생 검색 → 교재 선택 → 구매 확인일·판매 확인 메모 입력 → 등록 및 개방.
- 형법(총론·각론), 수사·증거, 공판을 독립적으로 개방·중지. 여러 권 동시 등록 가능.
- 교재·이용 상태 필터, 학생별 최근 변경 이력 최대 50건, 변경 사유·처리자·시각 제공.
- 추가 구매는 다른 교재에 영향을 주지 않는다. 중복 등록을 차단하고 오래된 관리 화면의 저장은 충돌로 반환한다.
- 전체 이용 중지 상태는 교재 구매로 자동 해제하지 않는다. 관리자가 ‘OX 전체 재개’를 별도로 선택한다.
- 현재 이용 기간 제한 없음. 제안서의 365일은 확정되지 않았으므로 자동 만료를 구현하지 않았다.
- 기존 계정 대상이며 비수강생 가입, 외부 결제·인증코드, 새 판본 상품 관리는 이번 범위에 포함하지 않았다.

## 기존 이용자와 기록

- 마이그레이션 적용 시 `ox_members.allowed=true`인 기존 이용자는 세 영역의 `legacy` 권한을 부여받는다. 구매 내역으로 위장하지 않고 ‘기존 이용자’로 표시한다.
- 이전에 등록 해제된 계정에는 자동 권한을 부여하지 않는다.
- 기존 서비스 운영 스위치를 변경하지 않는다.
- 권한 중지 시 풀이·진도·북마크·메모를 삭제하지 않는다. 재개방 시 기록이 다시 보인다.

## 접근 제어

- 서버가 문항 → 단원 → 학습 영역을 조회해 권한을 판단한다.
- 기존 전체 bootstrap과 점진 로딩 bootstrap, 문항 본문, 채점, 정답·해설 상세, 메모 저장을 모두 제한한다.
- 단원, 문항, 진도, 메모 존재 여부, 통계, 오늘 풀이 수는 허용된 영역만 반환한다. 잠금 안내용 교재명은 세 영역 모두 제공한다.
- 구버전 관리자의 전체 등록 요청으로 신규 전 영역 권한을 만들 수 없다.
- 새 테이블은 RLS를 사용하고 브라우저 역할의 직접 접근을 금지한다. 서버 역할만 함수·테이블을 사용할 수 있다. 관리자 API는 쓰기 권한을 확인한다.
- 학습 도중 권한 거부 응답을 받으면 클라이언트의 문제·해설·메모·진도 캐시를 비우고 이용 상태 새로고침을 안내한다. 이미 열람한 내용 자체를 소급 회수하는 기능은 아니다.

## 검증 결과

- `npm run test:criminal-law-ox`: 기존 SQL/API 테스트와 신규 교재 권한 테스트 통과.
- 신규 테스트: 구매 조합 8가지, 기존 이용자 전환, 구·신규 로딩 경로, 미구매 상세·채점·메모 차단, 혼합 문항 요청 거부, 다른 학생 격리, 추가 구매, 부분 중지, 재개방 기록 보존, 변경 이력, 관리자 권한, 중복 등록·오래된 revision 차단, 브라우저 DB 역할 차단.
- `scripts/ox-books-ui-qa.cjs`: 실제 API·SQL·렌더러를 합성 계정/로컬 PGlite DB에 연결해 확인. 오프라인·온라인 관리반·인터넷 수강생, 관리자 등록·중지·이력, 공판 단권의 초기 영역, 잠금 안내, 학습 중 중지, 재개방, 추가 구매 새로고침, 읽기 전용 관리자 확인.
- 390px·1100px 화면에 가로 넘침 없음. 모바일 잠금 화면과 관리자 등록 폼 스크린샷 확인.
- 기존 `npm test`: 원본 Windows CRLF 파일을 정규식으로 읽는 성적 테스트에서 실패했으나, 현재 작업본을 별도 LF 검증 폴더로 복사한 뒤 전체 통과. 원본의 무관한 파일은 수정하지 않음.
- 별도 검증 폴더에서 `npm run build` 통과. 배포 직전 운영 사이트의 공개 설정으로 production 모드 빌드와 생성 설정 일치를 추가 확인했다. 원본 `config.js`는 유지.
- 변경 JS 구문 검사 및 `git diff --check` 통과.
- 운영 DB: 기존 이용자 3명에게 legacy 권한 9개와 이력 9개를 부여했다. 기존 등록 상태 지문, 풀이 195건, 진도 192건, 메모 6건, 최종 성적 237건 및 성적 지문은 적용 전후 동일했다. 기존 이용자 3명 모두 전체·점진 로딩에서 공개 문항 2,543개, 단원 65개, 영역 3개를 조회했다.
- 운영 Security Advisor: WARN/ERROR 없음. 서버 전용 테이블의 RLS 정책 없음 INFO가 49개에서 51개로 증가했으며, 신규 두 테이블은 브라우저 역할의 직접 접근이 차단됨을 확인했다. [Supabase 안내](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy).
- 실제 운영 마이그레이션 번호 `20260921113944`에 맞춰 로컬 SQL 파일명과 테스트 참조를 정렬했다.

## 최종 승인 후 적용 순서

1. 운영 마이그레이션 이력과 기존 이용자 수·학습 기록을 확인한다. 동시 관리자 등록 변경이 없는 시점에 마이그레이션을 적용한다.
2. `20260921113944_ox_book_access.sql` 적용. 기존 전체 허용자의 세 영역 권한 보존, RLS·권한 설정과 운영 Advisor를 확인한다.
3. API와 앱 자산을 함께 배포한다. 서비스 워커와 JS 자산 버전은 `20260921-ox-book-access`로 갱신했다.
4. 테스트 계정으로 단권·추가 구매·중지·재개방을 확인한다. 실제 수강생 권한을 임의로 변경하지 않는다.
5. 문제가 발생해 앱을 롤백하더라도 교재별 권한 검사가 없는 옛 DB 함수를 복원하지 않는다. 서버의 접근 제한과 기록을 유지한 상태에서 수정한다.

기존 작업 중이던 `final-scope-data.js` 수정은 그대로 보존했다.
