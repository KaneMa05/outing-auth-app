# RONPARK STUDYCAFE 출시 체크리스트

## 현재 상태

- 스터디카페 화면과 로컬 폴백: 구현 완료
- 온라인 학생 기기 인증 API: 구현 완료
- 전체 자동 테스트: 통과
- 운영 Supabase 스터디카페 테이블: 미적용
- 활성 온라인 학생(`id like '2%'`): 0명
- Git push 및 Vercel 배포: 미진행

## 1. 적용 전 확인

```powershell
npm.cmd test
npm.cmd run check:study-cafe
```

`check:study-cafe`는 읽기 전용이며 URL이나 서비스 역할 키를 출력하지 않는다. 마이그레이션 전에는 네 테이블이 `미적용`으로 표시되는 것이 정상이다.

## 2. 데이터베이스 적용

1. Supabase Dashboard에서 운영 프로젝트가 맞는지 확인한다.
2. 데이터베이스 백업 또는 Point-in-Time Recovery 상태를 확인한다.
3. SQL Editor에서 `supabase/add-study-cafe.sql` 전체를 한 번 실행한다.
4. 오류가 없으면 아래 명령을 다시 실행한다.

```powershell
npm.cmd run check:study-cafe
```

네 테이블이 모두 `준비됨`으로 표시되어야 한다. 마이그레이션은 기존 학생·출석·외출 테이블을 수정하지 않고 스터디카페 전용 객체만 추가한다.

## 3. 제한 테스트 계정

기존 학생 관리 화면에서 다음 조건의 테스트 학생을 한 명 등록한다.

- 등록번호: `2`로 시작하는 미사용 번호
- 상태: 활성
- 이름: 테스트 계정임을 구분할 수 있는 이름
- 직렬: 실제 온라인 학생에게 사용할 직렬 중 하나

학생 앱에서 비밀번호와 기기를 등록한 뒤 아래 순서로 확인한다.

1. 오프라인 학생 메뉴인 출석·외출이 표시되지 않는다.
2. 스터디카페에서 빈 좌석을 선택한다.
3. 과목을 선택하면 3초 카운트다운 후 타이머가 시작된다.
4. 일시정지 시간은 순공시간에 포함되지 않는다.
5. 과목을 종료해도 좌석이 유지된다.
6. 다른 과목을 시작하면 과목별 시간이 분리된다.
7. 좌석 비우기를 눌렀을 때만 좌석이 반환된다.
8. 다른 기기에서 같은 좌석을 동시에 선택할 수 없다.
9. 일간 랭킹에서 본인은 `나`, 다른 학생은 가려진 이름으로 표시된다.
10. 캐릭터 색상과 과목 편집 결과가 새로고침 후 유지된다.

## 4. 장애·복구 확인

- API 또는 새 테이블에 문제가 생기더라도 기존 관리반 출석·외출 기능은 영향을 받지 않아야 한다.
- 브라우저 연결이 2분 이상 끊기면 실행 중 세션을 마지막 서버 시각으로 마감하고 좌석을 정리한다.
- 단순 화면 장애는 배포 롤백으로 복구한다.
- DB 롤백은 스터디카페 데이터를 폐기해도 된다는 확인을 받은 경우에만 `supabase/remove-study-cafe.sql`을 수동 실행한다.

## 5. 공개 순서

1. 테스트 계정 1명
2. 내부 운영자 확인
3. 온라인 학생 2~5명 제한 공개
4. 하루 동안 좌석 충돌·타이머 누락·랭킹 집계 확인
5. 전체 온라인 학생 공개

Git push와 Vercel production 배포는 최종 승인 후에만 진행한다.
