론박스터디 면접 테스트 질문·예시 답변집
작성일: 2026-11-11 | 질문 세트: 20261111-test-only

사용 범위
현재 허용된 공채 테스트 계정을 기준으로 한다. 직무 3개, 인성 3개만 사용한다.
직렬별 이용 범위를 넓히지 않는다. 다른 직렬에는 원래 허용된 테스트 문항만 나타난다.
실전 모의면접은 인성 P1→P2→P3 순서로 진행하며 메인 질문마다 꼬리질문을 2개 생성한다.
총 9문답이며 조기 종료·연결 장애·10분 제한에 도달하면 완료한 부분만 기록한다.
꼬리질문은 앞 답변을 듣고 매번 생성한다. 이 문서의 예상 질문은 앱에 고정 주입하지 않는다.

모든 경험과 인물은 가상이다. 예시 답변은 음성 인식·문답 흐름 검증용이며 실제 지원자의 경력으로 저장하지 않는다.
아래 답변집과 시나리오 대본은 테스트 진행자가 읽는 자료다. 질문 목록 API와 Live 면접관에게 예시 답변을 전달하지 않는다.
직무 연습 판정은 저장된 원문 예시와 비교하는 기존 기능을 유지한다. 아래 예시로 운영의 채점표나 원문 답변을 덮어쓰지 않는다.
인성에는 단일 정답을 가정하지 않고, 실제 발화의 상황·행동·결과가 확인되는지 본다.

1. 직무 질문과 예시 답변

J1 | V-pass
문항 ID: q-1b0b4b1339e0cba9b893bc93

기본 예시
브이패스는 어선의 위치와 식별 정보를 육상에 전달하는 어선 위치 발신 시스템입니다. 출입항 확인과 조난 시 위치 파악에 도움을 줍니다. 주변 선박과 항해 정보를 교환하는 에이아이에스와는 구분해서 이해하고 있습니다.

확인할 핵심
어선 위치·식별 정보, 육상 전송, 출입항·조난 위치 파악이라는 관계가 전달되는지 확인한다. 장치가 구조 자체를 수행한다고 말하지 않는다.

일부 누락 예시
브이패스는 어선의 위치를 알려주는 장치입니다. 그 밖의 활용 목적이나 다른 장치와의 차이는 정확히 설명하기 어렵습니다.

명백히 잘못된 설명 예시
브이패스는 선박의 엔진 고장을 자동으로 수리하는 장치입니다. 위치 정보를 보내는 기능은 없다고 알고 있습니다.

J2 | 선위통보제도
문항 ID: q-d3a575d9f82bb682bd7014d8

기본 예시
코스렙은 우리나라 주변 해역에서 수색과 구조를 돕기 위한 자발적 선위 통보 제도입니다. 선박이 항해 계획과 현재 위치, 계획 변경 사항, 최종 통보를 전달합니다. 이 정보는 선박의 이동 상황을 파악하고 조난 시 대응하는 데 활용됩니다.

확인할 핵심
수색·구조 목적, 자발적 참여, 항해계획·위치·변경·최종 통보를 구분하는지 본다. 자동 위치전송 장치나 모든 선박의 관제 의무 신고와 혼동하지 않는다.

일부 누락 예시
코스렙은 선박의 위치를 알리는 제도입니다. 항해 계획이나 변경 통보까지는 기억나지 않습니다.

명백히 잘못된 설명 예시
코스렙은 어선의 엔진을 원격 제어하는 자동 장치입니다. 선박이 정보를 통보할 필요는 없습니다.

J3 | 깨진 유리창 이론에 대해서 아는가?
문항 ID: q-b77be4bbd97dd0b89bb1d7d4

기본 예시
깨진 유리창 이론은 방치된 무질서가 관리되지 않는다는 신호로 받아들여져 더 큰 문제와 연결될 수 있다는 설명입니다. 다만 작은 무질서가 반드시 큰 범죄를 일으킨다고 단정할 수는 없습니다. 현장에서는 작은 위험과 시설 훼손을 살피되 원인을 확인하고 적절하게 개선하는 태도가 필요하다고 생각합니다.

확인할 핵심
무질서 방치와 관리 신호의 의미를 설명하는지 본다. 모든 경미한 위반을 강하게 처벌하면 범죄가 반드시 사라진다고 단정하지 않는다.

일부 누락 예시
깨진 유리창을 빨리 고치는 것이 중요하다는 이론입니다. 무질서나 범죄와 어떤 관련이 있는지까지는 설명하지 못하겠습니다.

명백히 잘못된 설명 예시
깨진 유리창 이론은 작은 위반을 모두 강하게 처벌하면 큰 범죄가 반드시 없어진다는 법칙입니다.

2. 인성 질문과 예시 답변

P1 | 학창시절 동아리 활동은?
문항 ID: q-1a757da6894404dd4e00aaaa

구체적인 예시
대학교 봉사 동아리에서 지역 행사 준비를 맡았습니다. 처음에는 담당자가 정해지지 않아 준비물 확인이 자주 빠졌습니다. 저는 공유 체크리스트를 만들고 각 항목에 담당자와 마감 시간을 적었습니다. 행사 전날에는 담당자와 준비 상태를 확인했고, 행사 당일에는 준비물 누락 없이 진행했습니다. 이 경험으로 역할을 명확히 하고 중간에 확인하는 협업의 중요성을 배웠습니다.

피드백 확인점
행사의 규모나 동아리 이름을 AI가 임의로 덧붙이지 않아야 한다. 본인의 행동인 체크리스트 작성과 사전 확인, 결과인 누락 없는 진행을 구분한다.

추상적·보완 필요 예시
동아리에서는 열심히 했고 친구들과 사이가 좋았습니다. 맡은 일은 잘했고 좋은 결과가 있었습니다.

P2 | 실패했던 경험이 있나요?  / 실패를 통해 무얼 배웠나요?
문항 ID: q-220afd909dd6efe1c389fae1

구체적인 예시
조별 발표에서 제가 확인을 소홀히 해 통계 자료의 출처를 빠뜨린 적이 있습니다. 팀원에게 제 책임을 설명하고 발표 자료를 수정했습니다. 이후에는 출처 대조표를 만들고 두 명이 교차 검토하도록 제안했습니다. 다음 발표에서는 같은 누락이 없었습니다. 빨리 끝내는 것보다 확인 가능한 근거를 남기는 습관이 중요하다는 점을 배웠습니다.

피드백 확인점
실패의 원인과 본인의 책임, 수정 행동, 다음 결과를 실제 발화에서 찾아야 한다. 한 번의 경험으로 책임감·성격을 확정하지 않는다.

추상적·보완 필요 예시
실패는 누구나 하는 것이고 저는 실패할 때마다 성장했다고 생각합니다. 앞으로도 열심히 하겠습니다.

P3 | 행사를 해야 하는데 예산과 인력이 부족하다면 어떻게 할 것인가?
문항 ID: q-6b5c347c76f4ac625b16a37d

구체적인 예시
행사의 목적을 먼저 확인하고 꼭 필요한 프로그램과 줄일 수 있는 항목을 나누겠습니다. 예를 들어 안내 인쇄물은 줄이고 행사장 안내와 참여자 응대에 인력을 우선 배치하겠습니다. 조정안은 담당자에게 보고해 승인받고, 남은 인원별 역할과 시간을 정하겠습니다. 안전이나 기본 운영이 유지되지 않으면 무리하게 진행하지 않고 규모와 일정을 다시 협의하겠습니다.

피드백 확인점
목적·우선순위·승인·역할 분담·무리한 진행 중단이 연결되는지 본다. 실제 하지 않은 행동을 이미 수행한 것처럼 기록하지 않는다.

추상적·보완 필요 예시
인력이 부족하면 모두 더 열심히 하면 됩니다. 어떻게든 원래 계획대로 전부 진행하겠습니다.

3. 실전 모의면접의 진행 규칙

P1 답변 → P1 답변에서 꼬리질문 1 생성 → 그 답변에서 꼬리질문 2 생성 → 답변 완료 후 P2로 이동한다.
P2와 P3도 같은 순서를 적용한다. 메인 답변과 꼬리 답변은 별도 문답으로 저장한다.
꼬리질문은 최신 답변의 실제 표현을 근거로 삼고, 같은 메인 질문의 이전 문답을 참고한다.
아직 말하지 않은 경험, 평가, 모범답안, 점수는 면접관이 제공하지 않는다.
답변을 못 알아듣거나 생성에 실패하면 답변을 유지하고 안내한다. 꼬리질문을 생략해 다음 메인 질문으로 넘어가면 실패다.

5. 반영 상태

테스트앱 표식이 있는 인증된 요청에만 적용한다. 일반 앱의 질문 목록·기존 진행 규칙은 유지한다.
공용 서버에 테스트앱용 분기를 배포한 뒤 Debug 테스트앱을 갱신해야 한다.
연결 오류 수정 마이그레이션과 테스트 문항 제한 마이그레이션은 일반 요청에서는 기존 정책을 유지한다.
운영에서 테스트할 때에는 기존 허용 계정으로 로그인해 질문 3개씩과 실전 메인 순서를 확인한다.
